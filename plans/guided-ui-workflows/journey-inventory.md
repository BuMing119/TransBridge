# S01 用户旅程与现状基线

- **Feature**：`guided-ui-workflows`
- **Story**：S01 旅程、术语、线框图与可用性基线
- **证据日期**：2026-08-24
- **证据范围**：S06 开始前的 production UI、FR25 公开 coordinator/shell/view ports；不把并发开发中的后续 Story 改动当作现状
- **配套合同**：[ux-contract.md](ux-contract.md)、[wireframes.md](wireframes.md)

## 1. 测量约定

为避免把“点击数少”误当作“容易理解”，本基线记录以下指标：

- **D（用户决策）**：用户必须理解差异并选择一个业务分支，或填写完成任务所必需的任务输入。单纯切换页面、点击已经决定的主动作、关闭成功提示不计为 D。
- **M（模态窗口）**：一次 `exec()` 对话框、文件/目录选择器、`QMessageBox` 或输入框。普通顶层工具窗口和页面内投影不计为 M。
- **N（菜单穿越）**：为了找到任务入口而打开一次顶层菜单。快捷键和页面内主动作不计为 N。
- **返回上下文**：任务结束后用户能够继续操作的工程、翻译内容、筛选、选择和页面位置。
- **固定成功夹具**：单个已加载插件、默认翻译版本、配置有效、路径可写、远端权限有效；除旅程特别说明外，不引入额外冲突。

“确认提交”只有在用户仍需判断影响时才计为决策。成功提示的“确定”只计模态，不计决策。每个目标值都假定用户接受系统根据当前上下文给出的安全默认值；主动展开高级配置产生的额外选择不计入核心旅程。由于 S01 与 S06 在同一共享工作区并发开发，自动化 characterization 只冻结跨迁移仍必须成立的公开 intent/取消/恢复合同；本文件保存 pre-S06 菜单和路径基线，避免合法的 S06 导航替换导致基线测试反向阻塞开发。

## 3. 旅程明细

### J01 首插件并创建本地工程

- **用户目标**：第一次打开应用，选择 ESP/ESM/ESL，得到可编辑的本地工程。
- **当前入口**：启动后的 Workbench `+ 新建项目`，或“文件 → 新建项目…”，然后另行“文件 → 解析插件…”。
- **当前路径**：无 token 时先出现 ParaTranz 配置；V2 权威模式下点击新建只显示 `Legacy Project creation is disabled...`，无法继续。legacy 路径还需要工程名输入、创建成功提示和解析配置对话框。
- **当前默认焦点**：未显式定义；依赖 Qt 控件构造顺序。解析对话框的只读插件路径框不能直接输入，必须再找“浏览”。
- **取消**：关闭配置、工程名或解析配置均返回原 Workbench；已完成 legacy 空工程创建后取消解析会留下空工程。
- **失败/禁用反馈**：V2 使用状态栏英文消息；不是主动作附近的原因，也没有可恢复入口。
- **当前任务反馈**：解析进度借用 Step2 进度条；不进入统一任务投影。
- **当前返回上下文**：解析成功后激活新的 collection slot；legacy 工程与解析不是原子事务。
- **代码证据**：`MainWindow.__init__`、`ProjectCoordinator.new_project()`、`ParseCoordinator.parse_plugin()`。
- **P0 冻结目标**：开始中心的 `project.create_from_source`；先选插件，再在同页编辑建议工程名/迁移来源，正式提交前零持久化；成功进入 Workbench，失败保留 draft；不经过菜单、ParaTranz/LLM 配置或 legacy 建项。

### J02 继续上次工程

- **用户目标**：启动后回到上次本地工程和翻译版本。
- **当前入口**：隐式启动恢复；也可“文件 → 打开项目…”或 ProjectBar `打开项目`。
- **当前路径**：`MainWindow` 先处理 token，再调用 `ProjectCoordinator.init_workspace()`；有 token 时自动恢复无需决策，无 token 时必须先处理一个无关配置模态框。
- **当前默认焦点**：配置框/主窗口均未形成旅程级焦点合同。
- **取消**：关闭启动配置后仍会继续恢复；手动打开时，dirty 状态追加保存/放弃/取消确认。
- **失败/禁用反馈**：自动恢复失败主要落状态栏；没有最近工程/恢复失败卡片。
- **当前任务反馈**：复用 Step2 进度条，恢复源 ESP 后启动另一个 `ApiWorker`。
- **当前返回上下文**：工程、版本和筛选状态可恢复；筛选通过固定 3 秒 timer 延迟应用。
- **代码证据**：`MainWindow.__init__`、`ProjectCoordinator.init_workspace()`、`ProjectCoordinator._start_current_project_open()`。
- **P0 冻结目标**：有效工程仍直接自动恢复；缺少可选云端配置不阻断。失败才显示开始中心，并把失败原因和 `project.open`/最近工程恢复动作放在同一上下文。

### J03 导入已有译文

- **用户目标**：给当前插件/翻译内容套用 EET、XT、Strings 或已翻译插件中的译文。
- **当前入口**：“文件 → 应用迁移源…”。JSON 是 Workbench 的另一个 `导入JSON` 入口，语义与迁移源分离。
- **当前路径**：先有活动 slot；打开迁移配置，再用文件/目录选择器选来源并提交。
- **当前默认焦点**：未显式定义；迁移来源字段均为只读框加多个“浏览/清除”按钮。
- **取消**：配置或来源选择取消不会启动 worker；输入不会持久保留供下次继续。
- **失败/禁用反馈**：无 slot 时状态栏提示；菜单 disabled 时没有原因。迁移源内部多个异常被静默跳过，最终只能看到命中数。
- **当前任务反馈**：Step2 进度条；没有来源级成功/失败明细。
- **当前返回上下文**：仍在当前 slot，刷新 collection；筛选/选择能否保持依赖现有 Step2 刷新语义。
- **代码证据**：`ParseCoordinator.apply_migration()`、`ParseCoordinator._run_migrate()`、`WorkbenchWidget._on_import_json()`。
- **P0 冻结目标**：`translation.import_source` 从当前翻译内容附近进入，必要的系统文件选择器保留；选择结果回到页面内 draft，提交、取消、失败均保持当前工作对象。

### J04 AI 翻译并检查结果

- **用户目标**：对当前范围运行一次 AI 翻译，然后定位并检查结果。
- **当前入口**：“小工具 → AI 自动翻译”。
- **当前路径**：目标选择模态框 → 配置顶层窗口 → 模式/范围/覆盖和长期 provider 配置 → 开始；术语为空等条件可能追加确认。开始后配置窗口关闭并激活专用进度窗口。
- **当前默认焦点**：未形成稳定合同；大量长期配置与本次运行选项同层。
- **取消**：目标选择可取消；关闭运行配置不启动；运行窗口关闭行为由独立 RunController/worker 管理。
- **失败/禁用反馈**：无插件、无 API Key、无模型、无 ESP、空 scope 均通过阻塞消息框逐项发现。
- **当前任务反馈**：独立进度窗口；已实现启动后置前，但不属于全局任务中心。
- **当前返回上下文**：进度窗口可调用 `locate_entry`；报告、历史和再次运行分散在多个窗口。
- **代码证据**：`ToolWindows.open_ai_translator()`、`AITranslatorWindow.open_for_translation()`、`AITranslatorWindow.on_start()`、`start_translation_run()`、`WorkbenchWidget._track_ai_progress()`。
- **P0 冻结目标**：`translation.ai.run` 默认绑定当前翻译内容，记忆模式/范围/覆盖策略；主页面只显示本次 RunSpec 摘要和估算。缺配置在主动作旁解释；运行立即投影任务，完成后提供定位问题和再次运行。

### J05 ParaTranz 上传与下载

- **用户目标**：把当前翻译内容同步到已选择的 ParaTranz 云端项目，或下载合并远端译文。
- **当前入口**：“文件 → 上传至 ParaTranz/下载合并”；云端项目在另一个顶层标签中选择。
- **当前路径**：上传至少经过模式/备份/译文策略选择和完成提示；分类上传还可能追加文件选择与冲突解决。下载经过远端文件选择和完成提示。
- **当前默认焦点**：操作对话框各自定义，未形成共享预检/提交焦点合同。
- **取消**：各模态可取消；远端冲突检测完成后取消不会上传，但过程横跨多个 worker/对话框。
- **失败/禁用反馈**：无 collection/project/权限时 QAction 直接 disabled 且 tooltip 为空；直接调用 coordinator 也会静默返回。
- **当前任务反馈**：复用 Workbench Step2 进度；上传冲突检测和正式上传是两个 worker，没有统一 Run ID。
- **当前返回上下文**：仍在 Workbench，但完成结果是消息框；没有稳定的失败项筛选或云端项目导航。
- **代码证据**：`OperationCoordinator.update_operation_menu_state()`、`UploadCard.upload()`、`DownloadCard.download()`。
- **P0 冻结目标**：`sync.paratranz.upload`/`sync.paratranz.download` 打开同构操作计划；明确本地工程、当前翻译内容、云端项目、范围、覆盖与风险，只在最后提交一次；结果返回原工作对象。

### J06 写回当前插件

- **用户目标**：把当前版本译文写入新的插件或其他受支持输出。
- **当前入口**：“文件 → 写回文件…”。
- **当前路径**：选择输出类型；多版本时追加模式确认；选择保存路径；完成后消息框。错误前置校验散落在目标选择之后。
- **当前默认焦点**：未形成共享合同。
- **取消**：目标、版本模式或路径选择均可取消；正式 worker 启动前通常无写副作用。
- **失败/禁用反馈**：无 collection 时菜单 disabled 无原因；缺 ESP 路径/解析 plugin 在开始路径后用消息框提示。
- **当前任务反馈**：Step2 进度；完成/失败为消息框，不提供 artifact 导航或失败项重试。
- **当前返回上下文**：留在 Workbench；输出路径只存在于完成消息。
- **代码证据**：`OperationCoordinator.write()`、`WriteCard.write()`、`WriteCard._write_esp()`。
- **P0 冻结目标**：`publish.write` 操作计划预填当前版本和安全输出建议；提交前完成可写性、覆盖、备份和阻断条目预检；完成后在任务结果中提供打开目录/再次写回。

### J07 FOMOD 构建

- **用户目标**：从新版/可选旧版归档构建已翻译、过滤后的 FOMOD 产物。
- **当前入口**：“小工具 → FOMOD 安装包翻译”。
- **当前路径**：打开模态 FOMOD 面板，分别选择输入/输出，理解过滤预设、语言、AI 和归档格式后运行。
- **当前默认焦点**：未显式定义；主动作与所有高级选项同页。
- **取消**：关闭面板或文件选择器可取消；运行后没有统一取消合同。
- **失败/禁用反馈**：缺输入/输出使用消息框；worker 失败写入面板文本。
- **当前任务反馈**：面板内无限进度条；不进入 TaskRuntime/全局任务中心。
- **当前返回上下文**：结果停留在 FOMOD 模态面板；输出路径不可作为统一 artifact action。
- **代码证据**：`ToolWindows.open_fomod()`、`FomodPanel._run()`。
- **P0 冻结目标**：`publish.fomod` 作为开始中心/“同步与发布”专项操作计划；记忆低风险设置，突出新版归档与输出；运行后可离开页面并从任务中心返回结果。

### J08 失败恢复

- **用户目标**：看懂失败、修复输入，并安全恢复或重试。
- **当前入口**：没有全局入口；解析/同步/写回使用 Step2+消息框，AI 使用独立 checkpoint/进度窗口，Smart Assistant 另有自己的任务监控。
- **当前路径**：用户必须记住原入口并重做之前的选择；有些失败只显示状态栏或文本。
- **当前默认焦点**：无统一规则。
- **取消/失败反馈**：worker 能取消与否、报告和 checkpoint 能力各自实现；展示层无法解释为什么某些任务不可恢复。
- **当前任务反馈**：存在多个互不等价的任务视图；Smart Assistant 监控按字符串状态直接显示暂停/恢复按钮，不是全应用能力矩阵。
- **当前返回上下文**：不稳定，通常无法从失败项直接回到原词条/工程/输出。
- **代码证据**：`OperationCoordinator.run_worker()`、AI `RunController`、`TaskMonitorWidget`、`FomodPanel`。
- **P0 冻结目标**：`task.open_activity` 展示真实 owner/Run ID/capability/artifact；恢复只针对有效 checkpoint，重试调用 typed factory 创建新 Run ID，非幂等任务重新预检。

### J09 熟练用户快捷操作

- **用户目标**：不依赖教学文本完成解析、保存、AI/助手切换和常用上下文动作。
- **当前快捷键**：`Ctrl+O` 解析插件、`Ctrl+S` 保存、`Ctrl+R` 刷新云端项目、`Ctrl+Q` 退出；智能助手同时占用 `Ctrl+Shift+I` 和 `Ctrl+K`。
- **当前问题**：AI/FOMOD/写回没有快捷入口；同一智能助手有“小工具”和“视图”两个菜单项与两套快捷键；`Ctrl+K` 会阻塞后续命令搜索候选。
- **当前返回上下文**：助手是 dock；AI 是顶层配置/进度窗口；保存反馈短暂改变按钮文字。
- **代码证据**：`MenuBuilder.build()`、`ToolWindows.on_assistant_visibility_changed()`。
- **P0 冻结目标**：compact 模式不移除任何业务能力；一个 intent 只有一个 shortcut owner，重复入口只转发同一 intent；S12 再冻结命令搜索快捷键。

## 4. 入口与风险盘点

### 重复或孤立入口

- 智能助手同时存在“小工具”和“视图”入口，并占用两套快捷键。
- 新建/打开工程同时在“文件”菜单和 ProjectBar；当前没有稳定 intent ID 证明二者始终等价。
- JSON 导入在 Workbench，EET/XT/Strings 迁移在文件菜单，同属“导入已有译文”但用户模型不同。
- AI、词典、FOMOD 被放入“小工具”，与它们实际承担的翻译/发布任务不符。
- Task Monitor 只存在于 Smart Assistant，其他后台任务分别使用 Step2、独立窗口或面板内进度。

### 危险操作

- 写回、上传、下载合并的主入口与普通文件动作并列，影响对象和覆盖范围要进入弹窗后才可见。
- `移除集合` 会清空内存解析结果；虽有确认，但与高频 `导入JSON` 同层。
- 删除版本不可撤销；V2 有确认，但缺少可恢复性说明之外的替代方案。
- legacy 新建工程先写持久化再解析，取消/失败可能留下空工程。

### 无法解释的禁用或失败

- 上传/下载/写回 QAction 只设置 enabled，无 tooltip/reason。
- V2 新建工程入口仍可点击，但只显示英文 migration-gate 消息。
- 无活动 collection 的上传/下载/写回 coordinator 静默返回。
- 解析恢复失败会隐藏进度，但 `restore_parse_esp()` 的 `_on_error` 不向用户说明原因。
- AI 配置缺口按开始后的消息框逐个暴露，而不是在主动作旁一次解释。

## 5. S01 冻结结论

- FOMOD P0 入口保留在开始中心的专项任务和“同步与发布”，暂不升级成主页面。
- 正常自动恢复保留；开始中心只用于无恢复目标、恢复失败或用户主动返回。
- J01、J08 使用能力型替代目标，不用不存在的当前成功链伪造 30% 改善。
- 后续 Story 改变本文件基线时，必须同时更新 characterization test 或在新目标测试中显式标记被替代的现状断言；不能静默删除证据。
