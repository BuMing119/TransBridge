## 第九轮：统一工程恢复与持久来源成果（用户已授权）

实际场景：用户指定名为“老滚5”的工程，80 个 plugin.sse 来源、96,306 条词条、活动版本约 72 MB。当前代码单次只读 prepare 为 36.6 秒，来源准备 28.1 秒（含二进制解析 19.1 秒）、schema 6.2 秒；这是诊断采样，不是稳定性能基线，也不包含真实主窗口安装。

- [x] 阶段 1：重新审计实际来源与完整窗口入口；Astra 独立架构审查，固定修改前源码与隔离项目副本。
- [x] 阶段 2：持久来源成果存储与显式 codec；不可变 JSON 元数据及独立二进制 blob，完整保存基线、上下文和本地化依赖，内容 ID 校验，原子发布与损坏诊断。
- [x] 阶段 3：SourceRegistration 正式引用成果；统一 preparer、opener 与已有切换事务。新建/加源/更新生成成果；旧工程首次解析后在激活事务补引用，prepare 不修改活动工程。重启与版本切换恢复已保存来源，不读取外部文件。
- [x] 阶段 4：工程包保存、导入及源文件输出消费同一完整来源成果，包含 BSA 字符串；换路径/副本身份重定位，旧包在入口升级。外部源变化不使已保存工作状态失效，覆盖输出保持现有目标冲突处理。
- [x] 阶段 5：冷启动/切工程/切版本/源更新/包往返回归，新 Agent 独立复审；相同实际项目副本取得 5 份前后阶段样本，区分首次建立成果与再次启动；全库 Ruff/格式及增量记录完成。基线报告故障、单次 Windows 临时文件替换失败复验和清理证据见增量 010，不声称一次全套全绿。

契约与验收：Project/Variant 仍是唯一编辑及版本权威。成果保存来源修订的原始输入和解析基线，不保存后续人工编辑、不创建正式版本；多个版本共用引用。成果 ID 绑定完整内容及依赖闭包，同插件不同 STRINGS 不混用。打开命中引用不得通过 stat/hash/parse 访问 live 来源；权限仍按调用上下文检查。缺引用时首次走既有解析，缺源或身份不匹配保留恢复视图；损坏成果不得静默换成当前外部内容。codec/parser 版本显式管理，不反序列化可执行对象。成果写入先于工程引用事务，未引用成果不改变活动状态；暂不自动清理可能由备份引用的内容。

分工：核心 codec/store、注册/打开接线为两个编码切片；主会话处理包边界与集成。性能 Agent 使用固定 before 源码和只读原文件，所有可写服务均指向独占临时副本，不修改用户项目。初次建立成果成本与 warm restore 分别报告。72 MB 版本记录是否拆分以本轮测量决定，不为追求数字删除首次校验或引入第二套版本格式；UI 重复刷新仅在实测或必要集成中处理。

此轮扩展第八轮范围：跨次启动来源成果现在在范围内；第八轮“不增加跨次解析缓存”的条款仅描述当时交付边界。具体持久契约统一维护于 ADR-049，并取代 ADR-044 关于尚未保存完整来源的限制。

交付：来源成果/包/下游读取统一，独立审查补修真实折叠、旧包身份、嵌套元数据及重复持久化；实测再补修 codec 重复遍历和 schema 子校验器分配。最终联合 872 项为 871 通过、1 项 WinError 5，相关 9 项复验全过；后补 schema 执行测试最终 40 项及独立差分全部通过。静态检查通过。

实际“老滚5”准备阶段中位 104.762→58.453 秒（约减少44.2%）；完整重开仍中位92.169秒、事件循环间隔约5.755秒，尚未解决所有启动体验问题。最终首次建立成果155.904秒，新进程重启86.157秒，增加约669MB成果存储。不能把准备阶段降幅当作整体提速；基线完整耗时样本不足的限制见记录。

后续按需物化需独立实施契约：区分注册来源和已载入视图，统一选源 worker、投影一致性、桌面AI范围捕获及批量写出/迁移。现行这些消费者依赖完整 slots，不能仅删未选来源或置空 collection，否则会误判保存并缩小任务范围。延迟成果校验还需来源级错误/恢复状态；本轮保留正确完整视图，不将这一后续切片混作已完成。

实施约束：不引入新版本系统、全局无限缓存或跨进程的未验证信任；保存仍允许当前整文件格式，但同内容不反复做 schema/语义处理。完整 bytes 变化即不复用，不能用 revision、长度或 mtime 代替；保留磁盘实际读取、CAS、写后读回、日志完整性和冷恢复检查。当前 DTO 嵌套 dict 可变，证据必须私有并隔离交付；旧 schema 的只读读取不可冒充迁移完成。准备/发布同一候选只生成一次冻结词条数据，真正变化不能误命中。暂不增加跨次启动的解析缓存或未打开来源的全新存储机制；先去掉已测明的重复计算及未用索引工作，保证导出/编辑来源完整。

验收：正常打开未变记录完整 schema 各一次、同一保存版本 from_dto 一次、候选词条投影一次；同 revision 外部改内容、准备后替换/删除、返回 DTO 篡改、失败写入、旧迁移和冷日志损坏均不绕过保护；clean 保存及退出没有额外全量构建，保存期间新编辑仍 dirty。性能报告注明合成样本与完整 MainWindow 未覆盖部分，不凭计数宣称真实用户工程的加速倍数。
