# UI 交互审查整改

- 方案状态：草稿；依据 2026-10-12 审查结果及用户 bm-pilot 授权实施。
- 实施状态：S01～S04 本地完成；QA 与[增量记录](../../docs/changelogs/ui-interaction-remediation/story-01-to-04/2026-10-12-001-ui-interaction-recovery.md)完成。
- 关联：FR26、FR27、NFR1.6；[ADR-021](../../docs/adr/021-ui-presentation-modularization.md)、[原引导计划](../guided-ui-workflows/plan.md)。

## 目标和边界

修复本轮确认的八项交互问题：编辑失败丢草稿、选择范围误导、检查按钮不更新列表、快照重复触发、统计筛选丢搜索、顶部状态被挤掉、隐藏筛选难清除、错误通知难回看。

保留完整文件写回、领域提交、文件格式和现有任务运行时语义；不引入新的撤销系统，不改云端 API，不提交或发布。使用已有 Qt View/Presenter/Intent 边界和主题基础。既有未提交工作以本轮修改前副本区分，不归入本次增量。

## 当前事实及责任边界

- Step2 的筛选在 FiltersView，统计卡在 StatisticsSummary；后者遗漏 search_all。“检查”只写 AppContext.filter_state，无消费者更新列表。
- 表头把无选择显示为全部选择；实际写回按整个集合构建计划，应明确说明，不能截断输出文件来迎合选择状态。
- 快照信号在 Workbench 和 MainWindow 重复接线。
- 顶部上下文单行布局会把工程名称和保存状态压到零宽。
- Step2 超过 700 行，本次将行内编辑作为完整、可单测切片提取；不继续向其增加草稿职责。提取后仍为 716 行，保留现有标签、状态操作及兼容转发，避免把本次缺陷修复扩大成多个交互切片的迁移；残留风险是门面仍承担过多装配。后续增加标签/状态操作或术语能力前，应继续按这些职责提取，不能再向门面增加业务逻辑。MainWindow 仅修改必要的接线及通知转发。新增可恢复编辑与通知展示分别由专门模块负责。

## Story 04：可回看的错误反馈

- [x] 普通通知仍短暂显示；明确失败提示持续至关闭，并提供完整详情、复制和可用的重试入口。

- [x] 解析、保存、通用后台失败入口使用明确错误语义；解析恢复重新打开配置，用户选择文件并确认后才执行；不自动重放旧任务。
- [x] 插件读取失败不再显示成功 0 条；PluginParser 增加可选 raise_on_error，UI 显式开启，其他调用方保持默认行为；合法空插件仍允许解析。
- 文件：shell/status_presenter.py、独立通知展示模块、必要 MainWindow/parse coordinator 转发、parser/plugin_parser.py 及测试。
