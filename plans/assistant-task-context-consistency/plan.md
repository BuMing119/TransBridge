# 助手任务、上下文与本轮撤销综合实施计划

- 状态：本版本地实现与离线验收完成；用户已确认产品交互并授权 bm-pilot 推进。未测收益与未覆盖逆操作明确保留，不代表所有写操作均可撤销。
- 日期：2026-09-23。
- 需求：FR30.16～FR30.26；[需求](../../docs/requirements.md)。
- 架构：[ADR-043](../../docs/adr/043-assistant-turn-results-and-undo.md)，继承 ADR-040/041 的权威请求与不可变历史。
- 本计划统筹此前完整讨论，不以“撤销按钮”替代任务状态、压缩、缓存和 UI 分层改进。

## 目标与边界

执行恢复由代码及 DAG checkpoint 负责，模型只获取必要决策材料。普通状态变化不重复注入完整账本；压缩后新旧权威明确；完成详情可按权限查询；结果提交不依赖 Qt 回调先后。取消默认停止并保留已提交结果，不弹选择框；停止收尾后提示“本轮已停止”并提供“撤销本轮修改”。只有用户点击才撤销已提交修改，未提交临时投影仍按业务合同清理。

本轮指一条真实用户 ingress 及由它引发的模型回合、工具与图执行，不等同于一次 API 调用或整个长期 UserRequest。批量路由涉及多个输入时必须明确归属，不通过取最后一条消息猜测。对话、审计和撤销事实保留。撤销不自动恢复 DAG、不重放旧工具、不向模型注入 checkpoint。

不新增跨进程自动恢复、通用外部系统逆操作、无限重试或递归摘要。无法撤销的外部效果、记录缺失、范围变化和冲突必须可见，不将部分恢复显示为完整成功。原有工作区的聊天路由改动保留。

## 当前证据

- 既有上下文 S11/S13 已实现并曾通过 1263 项相关测试；S12 的后台读取后 GUI 完整复验/保存尚未解决；真实模型语义及缓存收益仍未测。
- 本轮前置核实 132 项取消/提交/checkpoint/查询测试通过。机制探针确认取消后清理失败被 cancelled 覆盖；恢复投影误走新业务写许可；commit 和 completed 之间有取消窗口。
- DAG 有 checkpoint，但常规助手身份和恢复入口未形成完整可恢复合同；completed 可能包含失败节点。保留这些事实，不据此承诺取消后恢复上一 checkpoint。
- Project/Variant 聚合提交和磁盘 save 不等价；整份 snapshot restore 会覆盖无关后续编辑，不适合作为本轮 undo。

## Story 与推进顺序

- [x] S01：复核必要决策材料、状态版本、压缩和缓存的既有实现及验收边界。
- [x] S02：取消清理失败与安全投影恢复。
- [x] S03：控制工具结果的应用层提交与取消终结。
- [x] S04：查询、回答及相交取消入口的后台接线。
- [x] S05：本轮身份、修改凭证与保守撤销资格。
- [x] S06：显式撤销执行、停止后提示按钮及恢复一致性。
- [x] S07：联合回归、故障注入、响应验证及增量记录。
- [x] S08：清理旧执行旁路与过时上下文策略（2026-09-23 实现及离线回归完成）。

依赖：S02 与 S03 可并行；S04 依赖 S03；S05 的归属/存储合同先于 S06；S07 汇合所有路径。没有完成证据不勾选。

### S01 必要材料与缓存

沿用 [assistant-context-compaction](../assistant-context-compaction/plan.md) S11～S13，避免重复实现。核对 decision_context、state_seq、旧格式显式失效、A→B→A、压缩重排和官方 OpenAI 自动前缀缓存。验证完成记录增长不扩大活动决策材料；恢复/撤销事实以新材料追加，不改写旧字节。原始选择范围和全摘要链仍可能超容量；真实命中率另测。落点为 application/assistant_context、context_runtime、assistant_prompt_cache 及现有测试。

### S02 取消清理失败与投影恢复

新增明确的取消清理失败异常/结果合同，不把所有取消期间网络异常都改成业务失败。runtime 对显式清理失败保留失败终态与原因；翻译/润色按此合同报告。恢复临时投影与新业务写入授权分离，但核验原集合及版本身份，优先最新权威状态，缺失时明确失败。已有正式提交保留，普通取消不触发本轮撤销。落点：application/tasks、tools/task_manager、tool_translator、独立投影恢复模块及 types 薄接线。验证真实 worker 取消→清理失败、取消 gate 下恢复、换版本及新编辑保护。

### S03 控制工具结果提交

详见 [Story 03](stories/story-03-control-results.md)。新增独立应用用例处理父调用校验、结果归属、幂等和单一终结，复用 Session 事务及 append_messages。查询与回答业务验证独立；旧回合不能提交成功。保存失败不向内存发布成功；同调用冲突显式报错。落点：application/assistant_requests/control_results.py、scheduler 的窄同步接口、相关测试。取消与提交由同一机制排序，不能只持 service 锁后放任 scheduler.release 穿过。

### S04 后台接线

将 state/history/result 查询与回答完成声明的核验和保存移到后台；GUI 仅接纳已提交的不可变结果。为应用层拥有的控制工具调用设置内存收尾归属，避免 SessionController 自动合成冲突取消结果；中断应后台完成取消及租约释放，前台立即停止调度。检查相邻 state/command/save_history 及关闭 drain，不以 shutdown(wait=False) 丢弃必要写入。落点：request_*_binding、conversation_manager/session_controller 和相应 Qt 测试。验收暂停点覆盖提交前取消、提交后通知前取消、切换、重复结果、保存失败与慢存储。

### S05 本轮修改凭证

详见 [Story 05](stories/story-05-round-undo.md)。明确定义 ingress→工作轮次→request revision/effect 归属。捕获实际修改的前后值及目标身份/修订，不将整个 Variant snapshot 直接恢复。凭证必须与业务提交有可核验关联；跨 Session/Project 保存失败不能谎称可撤销。旧轮次没有凭证时显示不可用原因。用户已选择本版扩展其他写操作，不限译文/阶段；分领域实现逆操作，见 [Story 06](stories/story-06-write-capabilities.md)。未适配操作阻止“完整撤销”承诺。落点：独立 application/assistant_requests 轮次凭证模块、项目命令适配、gate 薄接线、持久存储和故障注入测试。

### S06 撤销与提示

默认取消无选择框，已提交结果保留；停止完成后显示提示和“撤销本轮修改”入口。点击后核对无运行/未知操作、修改归属、目标版本与后续编辑；存在冲突不覆盖。按已适配逆操作恢复，保留审计；使相关执行许可和旧 DAG 恢复资格失效，不回退用户请求序号。重复点击幂等，重启/通知丢失能核对已发生操作，不盲目重试。若不能完整撤销，说明范围，不先执行部分恢复。落点：独立 undo 用例与薄 UI binding、请求状态投影；具体接口以 Story 05 和实现核验为准。

### S07 验证与记录

聚焦测试后联合运行 assistant_context、assistant_requests、smart_assistant、相关 UI、TaskRuntime 及项目逆操作测试；ruff check/format src tests，diff --check。实测 Qt 慢存储心跳，不能以函数在 worker 替代响应验证。记录命令、失败、未测范围；不调用付费模型、不自动提交/push。清理本任务临时目录，保留所有用户文件。

### S08 旧线路收拢

助手写操作必须具备撤销服务和可验证的真实用户轮次，缺失时在写入及 effect 登记前报错。旧任务保持可读，新的真实用户输入通过既有路由建立后续工作轮次；不补造旧操作的撤销归属。允许执行但不能安全撤销的领域操作仍登记归属并展示限制。独立 MCP/非助手工具继续使用领域命令，不伪造助手会话。

抽出新上下文正在使用的消息规范化和协议分组能力，删除生产中的旧选材组装策略；旧摘要生成/刷新入口退出正式流程，保留读取与迁移验证，必要的确定性重建仅用于验证旧摘要。新路由继续复用状态 reducer，移除无正式调用需求的旧直接事务入口，测试准备数据使用测试辅助代码。

验收：缺服务/缺轮次不写入、不登记半成品 effect；新输入后可正常执行并生成凭证；独立工具不强制助手身份；旧摘要验证不弱化；新上下文协议与压缩回归通过；路由取消/原子回执回归通过。先分模块测试，再联合助手测试及 Ruff；不改变远端撤销范围，不引入失败后切回旧策略的兼容层。

完成证据：联合助手回归 1351 passed / 1 skipped，补充任务运行时/MCP 入口 89 passed，合计 1440 passed / 1 skipped；跳过项需 Windows 符号链接权限。全仓 Ruff check/format 通过（1409 文件），两个当前投影评估脚本冒烟通过。旧摘要内部确定性重建仅作旧格式精确校验；测试 fixture 的路由 reducer 提交不作为模型执行入口。详见 [S08 增量](../../docs/changelogs/assistant-task-context-consistency/story-08-legacy-path-cleanup/2026-09-23-001-remove-legacy-execution-paths.md)。

## 风险、兼容与待定技术细节

- 不回写历史摘要和旧状态；新增工具 schema 变化可有一次缓存配置失效。
- Undo 跨存储原子性、输入归属及外部写入的可逆范围必须先核实；无法保证时显式禁止撤销，不能靠旧快照覆盖。产品已确认，不据此假装技术合同都已实现。
- 保留执行器已有提交屏障。清理失败与 undo 失败各自报告，不被普通 cancelled 隐藏。
- 模块超过仓库体量阈值仅加薄接线；新职责抽为独立、可测试模块。
- 回退采用保留新数据读取/诊断的方式；没有凭证的旧轮次不补造“可撤销”资格。

## 本地实现结果与明确限制

最终联合回归 1434 passed / 1 skipped；全仓 Ruff check/format 通过，1406 文件格式检查；详见[实施增量](../../docs/changelogs/assistant-task-context-consistency/story-02-to-07-implementation/2026-09-22-001-control-results-and-round-undo.md)。

控制查询、回答和路由都在后台裁决并持久提交唯一工具回执；慢查询及慢撤销相交的停止、取消、新输入、隐藏和路由响应有真实 Qt 心跳测试。旧 prepare_model_input、_still_admitted 和部分 clarify 仍有 GUI 权威读取；本版未声称整个助手已消除所有同步 I/O。

撤销已覆盖既有条目的译文/阶段/external_refs、标签及标签库、明确配置字段、pack_archive/write_back 的授权文件和本地 ParaTranz 绑定。新增/删除条目、来源结构、解包目录、词典整库、术语联合状态和远端效果不在安全自动撤销范围；执行前提示，停止后按凭证说明。不是“仅译文版”，也不声称完整覆盖所有写操作，详见 Story 06。

撤销按域先全部预检，再执行带版本核验的逆操作；中途失败保存进度、禁止自动重放，不承诺跨域原子性。完成后追加持久对话事实并合入当前模型历史；最近恢复材料由单调序号决定，旧工具成功记录和摘要原文不改写。撤销后的旧轮次不能直接恢复执行，新的真实输入可建立新轮次。

本地凭证/备份随实际操作积累，不进入模型上下文，自动清理/保留期限另需数据生命周期合同。真实模型语义、供应商缓存命中/成本和多样本 P95 仍未测，不以离线测试替代。

## 模型输入示例

以下为字段简化示例，不是线上请求抓包：

```text
system: 固定规则与工具定义
assistant: 历史摘要 S1（历史资料，不授予执行许可）
user: request_decision_context {state_seq: 11, active_items: [翻译进行中]}
tool: 翻译已提交 20 条
user: request_decision_context {state_seq: 12, active_items: [], settled_counts: {satisfied: 1}}
assistant: round_undo_receipt {status: undone, round_id: 用户输入甲}
```

程序最新事实是该轮已撤销；工具的成功仍是发生过的历史，不能当作译文现在仍保留。后续决策材料提供最近恢复状态。普通追加不回写 seq 11；压缩后保留最高序号当前材料、原摘要链及必要尾部，新旧以序号识别。请求/图 checkpoint、完整条目变更凭证和文件备份不作为上述模型材料发送。
