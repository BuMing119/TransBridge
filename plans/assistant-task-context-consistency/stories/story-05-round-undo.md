# S05～S06：本轮修改凭证与用户显式撤销

- 状态：本地实现，联合验证中；跨存储中断保留待核对事实，不自动重放。
- [Plan](../plan.md)、[ADR-043](../../../docs/adr/043-assistant-turn-results-and-undo.md)。

## 产品合同

取消默认保留本轮已提交结果，无选择弹窗；停止收尾后提示“本轮已停止”并提供“撤销本轮修改”。按钮只发显式撤销命令，不恢复执行。不可完整撤销时说明范围/原因，不能先部分执行。原对话和审计保留。

## 数据流与计划新增接口

1. ingress 接纳时建立工作轮次身份，与原始用户 message_id 关联。路由、修订和执行准入显式传递该身份；不得使用最新消息猜归属。一个输入可产生多个请求，长期请求也可跨轮次。
2. 在业务权威提交边界捕获前后值、目标身份/版本、effect 与 round 引用。条目、配置和本地绑定仅在凭证修订链连续时合并净变化；本轮重复覆盖同一文件暂明确拒绝合并，不重放任一旧前像。没有能力适配器的写操作记为不支持，工具能力声明不能代替实际凭证。
3. 凭证发布与业务保存核对：Project 内存 commit、Project 磁盘 save、Session 保存分别识别。写前意图/事后核验必须能处理崩溃；缺证据进入待核对，不能据当前值猜“上次撤销成功”。
4. 独立 undo 用例先确认所有关联操作已收尾且无未知结果，检测目标变化、后续同字段编辑与本轮之外的写入。使用最新权威版本的 CAS 逆修改，保护无关字段；不使用全量 snapshot restore。
5. 撤销结果与执行失效事实持久化，旧许可及 DAG 恢复不能重放已撤销工作；新模型材料说明撤销事实，不改写历史摘要。重复命令按持久操作身份核对结果。
6. UI 只显示后台生成的能力/结果投影；点击时重新校验，不把按钮可用状态当授权。

## 已有接口与限制

GuiProjectCommandFacade.replace_entry_states 支持译文/阶段的身份与 revision 检查；replace_entry_records 覆盖既有条目的译文/阶段/external_refs，标签另走 replace_labels；新增/删除条目不在此逆操作合同内。lifecycle.commit_active_variant 是权威内存提交，不等同 save_active。Snapshot restore 整体覆盖，不可直接使用。新增 work_round_id 显式保存真实用户 message_id；effect 准备与撤销归属登记同一 Session 事务，旧空归属不补造。

RoundUndoService 先持久化 pending intent，再执行业务命令，后像核验成功才记录凭证。撤销前全域预检，执行时逐域记录 applying/applied；文件部分失败保存 restored/remaining/errors。跨存储失败保留 undoing，禁止自动重试；全部完成才追加对话撤销事实。单调 undo_sequence 决定最近恢复材料，模型不按字典顺序猜新旧。已完成的重复调用返回既有结果，不再执行逆操作。

完整凭证和文件备份留在本地持久存储并随实际写入增长，不发送给模型。当前不自动清理这类审计数据；需后续明确保留期限和删除合同，不能为了缩小模型上下文误删恢复依据。模型仅接收有界的最近恢复事实，普通请求仍按既有归档机制处理。

## 验收与风险

覆盖多模型回合一个用户轮次、多输入路由、取消未提交写入、已提交后取消、同字段人工编辑、无关编辑、跨版本、外部副作用、不支持项、运行/未知结果、部分提交失败、撤销中崩溃与重复点击。纯查询轮次明确“没有可撤销的业务修改”。先固定支持能力，再接按钮；不以“按钮存在”代表完整恢复功能。
