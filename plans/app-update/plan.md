# 应用更新检查与安装

状态：草稿；S01～S03 本地实现与相关验证完成（2026-11-11）；扩大检查保留 1 项既有环境版本不一致，见 [S03 增量](../../docs/changelogs/app-update/story-03/2026-11-11-001-automatic-install-and-restart.md)。

## 目标与范围

Windows 安装版在启动后后台检查公开 GitHub 仓库 `BuMing119/TransBridge` 的最新正式 Release；侧边栏提供手动检查入口。有更高版本时显示提示，用户可查看更新说明，点击“更新并重启”后下载并校验完整安装包，再通过现有关闭流程保存工程、自动安装并重新打开新版。

本轮不创建或发布 GitHub Release，不自动安装未经用户点击授权的更新，不加入私人仓库令牌、增量补丁或安装失败后的自动回滚。源码运行可检查版本，但不得直接触发安装。自动安装保留进度窗口及 Windows 管理员权限确认，不重启操作系统。

## 现状与约束

- `pyproject.toml` 是版本源，打包时 `transbridge.spec` 收集包元数据；Inno Setup 使用相同版本号、稳定 AppId 与 `UsePreviousAppDir=yes`。
- 安装器需要管理员权限，保存用户数据。手动安装仍由交互选项控制启动；自动更新使用 `/SILENT`，安装器原有 `skipifsilent` 避免重复启动，重启由原用户进程负责。
- `MainWindow` 的关闭可能异步保存或被取消。只有成功进入 `QApplication.aboutToQuit` 后才能交接安装器。
- 当前工作区含其他功能的未提交修改；本计划只记录应用更新切片。

## S01：可信版本检查与下载

新增无 Qt 依赖的更新服务：只接受固定仓库、严格版本标签和命名匹配的 Windows 安装包；比较四段版本号。404 或未出现更高正式版时返回无更新。使用限时 HTTPS 请求，要求 SHA-256 校验信息，流式下载到用户可写的缓存目录；中断、取消、文件长度或哈希错误须清理未完成文件且不能返回可执行路径。

验证：模拟 Release API、异常响应、版本边界、资产缺失、恶意 URL、错误哈希和取消下载的聚焦测试；不依赖真实发布。

## S02：桌面入口与安全安装交接

侧边栏显示“检查更新”，发现新版后显示可访问的新版本状态。启动后检查与手动检查均在后台执行；手动操作显示无更新或失败原因。用户确认后展示下载进度与取消操作，完成后按 S03 自动退出安装。沿用窗口关闭中的保存和恢复逻辑；关闭被取消时撤销安装交接；关闭时取消正在进行的下载。独立 Windows helper 等旧进程完全退出并重新核对 SHA-256，再经 UAC 启动 Inno Setup。

验证：导航意图、状态提示、下载取消、关闭取消和安装交接的 UI 测试；相关主窗口与安装器回归。

## S03：一键更新、自动安装与重启

依据：2026-11-11 用户要求点击更新后自动安装并重启，并以 bm-pilot 授权端到端实施；无新增公共数据契约或 ADR。

验收行为：

- 点击“更新并重启”即授权本轮下载、保存退出、安装与重启。后台检查只提示；下载线程完全结束后才能自动进入关闭流程，失败、取消或迟到结果不得触发安装。
- 保存、编辑保护和后台任务关闭沿用现有生命周期。取消退出或有其他主窗口时保留已下载包，用户可再次点击“保存并重启”继续，不反复自动退出。
- helper 等待旧进程退出并校验安装包，以 `/SILENT /SP- /SUPPRESSMSGBOXES /NORESTART` 安装到当前应用目录，等待退出码。仅成功后启动当前路径的新应用，继承 helper 原用户权限，不经提权安装器启动应用。
- 取消 UAC、安装失败、需要重启 Windows 或应用启动失败时不自动继续，立即提示原因并记录错误与安装日志位置，下次手动启动也可查看错误。
- 普通手动安装行为、完整安装包命名和用户数据保持；更新逻辑升级随下一次发行进入安装版，现有旧客户端首次升级仍沿用其旧流程。

实施落点：`ui/shell/update_controller.py` 管理下载完成自动衔接，`update_dialog.py` 明确按钮与提示，`update_handoff.py` 等待安装并处理退出码/重启。已有安装脚本支持静默安装且跳过自动启动，无需改动。测试沿用 `test_update_download_flow.py`、`test_update_dialog.py`、`test_update_controller.py`、`test_update_handoff.py`；新增独立 PowerShell 执行测试验证 helper 的真实控制流、真实异步保存关闭集成测试及私人安装包的安装重启冒烟测试。

验证顺序：更新服务与 UI 聚焦回归 → Windows helper 分支执行与隔离安装包升级回归 → 主窗口关闭/保存相关测试 → 全库 Ruff 检查与格式检查。测试不得覆盖真实安装或操作真实用户数据。

## 依赖、兼容与回退

S02 依赖 S01，S03 依赖 S02。首次带更新功能的版本仍需由现有用户手动安装一次；之后发布更高版本才会触发自动提示。发布时需使用 `vX.Y.Z.W` 标签、对应 `TransBridge_vX.Y.Z.W_Setup.exe`，并提供 GitHub API `digest` 或同名 `.sha256` 资产。无 Release、断网或资产不完整时，现有翻译功能继续可用。更新器不得修改安装目录或用户数据；安装覆盖仍由原 Inno Setup 脚本负责。撤回本功能只需恢复下载后手动安装交接，不迁移业务数据。SHA-256 仅验证下载文件与发布信息一致；未来正式发布宜为安装包签名以提供发行者身份验证。helper 超时、校验失败、UAC 被取消或安装失败会提示并留下失败记录；已下载文件保留在用户缓存目录，不承诺自动回滚。
