# AI 任务完整恢复

状态：已完成（2026-10-24）

## 目标与现状

翻译、校对与混合任务在暂停退出、异常退出后能够继续；已保存候选不重复翻译，完整后处理阶段可接续，待确认结果及用户决定可以恢复，最终仍经过项目写入与保存边界。扫描、校验、恢复和序列化均在后台执行。

现有历史恢复仅支持纯校对。翻译 runtime-v2 检查点保存了候选，却未接入历史恢复；后处理阶段恢复尚未接到生产入口。旧任务的历史报告保存了范围与修改前内容，但没有完整执行配置。

## 契约与兼容

- logical task 与每次执行 run 分离；每个来源按完整 EntryKey 隔离。新执行不伪造旧运行指纹或提交证据。
- 新恢复记录保存去凭据配置、overwrite、源范围、原始输入和执行链。严格核对项目、版本、原文、上下文、当前译文与状态；跨进程重建的 revision 不单独作为恢复失败条件。
- 旧任务仅在范围与候选可以证明归属时提供兼容接续，明确使用当前配置；完整旧文件保持原样。旧候选重新进入校对/后处理，不能直接算作最终成果。
- 新任务在任何模型调用前持久化恢复记录。已通过完整流程的结果与用户采纳决定独立原子保存；恢复到确认/应用步骤时不再请求模型。
- 同进程启动预留和跨进程非阻塞 OS 锁防止重复接续；进程异常退出自动释放锁。取消不自动复活，重新开始创建独立任务。
- 不执行真实付费模型调用，不自动恢复并覆盖用户现有项目。本次不把 Python 原生崩溃原因的修复混入恢复功能。

## Story 与验收

1. **S1 候选发现与旧任务兼容**：新增只读 schema 1/2 检查点读取，验证校验链；历史报告与运行/源身份匹配，主翻译优先；损坏文件明确报错。测试旧历史、错误来源、篡改和截断。
2. **S2 执行恢复**：按有效候选排除已完成模型工作，名称准备、主翻译和完整后处理阶段接续；校对保持既有检查点兼容。测试模拟中断、仅剩余请求、混合来源、暂停取消及报告证据。
3. **S3 恢复入口与所有权**：所有任务创建恢复清单，历史与启动提示支持翻译/混合；严格输入核验，防重复启动；旧校对兼容。测试输入变化、已保存结果、模式/配置/范围与启动竞态。
4. **S4 结果与保存恢复**：独立存储有效结果和用户决定，恢复后保留待复核信息、拒绝项和确认状态；保存前后中断不会重复应用或丢结果。测试原子结果存储、恢复 ledger、预览与正式保存。
5. **S5 验证与记录**：聚焦测试后扩展到恢复/运行/检查点/UI 回归，20k 词条离线恢复验证，Ruff 检查；记录可归属本次的 diff 与兼容限制。

## 文件边界

- application/translation：检查点只读接口、旧任务候选适配、恢复结果存储与独占执行锁；不依赖 Qt。
- ui/tools/ai_translator：后台恢复准备、request 接线、进度窗口生命周期、结果恢复和历史发现。
- ai_translator / application 后处理：复用候选与完整阶段检查点，维持正式提交边界。
- tests：对应应用层、执行层、UI 生命周期测试。新独立模块承接新责任，已有大模块只作局部接线。
