# 打开文件、导入译文与导出文件窗口

- 日期：2026-11-08
- 状态：S01～S04 本地实现、相关验证及文档记录完成
- 依据：本会话的两个简化窗口原型及用户确认；沿用 [ADR-017](../../docs/adr/017-translation-io-kernel-v2.md) 的格式与发布边界。

## 目标与边界

工作台当前内容附近提供“导入译文…”和“导出文件…”两个独立入口。
导入窗口显示目标来源、单个译文文件及已有译文处理策略；导出窗口显示来源、输出格式与保存位置。
单文件输出位置提供“保存回原文件”和“另存为…”：前者填入可用的原路径，原格式一致时可用，仍通过导出时的覆盖确认和备份；后者选择新位置。格式选择框使用随主题配色的明显下拉箭头。
不展示匹配预览、填充/替换统计、检查清单，不要求用户点击“检查”后再确认。
必要的内容识别、唯一匹配、工程版本检查、发布预检、覆盖确认、备份及原子写出仍执行，错误按需显示。

ESP-ESM Translator XML、ESP-ESM Translator EET、xTranslator XML、xTranslator SST 保持独立。
DSD JSON 与 ParaTranz JSON 使用不同名称及序列化契约，不能因为同为 .json 而混用。
保存工程仍为独立动作；不修改 CLI/助手权限、持久化格式或用户样本，不提交 Git，不使用 computer-use。
此次不重新设计开始页、来源列表或工程创建；沿用已有入口。保留插件套用、Strings、批量等既有能力。

## 实施前事实

- 主工作台位于 `ui/workbench/widget.py`；“导入已有译文”当前打开多路径迁移表单。
- `ParseCoordinator.apply_migration` 捕获工程/版本/集合身份，`migration_coordinator` 后台准备并提交。
- 导出通过操作 facade、`WritePlanDialog`、后台预检和正式发布；当前需要手动预检。
- 原格式写出不允许任意跨格式转换；JSON 导出应为独立的条目序列化路径，复用统一发布保障。
- 任务开始时 Git 仅 `.transbridge/` 未跟踪（既有用户运行数据），不触碰。

## Story 01：独立导入译文窗口

- 新建聚焦的 `ui/workbench/translation_import_dialog.py`；由迁移入口使用，保留旧解析入口兼容。
- 单文件选择按内容识别，歧义 JSON 明确选择 DSD JSON 或 ParaTranz JSON；Strings 保留相关选项。
- 默认仅填空；显式允许替换已有译文。复用唯一匹配及锁定/隐藏条目保护，不新建原文或来源。
- 文件读取和匹配沿用后台 worker，提交前验证目标版本；再次导入不得因历史来源路径而静默忽略。
- 完成只报告结果状态；无可应用条目或错误应明确，不虚报成功。
- 验收：各格式真实导入、策略不同结果、目标变化拒绝、歧义/损坏拒绝、无预览或统计控件。

## Story 02：简化导出与独立 JSON 契约

- `write_dialog.py` 承担导出选项及简洁状态；点击导出自动后台预检，成功后提交，异常时停留并报告。
- `write_plan`/`write_feature` 连接原格式、允许的 SST 生成及独立 JSON 导出能力。
- JSON 输出使用已有两种 serializer，独立应用服务负责准备/验证/发布，不放宽原生 adapter 转换边界。
- 批量、备份、覆盖确认、原文/译文方案和来源快照保护保持；已有文件才显示必要覆盖决策。
- 验收：原格式与两种 JSON 内容正确；无需手动检查；失败不写文件；更改选项不能复用过期检查；重复点击不重复提交。

## Story 04：固定布局打开翻译文件入口（2026-11-08 用户确认）

替换仍使用旧完整表单的“解析插件”入口，统一为“打开翻译文件”。主来源支持插件、两种 XML、二进制 EET、SST、DSD JSON 和 ParaTranz JSON，按内容识别，歧义时明确选择；保留插件多选并允许逐文件处理。已有译文为单一可选来源，复用已实现的保留/替换策略和保护规则。

- 固定布局：译文区域始终存在，未勾选时禁用；格式、Strings 语言、跳过空原文和错误位置均预留空间，不通过折叠增减窗口高度；底部按钮保持原位。
- `ui/workbench/open_file_dialog.py` 负责表单；`application/io/open_file_options.py` 定义不可变选项；后台准备独立放入 `application/io/open_translation_file.py`，复用现有格式 adapter 和译文导入，不修改 codec。
- `ui/coordinators/open_file_coordinator.py` 管理后台任务及工程版本保护。ParseCoordinator 仅替换旧入口委托；不向已有大类加入新解析责任。
- 一次解析捕获完整来源和初始译文状态后正式登记，避免重读可变来源；提交绑定原工程/版本和修订，重复来源及切换工程不会静默覆盖。
- 保留旧 ParseConfig/旧内部解析方法供兼容调用，但主工作台和菜单不再打开旧 ParseConfigDialog。同步入口文案、需求、UI 文档及旧类注释，保留历史日志。
- QA：固定几何/取消/格式列表、真实格式打开+可选译文、损坏和歧义失败、工程变化拒绝、来源保存后可恢复、相关旧解析/导入/导出回归与 Ruff。
