# 智能助手使用体验修复

状态：S01～S23 本地实现、验证及增量记录完成。用户于 2026-10-16 再次调用 bm-pilot 后，已按九项修复方向补齐流程闭环，保留简洁默认界面。

关联：[对话式界面](../assistant-conversation-ui/plan.md)、[ADR-040](../../docs/adr/040-assistant-user-request-lifecycle.md)、[ADR-041](../../docs/adr/041-assistant-context-compaction.md)、[ADR-043](../../docs/adr/043-assistant-turn-results-and-undo.md)。

## 目标与边界

修复附件显示与实际输入不一致、确认卡结果失真、确认信息不足、冻结范围不可见、运行中发送入口缺失、长对话回看、会话导航和紧凑窗口问题。保留请求身份、审批、执行 lease、取消与安全撤销契约，不调用真实模型或远端服务，不修改既有术语工作线。

当前已用真实 Qt 和离线模型入口复现问题；基线智能助手 UI 回归 180 项通过，说明需补充场景覆盖。现有 ChatWidget/panel/orchestrator 已偏大，新职责放入独立、可测试模块，仅在原文件接线。

## Story 与验收

### S01 附件与补充输入

- 附件正文经过真实请求链进入模型输入，并作为参考资料而非系统指令；后续上传、移除生效，不伪称未提供的资料已可读取。
- 附件按会话隔离，预览、移除、清空标签一致；后台解析遵守会话代际，迟到结果不串会话。明确会话恢复与上下文预算边界。
- 运行中同时可点击发送补充和停止；Ctrl+Enter 与发送按钮语义一致。
- 文件：input_view、chat_widget 最小接线、context_builder/orchestrator 最小接线；独立附件状态、解析和上下文模块及测试。
- 验证：捕获离线 provider 实际输入；首次/后续附件、切换/清空/迟到结果、点击发送/停止及键盘回归。

### S02 可核对的确认与执行结果

- 工具、批量和计划确认展示可读操作名、目标范围、参数和变更预览。
- 原卡片随实际结果显示成功、失败、取消或待核对；不把后台任务接纳当作提交完成。
- 迟到结果不能更新新轮次/新会话的确认卡，既有审批与取消屏障保持有效。
- 文件：tool_card、plan_card、confirmation_view、plan_execution_binding、react_execution_binding，独立确认展示模块及测试；主会话统一接入 chat_composition。
- 验证：真实离线工具完成/失败、取消与会话切换回调、批量/计划参数预览。

### S03 提交范围与可读文案

- 请求显示提交时项目/版本/选择数量，能查看具体范围；工作台随后变更选择不改变已有任务展示。
- 旧存档没有展示信息时诚实显示已保存的标识或未知，不用当前选区猜测。
- 将用户操作文案改为直接可理解的“补充要求属于哪个任务”等措辞，保持实际控制命令不变。
- 文件：request_binding、request_view_refresh、request_progress_view、request_list_view、conversation_presentation；新增冻结范围展示模块与测试。
- 验证：换选区、恢复会话、来源消息消失/恢复、无选择及旧数据兼容。

### S04 长对话阅读与回看

- 用户向上阅读时新消息/流式内容不抢滚动位置；位于底部时继续跟随，保留明确回到底部入口。
- 保持可见控件数量上限，同时可分页回看更早内容；消息标识与请求卡定位仍正确，清空/切会话不残留历史。
- 长回答可选择复制；旧确认控件不得通过历史回看重新获得可执行能力。
- 文件：message_list_view、message_bubble、streaming_presenter；独立历史阅读模块；chat_composition 仅接线。
- 验证：超过 100 控件历史、流式输出期间阅读旧消息、分页位置与清空、主题往返及请求卡恢复。

### S05 会话、模型和窗口

- 正式会话首次用户消息可自动命名，手工名称保持；隐藏搜索时不留下不可见过滤条件。
- 长标题重命名保留完整内容；键盘可选择和管理会话。
- 模型配置变更后标题更新；最小尺寸与窄屏可见输入、附件、发送及停止操作。
- 文件：panel 最小接线、session_list_widget、session_binding、既有 session command facade、独立窗口展示模块及测试。
- 验证：正式保存端口、重复保存/手工命名、隐藏过滤、键盘与长标题、模型变更、最小/窄/桌面 Qt 几何。

### S06 以用户目标组织任务

会话始终提供任务入口；请求、事项和关联后台工作汇总到同一个任务，展示阶段、完成数量和待处理原因。暂停、继续、取消与定位原始消息可直接使用，诊断过程保留在次级入口。关联后台工作不得重复展示为另一个用户任务；无关联的历史后台工作继续可管理。暂停/恢复同时控制实际后台运行代次、线程暂停信号和持久等待状态；清理只影响当前会话可见的任务。实现落点为独立任务投影、request_progress_view、request_list_view、task_monitor、request_task_control 与 conversation_presentation；验证任务关联、控制身份、待确认和完成状态。

### S07 明示当前执行方式

输入区常驻“执行前确认 / 自动执行常规操作”选择，恢复会话时同步真实状态，并说明高风险操作仍需确认。沿用现有授权判断，不扩大自动执行权限。验证切换、恢复与窄屏。

### S08 可核对的变更预览

确认前展示原文、当前译文、拟写入译文和完整影响范围；无法确定的信息明确标注。快照来自该次确认上下文，禁止用执行后的当前值充当历史值。使用独立只读预览模块，保留底层审批和执行复验。验证真实字段、缺失数据、批量目标与取消。

### S09 可验收的任务结果

任务完成后提供稳定的结果/失败项入口；只根据保存的执行凭据展示变更、输出位置和撤销范围。定位词条须验证项目与版本，目录打开只使用实际结果路径；撤销指明任务与范围并沿用提交前重验。验证成功、部分失败、未知结果、无凭据、过期上下文与安全撤销。

### S10 根据当前状态引导开始

空态区区分未配置模型、未打开项目和可以开始三种情况，提供真实设置与打开项目入口及相关建议。没有宿主能力时不展示无效按钮。验证能力缺失、配置变化与打开项目后的更新。

### S11 一致的技能启动行为

快捷建议先进入输入区；技能先显示说明、可编辑请求和显式执行入口，发送未被接纳时保留内容可重试。界面统一使用“技能”；切换、清空会话和关闭时预览失效。验证编辑后输入、只预览不发送、拒绝后重试与会话隔离。

### S12 响应式布局与层级

强化任务目标、状态和主要操作的视觉层级；输入框按内容增长但有高度上限；窄屏保留会话标题、新建和会话切换入口，减少不必要边距。验证最小、窄屏和桌面尺寸下输入、发送、停止与任务入口无裁切。

### S13 在会话中检索历史

在消息流内分页回看、搜索完整历史并按消息 ID 跳转；提供整条消息复制，流式内容也可复制。历史只读，当前可见消息保持上限，回看时新内容不抢位置并提供回到最新提示。验证超长会话、跨页搜索、任务源定位、历史确认不可重执行以及清空/切换/销毁。

第二阶段按文件归属并行：交互与引导 S07/S10/S11/S12，确认与结果 S08/S09，历史 S13；主会话负责 S06、共享接线及联合验证。保留第一阶段和无关工作区变更，不提交或推送。

### S14 合并页首入口

- 标题栏只保留一行会话标题和模型；项目/选区、活动任务状态及会话菜单合并成紧凑一行，不保留整行任务按钮。
- 无活动任务时隐藏状态按钮；全部任务、历史搜索仍可从会话菜单进入，Ctrl+F 只作用于本助手及其子控件。
- 补充要求归属等待处理时维持明确提醒，任务详情按需展开，原始要求定位后收起详情。
- 文件：conversation_presentation、panel_header、theme_support 和独立聚焦测试。验收空态/进行中/待处理/完成态、菜单和快捷键、长上下文及窄屏。

### S15 按状态展示任务

- 正常运行默认只显示状态、进度与轻量详情入口；完整目标、提交范围、步骤、暂停/取消及原始要求在展开后可达。
- 完成态默认收起过程，只保留完成摘要与结果入口，尊重用户已手动展开的状态；失败、待确认和结果未知时主动展示相应待处理信息和必要行动。
- 用户手工展开/收起不会被普通刷新覆盖；任务控制、范围核对、失败项、结果与撤销能力不回退。
- 文件：request_progress_view 及必要的独立状态展示切片；验证状态转换、展开稳定性、控制/结果回调与源消息身份。

### S16 紧凑输入区

- 编辑器下方只有一行工具栏，包含附件、当前执行方式、更多、停止及发送；执行方式始终可见并与真实设置一致。
- 运行中没有补充文本时突出停止，有补充文本时可以发送补充；键盘发送和附件解析状态保持原语义。
- 次级按钮弱化默认边框，主要发送行为保留强调。480px 窄屏、中文字体、长输入及附件状态下无裁切、无窗口被迫扩宽。
- 文件：input_view、execution_mode_view、composer_editor；验证真实 Qt 几何与已有提交交互。

### S17 按需显示历史与消息操作

- 没有更早消息时历史工具条整体不占空间；搜索从会话菜单或 Ctrl+F 展开，可显式关闭/Escape，历史浏览位置保持稳定。
- 消息复制仅悬停或键盘聚焦时显形，不跳动布局、不丢失键盘访问，流式复制仍返回完整原始文本。
- 去掉逐条助手重复品牌名称，保留角色无障碍描述、定位标记和只读历史边界。
- 文件：history_navigation、message_bubble 及对应回归。验收分页/完整搜索/错误反馈/迟到消息/主题往返/键盘操作。

实施顺序：共用轻量按钮样式与本轮基线 → 三个互斥实现面（输入/标题、任务卡、历史/消息）并行 → 主会话合并页首和快捷键 → 联合 QA 与增量记录。视觉回退可按 S14～S17 局部恢复，不需数据迁移。

### S18 会话与输入隔离

所有接纳回调先核验会话及提交代际；旧失败不能覆盖当前草稿或停止另一会话。当前草稿已编辑时保留失败输入的可恢复内容。停止状态按会话隔离，目标会话的持久暂停状态仍生效。文件：request_binding 与独立接纳协调模块、聚焦 Qt 测试。覆盖同会话新草稿、切走/切回、迟到成功/失败、停止后换会话、关闭回调。

### S19 持久清空边界

清空结束当前对话轮次并设置持久的可见历史边界；后台任务、结果与撤销证据仍能从任务详情查看。切换、重开、旧投影保存和迟到接纳不能恢复被清空气泡；失败不能伪报清空成功。文件：chat_widget 最小接线、独立清空协调器、session facade/service 及历史投影；覆盖正式 Session 存储的清空/恢复/并发保存。新增可选状态字段兼容旧会话，不删除执行证据或用户文件。

### S20 确认启动与失败诊断

runtime 注册、执行器构造及启动失败均在原卡反馈并退出执行态；未确定是否发生副作用时不得自动重放。后台失败诊断独立于成功提交凭据持久保存，结果页显示真实原因。文件：plan_execution_binding、plan_task_runtime（按需）、task_events、result_review 及对应测试。覆盖提交前/后失败、初始化异常、租约失效和会话恢复。

### S21 恢复与输入澄清

终态失败/取消提供明确的“重新处理”入口，创建关联新请求并说明重做范围；上下文等待能看见原因及重试操作。仅目标歧义进入选择任务；结构错误进入可重试/放弃的重新规划路径，不重放已接纳事项。文件：request_list_view、request_progress_view、request_management_binding、request_view_refresh、routing/management/turns 和必要独立模块。覆盖旧存档、部分接纳、重复点击、状态变化、未知执行结果。

### S22 请求级技能与动态上下文

技能上下文随成功接纳的输入绑定到所属请求，失败无全局残留；普通请求不继承其他请求的技能。当前项目快照每轮刷新，静态规则与技能分别保留，已提交任务执行范围保持冻结。文件：skill_executor、input_acceptance、conversation_orchestrator、上下文投影及独立上下文模块；chat_widget/request_binding 公共接线由主会话完成。覆盖拒绝启动、异步接纳失败、技能后普通请求、跨项目、恢复与压缩。

### S23 服务就绪状态

模型名与服务可用性分离，统一检查模型/地址/凭据等必要条件；缺项时保留配置入口，发送前给出具体说明。文件：window_presentation、panel_header、onboarding/panel 必要接线与独立就绪投影；覆盖空配置、部分配置、配置变更、无宿主设置入口。

实施归属：主会话负责 S18/S19 及共享接线；三个互斥子任务负责 S20、S21、S22/S23。Qt 测试串行运行，纯应用测试可并行。已有大文件仅作局部接线；新职责抽取完整、独立可测切片。当前无公共架构选型或外部写入，不新增 ADR。

## 兼容与验证约束

S01、S02、S05 可按独占文件并行；主会话实现 S03/S04 并统一集成接线。新增展示字段采用向后兼容的可选投影，不改变存储 schema 或模型控制协议；旧数据降级显示而不猜测事实。附件、历史只在其明确拥有的会话内消费，读写仍走现有应用层。文档与共享索引只增加本任务条目，保留已有未提交内容。

最终验证以新增回归、智能助手 UI、相关 smart_assistant/application/persistence 测试和 `uv run ruff check src tests`、`uv run ruff format --check src tests` 为准；测试失败先判断归属，不混入无关修复。任务结束清理自建临时目录，不提交 Git。
