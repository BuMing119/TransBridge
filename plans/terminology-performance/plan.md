# 术语系统性能优化

- 日期：2026-10-15
- 状态：S01～S08 三批实现、五轮性能复测及相关回归完成；最终去重 1564 项通过、1 项真实账户测试跳过。冷首屏及部分 50k 事件间隔仍超性能预算，详见交付结果。

## 目标与基线

改善术语保存、分页、方案管理、搜索及方案投影的等待和主线程阻塞，并完成相同合成数据下的性能复测及功能回归。保留当前未提交的前轮修复和用户版本配置；本轮开始前完整源码快照用于区分增量。不新增依赖、不访问真实 LLM 或远端写接口，不自动提交。

2026-10-15 五次初测：1 万条单词保存 6.026 秒（5.741～6.270），5 万条启用同规模方案后的下一页 10.922 秒（10.645～11.401）；2 千映射管理器打开同步回调 3.230 秒（0.826～3.341）；5 万差异搜索每轮最慢单键中位 1.888 秒，5.5 万导入预览为 1.431 秒。环境 Windows 11 / Python 3.12.12 / Qt 6.10.0，真实 SQLite 和 offscreen Qt；原始样本已留存仓库外。设备其他负载未严格控制，复测报告中位数及范围，区分冷启动、热查询和后台完成时间。

- 最终联合回归 1563 passed、1 skipped、1 deselected（51.31 秒）；另补跑被排除的 50k slow 报告 1 passed（35.53 秒），去重 1564 项通过。专用 ParaTranz 账户未配置，live 合同跳过；未执行真实 LLM、远端写入、安装包或全仓库 pytest。Ruff check / format 覆盖 src/tests 1723 文件及七个性能脚本，diff 检查通过。最终测试在获准放开已确认的 Windows sandbox 硬链接/本机测试限制后运行，未改断言。
- 冷加载复测发现完整 JSON 的 C 扫描/编码和 GC 会跨线程阻塞 Qt，补充 no-op 对象边界、消费私有解析树与规范化后分块编码。独立审查和 70 项聚焦回归确认格式、摘要、未知字段、异常 cause、自定义 hook 顺序兼容；未调整全局 GC/线程参数或预算。真实 50k 冷加载最大事件间隔中位由 586ms 降至 219ms，但五轮四轮仍高于 200ms，最大 222ms。

## 交付结果与剩余预算

- 五轮中位：10k 保存 6.026s→2.305s；50k 同序列热下一页 10.922s→4.06ms；2k 映射编辑器同步打开 3.230s→35.79ms；50k 同步入站往返翻页 1.030s→74.52ms。完整原始样本、范围、测量边界与实际命令见[增量记录](../../docs/changelogs/terminology-performance/story-01-to-08/2026-10-15-001-terminology-performance.md)。
- 真实后台 10k 保存的最大 Qt 间隔 183ms；完整冷加载 10k/50k 仍超过 500ms，50k Qt 首屏完成中位 8.422s，部分事件间隔超过 200ms。没有把快速提交回调或预热后的首屏当作完整操作完成时间。
- 1k 保存中位约 218ms，初测 156ms，未显示吞吐收益；有界缓存的 50k 同序列峰值 RSS 增量中位约 195MiB，初测 176MiB。以上代价和预算残项保留，不宣称性能全面达标。
- 本轮保持 DB schema、canonical bytes、namespace 与对外兼容入口，不新增依赖或改动用户既有版本配置。若要求大规模完整冷首屏也达标，后续需独立设计可重建按行查询投影及事务/迁移验证，不能跳过摘要校验。
