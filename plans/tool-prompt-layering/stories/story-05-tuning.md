## 验收标准

- [ ] 根据 Phase 3 测试结果调整目录摘要措辞（目标：目录匹配准确率 >= 95%）
- [ ] 评估预加载工具数量（当前 2 个），若 Phase 3 发现某工具在 >80% 会话中通过 `get_tool_help` 加载，考虑加入预加载列表
- [ ] `build_tool_help` 返回格式微调（若 Phase 3 发现参数填充准确率低于 full schema 模式）
- [ ] 路由表关键词覆盖验证（7 行映射表是否覆盖实际用户表达，必要时扩充）
- [ ] 最终测量报告：system prompt 各段 token 精确数 + 节省比例

## 数据流

```
Phase 3 测试结果
    │
    ├─ 准确率对比数据
    │   ├─ >= 95% → 无需调整
    │   └─ < 95% → 逐个 namespace 检查目录摘要措辞
    │       └─ 修改对应 ToolSpec.summary → 重新运行 Phase 3
    │
    ├─ 跳过率数据
    │   ├─ < 5% → 无需调整
    │   └─ >= 5% → 强化路由表规则措辞
    │       └─ "不要凭目录摘要" → "禁止凭目录摘要"
    │
    ├─ 参数填充数据
    │   ├─ 表格格式准确率 >= prose → 保持表格
    │   └─ 表格格式准确率 < prose → 切换为 prose 段落
    │
    ├─ get_tool_help 调用频率
    │   ├─ 某工具 >80% 会话被按需加载 → 评估加入预加载
    │   └─ 某预加载工具 <20% 会话被使用 → 评估移出预加载
    │
    └─ 路由表命中率
        ├─ 全部 >= 90% → 无需调整
        └─ 某行 < 90% → 扩充关键词列
```

## 实现步骤

### 步骤 1: 分析 Phase 3 数据并确定调优项

**涉及文件**: 无（分析活动）

**实现要点**:
- 审查 Story 04 的全部测试结果
- 逐项对比调优触发条件，列出需要调整的项

**边界条件**:
- 若全部达标 → 跳过所有调优，直接产出最终测量报告

### 步骤 2: 逐项微调 + 验证

**涉及文件**: 根据步骤 1 结果确定

**实现要点**:
- 每次只改一个维度

**边界条件**:
- 调优 3 轮后仍不达标 → 记录为已知限制，不在本次继续优化

## 风险与注意事项

- **注意**: 调优是迭代过程，每次只改一项。改多项会导致无法归因效果
- **注意**: 预加载工具数量增加会减少 token 节省率，需权衡。当前 target 是 ~1,040 tokens（2 个预加载），每增加 1 个预加载工具约增加 150 tokens
- **注意**: 若最终跳过率无法降到 <5%，将路由表规则 3 升级为"**禁止**凭目录摘要直接调用非预加载工具，必须通过 get_tool_help 获取完整定义后再调用"（加粗强调 + 硬约束措辞）
