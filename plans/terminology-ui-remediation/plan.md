## 实施约束

三批顺序推进，每批内按无重叠文件职责并行。已有大模块先按审核交互、发布/历史、任务反馈等完整职责提取，再扩展；不使用 mixin 或新的通用大 Controller 隐藏规模。遵守 revision/CAS 与不可变快照，不通过放宽保护实现“可点击”。不新增依赖或数据库迁移，若既有合同不足优先增加窄应用接口。

配置与源码中的未知用户内容不改写；本轮产出单独增量记录，不修改既有历史日志。未运行的真实服务或压力门槛如实说明。

职责复核：窗口、方案编辑、审核、发布/历史交互、分页缓存/异步派发已按职责提取。既有 `bootstrap/terminology.py` 为 683 行，新增部分仅为 browse 依赖接线；`persistence/terminology/repository.py` 为 583 行/45 方法，此轮仅补现有仓库的窄查询委托，复杂查询放在 `conflict_queries.py`；`presenter.py` 为 453 行/36 方法，保持 UI 门面兼容，新增语义由独立应用模块承载。继续拆掉公共门面会扩大本次兼容风险；不再向它们增加实现职责，下一次新增业务能力时先提取端口分组/组合装配，并以现有合约验证兼容。
