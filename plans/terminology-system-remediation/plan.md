## 目标与边界

修复本次审查确认的九类缺陷：候选转草稿异常、重建丢失/遗漏决定、过期构建发布、窗口上下文混用、预览与导出不一致、同步认领丢失、全失败重试失效、检索开关旁路及重复平方级匹配。

沿用现有领域合同和版本线；保留人工决定、作用域、抑制及不可变历史。只修改本地实现与测试，不访问真实 ParaTranz 写接口、不提交或推送。用户既有 `pyproject.toml` / `uv.lock` 版本变更不属于本计划。

## S01：构建、草稿协调与发布输入校验

- 落点：`bootstrap/terminology_workloads.py`、`bootstrap/terminology_storage.py`、`application/terminology/`、`persistence/terminology/` 及对应测试。超过规模阈值的模块只保留委托，新的协调责任提取到独立领域模块。
- 改正 keyword-only 身份函数调用，使用现有归并规则协调新证据与人工决定；已有草稿按 revision 保护更新。
- 发布检查构建时的项目/版本及来源输入，而不是仅检查点击发布后的新快照；允许构建后合法人工编辑草稿。
- 验收：真实非空候选可成稿；已发布人工新增、译名、抑制和无证据项在重建后保留；已有草稿能接纳新候选；来源改变必须重建，旧持久化结果缺少足够证明时明确拒绝。
- 验证：领域/SQLite 回归、生产 runner 和 commit guard 测试、必要的持久化兼容验证。

## S02：译名方案窗口身份与一致投影

- 落点：`ui/tools/terminology/`、`ui/workbench/`、`application/terminology_profiles/` 及对应测试。
- 窗口全部功能使用同一 Project/Variant；主工作区切换时可靠失效或重建旧窗口，防止共享控制器继续操作另一工程。
- 预览和导出复用完整投影规则；明确条目特例优先于普通映射完整性检查。
- 验收：A→B 切换后不存在混合上下文；缺失映射诊断和输出一致；override 在预览与导出中一致生效；公共译文不被改写。

## S03：同步认领与重试恢复

- 落点：`application/terminology_sync/` 及其测试。
- 对确认的 ADOPT_LINK 持久化关联和共同基线，不发送远端写请求；所有有效 retry token 采用一致的基线校验，继续阻止真实状态变化。
- 验收：首次同内容认领后本地改译文规划 UPDATE_REMOTE；首次全失败后可重试；已成功项不重复写；真实远端、目标、版本变化仍被拒绝。

## S04：检索开关与有效术语索引

- 落点：`ai_translator/term_database.py`、`project_terminology_adapter.py`、`application/terminology/effective.py` 及聚焦测试；索引责任独立实现。
- 在读取/匹配公共入口统一遵守 retrieval_enabled；关闭时不加载动态库或项目术语，不直填、不生成强制术语要求。
- 建立规范原词和作用域索引，消除合并中的逐词全库扫描；缓存按不可变快照/作用域隔离，不缓存易变化的 legacy 合并结果。
- 验收：开关关闭的完整翻译仍由模型处理；开启后的匹配行为、别名、抑制、插件优先级保持一致；快照更新不复用旧索引；复测 6000 术语/5 条文本场景。

## S05：验证、兼容与记录

- 每条修复先补能捕捉原缺陷的回归，再运行相关领域、持久化、UI/翻译/同步集成测试；运行全库 Ruff 检查、格式检查和 diff 检查。
- 不以测试数量代替行为验证；网络和沙箱限制单独记录，必要时申请仅用于本地测试的执行权限。
- 发布历史不原地修改；任何新构建证据字段均须保留旧数据读取能力，不能证明 freshness 的旧构建要求重新构建。
- 用 bm-chronicle 按实际 diff 记录改动及验证；清理本任务临时目录。
