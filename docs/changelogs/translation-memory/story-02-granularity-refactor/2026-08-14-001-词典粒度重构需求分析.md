# 001: 词典粒度重构需求分析

**日期**: 2026-08-14
**类型**: 改
**关联**: Epic: 翻译记忆（词典）系统 > Story 02: 词典粒度重构（一文件一 mod + 多词典组合查询）

## 修改文件

### `docs/requirements.md` (改)
- **修改内容**: 重写 FR15.1.1「翻译记忆数据模型」——从「两档 scope + scope_id 标签的大库混装」改为「一文件一 mod + 单表权威对象 + 双索引」：词典以模组文件（.esp/.esl/.esm/txt）为粒度，存为 `.tbdict` 文件（内容 JSON）；scope 从「切割维度」降级为「单值属性标签」（project/global，支持 GUI 切换）；词条主键改为 `sha1(mod名|原文)`（不含 scope，与位置解耦）；新增持久化字段 `source_mod`（来源 mod 名）与 `form_id_with_plugin`（完整 FormID 含插件名）。
- **原因**: 用户明确要求词典「大家共享使用」「一个 mod 对应一个词典文件」，当前大库混装模型无法按 mod 隔离、无法作为独立文件分享；经技术议会（5 专家×2 轮）评审确认「词条缺乏 mod 来源身份」为根本缺陷，需结构性重构。

### `docs/requirements.md` (改)
- **修改内容**: 新增 FR15.1.6「词典粒度重构（多词典组合查询）」6 个子需求：①一文件一 mod（严格绑定，文件名=mod 名）；②多词典全查兜底（同名 mod → 其余 project → 其余 global）；③冲突可视化仲裁界面；④scope 修改 GUI；⑤分享/导入（导入/导出/打开目录三按钮）；⑥旧数据弃置（不迁移）。并在需求变更历史表追加本次重构记录。
- **原因**: 将议会结论与用户逐条确认的 13 项设计决策固化为可验收需求，作为后续 ADR/方案/编码的契约基础。
