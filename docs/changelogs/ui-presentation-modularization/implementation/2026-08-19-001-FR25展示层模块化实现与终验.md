# 001: FR25 展示层模块化实现与终验

**日期**: 2026-08-19
**类型**: 重构/测试/文档
**关联**: Epic: UI 展示层模块化 > FR25 / NFR1.5 > Story 01～08

## 目标

按 ADR-021 和 `plans/ui-presentation-modularization/plan.md` 完成 UI 上帝窗口拆分，在不改变公开入口、业务状态所有权和用户可观察行为的前提下，把 MainWindow、Workbench、AI Translator、Smart Assistant 及其余超重 UI 收敛为 View / Presenter-Coordinator / Binding / Composition 功能切片，并用依赖、生命周期和原生 Windows 性能门禁完成终验，为 FR24 UI Foundation 提供稳定接入面。

## 修改文件

### `src/transbridge/ui/presentation/`、`scripts/audit_ui_modularity.py`（增）

- **具体变化**: 新增 Qt-free 的 ViewPort、ViewState、UiMessage、BusyState 和幂等 Subscription/Binding 合同；新增 UI 模块化静态审计，覆盖规模门禁、跨组件私有访问、parent traversal、View 直连 infra/persistence、模块级可写 UI singleton 和 import cycle。
- **原因**: 先建立可执行的依赖与生命周期边界，避免仅通过移动方法或改名 controller 降低文件行数。

### `src/transbridge/ui/main_window.py`、`src/transbridge/ui/shell/`、`src/transbridge/ui/coordinators/`（改/增）

- **具体变化**: 将菜单构造、状态呈现、工具窗口复用、窗口关闭协议，以及解析、操作和项目协调迁入显式 owner；`MainWindow` 保留原公共入口并收敛为顶层布局、导航和 composition shell。
- **具体变化**: 工具窗口统一管理复用、激活和 dispose，coordinator 通过公开 Workbench / application ports 工作，不再依赖跨组件私有字段。
- **原因**: 消除约 2140 行 MainWindow 中混杂的业务编排和资源生命周期职责，同时保持既有 import 与用户行为兼容。

### `src/transbridge/ui/workbench/`、`src/transbridge/ui/workbench/cards/`（改/增）

- **具体变化**: Step1 拆为 SourceInputView 与 ParsePresenter；Step2 拆为 Filters、TranslationTable、Labels、EntryMenu、Progress 等 View/Presenter 切片；上传、下载和写回卡片接入 OperationCardPresenter 及独立表单 View。
- **具体变化**: `WorkbenchWidget` 与 Step2 新增公开的 selection、filtered projection、entry locate 和 labels ports，供 MainWindow 与 AI Translator 使用；旧类与 import 路径继续作为兼容 facade。
- **具体变化**: TranslationTable 使用 parent-owned single-shot timer、render generation 和关闭保护；销毁时停止批次并释放 pending 引用，迟到批次不访问 deleted QObject。
- **原因**: 保留大集合增量渲染、row identity、selection 和 projection 语义，同时移除对 `_step2`、`_table`、列常量等私有实现的耦合。

### `src/transbridge/ui/tools/ai_translator/`（改/增）

- **具体变化**: AITranslatorWindow 拆为 Config、Scope、PostProcess、Run、Result 的 View/Presenter/Controller；具体控件由 View 持有，Presenter 负责规则分类、估算、workload 和结果映射。
- **具体变化**: RunController 显式持有 mixed/polish worker 与 progress owner，拒绝重复启动，终态释放，关闭时取消/停止；run-id/owner guard 丢弃重跑或关闭后的迟到信号。
- **具体变化**: AI Translator 仅消费 Workbench 的公开 `filtered_entries()`、`locate_entry()` 等窄端口，不再查找 MainWindow 或导入 Step2 私有 helper/常量；正式结果提交继续保留 V2 identity envelope。
- **原因**: 将配置、作用域、执行和提交的责任及生命周期分开，避免 View 构建 workload 或窗口直接拥有隐式跨组件依赖。

### `src/transbridge/ui/tools/smart_assistant/`、`src/transbridge/smart_assistant/conversation_orchestrator.py`（改/增）

- **具体变化**: ChatWidget 拆出 composition、message list、streaming、session、task、confirmation、input 和 lifecycle binding；保留 ChatWidget、Panel 及既有 bubble facade 公共入口。
- **具体变化**: 会话轮次使用 generation guard，取消、切换和 shutdown 后的排队 chunk/finish/error 被丢弃；Task 更新采用事件通知与 100 ms single-shot 合并刷新，不再使用持续 UI polling。
- **具体变化**: Dock 点击关闭改为隐藏复用，应用退出时由 ToolWindows 统一 dispose；真实 worker shutdown 支持 wait/timeout，关闭后的 binding、timer 和 dispatcher 可幂等释放。
- **原因**: 保证 SessionController → Orchestrator → ToolExecutionHandler 的单一权威链，消除重复路径、迟到事件污染和“关闭后复用已失效面板”的生命周期问题。

### `src/transbridge/ui/paratranz/`、`src/transbridge/ui/context.py`、`src/transbridge/ui/projection_types.py`（改/增）

- **具体变化**: 抽出字符串导航与对话框生命周期责任，补齐非模态对话框关闭/迟到回调保护；纯 projection 类型从 AppContext 迁出。
- **具体变化**: AppContext 仅保留 ADR-018 规定的 projection/compatibility facade，新 Presenter 不再依赖完整 AppContext。
- **原因**: 收敛剩余超重 UI 和兼容面，并避免为降行数引入共享可写状态 mixin。

### `tests/ui/characterization/`、`tests/contracts/ui/`、`tests/integration/gui/`、`tests/performance/` 及相关 UI/Smart Assistant 测试（增/改）

- **具体变化**: 增加公共 import、intent 到 command、可见状态、错误/取消、run/render generation、窗口销毁、重复终态、100 次创建销毁和 10,000 条数据交互覆盖。
- **具体变化**: 扩展原生 Windows benchmark 与比较器，记录冷启动、窗口打开、关键交互、GUI heartbeat、RSS、订阅/timer/worker 和 QObject wrapper。
- **原因**: 用可观察合同与资源证据证明结构重构等价，不把私有方法或整屏截图当作唯一合同。

### `docs/requirements.md`、`docs/adr/021-ui-presentation-modularization.md`、`plans/ui-presentation-modularization/` 及 FR24 迁移清单（改）

- **具体变化**: FR25/NFR1.5、ADR-021、S01～S08 验收项更新为已实施；记录最终规模、审计、生命周期和性能证据，并解除 FR24 生产接入的前置阻塞。
- **原因**: 让需求、架构决策、实施计划和真实代码状态保持一致，明确 UI Foundation 应接入新的公开 View/Presenter 边界。

## 结果

- `MainWindow` 从约 2140 行/80 方法收敛到 473/13；`AITranslatorWindow` 从约 1617/42 收敛到 449/30；`ChatWidget` 从约 1250/68 收敛到 451/30。
- Workbench 按输入、筛选、表格、标签、菜单、进度和 operation cards 完成功能切片；Step2 保留为兼容 facade，并登记 review 例外。
- parent lookup、跨组件私有访问、View-infra、模块级 UI singleton 和 UI import cycle 的未登记发现归零。

- Smart Assistant 定向门禁 → **93 passed**；扩大回归 → **482 passed, 2 failed**，两项失败已在拆分前 `HEAD` 独立复现，未归因于 FR25。

- `git diff --check` → **通过**（仅既有 Windows LF/CRLF 提示）。

## 遗留项

- `AppContext` 仍是 ADR-018 compatibility facade，方法数超过 hard gate，已登记 owner、原因和退出条件；本 Epic 不擅自删除 legacy API。
- Step1、Step2 与两个 card view 高于 500 行/30 方法 review target、但低于 700 行/40 方法 hard gate，均有明确 review 例外；其中 Step2 为 601 行/40 方法。
- legacy 非权威 Step2 编辑仍会触发现有 direct-mutation deprecation warning，未扩散到新 Presenter。
- Smart Assistant 扩大套件中两项既有失败分别涉及 agent tool `start_translation` 结果和 ExecutionEngine `retry_handler`，已在重构前基线复现，未在本 Story 越界修复。
