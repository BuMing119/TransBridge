# V3 权威工程 UI 缺口闭环

- **日期**：2026-09-01
- **Epic**：`v3-ui-gap-closure`
- **Story**：S01～S05
- **Plan**：[V3 权威工程 UI 缺口闭环](../../../../plans/v3-ui-gap-closure/plan.md)
- **类型**：实现、回归测试与综合 QA

## 背景与目的

对照 V2 需求和当前 schema v3 的真实调用链，桌面端仍缺少工程删除/重命名、快照删除、JSON/SST 迁移导入、归档冲突恢复、任务历史动作，以及 V3 权威工程下的批量 AI、下载和写回闭环。本次按一个明确的产品语义补齐：工程只有一个“删除本地工程”动作，删除 TransBridge 管理的数据，但永不删除用户选择的外部源文件。

工作区在任务开始前已有大量未提交修改。下列内容只记录能够由本次 plan、实现过程和测试证据可靠归属的符号或段落，不把其他 dirty 文件归入本 Epic。

## Story 01：工程生命周期管理闭环

### Application 与 persistence

- `src/transbridge/application/projects/management.py`（新增）：加入 `ProjectManagementCommands.rename()` / `delete()`、`ProjectDeletion` 和 persistence port；重命名要求活动 Project 与上下文一致，删除要求精确确认名。
- `src/transbridge/application/projects/lifecycle.py`（修改）：加入 `commit_project_update()` 的 Project revision 提交和 `accept_project_deletion()`；持久化删除成功后清除活动 aggregate、lease、prepared/export 状态并发布投影事件。
- `src/transbridge/application/projects/snapshots.py`（修改）：为 `ProjectSnapshotPort` 和 `ProjectSnapshotCommands` 增加按当前 Project/Variant 归属校验的 `delete()`。
- `src/transbridge/application/projects/__init__.py`（修改）：导出新的项目管理与快照命令合同。
- `src/transbridge/persistence/project_management.py`（新增）：实现按 Project ID 收敛所有权的事务删除；删除 Project、Variant、快照、Project 资产、备份、catalog 和 active pointer，先撤销目录发现性并保留精确 preimage 供故障恢复；不读取 `source.location` 作为删除目标。
- `src/transbridge/persistence/project_snapshots.py`（修改）：实现快照删除，并校验快照中的 Project/Variant owner。
- `src/transbridge/persistence/v2/filesystem.py`（修改）：增加 fail-closed 的树文件枚举、文件删除、空树清理及 Project/backup 固定路径；递归枚举拒绝符号链接和根目录逃逸。
- `src/transbridge/persistence/v2/lifecycle_transactions.py`（修改）：Project 重命名使用 revision CAS，同时发布 Project 文档与 catalog；任一写入失败时恢复精确 preimage。
- `src/transbridge/bootstrap/persistence.py`（修改）：构造并暴露 `project_management`，复用既有 lifecycle、repository 和 baseline registry。

### UI 与入口

- `src/transbridge/ui/coordinators/project_management_coordinator.py`（新增）：提供重命名与单一删除交互；确认框显示精确工程名、不可撤销提示和“外部源文件不会被删除”；当前工程删除后返回开始中心，非当前工程只刷新列表。
- `src/transbridge/ui/coordinators/__init__.py`（修改）：导出项目管理 coordinator。
- `src/transbridge/ui/shell/action_catalog.py`（修改）：增加工程重命名、工程删除和快照删除 Intent。
- `src/transbridge/ui/shell/menu_builder.py`（修改）：在工程/版本菜单加入统一 Intent 入口。
- `src/transbridge/ui/shell/intent_composition.py`（修改）：把菜单、工作台和开始中心的重命名/删除请求路由到同一个 coordinator；快照删除路由到正式 snapshot command。
- `src/transbridge/ui/shell/start_center.py`（修改）：转发本地工程删除请求。
- `src/transbridge/ui/shell/start_center_controller.py`（修改）：把开始中心目标 Project ID 和显示名交给统一删除意图。
- `src/transbridge/ui/shell/start_center_landing.py`（修改）：保持开始中心本地工程管理入口的一致组合。
- `src/transbridge/ui/shell/start_center_projects.py`（修改）：在工程列表上下文菜单增加“删除本地工程…”。
- `src/transbridge/ui/workbench/_project_bar.py`（修改）：在当前工程菜单增加重命名/删除，在快照菜单增加删除还原点。
- `src/transbridge/ui/main_window.py`（修改）：创建 `ProjectManagementCoordinator` 并连接 ProjectBar 信号到统一 Intent。

### 测试

- `tests/persistence/v2/test_project_management.py`（新增）：覆盖重命名原子发布/回滚、确认名变化拒绝、当前/非当前 Project 删除、删除故障恢复和外部源保留。
- `tests/persistence/v2/test_project_snapshots.py`（修改）：覆盖快照删除与 owner 不匹配拒绝。
- `tests/persistence/v2/fakes.py`（修改）：为递归枚举、删除和故障注入补齐 persistence fake。

## Story 02：JSON 与 SST 正式迁移导入

- `src/transbridge/application/io/migration_import.py`（新增）：解析 ParaTranz、DSD、TransBridge JSON 与 SSU8/SSU9 SST；只生成既有且唯一可证明 `EntryKey` 的候选草稿，并为未知/歧义格式、空源、无译文和冲突映射返回稳定诊断。
- `src/transbridge/ui/workbench/_parse_config_dialog.py`（修改）：增加 JSON/SST 文件选择和明确格式，保留拖放预审产生的 `format_id`。
- `src/transbridge/ui/coordinators/parse_coordinator.py`（修改）：后台完成全部解析、映射和跨来源冲突检查；成功后通过一次 `replace_entry_states` revision CAS 提交，失败或版本切换时不发布候选集合。
- `src/transbridge/ui/shell/intent_composition.py`（修改）：把 Drop Intent 的 `format_id` 传入迁移对话框和 coordinator。
- `tests/contracts/io/test_migration_import.py`（新增）：覆盖格式识别、唯一映射和稳定失败诊断。
- `tests/ui/test_structured_migration_import.py`（新增）：覆盖 JSON、SSU8 的真实 V3 UI 调用链、revision/dirty 更新及失败不部分修改。

## Story 03：工程归档恢复和系统打开

- `src/transbridge/persistence/project_archive.py`（修改）：新增 `ProjectArchiveInspection` 和只读 `inspect_import()`；同 ID 冲突可为 Project/Variant/快照/source relation 生成一致的新身份副本，同名冲突可在发布前重命名，始终拒绝覆盖现有工程。
- `src/transbridge/ui/coordinators/v2_project_transfer.py`（修改）：导入前展示同 ID/同名冲突策略，取消时不写盘；导入完成后由用户决定是否打开，不隐式替换当前工程。
- `src/transbridge/cli.py`（修改）：增加 GUI 专用 `--import-project`，与 `--open-project` 互斥；Windows 文件关联传入单个 `.transbridge` 路径时自动进入导入审查。
- `src/transbridge/entrypoints/gui.py`（修改）：向 GUI 应用传递 `initial_import_path`。
- `src/transbridge/ui/app.py`（修改）：把初始归档路径传到主窗口。
- `src/transbridge/ui/main_window.py`（修改）：启动后等待工程 worker 空闲，再调度归档导入，避免与初始化打开流程竞争。
- `tests/persistence/v2/test_project_archive.py`（修改）：增加同 ID 副本导入、同名重命名及引用一致性测试。
- `tests/integration/entrypoints/test_cli_entrypoint.py`（修改）：覆盖显式参数与裸 `.transbridge` 文件关联路由。
- `tests/ui/test_v2_project_transfer.py`（新增/修改）：覆盖正式快照和归档 GUI 调用链。
- `tests/integration/gui/test_ui_foundation_startup.py`（修改）：覆盖 GUI 初始导入参数接线。

## Story 04：任务中心真实动作

- `src/transbridge/application/tasks/actions.py`（新增）：加入 `TaskCenterActions` facade、恢复/导航 registry 和安全 UI projection；执行前重新读取不可变历史或恢复记录并校验 owner、来源和 revision。
- `src/transbridge/application/tasks/__init__.py`（修改）：导出任务中心动作合同。
- `src/transbridge/bootstrap/composition.py`（修改）：注册 task history、recovery/retry/navigation registry 和 `task_center_actions`；没有真实 feature handler 时不声明伪能力。
- `src/transbridge/ui/shell/task_center.py`（修改）：加入恢复、重试、打开结果、打开日志按钮，按 `available_actions` 控制可用性；动作后刷新历史与恢复目录。
- `src/transbridge/ui/shell/intent_composition.py`（修改）：接收 `TaskNavigationIntent` 并交回 Shell Intent 路由，不猜测 artifact 或日志路径。

- `tests/ui/test_task_center.py`（修改）：验证按钮只按 catalog 能力启用、导航转发和 overlay 复用。

## Story 05：V3 权威批量操作

### 批量 AI

- `src/transbridge/ui/tools/ai_translator/batch_runtime.py`（修改）：捕获选中 slot 的 Project/Variant identity 与 revision，在 detached collection 上运行，全部候选通过后以一次 `commit_translation()` CAS 提交；取消、失败或迟到结果不修改权威状态。
- `src/transbridge/ui/tools/ai_translator/_batch_translation_progress_window.py`（修改）：在 UI 宣告完成前调用 completion publisher，提交失败进入错误终态而不发布投影。
- `tests/ui/tools/test_ai_translator_slices.py`（修改）：覆盖成功单提交以及取消/失败零提交。

### 批量 ParaTranz 下载

- `src/transbridge/paratranz/workflow/downloader.py`（修改）：合并远端译文时保留 `EntryKey`、external refs、provenance 和 entry revision，只对实际变化递增 revision。
- `src/transbridge/ui/operations/authoritative_batch_download.py`（新增）：捕获多个来源的 detached candidate，拒绝重复 EntryKey，在所有结果可接受后通过一次 `replace_entry_records` 提交，再发布可见 slot。
- `src/transbridge/ui/workbench/cards/download_card.py`（修改）：移除 V3 批量阻断，委托新的权威 batch session；远端 create/delete 或不完整映射继续 fail-closed。
- `tests/ui/test_authoritative_batch_download.py`（新增）：验证提交前投影不变、单次 CAS 和身份保留。
- `tests/paratranz/test_workflow.py`（修改）：验证下载合并保持权威身份与 revision。

### 批量写回

- `src/transbridge/ui/operations/production.py`（修改）：为每个 hydrated slot 构造正式 `HydratedWriteDraft`，先预检全部来源，再由单个 TaskRuntime job 执行逐来源正式 workload，并返回逐来源 artifact/诊断。
- `src/transbridge/ui/workbench/cards/write_card.py`（修改）：V3 批量写回只在 facade 证明 hydration 能力时开放，不回退 legacy writer。
- `tests/ui/operations/test_production_facade.py`（修改）：验证全部来源先预检且每个目标均由正式写入 workload 发布。

### 权威边界合同

- `tests/contracts/projects/test_authoritative_mutation_paths.py`（修改）：把 batch AI、batch download 和新增投影发布函数纳入权威写路径 AST 门禁，禁止重新引入直接 legacy mutation。
