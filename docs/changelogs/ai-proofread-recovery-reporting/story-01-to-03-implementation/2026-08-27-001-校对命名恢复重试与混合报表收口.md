# Story 01～03：校对命名、失败恢复与混合报表收口

- **日期**：2026-08-27
- **Epic**：`ai-proofread-recovery-reporting`
- **Story**：Story 1 产品命名与兼容别名、Story 2 校对失败恢复与最终统计、Story 3 混合流程报表可见收口
- **关联计划**：[AI 校对恢复与报表收口计划](../../../../plans/ai-proofread-recovery-reporting/plan.md)

## 目的

将原机器名 `combined` 的产品主路径统一为“校对 / Proofread / `proofread`”，同时保留旧配置和旧调用的显式兼容入口。针对模型输出包装、部分条目无效和 Provider 调用失败增加有界恢复，使失败统计只表示恢复后仍失败的条目；补齐混合流程完成后的 canonical 报表展示和预览后台回填。

### Story 2：失败恢复、重试和最终失败统计

- **新增** `src/transbridge/application/translation/proofread_response.py`
  - 独立负责 Proofread 响应解码和条目级校验。
  - 只清除完整 Markdown JSON fence、完整 `<think>` 前缀、BOM 和空白，不进行语义性 JSON 猜修。
  - 对缺失、重复、空译文、未知键和保护语法损坏生成稳定诊断。
- **扩展** `src/transbridge/application/translation/proofread_stage.py`
  - 首次请求后只重试最终失败子集一次；恢复响应整体仍畸形且子集可拆时只二分一层。
  - 每个原始批次最多 4 次逻辑调用；Provider 连续失败最多两次，取消异常不重试。
  - 合并时保留首轮成功候选和原始候选身份；恢复成功后移除中间 ERROR/EXTERNAL 诊断。
  - 最终失败候选保持原译文，并以恢复后的 candidate 状态驱动流程、进度和报表统计。
- **修改** `src/transbridge/ai_translator/post_processor/proofread_pipeline.py`
  - 从最终候选投影校对结果，避免把已经恢复的中间失败计入失败条目。
