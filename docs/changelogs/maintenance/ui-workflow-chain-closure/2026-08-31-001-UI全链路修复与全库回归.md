## 背景与修复结果

用户要求从 UI 开始扫描全库，寻找空按钮、错误路由和未接通的业务链，并修复本轮发现的问题。扫描确认的 16 类断链已修复：

1. 词典重复刷新将已加载 ID 误判为磁盘冲突，正常文件被重命名为损坏文件。
2. AI 混合模式只有翻译、或用户拒绝全部润色时，没有提交已完成翻译，关闭窗口会回滚结果。
3. 本地化插件的 `string_id` 在条目快照和来源补全间丢失，导致译文无法正确写回。
4. 插件发布只处理主文件，Strings 使用暂存名称且未纳入统一覆盖、备份和回滚。
5. 术语入站复核编辑后仍可提交旧预览，跨页选择也会丢失。
6. 项目归档导入仍写已只读的旧 AppContext 属性，导致 V2 导入链中断。
7. V2 快照保存、恢复、项目导出仍依赖旧对象，工作台“管理快照”还是空回调。
8. 任务中心历史/恢复页仍能控制当前页隐藏选中的任务。
9. AI 并行子阶段异常未传到外层，可能报告成功或在兄弟线程退出前回滚。
10. 助手 V2 会话重命名/删除菜单仅记录警告，没有真实持久化动作。
11. 术语冲突搜索和风险筛选只改变 fingerprint，实际查询未筛选。
12. 术语分页查询替换时遗留 loading 状态，导致新请求不能启动。
13. ParaTranz 成员异步加载后未广播权限变化，多个页面的动作状态过时。
14. 已完成来源确认的插件写回仍重开原始 URI，来源被改动或删除后无法使用确认字节。
15. 测试 LLM 连接同步占用 Qt 主线程，界面在网络请求期间无响应。
16. CLI Unicode JSON 在 Windows 非 UTF-8 stdout 上可能编码失败。

交叉审查及回归还修复了 Windows V2 暂存路径过长、嵌套标签库重复冻结、快照上下文错配、旧归档无可靠来源时的数据保护，以及损坏版本错误码回归。归档、插件发布、筛选、复核草稿和连接测试的新职责分别抽出模块；已有大模块只增加局部接线或修复，不进行无关重构。
