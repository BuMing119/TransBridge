# 全仓 Ruff 格式与 Lint 基线

- **日期**：2026-08-28
- **Epic**：`maintenance`
- **Story**：`ruff-quality-baseline`（无独立 plan 的仓库维护任务）
- **类型**：维护 / 代码质量

## 目的

为 `src` 与 `tests` 中受现有 `pyproject.toml` Ruff 配置管理的 Python 文件建立一次性格式和 lint 基线。任务不调整 Ruff 规则、不新增全局忽略，也不通过大范围 `noqa` 掩盖诊断；对自动修复后仍涉及公共导出、前向注解或运行时行为的项目逐项审查并做最小修复。

任务开始时 Git 工作区无已跟踪或未跟踪改动，因此本记录覆盖的差异可完整归属于本次维护任务。除 Ruff 基线外，全量回归还暴露出重构后静态资源、打包入口、测试隔离和 Windows 字节保真基线未随新目录落点迁移的问题；这些问题已按最小范围补齐。生成物、缓存、用户配置和第三方代码未纳入差异。

## Ruff 诊断与处理

- 初始 `uv run ruff check src tests --statistics`：401 项，包括 E501、I001、F401、F822、UP037、UP045、F841、F821、E402 等；其中 235 项被初始统计标记为可安全自动修复。
- 初始 `uv run ruff format --check src tests`：118 个文件需要格式化。
- 运行 Ruff 安全修复与 formatter 后，人工处理剩余的未定义导出/名称、未使用局部变量、非顶层导入和超长行。
- 未修改 `pyproject.toml`，未新增 Ruff ignore 或 `noqa`；同时移除了本次拆行后已不再需要的局部 E501 `noqa`。

## 全量回归修复

- 新增并跟踪运行时必需的 `data/prompts` 与 `data/skills` 静态资源；用户侧 `data` 内容仍默认忽略，仅对白名单资源解除忽略。
- 新增统一资源目录解析：开发环境优先读取仓库/用户数据目录，冻结包在外部目录不存在时回退到 `sys._MEIPASS/data`；各 prompt loader 与 Smart Assistant skill loader 统一使用该入口。
- 补齐 `transbridge.spec` 与 `installer/setup.iss`，将 UI 图标、embedding catalog、prompts 和 skills 纳入可复现打包输入。
- 为三个 IO contract fixture 固定 LF 行尾并恢复登记哈希，避免 Windows checkout 改写字节后破坏保真测试。
- 隔离依赖本机 `transbridge.ini`、后台线程和语言配置的测试，并让 UI 测试替身覆盖真实面板的窗口图标接口。
- 性能门禁在进入稳定态后测量原有阈值；额外长时采样确认 RSS 增长为 Qt/分配器高水位而非线性泄漏。
