# Project catalog 缺失时恢复活动工程投影

- **日期**：2026-08-25
- **归属**：`maintenance/project-catalog-active-fallback`
- **类型**：兼容性与误判修复
- **关联场景**：开始中心“本地工程”只读投影

## 问题

用户数据目录中实际存在合法的 V2 Project 记录和 `active-project.json`，但 `project-catalog.json` 缺失。原 `V2ProjectCatalog.list_projects()` 在 catalog 为空时直接返回空快照，导致开始中心错误显示“尚无本地工程”。

该数据形态可能来自 catalog 功能引入前已存在的 V2 工程，也可能来自用户误删索引文件；Project 本体并未因此丢失。

## 真实变更

- `src/transbridge/persistence/project_catalog.py`（修改）
  - 移除 catalog 为空时的提前返回，仍继续读取活动工程指针。
  - 当活动工程未出现在 catalog 中时，使用 `ProjectRepository.path_for()` 推导 canonical 路径，读取并按当前 V2 schema 验证 Project 记录。
  - 验证成功后只在本次只读快照中补入活动工程；验证失败则返回稳定诊断，不写盘、不覆盖任何文件。
  - 保持活动工程优先、名称和 ID 稳定排序。
- `tests/persistence/v2/test_project_catalog.py`（修改）
  - 新增 catalog 缺失、活动指针和合法 Project 记录仍存在时的回归测试。
  - 明确断言恢复结果包含正确 ID、名称、canonical 路径和 active/available 状态，并且没有 write、replace、remove 或 mkdir 调用。
