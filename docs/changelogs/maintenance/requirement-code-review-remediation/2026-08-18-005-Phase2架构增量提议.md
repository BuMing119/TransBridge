# Phase 2 综合整改架构增量提议

- 日期：2026-08-18
- 归属：`maintenance/requirement-code-review-remediation`
- 阶段：bm-pilot Phase 2
- 状态：架构待用户确认

## 变更目的

基于已确认 FR17～FR23/NFR 增量和当前代码事实，建立入口、I/O、状态和任务四个长期架构合同。保留现有可用资产，以 Ports/Adapters、compatibility facade 和逐调用链门禁渐进迁移，不按九条整改线分别制造重复架构。

## 新增 ADR

- `ADR-016`：模块化单体应用层、单一 Composition Root、进程级 AppRuntime、调用级 RuntimeContext、能力注册、独立 `transbridge-mcp` 和安装态包/版本/入口单一来源。
- `ADR-017`：FormatAdapter、Parse/Write contracts、source snapshot、EntryKey/ExternalEntryRef、ParaTranz JSON 双 ID、离散 StagePolicy、Localized Strings fidelity 和原子发布。
- `ADR-018`：Project/Variant/Session 权威所有者、Repository/UnitOfWork、完整替换式 Variant、两阶段生命周期、V2 schema/迁移/隔离和 projection/dirty 语义。
- `ADR-019`：统一 TaskRuntime、JobSpec/JobRef、owner/run_id、互斥终态、能力型控制、取消 commit guard、幂等 checkpoint、可释放订阅和工作流提交模型。

## 既有 ADR 增量

- ADR-001/002：统一模型与 Collection 保留，V2 分离内部 EntryKey 和外部引用，并改为受控 mutation。
- ADR-004：QThread 降为 GUI backend adapter。
- ADR-006：JSON 资产保留，AppContext 所有权、overlay、Stage 推导和无模式迁移由 ADR-018 部分取代。
- ADR-008～011：Smart Assistant、知识/检索、infra 和 Graph 分别纳入 application、ports、owner 和 TaskRuntime 边界。
- ADR-012：MCP 改为 headless 独立 stdio 入口，协议/能力协商，stdio 凭据从环境或安全存储注入，复用统一安全策略。
- ADR-013：可选检索依赖、锁定和 disabled 零加载成为 capability 门禁。
- ADR-014/015：FOMOD typed transactional pipeline、TM 字段、ArchivePolicy 和 KeyMigrator 来源身份边界。

ADR-003、005、007 经评估保留历史算法/模板/动作规则，不新增独立更新；具体执行受 ADR-016～019 约束。

## 当前代码证据

- `ui/app.py` 直接完成 Agent/工具/MCP 注册并在 GUI 进程读取 stdio，且构造时缺失统一 RuntimeContext。
- 工具惰性 getter 会自行创建 `AppContext()`/`TaskManager()`；TaskManager 为进程单例并允许任意状态写入。
- TranslationEntry/Collection 仍假设历史 id/key，VariantStore 只保存非空译文且不持久化 Stage/provenance/revision。
- SessionController 使用 `assert` 校验状态；SessionManager 只保存消息，切换/owner 不构成事务。
- parser/writer 构造签名不同，Agent dispatch 与真实模块错配，Writer 直接写目标。
- MCP 使用 `select(stdin)` 与自定义逐请求 token；ParaTranz/FOMOD 直接编排具体客户端和实现。

## 外部规范核验

- MCP 官方 stdio 规范：客户端启动 server 子进程，stdin/stdout 只传 JSON-RPC，日志可写 stderr。
- MCP 生命周期要求初始化阶段协商 protocol version/capabilities；不应固定唯一版本。
- MCP 官方授权规范说明 stdio 不套用 HTTP 授权流，凭据应从环境获取。
- PyInstaller 官方文档确认 onedir 是一文件夹载荷并支持共享收集多入口依赖，符合已确认分发路线。
