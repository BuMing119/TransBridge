# 001: Phase 4 调优 — 工具目录瘦身 + 路由表扩充 + ToolRegistry 导入统一

**日期**: 2026-08-05
**类型**: 改
**关联**: Epic: 工具提示词分层加载 > Story 05: Phase 4 — 调优

## 修改文件

### `src/transbridge/smart_assistant/tool_registry.py` (改)
- **修改内容**: `ToolSpec.__post_init__` 中 summary 自动提取截断上限从 80 chars 缩短为 50 chars。效果：工具目录从 1,324 tokens 降至 1,249 tokens (-5.7%)。
- **原因**: Phase 0 测量（Story 01）发现工具目录 1,324 tokens 远超方案预估的 ~500，42 个工具摘要行累积导致目录偏重。缩短摘要截断是零风险瘦身手段。

### `src/transbridge/smart_assistant/prompts.py` (改)
- **修改内容**: `_build_routing_table()` 路由表关键词全面扩充——default(+概览/进度/查看), translator(+术语库/自动翻译/机翻), parser(+加载文件/读取插件), editor(+修改译文/标记/查找), paratranz(+平台/发布), proofreader(+检查/校验/跑后处理), writer(+保存/导出/输出/生成插件)。规则 3 从"不要凭目录摘要"升级为"**禁止**凭目录摘要直接调用非预加载工具，**必须**先通过 get_tool_help 获取完整定义"。路由表从 401→547 tokens (+146)。
- **原因**: Phase 0 测量发现原路由表关键词覆盖偏窄，用户的部分自然表达无法匹配到正确 namespace。措辞强化降低 LLM 跳过 get_tool_help 直接调用工具的风险。

### `src/transbridge/smart_assistant/tools/tool_default.py` (改)
- **修改内容**: `_register_default_tools()` 和 `_tool_get_tool_help()` 中的 `from src.transbridge.smart_assistant.tool_registry import ToolRegistry` 改为 `from ..tool_registry import ToolRegistry`（2 处）。
- **原因**: 修复 ToolRegistry 双重导入隐患——`prompts.py` 使用相对导入 `.tool_registry` 创建 `transbridge.smart_assistant.tool_registry` 模块实例，而 tools 子包使用 `src.transbridge.smart_assistant.tool_registry` 创建独立实例，导致工具注册到错误实例中。统一为相对导入消除模块分裂。

- **原因**: 同上，ToolRegistry 导入路径统一。
