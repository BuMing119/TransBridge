# 001: Phase 2 元工具注册与 Prompt 重构 + Phase 3 单元测试

**日期**: 2026-05-25
**类型**: 改
**关联**: Epic: 工具提示词分层加载 > Story 03: get_tool_help 注册 + build_system_prompt 重构, Story 04: 回归测试

## 修改文件

### `src/transbridge/smart_assistant/tools/tool_default.py` (改, +16行)
- **修改内容**: 新增 `_tool_get_tool_help(args, ctx)` 函数，调用 `ToolRegistry.build_tool_help()` 路由三种查询模式。在 `_register_default_tools()` 的 register_tools 列表末尾注册 `get_tool_help` 工具（default namespace, permission=read, 参数 tool/namespace 均可选）
- **原因**: LLM 需要一种标准化的方式来按需获取工具完整定义，替代将全部 41 个工具 Schema 一次性注入 system prompt

### `src/transbridge/smart_assistant/prompts.py` (改, +48/-22行)
- **修改内容**:
  - 新增 `_build_preloaded_tools()` — 构建 get_app_state + get_statistics 完整 Schema（~300 tokens），注入为「核心工具（始终可用）」
  - 新增 `_build_get_tool_help_schema()` — 构建 get_tool_help 完整定义 + 4 条使用规则（查路由表→调 get_tool_help→禁止凭目录直接调用→跨领域逐一加载）
  - 新增 `_build_routing_table()` — 7 行意图→namespace 映射表（~180 tokens），覆盖 default/translator/parser/editor/paratranz/proofreader/writer
  - `build_system_prompt()` 重构 — 组装为 5 段分层结构：预加载→工具发现→路由表→目录；接口签名不变
  - 删除 `HYBRID_SYSTEM_PROMPT` 中的「工具选择指南」段（~200 tokens，含常见场景和易混淆工具对）
- **原因**: 工具段从 ~14,000 tokens 降至 ~1,040 tokens（92.5% 节省）。旧工具选择指南信息移至 build_tool_help 返回结果中按需附带

### `tests/smart_assistant/test_tool_prompt_layering.py` (增, 28测试)
- **修改内容**: 28 个单元测试，覆盖：
  - Levenshtein 距离计算（4 测试）
  - ToolSpec.summary 自动提取（5 测试：含标记/无标记/仅①/截断/手动填写）
  - build_tool_directory 输出格式（3 测试：字符串/过滤废弃/default 排最前）
  - build_tool_help 各模式（8 测试：单工具/namespace/概览/不存在/模糊匹配/多 ns/不存在 ns/参数表格）
  - build_system_prompt 新结构（4 测试：分层结构/无旧指南/预加载工具/路由表完整性）
  - get_tool_help 工具集成（4 测试：已注册/单工具执行/namespace 执行/空参数执行）
- **原因**: Phase 3 回归测试的单元测试部分——确保核心基础设施正确性。LLM 回归测试（50+ prompts 准确率对比）需 API 调用，标记为手动运行
