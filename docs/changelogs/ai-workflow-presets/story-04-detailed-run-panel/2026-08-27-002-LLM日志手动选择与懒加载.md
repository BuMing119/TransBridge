# LLM 日志手动选择与懒加载

- **日期**：2026-08-27
- **Epic**：`ai-workflow-presets`
- **Story**：Story 4 统一详细运行面板
- **计划关联**：`plans/ai-workflow-presets/plan.md`
- **状态**：性能修复完成，聚焦 QA 与真实日志冒烟通过

## 目的

修复运行日志达到数千个文件后，窗口在 Qt 主线程一次创建数千个 `QTextEdit` Tab、读取全部内容并每 800 ms 全量刷新，导致点击“LLM 日志”后长时间未响应的问题。交互改为用户手动刷新文件索引、下拉选择日志、选中后才读取对应内容。

## 真实变更

- `src/transbridge/ui/tools/ai_translator/_llm_log_viewer.py`（修改）
  - 移除自动刷新计时器、自动刷新复选框、每文件一个 Tab 和全量文件内容扫描。
  - 增加“刷新列表”按钮与折叠式下拉选择器；刷新只更新文件名索引，选择变化后只读取一个日志文件。
  - 使用单个 `QPlainTextEdit` 展示内容，并限制最大文档块数。
  - 单个日志超过 2 MiB 时只读取尾部并显示截断提示，避免异常大响应再次占满主线程和文本控件。
  - 保留 `stop_auto_refresh()` 兼容入口，但窗口设计为纯手动刷新，不再启动后台轮询。
  - 保留翻译批次、术语、检测、修复、润色、裁决、汇总和流程诊断的可读标签。
- `tests/ui/tools/test_layout_stability.py`（修改）
  - 更新日志窗口工具栏稳定性断言以适配手动刷新按钮。
  - 覆盖初始下拉索引、选中后加载单文件、新日志在手动刷新前不可见、刷新后保留当前选择与内容。

## 兼容性与遗留项

- 日志落盘格式和目录不变；旧运行目录可直接查看。
- 运行中的新增日志不会自动出现在列表中，用户需点击“刷新列表”；这是本次明确采用的交互策略。
- 超过 2 MiB 的单文件只在窗口显示尾部，磁盘上的完整日志不会被修改或截断。
