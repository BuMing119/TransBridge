# 统一详细运行面板与 LLM 日志

## 目的

补齐 AI 翻译窗口中非纯翻译流程缺少运行细节的问题。润色、混合以及用户修改预设后形成的自定义阶段组合，改为按冻结的有效执行档案展示真实阶段、连续进度、状态统计和详细日志；同时复用翻译日志查看体验，让用户可以打开按翻译批次、校改阶段和单次 LLM 调用拆分的完整请求/响应记录。

### 统一进度模型与窗口组合

- `src/transbridge/ui/tools/ai_translator/workflow_progress.py`（新增）
  - 定义不可变 `WorkflowProgress`，统一阶段、当前/总数、总进度以及成功、失败、待审、问题和新增术语统计。
  - `stages_for_profile()` 只投影有效执行档案中真实启用的阶段；`WorkflowProgressTracker` 以线程安全、单调不回退的方式聚合串行或并行阶段进度。
- `src/transbridge/ui/tools/ai_translator/run_view.py`（修改）
  - 将原简化混合进度窗扩展为可复用的 `AiWorkflowProgressWindow`，展示执行摘要、总进度、阶段条、状态统计和连续详细日志。
  - 增加暂停/继续、安全停止和“LLM 日志”入口；保留 `AiMixedProgressWindow` 兼容入口并兼容旧 `MixedProgress` 信号。
  - 终态停止日志自动刷新；日志不可用时禁用按钮、更新提示并在详细日志给出明确原因，避免空白窗口。
- `src/transbridge/ui/tools/ai_translator/workflow_progress_runtime.py`（新增）
  - 组合独立润色 worker、TaskRuntime activity、统一进度窗、预览和终态 guard。
  - 将 `detailed_progress`、普通日志、取消、错误和结果提交接入既有控制器所有权边界。
- `src/transbridge/ui/tools/ai_translator/run_controller.py`（修改）
  - 独立润色启动改为委托 `workflow_progress_runtime.show_polish_progress()`，控制器继续管理活动、线程和迟到终态保护。
  - 混合运行传入冻结的执行档案，使窗口按真实阶段构建，并连接统一进度与日志信号。
- `src/transbridge/ui/tools/ai_translator/ai_translator_window.py`（修改）
  - 独立润色入口使用新的 worker factory 和统一进度组合，不再创建旧简化进度对话框。
  - 保持窗口 facade 为 500 行，没有继续向临界模块增加新业务责任。

### Worker 进度、暂停与日志接入

- `src/transbridge/ai_translator/post_processor/proofread_pipeline.py`（修改）
  - 增加可选 `log_callback` 并透传给 `PostProcessor.process_entries()`，让独立润色和混合校改可连续显示流水线内部诊断。
- `src/transbridge/ui/tools/ai_translator/_polish_worker.py`（修改）
  - 增加结构化 `detailed_progress` 和普通 `log` 信号，按有效档案创建阶段跟踪器并汇总成功、失败、待审和问题数。
  - 增加共享暂停事件、阶段日志落盘、日志可用性/错误投影，并在所有终态关闭日志句柄。
- `src/transbridge/ui/tools/ai_translator/_mixed_worker.py`（修改）
  - 翻译与校改子流程改为共享 `WorkflowProgressTracker`、暂停事件和统计锁；串行、并行模式均连续转发真实内部进度。
  - 接入 `AutoTranslator` 的 progress、log 和 stream callback，按 1-based 翻译批次保存原始提示词与流式响应。
  - 校改子流程复用冻结执行档案和带日志的 LLM client；完成时发布权威汇总统计并保持既有结果/报告接口。
- `src/transbridge/ui/tools/ai_translator/polish_runtime.py`（修改）
  - 为独立润色创建本次运行专属日志存储，并用透明日志 client 包装真实 LLM client。
  - 只有有效档案需要 LLM 时才创建 client，继续复用候选式 `ProofreadPipeline`。

### 可查看的持久化 LLM 日志

- `src/transbridge/ui/tools/ai_translator/workflow_log_store.py`（新增）
  - 按源文件、工作流和微秒时间戳创建运行日志目录，线程安全写入翻译批次、校改阶段、流程诊断和 LLM 调用日志。
  - 文件名经过安全归一化；每个片段立即 flush；关闭后拒绝迟到写，避免取消后的后台片段重新打开并截断日志。
  - 目录、写入或关闭异常采用可观测的尽力记录策略，不改变 AI 主流程，并向窗口暴露不可用原因。
- `src/transbridge/ui/tools/ai_translator/workflow_logging_client.py`（新增）
  - 透明代理 `LLMClient.chat()`、`chat_stream()` 和 `cancel()`，为每次调用保存完整 messages、token 上限、响应或原始错误。
  - 调用编号使用锁保护；日志异常只发出 warning，不覆盖模型结果或 Provider 原异常。
- `src/transbridge/ui/tools/ai_translator/_llm_log_viewer.py`（修改）
  - 从仅识别翻译批次扩展为识别“翻译批次、检测/修复/润色/裁决/汇总、LLM 调用、流程诊断”多类 Tab。
  - 窗口运行中关闭后再次显示会恢复自动刷新；任务终态主动停止刷新后不会错误重启。
