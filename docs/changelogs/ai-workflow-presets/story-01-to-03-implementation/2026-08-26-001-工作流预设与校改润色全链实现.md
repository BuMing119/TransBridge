# AI 工作流预设与校改润色全链实现

- **日期**：2026-08-26
- **Epic**：`ai-workflow-presets`
- **Story**：Story 1 模式预设配置与有效执行档案；Story 2 候选式校改润色流水线；Story 3 翻译/润色/混合入口统一接线
- **需求关联**：FR5.13、FR6.9、FR26.7.1
- **架构关联**：ADR-026
- **状态**：实现完成，综合 QA 通过

## 目的

修复 AI 翻译窗口中“高级配置可以编辑和保存，但独立润色或混合模式并未按配置执行”的设计问题。翻译、润色和混合继续作为易懂入口与推荐预设，但用户当前界面配置具有最高优先级；独立润色默认不再只是改善文风，而是执行错误检测、针对性修复、表达润色和最终裁决，并在正式集合之外先形成候选。

### Story 1：预设配置与不可变执行档案

  - 提供阶段摘要、稳定 digest、是否存在有效校改工作及是否需要 LLM 的派生合同。
  - 提供旧平铺配置迁移、预设校验、采集、保存和应用函数；翻译继承旧值，润色和混合首次使用完整校改推荐值。

  - 增加 `workflow_profiles` JSON 往返与非法数据回退；直接加载配置时应用翻译兼容预设。
  - 增加不携带 repository lock、credential store 和 environment provider 的 `copy_for_execution()`，修复真实持久化配置无法冻结运行快照的问题。
  - 未配置模型时仍允许保存非端点配置与工作流预设；端点三元组只在完整时原子持久化。
- `src/transbridge/ui/tools/ai_translator/config_presenter.py`（修改）

  - 保存时短暂投影翻译兼容 facade，持久化后恢复当前活动预设；运行取得的仍是用户当前有效配置。
- `src/transbridge/ui/tools/ai_translator/config_view.py`（修改）

  - `AiRunSpec` 增加不可变执行档案；运行配置复制优先使用 detached execution copy。

  - 润色预检按实际阶段判断空流程和 LLM 凭据需求，本地一致性/格式检测不再被无关模型配置阻断。

### Story 2：候选式检测、修复、润色和裁决

- `src/transbridge/ai_translator/post_processor/proofread_pipeline.py`（新增）
  - 在 `TranslationEntry` 副本上组合现有 Checker、Refiner、Polisher 和 Arbiter，使用 `apply_changes=False` 返回候选而不提前修改正式集合。
  - 投影原译文、问题、纠错候选、最终候选、裁决、信心度和接受状态；启用裁决但缺失 decision 时保守返回 pending/0，而不是误判 pass。
- `src/transbridge/ai_translator/post_processor/post_processor.py`（修改）
  - 将 checker、checkpoint、refiner、polisher 和 arbiter 的 `id`/`key` 历史别名统一为 `entry.id`。
  - 以替换后的修复译文副本作为 Polisher 输入，保证修复成果不会被从旧译文开始的润色覆盖。
  - 增加候选运行的 `apply_changes` 边界，并使规则裁决将阶段失败保守归为 pending/reject。
- `src/transbridge/ai_translator/post_processor/quality_gate.py`（修改）
  - 批量响应同时识别 `id` 和 `key`，回写 canonical `id`；合法 JSON 漏项生成 uncertain issue，不再静默视为无问题。
- `src/transbridge/ai_translator/post_processor/llm_refiner.py`（修改）
  - 批量修复响应统一 canonical identity；每个漏项生成 confidence=0、需要裁决的失败结果。
- `src/transbridge/ai_translator/post_processor/polisher.py`（修改）
  - 批量润色响应统一 canonical identity；每个漏项生成 confidence=0 的失败候选。
- `src/transbridge/ai_translator/post_processor/llm_arbiter.py`（修改）
  - 批量裁决响应按 canonical identity 关联并为漏项生成保守 fallback。
  - 润色阶段失败不得快速通过；存在润色候选时不再仅凭高信心修复结果绕过最终候选裁决。

### Story 3：独立润色、混合模式与 UI 提交边界

- `src/transbridge/ui/tools/ai_translator/_polish_worker.py`（修改）

- `src/transbridge/ui/tools/ai_translator/_mixed_worker.py`（修改）
  - 混合模式的已有译文分支复用同一 `ProofreadPipeline`，返回候选与 pass/failure 明细，不在 worker 中直接写正式集合。
- `src/transbridge/ui/tools/ai_translator/run_controller.py`（修改）
  - 独立润色 worker 的业务组合移至 `polish_runtime.py`，控制器继续负责线程、进度和终态 guard。
- `src/transbridge/ui/tools/ai_translator/ai_translator_window.py`（修改）
  - 模式切换委托 `ConfigPresenter` 保存并恢复预设；启动摘要来自有效执行档案。
  - 独立润色和混合入口传递冻结配置与候选结果；混合子流程没有有效质量阶段时明确跳过，不伪报润色成功。
  - 保存混合运行的预览策略，并将正式写入委托给结果边界。
- `src/transbridge/ui/tools/ai_translator/postprocess_view.py`、`quick_run_presenter.py`（修改）
  - 总开关文案覆盖“质量检查与优化”；快速运行状态展示实际阶段，在自定义流程不再符合预设名时使用中性执行文案。
- `src/transbridge/ui/tools/ai_translator/_polish_preview_dialog.py`（修改）
  - 预览扩展为原文、当前译文、检测问题、纠错候选、最终候选、裁决六列。
  - 表格点击信号只绑定一次；失败项不可接受，多行点击不会因重复 slot 调用反复切换。
- `src/transbridge/ui/tools/ai_translator/result_presenter.py`（修改）
  - 自动应用只提交 `accepted/pass` 候选，区分 rejected 与 failed；人工预览决定在唯一 mutation boundary 写入集合。
- `src/transbridge/ui/tools/ai_translator/result_view.py`（修改，本记录仅归属 `apply_window_mixed_result` 的预览提交行为）
  - 混合模式读取冻结的预览开关；关闭预览时只自动应用 pass，开启时复用六列预览并按用户决定提交。
  - 同文件中并行存在的 canonical 报表渲染改动不属于本增量，未在此记录其实现归属。
