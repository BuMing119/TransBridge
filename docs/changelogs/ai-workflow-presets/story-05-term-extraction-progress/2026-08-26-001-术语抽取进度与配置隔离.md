# 术语抽取进度与配置隔离

- 日期：2026-08-26
- Epic：`ai-workflow-presets`
- Story：Story 5「术语初始化进度与失败可见性」
- 需求：FR5.13.8

## 背景

混合任务在正式翻译前会从已有译文分批调用 LLM 抽取术语。旧实现没有独立进度信号，且 `NounExtractor` 会吞掉每一批异常；当凭据失效时，界面长期停留在 0/0，同时继续发起大量无效请求。排查还确认 AI 工具 UI 测试关闭窗口时会把测试配置自动保存到用户的默认配置仓库和 Windows 凭据存储。

## 变更

- `src/transbridge/ai_translator/existing_term_extractor.py`
  - 为存量译文术语初始化增加真实批次数、已完成批次、日志、暂停安全点和停止结果。
  - 首批认证、网络或解析异常后终止剩余批次；丢弃不完整的文本抽取结果，但仍允许安全的名称术语持久化。
- `src/transbridge/ai_translator/noun_extractor.py`
  - 增加调用方可选的异常传播语义；原有直接调用仍保持失败降级为空结果。
- `src/transbridge/ai_translator/translator.py`
  - 为 `translate()` 增加可选准备阶段回调，将术语抽取的准备、批次完成、跳过、停止和失败投影到运行层。
  - 抽取失败后继续使用名称术语和已有术语库，不再逐批静默重试。
- `src/transbridge/ui/tools/ai_translator/workflow_progress.py`
  - 新增“术语抽取”阶段，并支持仅在启用翻译和术语检索时把它排在“翻译”之前。
- `src/transbridge/ui/tools/ai_translator/_mixed_worker.py`
  - 将术语阶段接入统一混合进度、详细日志和 `stage_terms.log`。
- `src/transbridge/ui/tools/ai_translator/_translation_worker.py`、`_translation_progress_window.py`
  - 纯翻译 Worker 转发准备阶段信号；翻译进度窗口在正式批次开始前显示术语批次进度，之后切回翻译计数。
- `tests/ui/tools/conftest.py`
  - 为 AI 工具 UI 测试自动注入临时配置仓库和内存凭据存储，阻断测试自动保存对 `data/transbridge.ini` 与系统凭据的写入。
- `tests/ai_translator/test_existing_term_extractor.py`、`test_noun_extractor.py`
  - 覆盖多批次进度、日志、停止、首批失败快速退出和异常传播兼容语义。
- `tests/ui/tools/test_ai_translator_slices.py`、`test_workflow_progress.py`
  - 覆盖术语阶段顺序、混合 Worker 投影、阶段日志落盘及纯翻译窗口显示/切换。
- `docs/requirements.md`、`plans/ai-workflow-presets/plan.md`
  - 增加 FR5.13.8 与 Story 5 的验收、风险和完成证据。
