# 共享语言档案与通用提示词收口

- **日期**：2026-08-28
- **Epic**：`english-llm-prompts`
- **Story**：Story 04～06（语言中立后处理模板、严格共享语言档案、跨消费者与 UI 统一）
- **Plan**：[plans/english-llm-prompts/plan.md](../../../../plans/english-llm-prompts/plan.md)
- **ADR**：[ADR-033：共享语言档案与语言中立提示词](../../../../docs/adr/033-shared-language-profiles-and-neutral-prompts.md)

## 目的

消除“每个目标语言复制一套完整提示词”和各调用方自行维护语言名称映射的问题。目标语言配置现在只选择一个严格校验的语言档案，翻译、抽取、后处理和 FOMOD 统一把该档案中的模型可读语言名称注入英文通用模板。未知或损坏的语言档案在调用 LLM 前失败，不再静默回退到简体中文；按用户要求不保留旧提示词结构兼容层。

## 文件级变更

### Story 04：后处理阶段模板去重

- **修改 `src/transbridge/ai_translator/post_processor/quality_gate.py`、`llm_refiner.py`、`polisher.py`、`llm_arbiter.py`**：四个阶段只加载各自的 `default.toml`，并通过共享语言档案提供 `$source_lang` / `$target_lang`；移除缺失语言时的 `Simplified Chinese` 静默默认值。
- **新增 `tests/ai_translator/post_processor/test_language_neutral_prompt_loading.py`**：验证四个阶段只读取阶段级默认模板，不读取 `{locale}.toml`，同时能把受控语言档案中的 French/Japanese 注入模型提示词。
- **本地迁移 `data/prompts/{quality_gate,refinement,polish,arbitration}/default.toml`**：原按语言维护的四个模板合并为阶段级通用英文模板；旧阶段语言文件不再受支持。

### Story 05：严格共享语言档案与主提示词拆分

- **新增 `src/transbridge/config/language_profiles.py`**：定义不可变 `LanguageProfile`、`LanguageProfileError`、严格加载和发现接口；校验 locale 格式以阻止路径穿越，要求非空源/目标语言，并校验可选示例必须成对出现。发现接口跳过损坏档案并发出 warning。
- **修改 `src/transbridge/config/__init__.py`**：导出语言档案类型、错误和加载/发现入口，形成跨模块公共契约。
- **修改 `src/transbridge/ai_translator/prompt_builder.py`**：主翻译改为加载 `translation/default.toml`，术语抽取改为加载 `extraction/default.toml`；语言文件只提供元数据和可选示例。Python 内置 fallback 改为使用 `$game_name`、`$source_lang`、`$target_lang` 的语言中立英文模板；语言档案缺失时不执行 fallback。固定示例由语言档案数据安全序列化后注入，不再由语言文件持有整段指令。
- **修改 `tests/ai_translator/test_prompt_builder.py`**：删除旧 `translation.system` 兼容测试，增加阶段模板 fallback、固定示例注入及缺失语言档案明确失败测试，继续覆盖三消息结构、Prompt Cache 与 Structured Outputs 契约。
- **新增 `tests/config/test_language_profiles.py`**：覆盖合法档案、可选示例、非法/穿越 locale、缺失档案、不完整字段、发现时跳过损坏文件，以及仓库 `zh_CN` 文件只含元数据的结构约束。
- **本地迁移 `data/prompts/langs/zh_CN.toml`**：删除 `[translation]` / `[extraction]`，只保留 `[lang]` 和可选 `[example]`；新增 `data/prompts/translation/default.toml` 与 `data/prompts/extraction/default.toml`。

### Story 06：跨消费者与目标语言 UI 统一

- **修改 `src/transbridge/fomod/fomod_xml.py` 与 `xml_fidelity.py`**：移除各自的 locale-to-language 字典和裸 locale 提示方式，统一使用共享档案中的目标语言名称；档案解析错误不再被旧 FOMOD 的 LLM 异常回退吞掉。
- **修改 `src/transbridge/ui/tools/ai_translator/config_view.py`**：目标语言下拉框从已安装的有效档案动态生成，显示本地化名称但通过 item data 保存 locale code；已保存但不可用的代码会显示明确的不可用状态，而不是被静默覆盖。
- **修改 `src/transbridge/ui/tools/fomod/fomod_panel.py`**：复查发现原面板硬编码 `zh_CN`、`zh_TW`、`en`、`ja`，其中三个没有对应档案；现改为复用同一档案发现接口，避免显示必然失败的选项。
- **修改 `src/transbridge/smart_assistant/agents/agent_registry.py`**：翻译 Agent 改为“源文本到已配置目标语言”，不再固定英译中。
- **修改 `src/transbridge/smart_assistant/tools/tool_translator.py`**：`set_translation_config` 在修改配置前严格验证 `target_lang`，无效代码不会产生部分修改或保存。
- **本地修改 `data/skills/translate_with_terms.toml`**：移除“人名、地名保持英文”的固定策略，改为遵循活动语言档案和已批准术语表。
- **修改 `tests/test_fomod.py`、`tests/ui/test_fomod_journey.py`、`tests/ui/tools/test_embedding_retrieval_config.py` 和 `tests/smart_assistant/test_agent_tool_integration.py`**：分别验证 FOMOD 的模型可读语言名、两个动态语言选择器的 locale round-trip，以及配置工具拒绝不存在档案。

## 动机与兼容性

- 新增目标语言只需提供一个合法的 `langs/{locale}.toml`，不再复制六个翻译阶段的提示词。
- `LLMConfig.target_lang` 字段及其持久化值仍是 locale code，公共配置形状没有改名。
- 旧语言文件内的 `[translation]` / `[extraction]`，以及后处理阶段的 `{locale}.toml`，按明确要求不再读取；自定义模板必须一次性迁移到相应 `default.toml`。
- 新配置仍可默认选择 `zh_CN`，但运行时若该档案不存在或无效会明确失败，不会把其他请求猜成简体中文。
