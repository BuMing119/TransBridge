# 英文提示词迁移与回归门禁

- **日期**：2026-08-27
- **Epic**：`english-llm-prompts`
- **Story**：Story 01～03（翻译与后处理、智能助手与工具协议、直接调用与完整性门禁）
- **Plan**：[plans/english-llm-prompts/plan.md](../../../../plans/english-llm-prompts/plan.md)

## 目的

将 TransBridge 维护并发送给 LLM 或 Agent 的静态中文指令统一迁移为英文，同时保留中文目标输出、动态用户数据、占位符、JSON 契约、工具标识、Prompt Cache 分层和原生 Function Calling 行为。中文 UI 文案、日志、异常、工具展示名和其他不进入模型上下文的本地化内容不属于本次迁移。

## 文件级变更

### Story 01：翻译与后处理提示词

- **修改 `src/transbridge/ai_translator/prompt_builder.py`**：将翻译与术语抽取的 Python 回退提示词、动态批次说明和输出约束改为英文；增加仅在提示词渲染边界使用的已知批次类型英文映射，未知动态类型仍原样透传，避免修改共享业务分类或 UI 文案。
- **修改 `src/transbridge/ai_translator/post_processor/quality_gate.py`、`llm_refiner.py`、`polisher.py`、`llm_arbiter.py`**：将质量检查、修订、润色与仲裁的内置回退模板及模型指令改为英文，保留既有变量、JSON 字段、枚举和值域。
- **修改 `tests/ai_translator/test_prompt_builder.py` 及 `tests/ai_translator/post_processor/test_{quality_gate,refiner,polisher,arbiter}_prompt.py`**：更新精确措辞断言，继续验证模板契约、JSON 输出和阶段边界，而不是放宽原有断言。

### Story 02：Smart Assistant、Agent、Skill 与工具 Schema

- **修改 `src/transbridge/smart_assistant/prompts.py`、`context_builder.py`、`conversation_manager.py` 和 `reflexion/retry_handler.py`**：将系统、路由、上下文标题、观察/计划前缀和重试指令改为英文；保留“Respond in Chinese.”行为要求，因此迁移只改变指令语言，不改变助手面向用户的中文回答行为。
- **修改 `src/transbridge/smart_assistant/agents/agent_registry.py`**：将内置 Agent 的角色描述与系统提示改为英文，不改变 Agent 注册标识和执行路径。
- **修改 `src/transbridge/smart_assistant/skills/skill_executor.py`**：模型消息使用稳定的 Skill 名称注入英文前缀，避免把中文本地化展示名重新带入提示词；用户界面仍可显示本地化名称。
- **修改 `src/transbridge/smart_assistant/tool_registry.py` 以及 `tools/tool_{archive,default,editor,migrator,paratranz,parser,proofreader,translator,writer}.py`**：将进入分层工具目录、原生工具定义和参数 Schema 的描述改为英文；工具 `display_name`、`ToolResult`、日志和诊断消息保持中文，因为它们属于用户界面或运行反馈。
- **修改 `tests/smart_assistant/test_conversation_manager.py` 和 `test_tool_prompt_layering.py`**：更新模型可见文本的契约断言，同时保持原生 Function Calling 与分层工具发现测试。

上述部分涉及的部分文件同时含有工作区中既有的原生 Function Calling 变更；本日志只归属其中的提示词语言迁移，不把其他差异计入本 Epic。

### Story 03：其他直接 LLM 提示与完整性门禁

- **修改 `src/transbridge/fomod/fomod_xml.py`**：将 FOMOD 文本翻译的直接 LLM 指令和语言名称改为英文，保持输入输出结构不变。
- **修改 `tests/test_fomod.py`**：通过捕获模型消息验证新的英文指令，不改变 FOMOD 业务断言。
- **新增 `tests/smart_assistant/test_english_prompt_surface.py`**：运行时构建 Smart Assistant 系统提示、上下文、原生工具及参数描述、Agent 提示、Reflexion 重试消息和 SkillExecutor 注入消息，并拒绝仓库维护的静态汉字指令重新进入这些模型表面；测试不扫描任意用户数据或中文目标输出样例。
- **新增 `plans/english-llm-prompts/plan.md` 并修改 `plans/INDEX.md`**：记录三项 Story 的范围、边界、验收标准、并行实施关系和完成状态。

### 被 Git 忽略的本地 Prompt 覆盖

- 本地工作区还同步修改了 `data/prompts/**/zh_CN.toml` 与 `data/skills/translate_with_terms.toml` 中的模型指令，但仓库的 `/data/` 忽略规则使这些文件不属于当前 Git 差异。
- `zh_CN` 文件名、locale 名称和用于说明中文目标输出的样例被有意保留；本日志不将这些被忽略的本地覆盖伪装成可提交文件。

## 动机与兼容性

- 仓库维护者不再需要同步维护两套中文提示词措辞，模型侧契约统一使用英文。
- 公共工具名、JSON 字段、命名空间、模板变量和持久化格式均未重命名，无数据迁移要求。
- 英文系统指令继续要求 Smart Assistant 用中文回复；翻译管线仍按目标语言生成内容，中文源文本、术语和用户输入可正常出现在动态上下文中。
- UI 本地化与模型提示职责保持分离，工具展示名和结果反馈不会因本次迁移变成英文。

## 实际验证

- `python -m pytest tests/smart_assistant/test_english_prompt_surface.py tests/ai_translator/test_prompt_builder.py tests/ai_translator/post_processor/test_quality_gate_prompt.py tests/ai_translator/post_processor/test_refiner_prompt.py tests/ai_translator/post_processor/test_polisher_prompt.py tests/ai_translator/post_processor/test_arbiter_prompt.py tests/test_fomod.py -q`
  - 结果：`100 passed, 1 warning in 0.62s`；警告为 Windows 权限导致无法创建 `.pytest_cache`。
- 更宽的提示词与 Smart Assistant 聚焦测试曾分别达到 `166 passed`；两个并行实施分组分别报告 `88 passed` 与 `71 passed`。
- `python -m compileall -q src/transbridge/ai_translator src/transbridge/smart_assistant src/transbridge/fomod`
  - 结果：通过。
- AI 提示词分组的聚焦 Ruff check 与 format check 通过；相关 `git diff --check` 通过，仅报告工作区 LF→CRLF 转换警告。
- 扩展回归命令覆盖 `tests/ai_translator`、Smart Assistant 集成/工具合并、安全契约和 FOMOD 测试。
  - 结果：`330 passed, 2 failed, 27 errors`。27 个错误来自 pytest 临时目录 `PermissionError`；一个失败因缺少可选依赖 `xlrd`，另一个为 `test_start_translation_stop_and_status` 的状态断言失败。该结果不记为全仓通过。

## 遗留项

- Smart Assistant 分组未能执行 Ruff：仓库 `.venv` 指向缺失的 uv 管理 Python，系统 Python 也未安装 Ruff；修复环境后应补跑 `uv run ruff check src tests` 与 `uv run ruff format --check src tests`。
- 扩展回归中的临时目录权限、可选 `xlrd` 依赖和翻译停止状态断言需要在对应环境或业务任务中复验；它们不影响本次 100 项聚焦提示词测试的结论，但阻止声明全仓测试通过。
- `/data/` 下的 Prompt 与 Skill 文件是被忽略的本地运行时覆盖；若未来要求将默认模板随仓库分发，需要先明确数据目录的版本控制策略。
