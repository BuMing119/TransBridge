# 001: base.py 类型定义独立为 types.py

**日期**: 2026-05-22
**类型**: 增/改
**关联**: Epic: Smart Assistant 超重文件拆分重构 > Story 02: base.py 类型定义分离

## 修改文件

### `src/transbridge/smart_assistant/tools/types.py` (增)
- **修改内容**: 新建类型定义模块（345行），从 `base.py` 完整复制 5 个类：`ToolResult`（dataclass + 7个方法）、`ExecutionContext`（dataclass + safe_mutate/__getattr__/__setattr__）、`_FORWARDED_ATTRS` 常量、`HITLType`（Enum）、`HITLRequest`（dataclass）、`HITLResponse`（dataclass）。所有代码原样复制，零逻辑改动
- **原因**: ToolResult/ExecutionContext 被 39 个工具函数和所有工具模块 import，将它们与执行逻辑（guard_chain/decorators）混在一起导致 base.py 既是"类型定义仓库"又是"工具基础设施层"，605 行达到临界质量。分离后 import 关系更清晰

### `src/transbridge/smart_assistant/tools/base.py` (改)
- **修改内容**: 从 606 行缩减至 274 行。删除已迁移到 types.py 的类型定义（约 330 行），移除不再需要的 `json`/`dataclasses`/`enum` 导入。顶部添加重导出：`from .types import ToolResult, ExecutionContext, HITLType, HITLRequest, HITLResponse`。保留所有执行函数（`_build_guard_chain`/`execute_with_guardrails`/`filter_entries`/`resolve_scope_to_entry_ids`/`require_collection`/`validate_params`/`_apply_after_guards`/`_TYPE_MAP`）不变
- **原因**: 所有外部 `from .base import ToolResult` 路径通过重导出保持兼容，零 import 断裂

### `src/transbridge/smart_assistant/tools/__init__.py` (未改)
- **原因**: 现有 `from .base import ToolResult, ExecutionContext, ...` 通过 base.py 重导出继续可用，无需修改
