**类型**: 增/改
**关联**: Epic: Smart Assistant 超重文件拆分重构 > Story 04: 剩余模块精简收尾

## 修改文件

### `src/transbridge/smart_assistant/conversation_orchestrator.py` (改)
- **修改内容**: 新增模块级函数 `_create_llm_client(config, _cache=None)`（~35行），从 `_get_llm_client()` 方法中提取 LLM 客户端创建/缓存/复用逻辑（缓存键计算、mtime 检测、客户端创建）。`_get_llm_client()` 简化为配置加载 + 委托调用 `_create_llm_client()`。确认 `_get_prompt_builder()` 仅是 `PromptBuilder` 懒加载工厂，与 `prompts.build_system_prompt()` 职责不同，无重复。确认 `react_depth` 和 `auto_mode` 各有一次属性赋值 + 一组 property，无重复定义 bug
- **原因**: LLM 客户端创建逻辑内嵌在方法中 ~40 行，提取为模块级函数后可独立测试缓存策略和 mtime 失效逻辑

### `src/transbridge/smart_assistant/memory/memory_writer.py` (增)
- **修改内容**: 新建文件（~42行），完整复制 `MemoryWriterThread` 类（`threading.Thread` 子类），构造器签名不变：`__init__(self, storage_dir, metadata_path, index_path, get_metadata_cb, get_vector_store_cb)`。包含 `enqueue`/`run`/`_flush`/`stop` 方法
- **原因**: `memory_store.py`（335行）中内嵌的 MemoryWriterThread 与 MemoryStore 职责不同（异步写入 vs 向量检索），独立文件后两个组件可单独测试

### `src/transbridge/smart_assistant/memory/memory_store.py` (改)
- **修改内容**: 删除 `MemoryWriterThread` 类定义（约 120 行），移除仅由 MemoryWriterThread 使用的 imports（`os`/`deque`/`sanitize_for_storage`）。新增 `from src.transbridge.smart_assistant.memory.memory_writer import MemoryWriterThread`
- **原因**: MemoryWriterThread 外提后原位置重导出，MemoryStore 的 `__init__` 中创建 MemoryWriterThread 的代码不受影响

### `src/transbridge/smart_assistant/tools/task_manager.py` (改)
- **修改内容**: 新增 `on_finished(callback)` 方法——注册统一完成/失败回调（存储在 `_listeners["finished"]`）。新增 `notify_finished(task_id, success, message, data)` 方法——按 success 分发到 finished 和 legacy（completed/failed）回调列表。旧方法 `on_completed`/`on_failed`/`notify_completed`/`notify_failed` 保留为 deprecated wrapper，内部委托给新方法。`_listeners`、`remove_listener`、`reset()` 同步增加 `"finished"` 键。`set_main_thread_dispatcher`/`reset_dispatcher`/`get_handle` 保留不动（`chat_widget.py:712` 和 `tool_proofreader.py:129` 有活跃调用方）
- **原因**: `on_completed`+`on_failed` 和 `notify_completed`+`notify_failed` 两对方法各为镜像实现，合并为统一回调接口减少 API 表面积，旧方法保留为 wrapper 保证向后兼容
