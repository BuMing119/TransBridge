# V2 项目版本目录与 GUI 管理

- 日期：2026-08-18
- Epic：[project-session-persistence-v2](../../../../plans/project-session-persistence-v2/plan.md)
- Story：[S05 Projection、Dirty State 与 GUI Facade](../../../../plans/project-session-persistence-v2/stories/story-05-projection-dirty-facades.md)
- 状态：已实现并完成定向回归

## 背景

V2 Project、Variant 和生命周期服务已经存在，但工作台项目栏仍主要读取旧 `ProjectHandle`：V2 项目打开后可能继续显示“无项目”，版本下拉框没有可读目录，创建、复制、切换和删除版本也没有接入权威 V2 生命周期。重复激活同一版本还会无意义增加 Project revision。

本次整改补齐 V2 Project → Projection → AppContext → ProjectBar/MainWindow 的真实调用链，同时保留旧入口的兼容边界。

## 变更

### 应用合同与版本目录

- 新增 `src/transbridge/application/projects/catalog.py`：
  - 定义不可变 `VariantDescriptor` 和稳定的 Variant ID/显示名称目录。
  - 校验目录 ID、显示名称和唯一性，并提供新增、复制、移除目录项的纯函数。
  - 对只有一个未命名版本的既有 V2 Project 提供“默认”显示名，不要求重写存量数据。
- 更新 `src/transbridge/application/projects/models.py`：重复激活当前 Variant 时保持 Project revision 不变。
- 更新 `src/transbridge/application/projects/gui_facade.py`：增加 V2 空白版本创建、版本复制和删除命令；通过注入的 Repository、baseline、ID 与 lifecycle 端口执行，不直接修改 GUI 状态。
- 更新 `src/transbridge/application/projects/__init__.py`：导出版本目录公共合同。

### 持久化与装配

- 更新 `src/transbridge/bootstrap/persistence.py`：向 GUI Project 命令 Facade 注入 V2 Repository、baseline 与 ID 依赖。
- 更新 `src/transbridge/persistence/current_project.py`：打开 Project 时为其声明的所有 Variant 注册已验证 source baseline，使后续切换不退回无 baseline 的有损兼容路径。
- 更新 `src/transbridge/persistence/v2/repository.py`：增加经过根路径和既有记录校验的删除操作，供版本删除命令使用。

### Projection 与 GUI

- 更新 `src/transbridge/application/projections/adapters.py`：Project projection 增加项目名称、sources 和 Variant 目录。
- 更新 `src/transbridge/ui/context.py`：只读暴露投影后的 Project ID、名称、sources 和 Variant 目录，并通过 `project_changed` 通知界面。
- 更新 `src/transbridge/ui/workbench/_project_bar.py`：项目名称和版本下拉框改为读取 V2 projection；界面显示可读名称、操作传递稳定 Variant ID。
- 更新 `src/transbridge/ui/main_window.py`：接入 V2 新建、复制、切换和删除版本；耗时加载复用后台任务通道，完成后刷新权威 projection 和 source collection。

### 测试

- 新增 `tests/application/projects/test_variant_catalog.py`，覆盖默认名称、目录校验、增删与重复名称边界。
- 扩展 `tests/integration/gui/test_app_context_projection.py`，覆盖 V2 Project/Variant projection 和 ProjectBar 显示、选择行为。
- 扩展 `tests/integration/bootstrap/test_persistence_v2_projection_composition.py`，覆盖真实装配下的创建、复制、切换、删除和 revision 行为。

## 数据与兼容边界

- 未修改或重写 `data/` 下任何 Project、Variant 或 Session 文件。
- 既有 V2 Project 即使没有 `variant_names`，单一版本也会显示为“默认”。新增版本后，可读名称写入 Project 的可选 `variant_names` 元数据；不提升持久化 schema 版本。
- 旧 Project/Variant 入口仍保留；V2 权威路径不再依赖旧 display-name identity。

## 2026-08-18 全量自动加载性能补充

- Projection snapshot 改为单次递归冻结并共享不可变实例；读取 snapshot 不再对约 2 万条 entry 重复 `deepcopy`、JSON 序列化和递归冻结，`to_dict()` 仍返回隔离的可变副本。
- Step2 使用 Qt event loop 分批渲染，但无需“加载更多”按钮、滚动触发或其他用户操作：首批立即显示，后续批次自动调度，直至全部筛选结果加载完毕。
- generation token 会废弃旧筛选的排队批次；进度条反映真实已渲染数；定位尚未渲染的条目会在对应批次到达后自动选中。
- 真实约 19,470 行：首批 250 行约 0.08 秒，全部行约 2.43 秒；Projection snapshot 读取约 9 微秒。
- 定向测试 94 passed，扩展 persistence/projects/projections/GUI 回归 101 passed；Ruff 定向规则、compileall 和 diff-check 通过。正式 `uv run --locked` 仍被现有损坏的 `.venv` launcher 阻断，因此这些新增结果明确记录为系统 Python 3.13.5 证据。

仍保留两个已知边界：打开流程会为 legacy Collection 再解析一次 source（约 5 秒）；按产品要求，`QTableWidget` 最终仍持有全部行，极端数据量的模型虚拟化需另立范围。
