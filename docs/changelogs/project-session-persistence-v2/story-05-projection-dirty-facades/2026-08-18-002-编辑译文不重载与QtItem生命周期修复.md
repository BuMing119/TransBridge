## 问题

Step2 编辑译文后，Variant command 同步更新 projection。`AppContext` 对任何 projection revision 都无条件发出 `label_data_changed`，Step2 因而清空并重建全部行。原 `itemChanged` 回调随后继续调用已被 Qt 删除的 `QTableWidgetItem.row()`，产生 `RuntimeError: wrapped C/C++ object ... has been deleted`；用户位置、选择和已加载批次也随整表重建丢失。

## 变更

- `src/transbridge/ui/context.py::_apply_project_projection` 保存旧标签库和 entry-label 投影，仅在两者内容真实变化时发出 `label_data_changed`。译文、stage、revision 和 dirty 更新继续走各自状态，但不再误触发表格重建。
- `src/transbridge/ui/workbench/step2.py::_on_item_changed` 在进入同步 command 前提取 row、entry 和文本；command 返回后通过 `_find_rendered_translation_item` 重新取得当前 table item，不再解引用可能已经删除的 Qt wrapper。
- `tests/integration/gui/test_app_context_projection.py` 验证只有真实标签变化才发送标签通知。
- `tests/ui/test_step2_incremental_rendering.py` 覆盖两条用户成功链：正常译文 projection 更新不改变 render generation；同步 subscriber 强制重建并删除原 item 后，编辑仍不抛异常且译文正确显示。
- `plans/project-session-persistence-v2/stories/story-05-projection-dirty-facades.md` 增补 projection 信号语义和 Qt item 生命周期验收条件。
