# 富文本主题可读性与布局修复

- **日期**：2026-08-25
- **Epic**：`ui-foundation-framework`
- **Story**：S04 公共组件、主题适配器与有界资源缓存；S07 工具与富文本迁移跟进
- **状态**：已完成

## 修改内容

### `src/transbridge/ui/foundation/adapters.py`

- **操作类型**：修改
- `_css_color()` 对不透明主题色输出 Qt 富文本稳定支持的 `#RRGGBB`，仅在确有透明度时输出 `rgba(...)`。
- 不再把 Foundation 的 `#RRGGBBAA` canonical 表示直接写入富文本 CSS，避免 Qt 将八位十六进制颜色解析为错误透明度而使正文接近不可见。

### `src/transbridge/infra/markdown_renderer.py`

- **操作类型**：修改
- Markdown 标签先应用注入主题，再设置富文本内容，避免 `QLabel` 在 `setText()` 时捕获旧应用调色板。
- 将主题 CSS 作为经过 HTML 转义的内联样式包裹正文，使文本颜色在 Qt rich-text document 中显式生效；代码块继续使用既有独立 stylesheet。
- 普通 Markdown、加载失败占位和 fallback 标签均采用横向扩展、纵向内容上限策略，并移除渲染容器末尾 stretch，修复短文本被无意义白色区域拉高的问题。
- fallback 路径同样先应用主题再设置文本，保证解析失败时仍具有可读前景色。

### `tests/ui/foundation/test_theme_adapters.py`

- **操作类型**：修改
- 验证编译后的富文本样式包含当前主题的主文本色且不包含八位十六进制颜色。
- 验证 Markdown 生成的所有富文本标签均携带显式主文本色，同时保留代码块 stylesheet 与容器 stylesheet 合同。

## 修改原因

智能助手消息和上下文说明虽然接入了 ThemeSnapshot，但 Qt 富文本对 `#RRGGBBAA` 的解释与 Foundation canonical 颜色表示不一致，加上主题应用晚于 `setText()`，导致浅色主题下正文颜色极淡，用户无法辨认对话内容。Markdown 容器的纵向 stretch 还会把短内容扩展为大面积空白。此次修复在主题适配与渲染根路径统一解决颜色和布局问题，不在具体业务面板叠加局部样式补丁。
