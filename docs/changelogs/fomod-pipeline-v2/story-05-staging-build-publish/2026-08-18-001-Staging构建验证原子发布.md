## 增量内容

将 FOMOD 构建与归档出版物化到隔离 staging，验证后一次原子替换，并可靠清理：

1. **Staging 构建**（`application/fomod/publish.py::StagingPackPublisher`）：打包输出写入与目标同卷的目标父目录 `.name.<token>.stage<suffix>` 受限 staging 文件（保留目标格式后缀以便归档检测器按后缀分派），builder/pack 永不直接写正式路径；目标仅在唯一提交点被原子替换，绝不先删旧产物。
2. **重开验证**：`pack` 后用同一 `ArchivePolicy` 经 `inspect_archive` 重开，核对条目、hash/size、root layout 与安全预算；空档拒绝（FOMOD_ARCHIVE_EMPTY）、重开失败聚合为 `FOMOD_ARCHIVE_REOPEN_FAILED`。
3. **Manifest 对应**：成功发布写入 `FomodManifest`（`output_archive.manifest.json`，原子写），记录 run_id/target_locale/config_hash/new-old archive hash/policy ids/build fingerprint/artifact sha256+size，可从归档回溯其输入与策略。
4. **提交前门禁**：取消、run_id（commit guard）、目标指纹（`TARGET_FINGERPRINT_CONFLICT`）均在 replace 前检查；失败/取消保留既有目标并通过验证备份（`_backup_verified`）。
5. **清理策略**：`CleanupPolicy`（CLEAN_ALWAYS / RETAIN_ON_FAILURE / RETAIN_ALWAYS）；非保留时失败/取消清理 staging，清理失败记录 `STAGING_CLEANUP_FAILED` 诊断并保留残留路径；成功后 staging 已被原子替换消费。
6. **PublishStage 重构**：`fomod/stages.py::PublishStage` 由「直接 pack 到正式路径」改为调用 `StagingPackPublisher`，产出 `published_archive` + `publish_manifest` verified 工件。
