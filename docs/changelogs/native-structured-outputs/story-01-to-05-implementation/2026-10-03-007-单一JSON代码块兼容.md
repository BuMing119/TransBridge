## 原因与范围

用户要求在继续使用 Responses API 原生 JSON Schema 的前提下，兼容模型偶尔把完整 JSON 包在 Markdown 代码块中的输出。此前 006 增量将所有此类响应判为无效；本次只恢复完整、单一的 `json` 或无语言标签围栏，不接受任意文本修复或失败后改用另一协议。

## 本次变更

- `src/transbridge/infra/llm_structured_outputs.py`：完整响应与单一围栏严格匹配后剥离围栏；内部 JSON object 和原 Schema 校验均通过才返回纯 JSON。成功恢复时只记录 schema 名称，不记录译文。多围栏、附带说明、残缺围栏及内部数据无效仍失败。
- `src/transbridge/application/translation/postprocess_stages.py`：独立 Responses HTTP 后处理端口先将原始 `output_text` 交给共享结构化校验器，再解析业务结果，使其与主客户端使用同一围栏规则。
- `tests/infra/test_llm_structured_outputs.py`：覆盖 `json`、大写标签、无标签、CRLF、错误语言、附加文本、多围栏、截断、Schema 错误及日志不含译文。
- `tests/infra/test_openai_structured_outputs.py`：覆盖普通和流式 Responses 返回单围栏时最终结果为纯 JSON。
- `tests/application/translation/test_postprocess_structured_outputs.py`：覆盖 DeepSeek HTTP 后处理单围栏成功及附加说明失败。
- `docs/requirements.md`、`docs/adr/032-native-structured-outputs-for-ai-translation.md`、`plans/native-structured-outputs/plan.md`：更新兼容边界、流式最终校验与安全诊断；旧增量文件保持历史原样。
- `docs/changelogs/INDEX.md`：仅追加本 Epic 的新记录链接。
