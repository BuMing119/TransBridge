## 实现增量

本 Story 只建立「真实成功链 + 跨入口 parity」测试资产，不改 src 业务代码、不动全局索引（plans/INDEX.md、docs/INDEX.md、docs/changelogs/INDEX.md、remediation-ledger.md 均交由主线合并），不 git commit/push。

- 新增测试支撑模块 `tests/quality/success_chains.py`：
  - `SuccessChain` 值对象（chain_id、runner、受控 entrypoint 工厂列表、normalizer、semantic_assert、fixture_path+checksum、description）；
  - 7 份真实 fixture 的 sha256 checksum 注册表 `FIXTURE_CHECKSUMS`，`verify_fixture_checksums`/`preflight` 启动校验防漂移（漂移抛 `FixtureIntegrityError`）；
  - `run_chain_deterministic(chain, repetitions=3)`：同用例重复 N 次断言归一化输出一致；`assert_entrypoint_parity(chain)`：对同一 use case 经多个入口归一化后断言 outcome/counts/diagnostic 码/artifact 摘要一致；
  - `summarize(result)`：返回可比较 dict（outcome、counts/stats、diagnostic codes、entries、artifact 摘要、run_id、ChangeSet 条目数等），去除绝对路径与时间；
  - 全程使用真实序列化/组合根（`TranslationIoUseCase` + 真实 adapter、受控 HTTP 端口 + 真实 HTTP 栈、`PipelineEngine` + `default_stages`），mock 仅用于外部故障注入。

- 新增 pytest 资产 `tests/quality/test_success_chains.py`，覆盖：
  - EET / XT / Strings(SSE) / ESP / ParaTranz（离线双 ID）各自的真实 parse→write→reparse 成功链（`TranslationIoUseCase`，逐 fixture）；
  - 受控 HTTP 后处理链（refine→polish→arbitrate，`OpenAiPostProcessHttpPort` + `PostProcessWorkload`）；
  - FOMOD typed 九阶段成功链（复用 `PipelineEngine` + `default_stages`，发布并校验 verified archive）；
  - 跨入口 parity：GUI 直连 `TranslationIoUseCase` 与 Agent 侧同一 use case 服务，同一输入归一化后一致；
  - 确定性：每条成功链重复 3 次归一化输出一致；
  - fixture checksum 校验生效（改坏一个字节即检测，小型构造用例演示，未破坏真实 fixture）。
