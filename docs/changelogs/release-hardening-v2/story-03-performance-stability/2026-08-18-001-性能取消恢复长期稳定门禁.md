## 实现增量

新增 `tests/performance/`（新建目录），把已确认的性能/稳定性预算固化为「固定 corpus + 硬件档位 + P50/P95 测试 + 版本化阈值」：

- `benchmark_cases.py`：版本化 `HardwareTier`、`Thresholds`（`THRESHOLDS_V1` 为唯一预算真源）、`BenchmarkCase`（corpus hash / warmup / repetitions / tier / 阈值 / RSS 预算）与用例注册表（small-esp、medium-parse、ui-heartbeat、ui-progress、cancel-100、checkpoint-100k、session-500、archive-budget）。corpus 提供固定 SHA-256 指纹，漂移即显式报错。
- `measure.py`：自实现线性插值 percentile（P50/P95，无新依赖）；`sample_time` 基于 `time.perf_counter`（monotonic，独立于业务 `datetime` clock）；`measure_rss_growth` 用 psutil 实测 RSS，psutil 不可用时退回 tracemalloc 代理并明确标注「近似而非精确 RSS」；`run_isolated` 子进程隔离测跨进程峰值 RSS。
- `test_performance_gates.py`：12 条门禁，全部快速（整套约 10s），用小样本验证测量链路 + 边界不越；硬性预算实体保留在版本化配置，最终 Windows 硬件证据由 S05 给出。

## 预算结论（本机小样本 = 早期反馈；真正的 Windows 硬件最终证据由 S05 环境给出）

本机为 64 位开发机，且运行期间有其他会话并发负载，绝对值略波动，但对预算余量充足：

| 预算项 | 预算 | 本机实测（P50 / P95，早期反馈） | 结论 |
| --- | --- | --- | --- |
| 小 ESP 解析（sample.esp 3.95MB） | P95 ≤ 3s | 629.9ms / 1045.8ms（n=5，并发负载下） | ✅ 余量充足 |
| 中 ESP/EET（构造 10k 记录 ~2MB） | P95 ≤ 30s | 622.7ms / 660.2ms（n=3） | ✅ 余量充足 |
| 中 parse RSS | ≤ 1 GiB | 子进程峰值远低于 1 GiB（psutil） | ✅ |
| 取消 P95（并发 ≤3，100 个假 LLM 调用） | P95 ≤ 1s | 亚毫秒（0.0ms） | ✅ |
| checkpoint 100k save/load | P95 ≤ 100ms | 10k 样本 save 15.5/16.1ms、load 12.9/14.0ms | ✅ 链路/边界 |
| 500 轮 Session RSS 增长 | ≤ 15% | 0.14%（psutil，base≈95.4MB / peak≈95.6MB） | ✅ |
| UI heartbeat / progress | ≤200ms / ≤500ms | 边界探针（见下） | ✅（边界探针） |

**边界说明（未伪造 GUI 通过）**：本项目 GUI 为 PyQt，UI 自动化受限。因此 UI heartbeat/progress 提供「最小可执行探针」：`test_gate_ui_progress_delivery_boundary_p95_le_500ms` 与 `test_gate_ui_heartbeat_boundary_p95_le_200ms` 只验证事件回调/心跳调度器的投递延迟边界，明确标注为 boundary probe，**不**声称真机 PyQt 通过；真实 GUI 指标归属 S05。

**100k checkpoint 说明**：开发机对 100k 条目的真实 save/load 探针实测约 378ms（save）/ 222ms（load），**超过 100ms 预算**——该信号已记入本文档作为早期反馈，需在 S05 硬件复验（阈值**未**放宽，预算实体仍为 100ms@100k）。门禁本体的 100k 用例按规划使用校准的 10000 条目小样本验证测量链路与 100ms 边界不越，硬性 100k 证据留 S05。

## 踩坑与健壮性收尾

- **取消门禁公平性**：初版 `test_gate_cancel_p95_le_1s_concurrency_le_3` 在开发机并发会话饱和时偶发超 1s（wall-clock P95 受外部 CPU 饥饿影响）。修复：等待所有 3 个 worker 确认进入安全点轮询循环后才计时取消（测量真实取消传播延迟，而非「尚未被调度启动」worker 的启动时间），并发仍 ≤3，预算仍为 1s——未放宽阈值。修复后 0/6 全量 + 0/15 单测稳定通过。
- **100k 真实探针**：开发机对 100k 条目的真实 save/load 探针约 378ms/222ms，超过 100ms 预算——作为早期反馈记入本文档，阈值未放宽，留 S05 复验。
- **evidence 与并发临时文件竞争**：`tools/qa/run_evidence.py` 用 `git status --untracked-files=all` + `git ls-files --others --exclude-standard` 散列未跟踪文件作为 diff_sha256。此前各 Story 会话的 `qa-tmp-*` 临时目录未被 gitignore，并发会话运行时临时文件抖动导致 `PermissionError`。
  - 处理：把 `/qa-tmp-*/` 加入 `.gitignore`（各 Story 会话 TMP/TEMP 落点勿入库），evidence 工具据此跳过，消除竞争。这是唯一的仓库级改动，仅影响忽略规则，不改任何受保护索引/基线。
