# AI 任务项目术语状态与查看入口

- 日期：2026-09-11
- Epic：`ai-task-project-terminology`
- Story：`implementation`（对应计划“实施与验收”，直接实现，未另编 Story 编号）。
- Plan：[AI 任务中的项目术语展示](../../../../plans/ai-task-project-terminology/plan.md)

## 范围与原因

用户在 AI 翻译任务的“术语库”页无法识别当前项目术语库。原页面只展示动态词库、ParaTranz 和本地文件等来源配置；“查看/编辑动态术语库”打开动态词库，而项目术语工作台入口标为“前往术语工作台创建译名方案…”，难以发现查看项目术语的能力。

本增量依据本任务代码差异、新增文件和实际验证输出，记录项目术语摘要与查看入口的实现。归档时相关实现仍未提交，暂存区为空。没有生产文件删除或移动；原来源组内的工作台按钮由顶部项目术语面板中的按钮替代。

## 逐文件变更

以下生产文件位于 `src/transbridge/ui/tools/ai_translator/`。

- **新增 `project_terminology_view.py`**：`ProjectTerminologyPanel` 提供独立的“当前项目术语库”分组，显示所属工程/翻译版本、状态和术语版本；`render` 更新状态及版本，`set_context` 更新工程标签。长工程名和版本标识使用省略标签并提供完整提示文本；提供“查看项目术语库…”和“刷新”按钮，让用户明确区分项目术语与下方其他来源。
- **新增 `project_terminology_controller.py`**：`_ReadSummary.run` 在后台复用 `freeze_project_terminology` 读取当前有效快照，统计 `is_effective` 条目，区分已发布、已发布但为空、尚未发布及读取失败；错误保留日志上下文并显示恢复提示。`ProjectTerminologyController.refresh` 处理无工程、无服务和读取中状态；`_start` 通过线程池串行提交读取并合并刷新请求；`_ready` 用请求代次与项目身份拒绝过期结果。工程、翻译版本和译名方案变化，以及窗口显示/重新激活或手动刷新都会更新摘要；`close` 停止待处理刷新，迟到结果不更新已关闭窗口。
- **修改 `single_task_view.py`**：`_build_task_tabs` 在“术语库”页的来源配置上方插入项目术语面板；将现有 `save_term_source_as_scheme_btn` 控件契约绑定到新的查看按钮，继续复用工作台打开回调。`_build_terms_group` 移除旧的创建方案入口，避免出现两个指向同一工作台的按钮；来源排序、文件选择和动态词库编辑保留原有行为。
- **修改 `view_controls.py`**：`TranslatorControls._NAMES` 增加 `project_terminology_panel`，通过现有控件命名空间向窗口组合层提供面板。
- **修改 `ai_translator_window.py`**：`AITranslatorWindow.__init__` 注入工程上下文、工作台可用性及译名方案控制器，创建 `ProjectTerminologyController`；`closeEvent` 关闭项目术语控制器。项目身份或查看入口不可用时禁用查看按钮，已发布状态读取留在后台执行。
- **新增 `tests/ui/tools/test_ai_project_terminology.py`**：16 项参数化回归覆盖有效计数排除停用/待确认条目、与任务冻结版本一致、读取不在 UI 线程、已发布空库、未发布、损坏/不可用/异常/错误工程快照、缺少工程或服务、五类刷新触发，以及读取过程中切换工程或销毁窗口后的迟到结果处理。
- **修改 `tests/ui/tools/test_ai_translator_task_layout.py`**：更新工作台入口文案断言，验证“当前项目术语库”分组及查看按钮归属，同时保留四个任务页、原来源顺序和回调路由断言。
- **修改 `tests/ui/tools/test_ai_translator_story08.py`**：为工作台路由回归补充已保存工程/翻译版本身份，验证新按钮的可用条件下仍能打开原项目术语工作台。
- **新增 `plans/ai-task-project-terminology/plan.md`**：记录本轮局部实现的范围、阶段、验收语义与验证结果；明确数量是当前已发布版本中的有效条目总数。

本次归档新增本文件，并仅为该增量更新 `docs/changelogs/INDEX.md` 和 `plans/INDEX.md` 的对应入口；既有增量文件保持不变。
