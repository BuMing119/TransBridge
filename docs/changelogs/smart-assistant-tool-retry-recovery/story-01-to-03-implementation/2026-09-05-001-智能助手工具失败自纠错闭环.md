# 智能助手工具失败自纠错闭环

- **日期**：2026-09-05
- **Epic**：`smart-assistant-tool-retry-recovery`
- **Story**：S01～S03
- **Plan**：[Smart Assistant 工具失败恢复补齐](../../../../plans/smart-assistant-tool-retry-recovery/plan.md)
- **类型**：架构增量、实现、回归测试与 QA

## 背景与目的

Smart Assistant 原有 ReAct 路径会创建没有 LLM client 的 `RetryHandler`，因此工具失败后无法执行参数修复；
Graph/Plan 路径则自行加载客户端，并且只处理异常，不处理普通 `ToolResult(success=False)`。本次把两条路径统一到
一个有界、安全的 Reflexion 协调器：纠错模型同时获得脱敏后的当前参数、权威工具 schema 和结构化失败信息；
修正参数重新通过同一套 schema 与护栏后才允许重试。重试耗尽仍闭合原生工具调用并继续外层 ReAct。

本记录只覆盖当前 `smart-assistant-tool-retry-recovery` plan 可明确归属的差异。

## Story 01：共享重试协调器与结构化纠错上下文

- `src/transbridge/smart_assistant/reflexion/retry_executor.py`（新增）：实现 `ToolRetryExecutor` 与 `RetryOutcome`；
  统一归一化异常、字典结果和 `ToolResult`，按首次调用外最多三次重试执行有界循环，并记录 `attempt`、
  `retry_count`；支持取消、瞬态错误原参数重试、LLM 参数修复和无分析结果时安全停止。
- `src/transbridge/smart_assistant/reflexion/retry_handler.py`（修改）：改为按 `error_category`、`error_code` 和兼容
  文案分类失败；通过 provider 获取当前会话 LLM client；向分析模型发送脱敏后的当前参数、`ToolSpec.parameters`
  和结构化 `ToolResult`；只接受同一工具的完整 `adjusted_args`，并恢复进程内原始凭据值，避免模型读取、删除或
  改写敏感字段。客户端获取、模型响应和异常日志均执行安全降级与脱敏。
- `src/transbridge/smart_assistant/reflexion/__init__.py`（修改）：导出共享协调器及结果契约。
- `src/transbridge/smart_assistant/tools/base.py`（修改）：护栏拒绝不再压扁成单一文本；保留阶段、错误类别、错误码、
  `json_pointer` 和恢复建议，并允许 Graph 为轻量 ToolSpec 显式传入工具名。每次调整参数后继续复用
  `execute_with_guardrails()` 完成二次校验。
- `src/transbridge/smart_assistant/tools/types.py`（修改）：为 `ToolResult.fail()` 增加可选 `data`，承载结构化
  失败详情而不破坏既有调用形式。

## Story 02：统一 ReAct、Graph/Plan 与 Qt 执行边界

- `src/transbridge/smart_assistant/tool_execution_handler.py`（修改）：注入共享 `RetryHandler`/LLM client provider，
  ReAct 工具调用委托统一协调器；自动重试只允许 `read`、无需确认、非长任务且未显式禁用 retry 的工具；新增
  detached 执行结果，在 worker 中调用工具、在主线程统一写入会话和 UI，确保原生 `tool_call_id` 只闭合一次。
- `src/transbridge/smart_assistant/graph_executor.py`（修改）：删除执行器内部的配置和客户端加载；Graph/Plan 对异常与
  `ToolResult.fail()` 使用同一协调器，并在每次参数调整后重新运行护栏；write/admin 和需确认工具维持单次执行。
- `src/transbridge/smart_assistant/execution_engine.py`（修改）：增加可选 `retry_handler` 注入并转交 GraphExecutor，
  保持既有构造调用兼容。
- `src/transbridge/smart_assistant/conversation_orchestrator.py`（修改）：提供当前 provider-neutral LLM client 的公开只读
  端口，供组合根注入纠错分析器。
- `src/transbridge/smart_assistant/session_controller.py`（修改）：用异步 pending 返回值区分同步完成和后台 ReAct；
  后台调用完成前保持 `EXECUTING`，避免提前开启下一轮 LLM。
- `src/transbridge/ui/tools/smart_assistant/react_execution_binding.py`（新增）：以单 worker 执行安全只读调用，通过 Qt
  queued signal 回主线程显示实时重试状态和提交最终结果；用 generation 隔离取消后的迟到回调，并在关闭时非阻塞
  释放执行器。
- `src/transbridge/ui/tools/smart_assistant/chat_composition.py`（修改）：组合 LLM client provider、共享 retry handler、
  ReAct 后台 binding 和 SessionController 异步端口。
- `src/transbridge/ui/tools/smart_assistant/confirmation_view.py`（修改）：Plan 复用共享 retry handler；确认动作识别异步
  pending，避免后台执行尚未结束时重复触发 ReAct 继续。
- `src/transbridge/ui/tools/smart_assistant/chat_widget.py`（修改）：持有并关闭 ReAct binding；新消息、清空会话和关闭
  窗口时使在途结果失效。

- `tests/smart_assistant/test_input_validation_guard.py`（修改）：验证 schema 失败保留 `input` 分类、稳定错误码、恢复建议
