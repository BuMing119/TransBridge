## 背景与用户可见变化

模型网络超时后，请求会暂停并释放执行资格，但旧“重试”入口直接启动模型轮次，没有重新接纳请求，
导致 `TURN_LEASE_STALE: no request admitted for this model turn`。现在按钮复用请求管理恢复路径：
路由阶段恢复待处理输入，执行阶段继续原有暂停请求。已记录的工具结果保留，旧按钮不会为已结束请求创建后继请求。
这里恢复的是请求和已记录步骤；仍需重新发起模型调用，不支持从半截流式文本继续生成。

工具自纠错模型返回 `null` 等合法但类型错误的 JSON 时，原分析器会在 `parsed.get()` 处抛出异常。
现在校验顶层对象、布尔型 `retry` 和对象型 `adjusted_args`，不合规响应安全停止重试并保留原工具失败。

网络类工具失败原先立即重试，现在在既有安全重试资格内依次等待 1、2、4 秒。等待循环每次最多休眠 50ms，
检查调用方取消信号；取消后不再发起工具调用。默认仍为首次调用之外最多三次重试。

## 逐文件变化

1. **修改** [conversation_orchestrator.py](../../../../src/transbridge/smart_assistant/conversation_orchestrator.py)
   - `ConversationOrchestrator.retry()` 在存在请求 binding 时委托 `management.retry_failed_turn()`，
     避免绕过执行资格接纳；无请求 binding 的旧调用路径保持原有手动重试行为。
2. **修改** [request_binding.py](../../../../src/transbridge/ui/tools/smart_assistant/request_binding.py)
   - `RequestBinding.fail()` 在记录失败和释放资格之前捕获失败轮次所属上下文与请求 ID，供重试定位原请求。
3. **修改** [request_management_binding.py](../../../../src/transbridge/ui/tools/smart_assistant/request_management_binding.py)
   - 新增 `_failed_turn`、`capture_failed_turn()`、`retry_failed_turn()`。
   - 拦截关闭、非活动、上下文改变及已有执行资格的重试；路由恢复复用 `retry_inputs()`，
     未结束且暂停的请求复用 `control(request_id, "resume")`，防止旧按钮重启已完成请求。
4. **修改** [retry_handler.py](../../../../src/transbridge/smart_assistant/reflexion/retry_handler.py)
   - `analyze_and_adjust()` 优先解析完整 JSON，仅在 JSON 语法解析失败时兼容提取说明文字或代码块中的对象。
     因而不会把合法数组中的对象误识别为顶层重试指令。
   - 类型不合规时记录诊断并返回 `None`；修正 `adjusted_args` 错误日志，使其准确表示“停止重试”。
5. **修改** [retry_executor.py](../../../../src/transbridge/smart_assistant/reflexion/retry_executor.py)
   - `execute()` 为原参数瞬态重试接入有上限的退避，新增 `_wait_before_retry()` 实现可取消等待。
   - 调用前取消按实际已执行次数计数，未调用时 `attempt=0`；`_with_attempts()` 将 `retry_count` 下限限制为 0。
     等待期间取消仍返回 `TOOL_CALL_CANCELLED`，不会虚增执行次数。
6. **修改** [test_retry_executor.py](../../../../tests/smart_assistant/test_retry_executor.py)
   - 增加 10 种非法或类型不符分析响应的回归，验证原始错误码和首次调用结果保留。
   - 使用可控时钟验证网络重试发生于 0、1、3、7 秒；验证等待期间取消不二次调用及取消计数。
7. **新增** [test_network_retry_recovery.py](../../../../tests/ui/tools/smart_assistant/test_network_retry_recovery.py)
   - 复用真实 Qt 面板与临时 Session 存储 fixture，以离线 Provider 注入超时。
   - 覆盖路由/执行两个阶段和聊天按钮/请求清单两个恢复入口，共 4 个参数化场景。
   - 执行阶段先确认并完成只读工具，再让下一轮模型超时，验证恢复后请求 ID、单条输入和唯一工具结果保留；
     再次点击旧重试按钮不会重建已完成请求。
