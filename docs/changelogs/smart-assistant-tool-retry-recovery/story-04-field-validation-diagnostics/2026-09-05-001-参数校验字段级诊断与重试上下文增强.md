# 参数校验字段级诊断与重试上下文增强

- **类型**：错误契约增强、安全加固、回归测试与 QA

## 背景与目的

S01～S03 已让 Reflexion 同时获得当前参数、权威工具 schema 和结构化失败载荷，但 schema 校验的具体原因仍主要
位于首个错误的自然语言消息中。面对多个字段同时错误时，纠错模型需要自行解析文案并多轮发现问题。本 Story 将
参数校验结果扩展为完整、确定性排序的 `validation_issues[]`，让模型一次获得字段路径、约束类型、期望值和实际
JSON 类型；同时不复制实际参数值，继续由单独脱敏的当前参数提供修正依据。

本记录仅覆盖当前 S04 可明确归属的差异；既有 S01～S03 实现仍由上一条增量记录描述。

## 实现变更

- `src/transbridge/application/tools/schema.py`（修改）：
  - 扩展 `ArgumentValidationError`，增加稳定 `code`、schema keyword/schema pointer、`expected`、
    `actual_type` 及 `to_dict()` 序列化契约。
  - 为常用 JSON Schema 约束建立稳定代码，例如 `TYPE_MISMATCH`、`REQUIRED_FIELD_MISSING`、
    `UNKNOWN_FIELD`、范围、长度和集合约束代码；未专门映射的复杂约束使用 `SCHEMA_CONSTRAINT_FAILED`。
  - 返回全部确定性排序的问题；将 required 和 `additionalProperties` 错误展开到缺失或未知字段的 JSON Pointer。
  - 使用 JSON 类型名称并生成不回显实际参数值的稳定消息，避免枚举、范围等默认校验文案复制凭据或大段文本。
- `src/transbridge/smart_assistant/guardrails/base.py`（修改）：在 `GuardResult` 中增加可选
  `validation_issues`，供输入护栏无损传递全部字段诊断。
- `src/transbridge/smart_assistant/guardrails/input_validator.py`（修改）：schema 失败和根参数非对象失败均返回
  `ARGUMENT_SCHEMA_INVALID`、兼容首项 `json_pointer` 及完整问题数组。
- `src/transbridge/smart_assistant/tools/base.py`（修改）：
  - `_guard_failure()` 将护栏问题数组投影到 `ToolResult.data`，保留既有 `phase/json_pointer`。
  - `validate_params()` 装饰器使用相同的数据结构，并标记 `recovery_action="adjust_arguments"`。

## 测试变更

  字段级结构，并用 canary 验证实际参数值没有进入诊断载荷。
- `tests/smart_assistant/test_agent_tool_integration.py`（修改）：验证 `validate_params()` 的兼容错误字段、稳定问题内容

  `validation_issues[]`，且业务对象未被修改。
- `tests/smart_assistant/test_retry_executor.py`（修改）：验证 Reflexion 提示能够收到 `TYPE_MISMATCH`、期望类型和实际
  JSON 类型等机器字段。

## 遗留项

- `anyOf`、`oneOf` 等复杂组合约束目前保留为单项 `SCHEMA_CONSTRAINT_FAILED`，不展开每个候选分支；纠错模型仍可
  结合完整权威 schema 判断。常用字段级约束已具备稳定代码和精确路径。
- 本 Story 不涉及 UI 呈现变化，因此未执行人工 GUI 点击冒烟。
