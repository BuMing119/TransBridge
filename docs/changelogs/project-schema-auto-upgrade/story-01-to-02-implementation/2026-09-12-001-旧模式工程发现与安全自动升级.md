- **日期**：2026-09-12

- **类型**：持久化兼容、缺陷修复与回归防护

## 问题与根因

当前持久化 schema 从 3 提升到 4 后，一个仍为 schema 3 的合法 Project 在开始中心被显示为“工程记录已损坏”。只读检查确认该记录是可解析 JSON，身份、来源和 Variant 引用仍存在；同一文档通过 `migrate_to_current()` 的 V3→V4 内存迁移后可被当前 validator 接受。

根因不是用户数据发生变化，而是三个入口保留了具体历史版本的硬编码：Project catalog 和 catalog repair 只对 schema 2 调用迁移，工程打开预检只接受 `{2, SCHEMA_VERSION}`。因此，每次当前 schema 再提升时，上一合法版本都会绕过已有的通用迁移链并被误判。

本次增量只记录能够从当前任务上下文、目标文件 Git 差异、新增 plan 以及实际测试输出确认的变更。工作区中并行存在的智能助手上下文压缩、请求生命周期和其他未提交文件不属于本 Epic；共享需求与索引文件只记录本 Epic 对应的新增段落或行。

## 逐文件变更

以下路径均相对仓库根目录。

### 旧版本发现与正式升级

- **修改 `src/transbridge/persistence/project_catalog.py`**：`_project_document_for_projection()` 从只识别 schema 2 改为对所有 `version < SCHEMA_VERSION` 的记录调用显式迁移链；迁移仅生成内存文档，随后继续执行当前 schema、身份与引用校验。模块说明补充“目录查询只读、激活才发布迁移”的责任边界。
- **修改 `src/transbridge/persistence/project_catalog_repair.py`**：缺失 catalog 的候选扫描不再硬编码 schema 2；具有完整迁移路径的旧版 Project 可在内存迁移验证后加入新 catalog。服务仍只允许写派生的 `project-catalog.json`，不写回 Project/Variant。
- **修改 `src/transbridge/persistence/current_project.py`**：`prepare_path()` 的版本预检改为明确拒绝未来版本，把历史版本是否可迁移交给 `ProjectRepository.read_snapshot()` 和当前 validator。准备阶段继续不写盘；正常激活经既有 `V2ProjectCandidateLoader` 调用 repository `load()`，复用原版本备份、迁移验证、staging 和原子替换，将 Project 与活动 Variant 写为当前 schema。

### 回归测试

- **修改 `tests/persistence/v2/test_project_catalog.py`**：新增真实形态的 V3 Project 文档，验证 catalog 将其投影为可用，reason 为空，原始 Project 字节不变，且没有 write、replace、remove 或 mkdir 调用。
- **修改 `tests/persistence/v2/test_project_catalog_repair.py`**：新增 catalog 缺失时恢复 V3 Project 的测试，验证只发布 catalog 而不改 Project；测试数据为 schema 3 以上补齐 source registry 字段；未来版本改用 `SCHEMA_VERSION + 1`，避免下次升版后再次把合法旧版本写死为未来版本。
- **修改 `tests/persistence/test_project_recovery.py`**：把“准备保持旧记录不变、激活后升级”集成场景扩展到 schema 2 和 schema 3，同时验证 Project 与 Variant 最终均为当前 schema，已保存译文保持不变。

## 用户可见结果

- schema 提升后，具有完整迁移路径且能通过当前校验的旧工程在开始中心保持可见、可打开，不再被误报为损坏。
- `project-catalog.json` 缺失时，上述旧工程可参与启动自愈，但 Project/Variant 在扫描阶段仍保持原字节。
- 用户实际打开并正常激活工程后，Project 与活动 Variant 自动备份并升级到当前 schema。
- 损坏、未来版本、路径/身份不匹配、迁移失败或来源不可恢复记录不会被强制覆盖；来源不可恢复仍使用既有只读恢复语义。

## 兼容性、边界与遗留项

- 兼容范围限于 repository 已提供完整显式迁移链且具有 canonical 身份的持久化版本；无 canonical 身份的 legacy V1 工程包继续走既有导入/恢复路径。
- 当前 schema 和 catalog schema 均未因本功能提升；已升级记录由 repository 的版本化备份提供恢复证据，禁止通过手工改版本号伪造回退。
- 多进程同时写同一持久化根的强一致性不在本次范围内，沿用 ADR-024 的单进程桌面写入假设。
- 未运行全仓库 pytest、真实 GUI 人工点击、安装包或发布构建；功能不涉及网络服务。
- 本次计划范围内未完成项：无。
- 本轮归档不修改业务代码，不提交或推送 Git。
