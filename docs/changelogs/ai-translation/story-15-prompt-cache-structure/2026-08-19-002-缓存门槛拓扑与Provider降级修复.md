# 002: 缓存门槛、拓扑与 Provider 降级修复

**日期**: 2026-08-19
**类型**: 修复/测试
**关联**: Epic: AI 自动翻译 > Story 15: 翻译 Prompt 结构化与供应商缓存命中优化

## 目标

修复 Story 15 实现审查中发现的缓存资格误判与降级缺口：只有满足消息拓扑和 Provider 最小 token 门槛的稳定前缀才发送缓存参数；Provider 拒绝缓存扩展时退回标准请求，同时保持翻译提示词结构、动态术语语义和精确直填流程不变。

## 修改文件

### `src/transbridge/infra/prompt_cache.py`（改）

- **具体变化**: 将翻译缓存拓扑收紧为严格的 `SYSTEM(A) -> SYSTEM(B) -> USER`，并将后处理拓扑收紧为 `SYSTEM(FINAL) -> USER`；角色、位置、断点、profile 或 key 不一致时剥离内部元数据并禁用缓存。
- **具体变化**: 新增基于 `tiktoken` 的稳定前缀 token 估算。官方 OpenAI 显式断点按 1024 tokens、自动前缀按保守的 2048 tokens 判定；Anthropic 按模型门槛判定并为估算保留安全余量。tokenizer 不可用或统计失败时安全禁用缓存。
- **具体变化**: OpenAI 和 Anthropic 转换器只在拓扑有效且稳定前缀达标时附加 Provider 私有字段；短前缀始终输出无内部元数据的标准消息。
- **原因**: 原实现会给未达到 Provider 最低门槛的短前缀发送缓存参数，也未把不完整 A-only 或错误角色拓扑统一降级，无法形成真实、可解释的缓存命中行为。

### `src/transbridge/infra/llm_client.py`（改）

- **具体变化**: 缓存参数拒绝只识别 HTTP 400/422 且包含缓存相关语义的响应，不再把鉴权错误作为缓存降级条件。
- **具体变化**: Anthropic 普通与流式请求遇到缓存字段拒绝时，移除 `cache_control` 后各重试一次；保留旧 SDK 不支持 system content blocks 时的字符串 system 兼容分支。
- **具体变化**: 整理相关导入、类型和长行，使本次涉及代码通过 Ruff。
- **原因**: 补齐 Anthropic 与 OpenAI 一致的“只去缓存参数、只重试一次”失败降级，并避免掩盖真实鉴权故障。

### `pyproject.toml`、`uv.lock`（改）

- **具体变化**: 增加 `tiktoken>=0.12.0` 运行时依赖并更新锁文件，当前锁定解析到 `tiktoken 0.14.0`。
- **原因**: 缓存资格必须按目标模型 tokenizer 测量，不能依赖字符数或无意义填充估算。

### `src/transbridge/ai_translator/prompt_builder.py`（改）

- **具体变化**: 对本 Story 涉及的导入顺序、空行和长行做 Ruff 清理；三层消息结构、术语顺序和模式归一化语义不变。
- **原因**: 清除实施审查发现的相关静态检查问题。

### `tests/infra/test_llm_client_prompt_cache.py`（改）

- **具体变化**: 增加短前缀禁用、A-only 禁用、FINAL 角色错误禁用、tokenizer 失败禁用、Anthropic 短前缀无 `cache_control`，以及 Anthropic 普通/流式 HTTP 400 单次无缓存重试用例；达标路径改用足够长的稳定前缀。
- **原因**: 让测试覆盖真实 Provider 门槛和确定性降级，而不是只验证字段拼装。
