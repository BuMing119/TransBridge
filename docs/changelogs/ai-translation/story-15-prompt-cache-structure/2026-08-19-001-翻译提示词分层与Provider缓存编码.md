# 001: 翻译提示词分层与 Provider Prompt Cache 编码实现

**日期**: 2026-08-19
**类型**: 增/改
**关联**: Epic: AI 自动翻译 > Story 15: 翻译 Prompt 结构化与供应商缓存命中优化

## 目标

在不改变现有翻译质量、术语语义和精确直填流程的前提下，将翻译提示词拆成「通用 SYSTEM + 模式 SYSTEM + 动态 USER」三层，让官方 OpenAI 与 Anthropic Provider 能复用稳定前缀缓存；非官方兼容端点只收到无内部元数据的标准消息。

## 修改文件

### `src/transbridge/infra/prompt_cache.py` (增)
- **修改内容**: 新增 Provider Prompt Cache 内部缓存标记协议模块。定义 `PROMPT_CACHE_METADATA_KEY`、`PromptCacheDirective`（key/profile/breakpoint）、`build_prompt_cache_key()`、`attach_prompt_cache_directive()`、`extract_prompt_cache_directives()`、`validate_prompt_cache_directives()`（支持 `translation_layered` A/B 与 `single_stable_prefix` FINAL 两种策略的拓扑校验）、`is_official_openai_base_url()`、`openai_cache_capability()`（集中式保守能力表，未知模型默认 automatic_prefix）、`prepare_openai_chat_cache_request()`（普通/流式共用）、`build_anthropic_system_blocks()`（保留双 system block 并附加 ephemeral cache_control）
- **原因**: 集中管理内部缓存元数据，使 PromptBuilder 与后处理各阶段不感知 Provider 私有字段，保证标记无效时安全降级为无缓存普通请求；同时为 Story 14 提供单稳定前缀 FINAL 策略扩展点

### `src/transbridge/ai_translator/prompt_builder.py` (改)
- **修改内容**: 将 `_DEFAULT_TRANSLATION_SYSTEM` 拆为 `_DEFAULT_TRANSLATION_COMMON_SYSTEM` / `_DEFAULT_TRANSLATION_MODE_SYSTEM` / `_DEFAULT_TRANSLATION_USER` 三常量；新增 `_translation_mode()`（具体分类归一化为「实体短文本/对话/长文本」，未知回退长文本）、`_build_mode_system()`、`_format_terms_section()`（动态术语保持原遍历顺序，无术语返回空串）。`__init__` 一次性渲染通用 SYSTEM 并计算稳定 key；`build_translation_prompt` 签名不变，返回固定三条消息 system(A) -> system(B) -> user，A/B 共用同一 key。旧配置缺 `common_system` 时只把旧 `system` 迁移为通用 SYSTEM，动态术语绝不回附
- **原因**: 使通用稳定 SYSTEM 独立于批次动态内容，形成可复用的缓存前缀；术语仅迁移位置，内容/顺序/约束语义不变

### `data/prompts/langs/zh_CN.toml` (改)
- **修改内容**: `[translation]` 段拆为 `common_system`（语言对/角色/优先级/通用规范/格式保护/质量检查/JSON 协议/固定示例）+ `mode_system`（`<translation_mode>$translation_mode</translation_mode>`）+ `user`（`<task_category>$batch_type</task_category>` + `$terms_section` + `<translation_entries>$input_json</translation_entries>`）；`[extraction]` 原样保留
- **原因**: 与 PromptBuilder 的三层结构对齐，把动态术语和批次输入移入 USER

### `src/transbridge/infra/llm_client.py` (改)
- **修改内容**: `OpenAICompatibleClient.chat()`/`chat_stream()` 均调用同一 `prepare_openai_chat_cache_request`，`request_options` 经 `extra_body` 传递（openai 2.29.0 中 `prompt_cache_options` 非命名参数），缓存参数被 Provider 拒绝（401/400 含 cache 关键字）时仅去除缓存参数重试一次；`AnthropicClient.chat()`/`chat_stream()` 用 `build_anthropic_system_blocks` 保留双 system content block 并附加 ephemeral cache_control，老 SDK 拒绝 system list 时降级为拼接字符串重试一次
- **原因**: 使普通与流式请求共用同一转换器避免参数漂移，且不向 SDK 泄漏内部元数据

### `tests/ai_translator/test_prompt_builder.py` (增)
- **修改内容**: 30 个用例覆盖三消息结构、A/B 标记、模式映射、USER 动态内容与术语顺序/空值、input_json 协议、缓存 key 稳定性、旧配置迁移与 fallback
- **原因**: 保证 Story 15 PromptBuilder 分层与术语非回归

### `tests/infra/test_llm_client_prompt_cache.py` (增)
- **修改内容**: 11 个用例（mock 客户端，不联网）覆盖官方显式断点请求形态、自动前缀清洁消息、非官方端点无私有字段、普通/流式一致、缓存参数被拒单次降级、Anthropic system blocks 与字符串降级
- **原因**: 验证 Provider 缓存转换与清理边界
