# 003: 缺失 Tokenizer 安全降级修复

**日期**: 2026-08-19
**类型**: 修复/测试
**关联**: Epic: AI 自动翻译 > Story 15: 翻译 Prompt 结构化与供应商缓存命中优化

## 目标

修复运行环境尚未安装 `tiktoken` 时，`prompt_cache.py` 的顶层导入直接阻断 `PromptBuilder` 和 AI 翻译启动的问题。`tiktoken` 仍是项目声明的运行时依赖；本修复提供防御性降级，使依赖缺失只关闭 Prompt Cache 优化，不让核心翻译能力因缓存辅助组件不可用而崩溃。

## 修改文件

### `src/transbridge/infra/prompt_cache.py`（改）

- **具体变化**: 将顶层 `import tiktoken` 改为 `ImportError` 防护；缺失时保存不可用状态，并在 tokenizer 解析入口记录警告、返回 `None`。
- **具体变化**: 现有缓存资格计算在 token 估算不可用时继续走 `cache_mode=disabled` 和无 Provider 私有缓存参数的标准请求路径。
- **原因**: Prompt Cache 是性能优化而不是 AI 翻译启动的必要条件；当前 `.venv` 缺少该包时，原实现会在构造 `AutoTranslator` 的导入链上抛出 `ModuleNotFoundError`。

### `tests/infra/test_llm_client_prompt_cache.py`（改）

- **具体变化**: tokenizer 异常测试改为 patch `prompt_cache.tiktoken` 模块对象；新增 `test_missing_tokenizer_disables_cache_without_blocking_import`，验证缺包状态下消息保持标准字符串结构、缓存模式关闭且不生成 request options。
- **原因**: 同时覆盖“tokenizer 模块存在但调用失败”和“模块本身不存在”两类降级路径。

## 验证

- `python -m pytest tests/infra/test_llm_client_prompt_cache.py::TestOpenAICacheValidation::test_missing_tokenizer_disables_cache_without_blocking_import tests/infra/test_llm_client_prompt_cache.py::TestOpenAICacheValidation::test_tokenizer_failure_disables_cache tests/ai_translator/test_prompt_builder.py -q -p no:cacheprovider` → **32 passed**。
- 在缺少 `tiktoken` 的项目虚拟环境导入链验证 → `PromptBuilder` 可导入，token 估算返回 `None`，不再出现用户报告的 `ModuleNotFoundError`。
- 本次涉及文件的目标 Ruff 检查 → **通过**。

## 遗留项

- 项目元数据已声明 `tiktoken>=0.12.0` 且锁文件包含该包；仍应修复/同步本地 `.venv`，安全降级不能替代完整依赖安装，缺包期间 Provider Prompt Cache 会保持关闭。
- 当前将整个 `test_llm_client_prompt_cache.py` 与 PromptBuilder 测试放入同一进程运行时结果为 **46 passed, 4 failed**：模拟 `tiktoken=None` 后，外层 `estimate_prompt_tokens` 的 LRU 状态会影响后续要求缓存启用的用例。生产降级与定向测试通过，但测试隔离仍需后续清理，不能把该 50 项聚合套件记录为全绿。
