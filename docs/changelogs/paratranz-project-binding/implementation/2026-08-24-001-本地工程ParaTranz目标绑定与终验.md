## 背景与目标

此前 ParaTranz 管理页的“当前浏览项目”和上传、下载、合并使用的远端目标混在同一组会话状态中。用户必须先进入管理页选择项目，其他入口才可能工作；浏览行为还可能无意改变后续同步目标。

本次增量把 ParaTranz 目标改为本地 Project 持有的持久绑定，并将所有入口统一到“本次显式覆盖 → 工程绑定 → 未绑定”的解析合同。管理页只负责浏览，只有明确执行“设为当前工程同步目标”才会写入工程。

## 增量内容

### S01：绑定模型、Project Schema 与只读投影

- `src/transbridge/application/projects/remote_binding.py`
  - 新增不可变 `ParaTranzProjectBinding`、目标来源/状态枚举、解析结果和值对象转换函数。
  - 统一校验正整数项目 ID、规范化 endpoint、账号 ID 和 ISO 时间；拒绝带用户信息、查询参数或片段的 endpoint。
  - 绑定只保存项目身份和展示元数据，不保存 Token、API Key 或其他凭据。
- `src/transbridge/persistence/v2/schema.py`
  - 正式声明可选 `data.remote_bindings.paratranz`，补充 URL 与时间字段的语义校验。
  - 旧工程缺少该字段时继续按“未绑定”读取，未知 provider 扩展保持兼容。
- `src/transbridge/application/projects/lifecycle.py`、`src/transbridge/ui/context.py`
  - Project projection 暴露只读 `paratranz_binding` 与 Project revision。
  - Variant 切换保留工程绑定；Project 切换同步投影对应工程的绑定。

### S02：原子写入、统一 Resolver 与项目目录

- `src/transbridge/application/projects/models.py`、`ports.py`、`lifecycle.py`
  - 新增 `LifecycleProjectUpdate` 和 `commit_project_update`，为只修改 Project 元数据提供独立原子提交路径。
- `src/transbridge/persistence/v2/repository.py`、`lifecycle_transactions.py`
  - 新增带 revision 比较交换的 `save_if_revision`，并将冲突稳定映射为 `PROJECT_UPDATE_PERSISTED_STALE`。
  - 使用共享 Repository 实例内的锁保护 revision 检查与保存；提交失败时不发布新 active/projection，并保留当前 Variant dirty 状态。
- `src/transbridge/application/projects/remote_binding.py`
  - 新增 `ProjectRemoteBindingService`，作为设置和解除工程绑定的唯一 application 写入口。
  - 新增 `ParaTranzTargetResolver`，固定采用“显式覆盖 → 工程绑定 → 未绑定”，不读取管理页浏览项目或旧会话状态。
- `src/transbridge/paratranz/service.py`、`src/transbridge/paratranz/project_catalog.py`
  - “我的项目”目录支持完整分页、协作取消、TTL 有界缓存，以及 endpoint、账号和配置 revision 隔离。
  - 网络、认证、成员权限和配置变化被区分为可操作诊断，迟到结果不得污染当前选择器。
- application composition 与 `AppContext`
  - 注册并投影绑定服务，提供统一 resolve/set/clear 门面。
  - 旧 `paratranz_project_id` 仅接收新绑定的单向兼容投影，不再作为反向权威来源。

### S03：Workbench 就地目标与管理页显式绑定

- `src/transbridge/ui/workbench/remote_target_presenter.py`、`remote_target_view.py`
  - 新增当前工程远端目标视图，显示项目、来源、验证状态，以及更换和解除入口。
  - 选择器在后台完整加载“我的项目”，关闭、重载或配置变化时取消/忽略旧请求，并安全释放 QThread/服务资源。
  - 加载请求冻结 endpoint、账号和配置 revision；写入时再次核对当前工程 revision。
- `src/transbridge/ui/workbench/widget.py`、`src/transbridge/ui/workbench/_project_bar.py`
  - 将远端目标视图组合到工作台工程上下文附近，不把网络和持久化职责塞入 ProjectBar。
- `src/transbridge/ui/paratranz/project_panel.py`
  - 新增“设为当前工程同步目标”显式动作；普通浏览、切换、刷新不再修改 Project revision。
  - 绑定前异步验证当前账号确为项目成员，并防止配置或本地工程 revision 变化后的过期写入。
- `src/transbridge/ui/paratranz/target_context.py`
  - 为管理页、工作台卡片和兼容调用方提供统一目标上下文读取，清除对最后浏览项目的隐式依赖。

### S04：操作计划、预检与入口连续性

- `src/transbridge/ui/operations/production_support.py`、`production.py`
  - 操作请求冻结目标 ID、来源、绑定 revision、验证状态、endpoint、账号、配置 revision 和“设为工程默认”意图。
  - 未绑定时上传/下载入口仍然可发现；计划内可以填写本次项目 ID，并明确选择是否持久为工程默认。
  - 提交前重新核对目标身份；绑定、账号、端点、配置或项目变化会使旧预检失效并要求重新预检。
- `src/transbridge/ui/operations/coordinator.py`、`plan_presenter.py`、`plan_dialog.py`、`facade.py`
  - 远端预检移入 `ApiWorker`，避免阻塞 Qt 事件循环。
  - Presenter 在预检期间释放内部锁，并通过 request identity 丢弃迟到结果，避免取消、编辑或重复提交竞态。
  - 异常、编辑、取消、缓存淘汰和任务结束路径均关闭 ParaTranz service/client。
- `src/transbridge/ui/coordinators/operation_coordinator.py`、Workbench upload/download cards、`step3.py`
  - 菜单、卡片和步骤页提交同一 intent，不再用 `current_project` 或 session project ID 判断能力。
  - 旧 Step3 删除最后浏览项目回退与同步阻塞式 overlay。

### S05：Smart Assistant 与兼容入口迁移

- `src/transbridge/smart_assistant/tools/tool_paratranz.py`
  - 显式 `project_id` 严格作为本次覆盖；非空但无效的 ID 不会静默回退。
  - 缺省时使用统一 resolver；账号/端点不一致会阻止执行，切换项目在验证后通过正式 command 持久绑定。
  - 成功、失败、提前返回和后台完成路径均释放 ParaTranz service/client。
- `src/transbridge/smart_assistant/tools/tool_translator.py`
  - 术语等关联能力读取安全的绑定解析结果，不再依赖管理页浏览状态。
- Workbench cards、AI translator 与其他兼容调用点
  - 统一迁移到 `target_context`/resolver，避免形成新的会话级权威状态。

## 兼容性与剩余验证

- 旧 Project 无 `remote_bindings` 时按未绑定处理，首次显式绑定才写入新字段；旧读取器可忽略该附加字段。
- 未执行真实 ParaTranz 联机冒烟，避免读取或写入用户凭据；成员验证、分页、取消和错误分类由 fake/contract 测试覆盖。
- 当前 revision 比较交换保证同一进程、共享 Repository 实例内的并发安全；跨进程同时写工程文件尚无文件锁保证。
