## 问题

Workbench 的“选择 ParaTranz 同步目标”对话框标注为加载“我的项目”，实际却显示了 196 个公开项目。项目目录在 application/service 层使用 `uid="my"` 表达当前账号，但 ParaTranz 当前线上项目列表接口会静默忽略这个字符串查询值，结果等同于未按用户身份过滤。

只读线上对比证据：

- 修复前直接发送 `uid=my`：返回 196 个项目，首批项目 ID 与未过滤请求一致。
- 使用当前已验证账号的数字 UID：返回 17 个项目。
- 未在日志、测试输出或代码中写入 Token。

## 变更

### `src/transbridge/paratranz/api/paratranz_project_api.py`

- 保留上层 `uid="my"` 的公共调用语义，不要求 Project Catalog、Workbench 或 Assistant 改用另一套调用方式。
- `ParatranzProjectAPI.list_projects` 在发送 HTTP 请求前，将 `my` 解析为 `config.user_id`，最终请求参数为数字 UID。
- 当配置中没有经过验证的正整数用户 ID 时直接抛出明确错误，不再降级为未过滤的公开项目列表。
- 显式传入数字 UID 的既有调用保持原值，不受别名解析影响。

该修复与现有用户加载链保持一致：应用通过 `GET /users/my` 获取用户资料，将返回的 `id` 同步到 `current_user` 和 `config.user_id`；项目列表随后复用这个已验证 ID。

### `tests/paratranz/test_project_api.py`

- 新增 `my` 别名转换测试，验证分页、取消令牌和响应类型参数保持不变，仅 UID 被替换为已验证数字值。
- 覆盖用户 ID 缺失、零值、负数和布尔值，确认这些情况不会发出项目列表请求。
- 覆盖显式数字 UID，防止别名逻辑误改调用方指定的用户 ID。
