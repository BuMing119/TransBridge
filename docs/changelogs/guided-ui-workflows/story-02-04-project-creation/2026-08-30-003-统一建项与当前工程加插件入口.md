# 统一建项与当前工程加插件入口

- **日期**：2026-08-30
- **Epic**：`guided-ui-workflows`
- **Story**：S04/S05/S06/S07 建项与工作台入口跟进
- **类型**：UI intent 收敛与无效入口修复
- **计划关联**：[guided-ui-workflows plan](../../../../plans/guided-ui-workflows/plan.md)、[S04](../../../../plans/guided-ui-workflows/stories/story-04-start-center-guided-project.md)
- **前序记录**：[002 单确定按钮自动建项交互](2026-08-30-002-单确定按钮自动建项交互.md)

## 目的

开始中心、翻译菜单和工作台“管理”菜单此前同时暴露“选择插件开始翻译”“创建工程”和“准备新的翻译内容”，用户无法判断它们是新建工程还是修改当前工程。其中工作台“准备新的翻译内容”仅执行 `activate_slot("")`，空 key 不对应任何已有 slot，因此点击后没有可见效果。

本次把职责收敛为两条明确路径：全局 `PROJECT_CREATE` 只负责创建另一工程；`WORKBENCH_CONTENT_PREPARE` 只负责为当前工程选择并解析插件。前序 002 已记录的单“确定”自动预检/提交编排保持不变。

## 真实变更

### 单一公共建项入口

- `src/transbridge/ui/shell/action_catalog.py`、`intent_composition.py`、`start_center_controller.py`
  - 移除公开 `SOURCE_PARSE` / `PROJECT_CREATE_FROM_SOURCE` 建项入口，将插件、ESP/ESM/ESL 等搜索别名归入 `PROJECT_CREATE`。
  - 无 payload 的 `PROJECT_CREATE` 打开统一建项页；建项页选择插件时提交 `{"mode": "plugin"}`，文件拖放可继续用 `path` 直接进入同一 draft。
  - “创建空工程”保留为建项页内的高级子选择，不再作为与插件建项并列的公共入口。
- `src/transbridge/ui/shell/start_center_landing.py`、`start_center_projects.py`
  - 建项页主选择改为“选择插件”，高级选择明确为“创建空工程（不导入插件）”。
  - 开始中心文案不再把“翻译游戏插件”误写成另一个工程级入口。

### 当前工程添加插件

- `src/transbridge/ui/workbench/widget.py`
  - 将无效的“准备新的翻译内容”改为“为当前工程添加插件…”。
  - 点击后不再激活不存在的空 slot，而是发出 `WORKBENCH_CONTENT_PREPARE` intent。
- `src/transbridge/ui/shell/menu_builder.py`、`intent_composition.py`
  - 翻译菜单只保留同一“为当前工程添加插件…”动作，不再重复提供“选择插件开始翻译”的新建工程入口。
  - 新 intent 仅在已有工程时可用，并路由到既有 `ParseCoordinator.parse_plugin()`，加载为当前工作台的新翻译内容。

### 跨入口语义与文档同步

- `src/transbridge/ui/guidance/state_machine.py`、`qt.py`
  - 无工程状态引导用户进入统一建项页；空工程状态引导用户为当前工程添加插件，并把“新建其他工程”保留为次级动作。
- `src/transbridge/ui/drop_router.py`、`shell/context_help.py`、`tools/ai_translator/run_spec.py`
  - 插件拖放、上下文帮助和 AI 恢复动作统一指向 `PROJECT_CREATE`，避免第二套建项 intent。
- `src/transbridge/ui/i18n/messages.pot`
  - 纳入新的当前工程动作标签，移除本次废弃的重复标签。
- `docs/requirements.md`、`plans/guided-ui-workflows/*`、`plans/start-center-launch-hub/plan.md`
  - 同步 FR26.2、FR28.1、P0 旅程、线框图和计划中的统一建项入口及当前工程动作语义。

### 回归测试

- `tests/ui/test_workbench_slices.py` 验证管理菜单点击发出 `WORKBENCH_CONTENT_PREPARE`，不再是空 slot 激活。
- `tests/ui/test_main_window_shell.py` 验证菜单标签、可用性和 `PROJECT_CREATE` / 当前工程添加插件的独立路由。
- `tests/ui/test_start_center_guided_project.py` 验证建项页插件模式、空工程本地子选择和文案。
- guidance、拖放、命令搜索、当前用户旅程和主题旅程测试同步新的 canonical intent。

## 用户可见结果

- “新建本地翻译工程”是唯一工程级入口；进入后再选择插件或高级空工程。
- 翻译菜单和工作台“管理”菜单只提供“为当前工程添加插件…”，不会误导用户去创建同名工程。
- 原先点击无反应的工作台菜单项现在会打开现有插件解析流程；取消选择不会改变当前工程。
- 清空当前翻译内容后，可用该动作重新为当前工程选择插件；若要创建另一个工程，则使用“新建本地翻译工程”。
