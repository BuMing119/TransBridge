## 目的

前序修复让开始中心可以先“检查创建方案”，再通过第二次点击“创建并开始翻译”。用户复验后明确要求预检不应成为可见的操作步骤：页面只保留一个“确定”按钮，一次点击完成预检、创建和进入工作台；只有预检失败时才显示检测结果。

本次只收敛 UI intent 和 coordinator 编排。application 的 owner-bound、one-shot `prepare → commit` 两阶段协议及原子持久化边界保持不变。

## 真实变更

### 单一用户动作与内部两阶段编排

- `src/transbridge/ui/coordinators/guided_project_coordinator.py`（修改）
  - 保留原有 `prepare()` 与 `commit()`，供显式两阶段调用方和既有测试继续使用；新增 `create()` 作为一次用户动作入口。
  - `_prepare(commit_on_success=True)` 在预检成功后直接调用 `commit()`，不向 UI 发布 `PREPARED` 中间状态；同步与异步 dispatcher 都沿用 generation、in-flight 和 one-shot token 门禁。
  - 自动建项路径的前台提示统一为“正在创建本地翻译工程…”，提交期间的 draft 摘要不显示“已验证”中间结果。
  - 预检失败仍进入 `FAILED`，保留原 draft 并显示稳定 diagnostic，不调用 commit。
- `src/transbridge/ui/shell/start_center_controller.py`（修改）
  - 将开始中心的单一 primary intent 从 `guided_project.prepare` 改接到 `guided_project.create`，由 coordinator 在内部串联预检和提交。

### 固定“确定”按钮

- `src/transbridge/ui/shell/start_center.py`（修改）
  - draft 主按钮固定显示“确定”，不再根据 preview token 在“检查创建方案”和“创建并开始翻译”之间切换。
  - 单击或在工程名/版本名输入框按 Enter 都只发出一次既有 `prepare_requested` intent；`commit_requested` 不再由该按钮发出。
  - 更新 accessible name 为“确定创建本地翻译工程并开始翻译”，保留屏幕阅读器对最终动作的完整描述。

### 回归测试

- `tests/ui/test_start_center_guided_project.py`（修改）
  - 覆盖同步单动作 `create()` 只调用一次 prepare 和一次 commit，成功进入 `COMPLETED`，且观察者看不到 `PREPARED` 状态。
  - 覆盖异步 prepare 完成后自动排队 commit、统一前台文案以及提交期间不显示“已验证”。
  - 覆盖预检失败只显示诊断、不会调用 commit。
  - 覆盖 draft 主按钮在编辑和 prepared 状态下均只显示“确定”、只发出同一个 primary intent。
- `tests/ui/test_accessibility_contracts.py`（修改）
  - 移除旧 `commitReady` 属性设置，继续验证 Enter 触发一次 primary intent、Escape 仅返回开始中心。

## 用户可见结果

- 建项页面只显示一个“确定”主按钮。
- 用户点击一次后，程序在后台完成 ESP/已有译文预检和工程提交；成功后沿用既有 `_on_created()` 导航进入工作台。
- 不再展示“检测通过后请再次点击”的中间交互，也不会把检测统计作为提交中的可见步骤。
- 预检或提交失败时，页面会保留并显示对应错误；输入类问题修正后可再次点击“确定”。
