# 插件建项导航与已有译文合并修复

- **日期**：2026-08-30
- **Epic**：`guided-ui-workflows`
- **Story**：S02 权威的插件/空工程原子建项用例、S04 开始中心插件建项 UI
- **类型**：真实建项流程缺陷修复
- **计划关联**：[guided-ui-workflows plan](../../../../plans/guided-ui-workflows/plan.md)、[S02](../../../../plans/guided-ui-workflows/stories/story-02-authoritative-project-provisioning.md)、[S04](../../../../plans/guided-ui-workflows/stories/story-04-start-center-guided-project.md)

## 目的

用户从工作台菜单选择“选择插件开始翻译”后，虽然已选中 ESP，界面仍停留在原工作台；修复页面切换后，继续选择同一插件的已有汉化 ESP 又会在“检查创建方案”阶段得到 `PROJECT_SOURCE_IDENTITY_DUPLICATE`。根因是开始中心 draft 已创建但没有切换到可见页面，同时权威建项服务把拥有相同稳定记录身份的原版插件和汉化插件误当成两个独立 Variant 基线，而不是一组原文/译文来源。

本次修复让菜单入口可靠显示建项 draft，并将一个同身份汉化 ESP 的文本按稳定 `EntryKey` 合并到原插件基线，同时保留两条工程来源登记及其 `TRANSLATION_FOR` 关系。

## 真实变更

### 权威建项与来源物化

- `src/transbridge/application/projects/provisioning.py`（修改）
  - 引入区分“工程来源登记”和“Variant 实际物化基线”的 `_PreparedSourceSet`，预览中的来源数继续反映原插件与已有译文两个文件，Variant 条目数则只统计合并后的主基线。
  - 对“一个 primary 插件 + 一个同 namespace 的 migration 插件”开放受限合并路径；其他重复 namespace、缺少主来源 hydration 或多个同身份迁移来源仍返回稳定的 `PROJECT_SOURCE_IDENTITY_DUPLICATE`，不选择不确定的覆盖顺序。
  - `_merge_plugin_translation()` 按 `EntryKey` 对齐已有译文，只把非空、不同于原文且不会覆盖主基线既有译文的候选写入主基线和 UI hydration，并将对应状态设为 `TRANSLATED`。
  - Project source registry 仍使用所有来源 descriptor，因此原版与汉化版路径及显式来源关系不会因 Variant 去重而丢失。
- `src/transbridge/persistence/project_provisioning.py`（修改）
  - 插件解析器读取 ESP 时文本位于条目的 `original` 字段；migration 角色现在将该文本转换为候选 `translation` 和 `TRANSLATED` 状态，供 application 层执行同身份合并。
  - primary 角色及非插件格式仍沿用原有 baseline 映射，不改变普通建项解析语义。

### 开始中心可见导航

- `src/transbridge/ui/shell/start_center_controller.py`（修改）
  - 提取 `_show_start_center_view()`，并在 `_begin_project()` 创建 draft 后立即把持久化工作区切换到开始中心。
  - `_render()` 复用同一切换逻辑，兼容具有 `mode_tabs` 的新 Shell 和使用 `central_stack` 的旧 host。

### 回归测试

- `tests/application/projects/test_provisioning.py`（修改）
  - 覆盖同身份已有译文折叠后的来源数、单基线、译文状态、两条来源登记、来源关系和 hydration。
  - 覆盖多个同身份已有译文继续返回稳定冲突，锁定不静默覆盖的边界。
- `tests/persistence/v2/test_project_provisioning.py`（修改）
  - 覆盖 migration 插件文本到候选译文的 adapter 映射。
  - 增加原版/汉化 ESP 双来源的完整 prepare、commit、source registry、Variant snapshot 与 hydration 回归，并断言 prepare 阶段只解析两个来源各一次。
- `tests/ui/test_start_center_guided_project.py`（修改）
  - 覆盖从工作台发起插件建项后切换到 draft 页面、显示所选路径并自动建议工程名。

## 用户可见结果

- “选择插件开始翻译”选择 ESP 后会显示“创建本地翻译工程”页面，不再像无响应一样停留在工作台。
- 选择同一插件的一个已有汉化 ESP 后，“检查创建方案”不再因相同记录身份报错；创建完成后的工作台 hydration 与持久化 Variant 都包含已有译文。
- 工程元数据仍记录原插件和汉化插件两个来源及翻译关系；Variant 只保存一个稳定 namespace，避免重复 `EntryKey`。
- 选择多个同身份汉化 ESP 时仍明确报冲突，避免无提示地决定覆盖优先级。
