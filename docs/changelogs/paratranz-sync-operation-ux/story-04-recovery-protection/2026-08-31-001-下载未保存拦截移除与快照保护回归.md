## 目的与根因

用户在新版下载页已看到预计更新数量，但仍被“当前版本有未保存修改，不能直接合并”阻断，并要求由程序自动保存或创建快照，不应要求手动处理保存状态后才能下载。

生产适配器在创建 draft 时把 `context.dirty` 冻结为 `dirty_target`；下载 mapper 把该标记作为硬性阻断，同时它还参与请求摘要。已有下载任务其实会在正式同步前于后台创建恢复快照，因此未保存状态门槛与既有保护流程重复，且保存状态切换本身并不代表同步内容变化。

本次采用**沿用自动快照、移除未保存拦截**的方案，不新增自动保存动作，也不把创建快照等同于正式保存或清除 dirty 状态。

## 实际增量

### 1. 修改下载预检与请求摘要

**修改** [src/transbridge/ui/operations/mappers.py](../../../../src/transbridge/ui/operations/mappers.py)：

- 从 `OperationPlanDraft` 移除 `dirty_target` 字段及其 `request_digest` 输入。
- 从 `DownloadOperationMapper._specific_checks()` 移除 `DIRTY_VARIANT` 检查。
- 保留凭据、权限及其余既有预检；不取消目标身份或实际内容变化的保护。

**原因**：未保存修改可由执行前快照保护，不能单独阻断下载；自动保存仅改变保存状态时，也不应使相同内容的请求摘要失效。

### 2. 修改适配器与恢复保护文案

**修改** [src/transbridge/ui/operations/paratranz_sync.py](../../../../src/transbridge/ui/operations/paratranz_sync.py)：

- `create_sync()` 不再从 `context.dirty` 构造下载阻断条件。
- 在恢复能力可用时，说明改为“下载前自动创建历史还原点（包含未保存修改）”。
- 沿用已有 `_recovery_snapshot()` 和后台 `TaskRuntime` 执行顺序；本次没有重新实现快照服务，也没有把文件 I/O 移回 GUI 确认线程。

**原因**：用户点击下载后由程序自动保护当前内容，无需先手动保存或增加一次确认。

该文件由前次增量创建，目前 Git 仍显示未跟踪；本记录只归属上述后续修改，不重复记为本次新增整个模块。

### 3. 新增下载恢复回归测试

**新增** [tests/ui/operations/test_paratranz_download_recovery.py](../../../../tests/ui/operations/test_paratranz_download_recovery.py)，共 5 个参数化后测试用例：

- 有未保存译文时预检可通过；提交先返回后台任务，执行队列后才创建真实快照并应用云端译文。
- 从磁盘读取快照，验证它保存未保存的新译文、stage、标签和标签库，而非 `current.json` 中的旧译文。
- 自动保存完成后，相同内容的 draft 摘要保持一致，原计划仍可执行。
- legacy 快照 I/O 抛异常、V2 快照返回失败结果这两种情形均使任务失败，本地集合和未保存内容不被覆盖。
- 确认后实际译文又被编辑时，陈旧计划仍不能覆盖新编辑；未保存状态放行不等于取消内容新鲜度保护。

### 4. 补充 V2 未保存快照证据

**修改** [tests/application/projects/test_lifecycle.py](../../../../tests/application/projects/test_lifecycle.py)：

- 新增 `test_snapshot_captures_unsaved_variant_without_requiring_a_formal_save()`，以及 `EntryKey`、`VariantEntryState` 测试导入。
- 先把权威 Variant working copy 从 revision 2 修改到 3，再调用真实生命周期服务的 `save_snapshot()`。
- 验证 snapshot 包含未保存译文与标签、使用当前 revision；未执行正式保存，persisted revision 仍为 2，活动版本仍为 dirty。

同文件中的其他未提交测试变更不归属本次修复；生产生命周期与 `VersionPersistence` 在本次均未修改。

## 恢复语义与兼容边界

- 有活动版本、恢复服务可用且计划会修改本地内容时，沿用“后台准备与授权 → 创建下载前快照 → 正式同步”的执行顺序。
- legacy 快照采集当前集合；V2 快照读取当前权威 Variant 聚合，不要求先落盘。
- 快照创建失败仍停止同步并保留本地内容；没有恢复能力的上下文不显示自动历史还原点承诺。
- 不改动 Project/Variant 文件格式、远端 API 或下载冲突/删除策略，不需要数据迁移。
- 本次没有删除或移动业务文件。
