# ParaTranz 同步检查、下载进度与操作锁定

- **日期**：2026-08-31
- **Epic**：`paratranz-sync-operation-ux`
- **Story**：S03 自动预检与单次确认状态机；联动 S02 任务化页面、S04 结果展示与生命周期验收
- **关联计划**：[ParaTranz 上传/下载操作页重设计实施计划](../../../../plans/paratranz-sync-operation-ux/plan.md)
- **变更依据**：用户针对“从 ParaTranz 更新本地翻译”页面追加要求：检查、下载期间显示进度条，并锁定该页面的操作。

## 目的与行为变化

原页面检查时只禁用更换项目和确认按钮，同步选项、取消与关闭仍可操作；确认提交后台任务后窗口立即关闭，无法在当前页观察下载是否结束。本增量让页面从检查到执行结束都有明确反馈，并在忙碌期间禁止修改选项、重复提交或关闭页面。

- 检查与执行阶段显示不确定进度条；当前没有按条目或字节计算的实时百分比，不用模拟数值冒充下载进度。
- 忙碌期间禁用更换项目、同步策略、默认绑定、远端删除、确认和取消，拦截 Esc、窗口关闭及对话框结束入口。
- 确认下载后保留窗口，等待对应 TaskRuntime 任务的真实终态。成功显示完成和 100%；失败、取消停止忙碌显示并给出后续提示。
- 检查结束恢复控件原有权限；原本不可用的字段不会因解除锁定而被启用。任务结束后可关闭窗口，也可点击“重新检查”；不会直接复用上次确认再次同步。
- 上传共用同一专用页面，因此获得对应的进度提示与锁定行为；写回、FOMOD 的通用确认窗口保持原有关闭行为。

本增量按用户追加要求收紧检查与执行期间的交互；原草稿中“选项始终可编辑”的设计不是本次实现的验收依据。本次归档不改写历史日志或计划状态。

## 逐文件变更

### 修改 [paratranz_dialog.py](../../../../src/transbridge/ui/operations/paratranz_dialog.py)

- 在状态提示下增加采用现有主题组件样式的 `QProgressBar` 和可访问名称“同步进度”。
- `set_preflight_running()`、`set_execution_running()` 分别维护检查和执行状态，显示动态进度并失效旧的确认状态；页面初始化、选项变化和重检入口即时锁定操作。
- `_sync_controls()` 统一合并忙碌状态与 `EditableFieldState.enabled`，避免恢复操作时越过字段原有权限。
- `done()`、`closeEvent()` 拦截忙碌期间的对话框结束；确认和项目选择入口也检查忙碌状态。
- `execution_changed` 使用 Qt 排队连接调用 `render_execution()`，在 GUI 线程展示任务终态；`execution_finished` 通知释放任务订阅。
- 预检错误、阻断和任务终态提供“重新检查”，同时保留项目、策略与影响摘要，避免用户凭失效结果重复执行。

### 修改 [coordinator.py](../../../../src/transbridge/ui/operations/coordinator.py)

- `OperationPlanCoordinator.__init__()` 增加可选 `execution_observer`。
- `_begin()` 内的 `confirm()` 在提交前锁定支持执行反馈的窗口，成功提交后交给 observer 跟踪任务，不再立即 `accept()`。
- 提交失败先解除执行状态，再沿用现有重新预检路径；未配置 observer 或不支持执行反馈的窗口仍按原流程关闭。

### 修改 [facade.py](../../../../src/transbridge/ui/operations/facade.py)

- 为 coordinator 注入 `_observe_execution()`，复用 `TaskProjectionBinding`，按 owner scope 和本次 Run ID 转发任务状态，不增加轮询或第二套任务状态权威。
- 订阅启动时读取现有任务投影，覆盖任务在订阅前已完成的情况；任务结束或窗口销毁时关闭订阅。

### 修改 [plan_presenter.py](../../../../src/transbridge/ui/operations/plan_presenter.py)

- `OperationPlanPresenter.confirm()` 增加默认关闭的 `retain_session` 参数，供保留执行结果的专用页面使用。
- 保留会话时仍先消费一次性确认，提交后清除预检并禁用再次提交。后续必须编辑/重建草稿、重新预检并取得新确认；默认调用方继续关闭会话。

### 修改 [test_paratranz_sync_dialog.py](../../../../tests/ui/operations/test_paratranz_sync_dialog.py)

- 调整既有断言，明确检查完成信号后才允许确认和关闭。
- 增加检查/执行期间进度条、全部控件锁定、Esc/关闭/accept/reject 拦截、选项改变即时锁定和字段权限恢复回归。
- 覆盖预检 worker 错误、阻断结果与重新检查入口。
- 用实际 facade、presenter、TaskRuntime 与延迟 backend 验证上传/下载的完成、失败、取消终态；其他任务完成不能解锁当前页，后台线程事件必须经 Qt 队列更新页面。
- 覆盖订阅前快速完成、提交失败重检、父窗口销毁后的订阅清理，以及窗口销毁不代替用户取消后台任务。

### 修改 [test_operation_plan_presenter.py](../../../../tests/ui/operations/test_operation_plan_presenter.py)

- 增加保留会话时的一次性确认回归：上次确认不能重放，刷新输入并重新预检后可提交新任务，最后可正常清理会话。
