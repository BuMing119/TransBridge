# 007：修复会话恢复轮次计数与连续裁剪

**日期**：2026-09-12
**类型**：缺陷修复、回归测试
**Epic**：session-manager
**Story**：Story 01 — SessionManager 后端 + 序列化
**关联计划**：[Session 管理系统](../../../../plans/session-manager/plan.md)

## 问题与结果

用户追问默认保留 20 轮时，工具调用、工具结果与确认操作如何计数，检查发现恢复历史与运行时的轮次判定不一致：当前生成的英文工具结果以 `user` 角色存储，但恢复时未被识别为 observation，会被误算成新的用户轮次，导致过早裁剪。

回归测试还发现，存在 system 消息时，连续裁剪后的轮次起点会偏移。现已修复两处问题，使保存、恢复和连续加入新用户消息后的裁剪结果保持一致。

## 逐文件变更

### 修改：`src/transbridge/smart_assistant/conversation_manager.py`

- `_is_legacy_observation()`：从既有 `_OBSERVATION_PREFIX` 提取英文前缀，识别当前 `[Tool result - ...]` 格式，同时保留中文工具结果与计划执行结果的兼容识别。恢复时这些结果继续归属原轮次。
- `_trim()`：按实际切片移除的整个消息前缀调整保留轮次的起点，包括暂时移除的 system 消息；重新插入 system 后统一后移，修复连续裁剪产生的索引偏移。
- 保留默认 20 轮限制、公共接口和序列化格式，无须数据迁移。

### 修改：`tests/smart_assistant/test_conversation_manager.py`

- 新增 `test_round_trip_preserves_observation_turns_at_default_limit`：构造含 system、20 轮用户请求、原生工具调用与结果、英文 observation、计划结果的历史，验证反复保存恢复以及加入第 21—23 轮时，运行实例与恢复实例消息一致，旧轮次完整淘汰且 system 保留。
- 新增 `test_restored_result_formats_stay_in_their_original_turn`：覆盖英文工具结果、旧中文工具结果、计划结果三种格式，验证恢复后不会单独计轮，并随所属用户轮次一起裁剪。
