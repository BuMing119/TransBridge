## 目的与证据边界

用户明确要求“继续开发吧，包括摘要部分”，结束此前摘要暂缓的范围。本次将摘要从独立能力接到实际模型轮次，并补齐已规划的终态请求归档及离线附件维护。摘要是可重建的公开材料摘录，不是授权、请求状态或翻译项目快照。

归档核对 HEAD `4090f3a`、空暂存区、工作区差异、未跟踪模块正文及上一开发回合验证输出。工作区仍包含已记录的过程日志、时间线、对话评测、确认恢复和取消修复；这些不重复计入本次。`transactions.py` 虽仍未跟踪，已由前置过程记录实现，本次只记录其归档扩展。历史增量不修改。

## 逐文件变更

下列生产路径相对 `src/transbridge/`，测试、脚本及文档路径相对仓库根目录。

### 摘要生成、校验与持久化

- 新增 `application/assistant_requests/summaries.py`：`RequestSummary`、`plan_summary`、`validate_summary` 提供不可变摘要、确定性摘录和重建校验。默认保留最近 8 条相关消息，更早材料达到 8 条或 4000 字符时生成，正文最多 2400 字符；保存请求/会话/修订、覆盖水位、实际摘录来源、来源摘要值及生成参数。未知归属、其他请求、路由控制及隐藏推理字段不进入摘要；完成事实必须有当前修订的完整证据。
- 新增 `application/assistant_requests/history_scope.py`：从前置实现的 `smart_assistant/request_context_assembler.py` 抽出 `assign_history_requests`，让应用层摘要与模型投影复用相同来源归属规则。原模块保留兼容导出；共享输入、修订来源和工具调用关联不重新定义。
- 新增 `application/assistant_requests/summary_service.py`：`RequestSummaryService.refresh` 在后台读取权威 transcript 并生成，事务内对最新请求与来源重验后写入 `request_summaries`；相同缓存不重复发布。`prepared_material` 返回同一规范历史、有效摘要和请求摘要值，避免按持久化历史生成、却按不同 UI 历史消费。规范投影保留实际 provider 字段，去掉冗余元数据及空归属字段；无效派生缓存可忽略，发布失败带诊断。
- 修改 `application/assistant_requests/service.py`：`save_history` 将已持久化消息 ID 与 `recorded_ids` 合并，只为新消息补充归属，并使用 `setdefault` 保留已有消息所有者。修复请求 A 恢复准备时，把其他路径已保存的 B 回答误归给 A 的问题。

### 实际模型入口与异步生命周期

- 新增 `ui/tools/smart_assistant/request_context_preparation.py`：`prepare` 复用现有后台队列，先在原会话保存最新工具结果，再生成及读取摘要材料；派生生成失败记录日志并回退原材料，原始证据保存失败则阻止执行。两阶段回调分别检查当前视图与 admission，`_still_admitted` 在模型分派前重验租约、scope、revision、epoch、暂停及事项就绪状态。
- 新增 `smart_assistant/request_model_input.py`：`RequestModelInput.assemble` 处理脱离 UI 的材料快照，在后台完成归属投影、当前输入定位、准备结果的请求摘要值匹配和预算组装。冻结字段不宣称递归冻结所有内层字典，组装只读快照。
- 修改 `ui/tools/smart_assistant/request_binding.py`：接入 `context_preparation`，`prepare_model_input` 增加 `prepared_summary` 与 `defer_assembly`；默认同步接口保持兼容。准备阶段检查暂停及就绪集合，ReAct 续轮仍只重选原请求；第二阶段捕获重选后的新 admission，避免用旧轮次身份误丢合法工具续跑。
- 修改 `smart_assistant/conversation_orchestrator.py`：既有轮次启动入口先等待异步上下文准备，再调用模型阶段；回调受 generation 检查，错误交给请求失败处理。未配置该准备服务的既有调用保留同步兼容路径。
- 修改 `smart_assistant/request_context_assembler.py`：`assemble(summary=...)` 在必需状态、当前输入及工具协议满足预算后尝试放入有来源的普通材料摘要；仅排除全部被实际摘录来源覆盖的可选消息组，不依据覆盖水位整体删除旧原文。摘要放不下时回退原材料，必需内容仍不可静默丢弃。

### 终态归档与离线附件维护

- 新增 `application/assistant_requests/archival.py`：`compact_request_state` 将较早且无未决副作用的终态详情写入不可变 artifact，Session 内保留最近 100 个终态完整详情及所有活动请求。按终态事件顺序选择，兼容缺少事件的旧记录；小索引保存位置、身份、状态及校验值，派生摘要缓存可丢弃。`hydrate_request_state` 验证归属、内容和索引后按原顺序还原，重复还原保持幂等。
- 扩展前置模块 `application/assistant_requests/transactions.py`：`commit_request_change` 在命令/事件归约前还原归档，准备新详情后将请求索引和 manifest 同次条件保存；路由拒绝回退也先还原原状态，返回值提供完整请求。保存或 CAS 失败保留旧快照，新孤儿附件不能被当作已提交请求恢复。
- 修改 `application/assistant_requests/service.py`：`transact` 向事务服务传入 transcript store，`state` 透明还原归档，现有读取、继续及审计入口仍可访问完整详情。
- 新增 `persistence/assistant_attachment_cleanup.py`：`AssistantAttachmentCleanup.collect` 核对当前 Session、备份、保留/隔离记录、显式保留 manifest 及嵌套 typed 引用；先验证所有候选，再删除确定无引用的应用附件。损坏、未来/未知格式、未决 staging、活动写租约或路径越界使清理停止；不按文件年龄删除。报告列出候选、保留、已移除及可回收字节，默认只预览。
- 修改 `persistence/assistant_transcript_store.py`：`append` / `write_artifact` 加入 Session 写租约；新增 `read_attachment` 验证路径类别、digest 和分段条数，供引用遍历复用。仍先暂存不可变内容，再由 Session 条件保存正式发布。
- 新增 `scripts/maintain_assistant_storage.py`：`--root` 指定现有存储根，默认输出预览 JSON；`--apply` 必须配合 `--offline`，实际删除前重新扫描。offline 是调用者已停止所有写入者的声明，工具不能自动证明其他进程及其未提交引用均已消失。开发和测试只在临时数据根执行删除，未清理用户数据。

## 兼容性与遗留项

- 沿用 Session schema 4，不新增 envelope 版本迁移；请求归档通过当前服务透明还原，完整 transcript 保留。生命周期材料与翻译项目内容快照语义不变。
- 默认保留最近 100 个终态的完整内联详情，不表示整个会话、事件日志或归档索引的总大小有界；现有读取仍可能还原全部归档详情。
- LLM 自由摘要、embedding 检索和真实模型自然语言归属评估未实施；本次摘要采用确定性摘录，实际模型入口由本地替身验证，没有访问外部 API。
- Qt 中间异常根因尚未定位；Swig 和既有兼容 API 弃用警告仍存在。
- 附件实际回收依赖调用者停止所有写入者的离线条件；没有新增自动在线清理。
