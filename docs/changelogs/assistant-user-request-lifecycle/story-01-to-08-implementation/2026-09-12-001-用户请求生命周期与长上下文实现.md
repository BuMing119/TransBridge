## 目的与记录边界

为长期会话增加独立的请求和请求项，区分用户目标、模型轮次与后台执行。新问题回答期间，旧任务的结果写回原请求；当前回答结束后再继续旧请求，需要确认时等待用户。输入关系与回答覆盖由模型提出，正式身份、范围校验、状态迁移和保存由程序控制。

本记录归档设计记录之后的开发增量。Git 工作区还包含已经归档的取消与生命周期快照、20 轮恢复计数修复、AI 任务项目术语界面等改动，不将整个未提交工作区归入本 Epic。共享文件只记录本次请求层接线；原设计及其他历史增量保持不变。当前暂存区为空，未提交或推送。

## 逐文件变更

以下代码路径相对 `src/transbridge/`；测试与文档使用仓库相对路径。新增指本次实现引入，修改指已有文件的本次变化；前置工作中新建但仍未跟踪的共享文件明确标注为扩展。

### S01：输入、完整历史与存储

- 新增 `application/assistant_requests/transcript.py`：定义消息身份、工具调用关联、分段 manifest 和结果引用，保留完整证据及消费位置。
- 新增 `application/assistant_requests/ports.py`：提供历史分段、artifact 读写边界，使请求核心不依赖具体文件系统。
- 新增 `application/assistant_requests/history.py`：`stage_transcript` 合并不可变历史和 Session 投影，CAS 重试保留其他写者已经接纳的消息；复用已验证的不可变消息，减少重复冻结。
- 新增 `persistence/assistant_transcript_store.py`：`AssistantTranscriptStore` 保存不可变分段与结果附件，验证摘要及引用；大段解码缓存仍每次读盘核验内容，无变化保存跳过重复写入。
- 修改 `application/sessions/models.py`：Session 增加请求状态与历史 manifest，改进嵌套 JSON 验证和冻结，支持完整历史快照。
- 修改 `application/projections/adapters.py`：投影传递请求状态与 manifest，避免恢复时遗漏持久化信息。
- 修改 `smart_assistant/conversation_manager.py`：完整 transcript 与最近轮次投影分开；保存和回查使用完整证据，20 轮不再决定持久化历史长度。本次不重复归档此前的恢复轮次计数修复。
- 修改 `persistence/v2/models.py`：当前 envelope schema 升至 4。
- 修改 `persistence/v2/migration.py`：固定原 2→3 迁移终点，增加独立 3→4 迁移；保留现存旧历史，不推断旧请求目标。
- 修改 `persistence/v2/schema.py`：校验新增 Session 字段，保留不属于 Session 的既有数据结构。
- 修改 `persistence/v2/filesystem.py`：原子文件写入支持持久化刷新，供 Session 发布使用。

- 新增 `application/assistant_requests/service.py`：`RequestService` 统一前后台命令保存，以原 Session 为归属；先保存接纳结果，再通知界面或后续执行。
- 新增 `application/sessions/commands.py`：集中条件保存与一次冲突重载归约；已有未保存的本地状态不会被静默覆盖。

- 修改 `application/sessions/gui_facade.py`：GUI 历史保存委托统一事务与 transcript staging，避免裁剪投影覆盖权威历史。
- 修改 `persistence/session_lifecycle.py`：修订比较和 Session 保存纳入同一写事务。

### S04：执行接纳与异步结果归属

- 新增 `application/assistant_requests/task_events.py`：后台事件按执行引用写回原 Session 和请求，不依赖当前窗口。
- 新增 `application/assistant_requests/resource_admission.py`：按实际资源键协调跨会话写入，独立问答不占用业务写资源。
- 新增 `smart_assistant/request_execution.py`：`RequestExecutionGate` 统一工具、计划和提交接纳，拒绝过期轮次及伪造归属；只读成功不能证明执行项完成，等待批准时不提前物化执行批次。
- 新增 `smart_assistant/request_scope.py`：冻结入口范围并核验项目版本；本请求已经验证的提交可以推进版本基线，无关修改不能冒充原范围。
- 修改 `smart_assistant/tools/types.py`：增加类型化请求执行引用，传递请求、修订、事项与尝试身份。

### S05：调度、确认与完整回答

- 新增 `application/assistant_requests/scheduler.py`：每个会话一个有效前台轮次，按就绪事项选择工作；旧任务完成不抢占当前回答，主动停止阻止自动重启。`commit_answer` 将完整回答、覆盖证据和状态一起保存。
- 新增 `application/assistant_requests/task_controls.py`：任务中心暂停、取消和继续先记录请求项控制状态并核对许可，不能绕开请求层直接重启旧工作。
- 修改 `smart_assistant/session_controller.py`：接线前台完成、等待与中断；模型轮次状态和用户请求状态保持独立。
- 修改 `smart_assistant/conversation_orchestrator.py`：每轮准备请求上下文与阶段工具，完整返回交给控制协议处理；配置缺失或模型失败释放轮次并暂停请求，保留可见继续入口。
- 新增 `ui/tools/smart_assistant/request_confirmation.py`：`renew_confirmation` 在确认恢复时签发新的工具调用 ID，避免旧取消回执遮蔽真实执行结果。
- 新增 `ui/tools/smart_assistant/request_confirmation_binding.py`：确认绑定请求和修订，旧卡失效；焦点切换保留等待要求，批准只影响对应操作。
- 新增 `ui/tools/smart_assistant/request_outcome_binding.py`：集中回答提交、业务响应后续与失败收尾，持久化成功后才确认完成。
