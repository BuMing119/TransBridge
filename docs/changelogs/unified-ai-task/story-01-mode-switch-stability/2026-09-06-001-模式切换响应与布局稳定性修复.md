# AI 任务模式切换响应与布局稳定性修复

- 日期：2026-09-06
- Epic：`unified-ai-task`
- Story：Story 01（任务范围与统一入口）的追加修复；验证关联 Story 04。
- Plan：[统一 AI 翻译任务](../../../../plans/unified-ai-task/plan.md)

## 范围与原因

用户反馈翻译、润色、混合、自定义切换有明显顿感，且页面上下位移。本记录依据本任务执行过程、当前 Git 差异与新增回归测试，只归档这轮性能和布局修复。工作区仍含前序单/多来源统一运行链、旧批量文件删除及配置复制修复，不把这些首次实现计入本增量；已有历史日志保持不变。

根因包括互斥按钮取消选中与选中均触发切换、程序化配置回填触发中间态统计、预估与预检重复构建范围，以及自定义面板插入窗口顶层导致主体整体下移。

## 逐文件变更

以下生产路径均位于 `src/transbridge/ui/tools/ai_translator/`，操作类型均为修改；本增量没有生产文件删除或移动。

- `single_task_view.py`：`_connect_task_signals` 仅处理选中事件；`_build_header` / `_build_task_tabs` 将自定义面板从顶层移入基础配置公共范围之后，内容顶部对齐；`_scroll_tab` 保留固定纵向滚动条槽位并允许必要的横向滚动；`_build_footer` 按实际按钮文案预留宽度，避免模式切换牵动公共布局。
- `config_view.py`：`WindowConfigView.render_config` 使用 `QSignalBlocker` 把配置回填作为一次事务，`_render_config` 只更新后处理控件状态，不计算中间态范围；`ConfigAutosaveBinding` 增加可选刷新回调，合并范围刷新请求，同时保留未注入回调调用方的路径。
- `ai_translator_window.py`：增加单次零延时刷新定时器及 `request_task_refresh`，同一事件轮次的多次修改只计算最终状态；`on_mode_changed` 在激活自定义预设后读取有效模式并复位基础页滚动位置；`update_estimate` 一次构建范围供统计、侧栏计数与预检复用，并验证来源身份；等待刷新时禁用开始按钮、保留不可用预设原因，`closeEvent` 停止待执行刷新。
- `_window_actions.py`：`update_window_quick_run` 接受已构建的配置和任务，直接从该配置生成执行档案，避免预检再次收集范围；未传参数时保留直接调用能力。
- `view_state.py`：`update_mode_controls` 对非翻译模式禁用而非隐藏覆盖选项，保留共同字段位置；仅在混合模式显示规则区。
- `scope_view.py`：`build_scope_view` 限制公共范围面板的纵向扩展，混合预估复用公共统计标签，移除规则区内重复统计展示；模式扩展内容不再改变公共筛选字段位置。
- `custom_profile_view.py`：`build_custom_profile_view` 将配置选择与管理按钮分为两行，降低窄窗口最小宽度压力。
- `tests/ui/tools/test_ai_mode_switching.py`（新增）：6 项回归覆盖一次点击一次切换、预估与预检复用范围、快速切换仅计算最终模式、关闭取消待刷新、配置回填不产生用户变更信号，以及三组窗口尺寸/字体下公共锚点稳定；使用临时真实配置仓库并检查关闭后配置字节不变。
- `plans/unified-ai-task/plan.md`（修改）：记录本轮追加修复的边界、验收与实测结果，与前序统一入口实现记录分开。

### 性能证据

使用 `uv run python .tmp-ai-switch/measure.py`，离线构造 8,291 条合成数据（11 条未翻译，其余已有译文），每种模式切换 5 次；未调用真实 AI。最终同样本完整刷新中位数：翻译 22.13 ms、润色 42.10 ms、混合 80.82 ms、自定义 40.56 ms；基线分别为 121.13、162.54、577.75、347.53 ms。最终同步点击处理约 3～5 ms，每次切换的模式回调、预估和范围构建均为 1 次。

基线自定义模式使左右主体纵坐标从 105 变为 206；修复后四模式均为 105，底部纵坐标均为 712（未加载主题的同一测量窗口）。临时测量脚本与其专属目录在修复完成时已移除，长期回归保留在上述测试文件中。这是当次本机离屏测量，不是各类真实工程的固定性能保证。
