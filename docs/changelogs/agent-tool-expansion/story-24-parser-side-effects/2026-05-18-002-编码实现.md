# 002: Story 24 编码实现 — Parser 工具副作用补全

**日期**: 2026-05-18
**类型**: 改
**关联**: Epic: Agent 工具系统全面扩展 > Story 24: Parser 工具副作用补全

## 修改文件

### `src/transbridge/smart_assistant/tools/tool_parser.py` (改)
- **修改内容**: 
  - 新增 `_to_collection(result)` — 归一化各解析器返回值（PluginParser/EET/XT/SST/Strings）到 `TranslationEntryCollection`
  - 新增 `_create_slot(path, label, collection, ctx)` — 创建 `CollectionSlot` + `ctx.add_slot()` + `ctx.activate_slot()`，同名 slot 已存在时返回 fail
  - 新增 `_append_to_collection(collection, ctx)` — 将条目逐条追加（`overwrite=True`）到当前活跃集合，无活跃集合时返回 fail
  - 重构 6 个工具函数（`_tool_parse_esp`/`_tool_parse_eet`/`_tool_parse_xt`/`_tool_parse_sst`/`_tool_import_json`/`_tool_import_strings`）— 统一模式：解析 → `_to_collection()` → 按 `action` 参数分流到 `_create_slot` 或 `_append_to_collection`。原行为仅返回 `{entry_count}` 后丢弃解析结果
  - `_PARAM_SCHEMAS` 6 条目各新增 `action` 参数（`create_slot`/`append`，默认 `create_slot`）
  - `_register_parser_tools()` 全部 6 工具 permission 从 `"read"` 改为 `"write"`，description 补充副作用说明
- **原因**: FR9.12 — 使 LLM 调用解析工具后能真正落地解析结果（创建槽位或追加条目），而非仅返回条目数后丢弃。Permission 升级为 write 以触发 PermissionGuard HITL 确认机制。

### `tests/test_agent_tool_integration.py` (改)
- **修改内容**: `test_parser_tools_have_read_permission` 重命名为 `test_parser_tools_have_write_permission`，断言从 `"read"` 改为 `"write"`，注释引用 Story 24
- **原因**: 跟随 parser 工具 permission 从 read 升级为 write 的变更，确保测试与代码一致
