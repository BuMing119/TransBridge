**关联**: Epic: Agent 工具系统全面扩展 > Story 21: 工具描述强化 + 系统 prompt + 测试补全

## 修改文件

### `src/transbridge/smart_assistant/tools/tool_editor.py` (改)
- **修改内容**: `set_filters` 注册表 description 重写遵循三原则——①"需要筛选/搜索/过滤条目时用我，替代已废弃的 filter_by_stage/category/label/search_entries" ②stage 枚举 0-5,9,-1 + search_field 枚举 id/key/original/translation/context/all 前置 ③示例: set_filters stages=[1,2] + set_filters search_query="龙裔" search_field=translation。`manage_entry_labels` description 同三重写——①action 枚举 create/assign/unassign/batch_assign ②各 action 所需参数 ③示例: action=create name=重要 color=#FF0000
- **原因**: Story 21 — 合并后工具描述需让 LLM 准确选择工具，三原则（区分信号/参数前置/组合示例）确保消除碎片化后的工具仍可被正确调用

### `src/transbridge/smart_assistant/tools/tool_translator.py` (改)
- **修改内容**: `stop_task` 注册表 description 重写——①"停止翻译/润色任务时用我（替代已废弃的 stop_all_tasks）" ②区分"指定 task_id"与"不传=停止全部"两种模式 ③示例: stop_task task_id=xxx / stop_task（停止全部）
- **原因**: 三原则描述确保 LLM 理解 task_id 可选化语义

### `src/transbridge/smart_assistant/tools/tool_writer.py` (改)
- **修改内容**: `write_back` 注册表 description 重写——①"需要将译文写回源文件时用我" ②target=esp|eet|xt|strings 各目标推断规则（esp/strings需活跃槽位、eet/xt需已解析源文件）③示例: write_back target=esp / write_back target=strings path=./output
- **原因**: dispatch 表路由工具需要 target 枚举信息前置才能被 LLM 正确选择

### `src/transbridge/smart_assistant/prompts.py` (改)
- **修改内容**: `HYBRID_SYSTEM_PROMPT` 字符串末尾（"注意事项"段落后）追加"工具选择指南"段落——包含常见场景→对应工具映射表、3组易混淆工具对辨析（set_filters vs manage_entry_labels、get_visible_entries vs get_statistics、start_translation vs set_scope）、持久化操作确认提示
- **原因**: 合并后工具数减少但语义更复杂，LLM 需要工具选择指南才能在 45 个工具中准确路由

### `tests/smart_assistant/__init__.py` (增)
- **修改内容**: 空白 `__init__.py` 标记 smart_assistant 测试子包
- **原因**: 使 pytest 能正常收集该目录下的测试模块

### `tests/smart_assistant/test_tool_consolidation.py` (增)
- **修改内容**: 新建 ~370 行测试文件，5 个测试类共 34 个测试用例——TestSetFilters(10) 覆盖单/多维度/clear组合/None语义/无效值拒绝/向后兼容；TestStopTask(5) 覆盖指定/不指定/无效ID场景；TestWriteBack(9) 覆盖 4种target×有无slot/无效target/大写规范化；TestManageEntryLabels(6) 覆盖 4种action×正常/异常参数；TestDeprecatedWrappers(4) 验证 14 旧工具名 0 注册、4 新工具已注册、工具总数 45、schema 无旧工具条目
- **原因**: Story 21 验收标准——合并后工具需参数矩阵测试覆盖所有边界条件，schema 回归验证旧工具名不出现在 LLM 可用工具列表中

## 测试结果

- 全部测试 120 passed（86 原集成 + 34 新增），3 failed（预存）
- 定量验收：45 非废弃工具、4 合并工具注册、14 废弃 wrapper 未注册、0 旧工具名作为注册工具
