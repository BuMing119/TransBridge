## 修改文件

### `src/transbridge/smart_assistant/tools/tool_editor.py` (改)
- **修改内容**:
  1. 文件顶部新增 `import warnings`
  2. `_PARAM_SCHEMAS` 新增 `"set_filters"` 条目：6 个可选参数 `stages(categories/labels/search_query/search_field/clear`，全部 `required=False`
  3. 新增 `_tool_set_filters()` 函数（~50 行）：解析 6 个可选参数，`clear=True` 时先调用 `ctx.clear_filters()`，逐个维度检查——`None` 跳过/`[]` 清除/有值设置。含 stage 合法性校验和 search_field 白名单校验，未修改任何维度时返回 "未修改任何筛选条件"
  4. 5 个原筛选工具函数体替换为 deprecated wrapper：`_tool_filter_by_stage/category/label` + `_tool_search_entries` + `_tool_clear_all_filters`，保留 `@validate_params` 装饰器，内部发出 `DeprecationWarning` 后转发到 `_tool_set_filters()`
  5. `_register_editor_tools()` 注册表：移除 5 个旧工具注册（`filter_by_stage/category/label` + `search_entries` + `clear_all_filters`），替换为 1 个 `set_filters`（permission: read）
- **原因**: Story 17（工具架构合并路线A）——5 个筛选工具操作同一 `ctx.filter_state` 对象的不同 key，合并到单一入口 `set_filters` 消除碎片化。旧工具保留 deprecated wrapper 确保向后兼容，发出 DeprecationWarning 引导迁移

### `tests/test_agent_tool_integration.py` (改)
- **修改内容**:
  1. `TestSecurityGuardrails.test_read_permission_allowed`——`step["tool"]` 从 `"filter_by_stage"` 改为 `"set_filters"`，`args` 从 `{"stages": [0]}` 保持不变
  2. `TestSecurityGuardrails.test_execute_with_guardrails_allows_read`——`MockToolSpec(name=...)` 从 `"filter_by_stage"` 改为 `"set_filters"`，`execute_with_guardrails` 参数保持 `{"stages": [0]}`
- **原因**: PermissionGuard 通过 ToolRegistry 查找工具权限，`filter_by_stage` 已从注册表移除导致 "未知工具" 拒绝。更新测试引用为新工具名 `set_filters`
