# 001: 修复 19 项预存测试失败（纯测试侧同步）

**日期**: 2026-08-13
**类型**: 改
**关联**: Epic: 测试套件卫生 > fix（无 plan 的跨模块修复，灵活开发模式）

## 概述

全量 `pytest tests/` 从 **516 通过 / 19 失败** 修复为 **535 通过 / 0 失败**。根因：`TranslationEntry` 数据模型与 parser/writer API 已演进（复合 id 格式、key/context 语义对调、DSD 字段、`SSEPluginWithContext`、`extract_strings_with_context()`），但一批曾被 `.gitignore` 屏蔽后经 `f1009b4` 恢复的测试从未同步更新，断言停留在旧模型。全部 19 项均为测试侧陈旧，零真实代码缺陷。

## 修改文件

### `docs/test-reports/unit-test-staleness-qa-2026-08-13.md` (增)
- **修改内容**: QA 根因定位报告。逐条列出 19 项失败、分类为「根因 A：陈旧单元测试 17 项」与「根因 B：护栏默认拒绝未知工具 2 项」，并给出 6 个文件的精确修复清单。
- **原因**: 修复前先定位根因，区分「测试用例陈旧」与「真实代码缺陷」，确认本轮只改测试不改业务代码。

### `tests/converter/test_translation_entry.py` (改)
- **修改内容**: 4 项断言更新。`test_creat_from_eet_entry`/`test_create_from_plugin_entry`/`test_try_update_from_xt` 的 `id`/`key`/`context` 断言改为复合格式（`{edid}:{formid}|{index}~{GRUP}:{REC}`、key=id、context=rec）；`test_create_from_plugin_entry` 用 `SimpleNamespace` 替代 `Mock`（避免 Mock 自动属性干扰 `getattr` 默认值分支）；`test_to_dict` 期望增加 `string_id`/`full_form_id`/`dsd_type`/`dsd_index`/`dsd_editor_id` 5 字段；EET stage 语义修正为「`traduit` 为空才 stage=0」。
- **原因**: 数据模型演进后，`id` 从 `"edid:formid"` 变为复合格式，`key`/`context` 语义对调，新增 DSD 兼容字段；`create_from_eet_entry` 的 stage 判定从「仅 status==99」扩展为「status==99 或 traduit 非空」。

### `tests/parser/test_plugin_parser.py` (改)
- **修改内容**: 4 项修复。三个 `@patch("...plugin_parser.SSEPlugin")` 改为 `SSEPluginWithContext` 并补 `@patch(...PluginStringsLookup.from_plugin, return_value=None)`；`FakePluginString` 增加 `index`/`context`/`string_id` 属性（新增 `FakeContext` 类）；`test_create_item`/`test_parse_plugin_basic` 断言改复合格式。
- **原因**: parser 已从 `SSEPlugin.from_file` 迁移到 `SSEPluginWithContext.from_file`，旧 patch 目标失效导致真实文件打开失败返回空列表；`create_from_plugin_entry` 现访问 `ps.index`/`ps.context.quest`/`ps.string_id`。

### `tests/parser/test_xt_parser.py` (改)
- **修改内容**: `test_to_csv_file` 的列名集合断言加入 `"index"`。
- **原因**: XT 解析器 `to_csv_file` 现输出 `index` 列（数据模型新增索引字段）。

### `tests/writer/test_plugin_writer.py` (改)
- **修改内容**: 4 项修复。`make_fake_plugin()` 的 `plugin.extract_strings.return_value` 改为 `extract_strings_with_context.return_value`，并 stub `find_string_subrecord.return_value = Mock()`；三个集合应用测试的 entry 改为复合 id/key/context 格式；`replace_strings` 断言替换为 `find_string_subrecord.call_count`。
- **原因**: writer 已从 `extract_strings()` + `replace_strings()` 迁移到 `extract_strings_with_context()` + `find_string_subrecord().set_string()`；集合主索引已切为 `key`（复合格式），旧 `key="INFO:NAM1"` 无法命中 `get_by_key`。

### `tests/writer/test_eet_xml_writer.py` (改)
- **修改内容**: `test_apply_collection_updates` 的两个 entry 改为复合 id/key/context（context=`"INFO:NAM1"`/`"BOOK:DESC"`），`BOOK_Intro` 的 `stage` 0→1 并同步 `STATUS` 断言 "0"→"99"。
- **原因**: EET writer 现按 `(original, grup:champ)` 回退匹配（依赖 `context`），且 TRADUIT 写回受 `stage >= 1` 门控；旧 `context=None` + `stage=0` 组合无法命中且不写 TRADUIT。

### `tests/writer/test_xt_xml_writer.py` (改)
- **修改内容**: 3 项修复。三个集合应用测试的 entry 改为复合 id/key/context；`test_apply_collection_with_none_translation` 的 `updated` 断言 1→0（`translation=None` 条目被 XT writer 跳过）。
- **原因**: XT writer 按 `entry.id` 解析 edid/formid 桶 + `context` 基础部分校验 rec，旧 `context=None` 无法命中；`translation=None` 时 writer 通过 `not entry.translation` 跳过。

### `tests/smart_assistant/test_execution_engine.py` (改)
- **修改内容**: 2 项修复。新增 `NoopGuard`（`before_execute`/`after_execute` 返回 `GuardResult(allowed=True)`），`setUp` 将 `middlewares=[]` 改为 `middlewares=[NoopGuard()]`。
- **原因**: `GraphExecutor.__init__` 对空 `middlewares` 列表（falsy）回退到默认护栏链（含 `PermissionGuard`），而 `PermissionGuard` 按全局 `ToolRegistry` 校验，测试的假工具名 `tool_a` 等未注册被拒。注入非空 NoopGuard 可绕过默认链，专注测试图执行逻辑（不改 guardrail 行为）。
