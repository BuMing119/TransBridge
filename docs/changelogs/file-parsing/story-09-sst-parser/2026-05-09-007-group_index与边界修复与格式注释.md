# 007: group_index 字段 + header/chn_len 边界修复 + SSU9 格式注释

**日期**: 2026-05-09
**类型**: 改
**关联**: Epic: 文件解析 > Story 9: SST 解析器

## 修改文件

### `src/transbridge/parser/xt/sst_parser.py` (改)

- **SST_Entry 新增 `group_index` 字段**：`unk12 >> 16` 高 16 位，INFO 记录为 DIAL 主题编号（同一 quest 内第几个对话），QUST 记录为任务阶段编号，其他记录类型为 0。2318 条 INFO 有非零 group_index（1~28，12 个不同值）。原 `index` 字段仍为 `unk12` 低 16 位 +1（回复序号）
- **原因**：原有数据模型丢弃了高 16 位，导致无法将 INFO 回复按 DIAL 主题分组

- **修复 header 边界**：`_raw_header` 改用 `record_starts[0][0]`（第一条记录实际位置）替代计算值 `start = 12 + name_len + 2 + 8`。原计算值仅算首个插件名长度，忽略后续 master 文件列表（update.esm/dawnguard.esm/hearthfires.esm/dragonborn.esm/hlioremi.esp），导致 header 截断到 42B 而非完整 190B
- **原因**：header 截断使序列化器丢失 148B 的 master 文件列表，重建文件第一段记录偏移错误

- **修复 chn_len 边界条件**：尾记录中文提取条件 `chn_len < len(tail) - 4` 改为 `chn_len <= len(tail) - 4`。当 Chinese 文本占满整个 tail（无 extra 字节）时，原 `<` 条件拒绝提取，导致如"这就是你全部要说的？"被丢弃
- **原因**：边界不等式方向错误，恰好最后一字节受限

- **SSU9 格式注释**：SST_Entry/SST_Parser 添加完整 SSU9/SSU8 记录结构图、Header 结构说明（master list 格式）、各字段语义注释（f2 为 xTranslator 内部 ID、str_idx 为 7 值 bitfield、group_index 用途）
- **原因**：SSU9 格式逆向成果文档化，避免后续开发者重复挖掘
