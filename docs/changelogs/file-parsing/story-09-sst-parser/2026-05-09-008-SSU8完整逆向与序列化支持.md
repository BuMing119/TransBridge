# 008: SSU8 完整逆向、序列化支持与跨文件验证

**日期**: 2026-05-09
**类型**: 改
**关联**: Epic: 文件解析 > Story 9: SST 解析器 / Story 11: SST 序列化器

## 修改文件

### `src/transbridge/parser/xt/sst_parser.py` (改)

- **SSU8 解析器完整重写**：为每条记录填充 `_raw`（24B 头 + eng_text）、`_tail`（trail_len + trail_data + sep2 + global_seq + extra）、`_raw_header`（16B）、`_magic`（b"SSU8"）、`_trailing`（文件末尾截断/残余字节）
- **SST_Parser 新增 `_trailing` 参数**：保存文件末尾未解析的残余字节（如截断的第 171 条记录 48B），序列化时原样追加，保证字节级往返 100% 一致
- **SSU8 `group_index` 提取**：从 `field_a >> 8` 提取高 24 位，25 条 QUST 记录有非零值（0x000100/0x000300/0x001200），与 SSU9 的 unk12 hi16 设计一致
- **SSU8/SSU9 格式注释完善**：Header 各字段（跨 18/16 文件验证常/变量）、记录结构图、sep1（0x0100=可翻译/0x0000=音效）、sep2（0/1/2 文本状态）、rec_type、global_seq、extra 语义标注
- **原因**：SSU8 原先无 _raw 支持导致序列化器无法工作，且 field_a 高 24 位的 group_index 被丢弃

### `src/transbridge/parser/xt/sst_serializer.py` (改)

- **移除 SSU8 序列化拒绝**：`from_parser()` 不再拒绝 SSU8
- **新增 `_rebuild_ssu8()`**：SSU8 记录重建——24B 头模板 + eng_text（覆盖 str_len uint32 LE）+ trail_len + chn_text + 原样 sep2/global_seq/extra
- **`_rebuild_ssu9()` 重命名**：原 `_rebuild_record()` 改为 `_rebuild_ssu9()`，`to_bytes()` 按 magic 分发
- **`_trailing` 支持**：构造器和 `from_parser()` 读取 `sst._trailing`，`to_bytes()` 末尾追加
- **原因**：SSU8 解析器补齐 _raw 后，序列化器需对应支持

## 验证

- **18/18 SSU8 文件字节级往返一致**（含 16 个 CC mod + 2 个原文件，0~170 条/文件）
- **跨文件交叉分析**：Header[4-5]=0x0000 常量、Header[6-9]=0x00000000 常量、Header[10-11]=xTranslator 版本号、Header[12-15] hi16=导出批次ID
- SSU9 往返不受影响（1,858,993B 一致）
- 极端案例通过：空文件（0条）、wraithguard（非标准 rec_type 0x0AB0 等）、dawnfang（51KB）
