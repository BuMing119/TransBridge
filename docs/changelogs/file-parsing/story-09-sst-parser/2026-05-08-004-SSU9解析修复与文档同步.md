# 004: SSU9 解析修复与文档同步

**日期**: 2026-05-08
**类型**: 改
**关联**: Epic: 文件解析 > Story 09: XT SST 二进制解析器

## 修改文件

### `src/transbridge/parser/sst_parser.py` (改)

- **修改内容**:
  - `_VALID_EDID_SUFFIXES`: 新增 `DNAM`/`ITXT`/`NNAM`/`RNAM`/`SHRT` 五个后缀，覆盖 MESGITXT/QUSTNNAM/INFORNAM/NPC_SHRT/MGEFDNAM 等 EDID 类型（从 13 个扩展到 18 个）
  - `_parse_ssu9()` Phase 1: 移除 `str_idx == 256` 硬编码过滤，改为 `str_len == 0 or str_len > 100000` 仅校验长度，释放 str_idx=0/512/1024/16640/17408 等合法记录；新增 `str_idx == 0x4000` 过滤（该类型 39% 假阳性率，中文文本误占 English 偏移位置）；`record_starts` 元组从 5 元素扩展为 6 元素，新增 `unk12` 字段
  - `_parse_ssu9()` Phase 2: 从 `unk12` 低 16 位提取 per-EDID index `(unk12 & 0xFFFF) + 1`，与 XT XML REC id + 1 逻辑一致（unk12 高位 16 位 = idMax）
- **原因**:
  - str_idx 是记录类型标志而非固定值，硬编码 256 导致 2,239 条合法记录被跳过
  - EDID 后缀缺失导致 QUSTNNAM(98条)/MESGITXT(50条)/INFORNAM(27条)/NPC_SHRT(2条)/MGEFDNAM(8条) 全部丢失
  - SSU9 的 unk12 字段与 SSU8 的 field_a 结构相同，编码了 xTranslator 的 REC sub-index

### `scripts/sst2json.py` (改)

- **修改内容**: `--stats` 模式条目行新增 `idx` 和 `glob` 显示
- **原因**: 适配 `SST_Entry.global_seq` 新增字段，保持工具输出完整

### `plans/file-parsing/plan.md` (改)

- **原因**: 原 plan 描述基于初始实现的假设，与经过三轮修正后的实际代码差距较大，需同步
