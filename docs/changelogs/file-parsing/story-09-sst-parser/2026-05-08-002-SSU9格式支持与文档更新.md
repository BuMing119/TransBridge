# 002: SSU9 格式支持与文档同步

**日期**: 2026-05-08
**类型**: 改
**关联**: Epic: 文件解析 > Story 09: XT SST 二进制解析器

## 修改文件

### `src/transbridge/parser/sst_parser.py` (改)
- **修改内容**: 新增 `_parse_ssu9()` 类方法——通过模式匹配扫描 62K+ 记录起点（EDID 后缀 + idx=256 + UTF-16LE 验证），从尾部提取 4B 长度前缀的中文翻译字符串。`SST_Entry` dataclass 新增 `translated_text: str`（SSU9 双语文件的译文）和 `f2: int`（SSU9 第二 ID 字段）两个可选字段，SSU8 专用字段（index/trail_hash/extra）设默认值。`from_file()` 工厂方法改为读前 4 字节魔数，自动分发 `_parse_ssu8()` / `_parse_ssu9()`。`to_json()`/`to_csv_file()` 适配新增字段。
- **原因**: 用户提供的 Skyrim 完整 SST 文件为 SSU9 格式（17MB），原 SSU8 解析器无法处理。SSU9 是 xTranslator 新版格式，头含插件名、记录含 4B FormID 前缀、支持单文件内 English+Chinese 双语存储，与 SSU8 差异显著。

### `src/transbridge/converter/translation_entry.py` (改)
- **修改内容**: `create_from_sst_entry()` 新增逻辑——若 `sst_entry.translated_text` 非空则将其作为 `translation` 并设 `stage=STAGE_TRANSLATED`（1），无译文时保持 `translation=""` / `stage=STAGE_UNTRANSLATED`（0）。
- **原因**: SSU9 文件天然包含完整的 English→Chinese 翻译对，直接利用可省去后续迁移源合并步骤中的人工匹配。

### `scripts/sst2json.py` (改)
- **修改内容**: 移除内联的 SSU9 解析代码，改为统一调用 `SST_Parser.from_file()`。输出 JSON 增加 `format` 字段（SSU8/SSU9），`--pretty` 模式下输出 `translation_entry` 完整字典。
- **原因**: 解析器已内置双格式支持，脚本应复用而非重复实现。
