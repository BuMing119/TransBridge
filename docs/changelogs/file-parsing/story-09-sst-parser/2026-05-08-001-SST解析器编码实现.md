# 001: SST 二进制解析器编码实现

**日期**: 2026-05-08
**类型**: 增
**关联**: Epic: 文件解析 > Story 09: XT SST 二进制解析器

## 修改文件

### `src/transbridge/parser/sst_parser.py` (增)
- **修改内容**: 新建 `SST_Entry` frozen dataclass（edid/form_id/text/index/trail_hash/extra 六字段）和 `SST_Parser` 解析器类。`from_file()` 工厂方法按 SSU8 二进制格式逐条解析变长记录：校验魔数 → 跳过 16B header → 循环读取 2B类型+8BEDID+4BFieldA+4BFormID+2B分隔符+4B字符串长度+N B UTF-16LE文本+4B尾部长度+M B尾部数据+1B分隔符+4B序号+2B额外ID。异常容错包含魔数校验（非 SSU8 → ValueError）、文件截断（warning+break）、UTF-16LE 解码失败（warning+继续）、尾部长度合理性检查（trail_len>100 → break）。`to_json()`/`to_json_file()`/`to_csv_file()` 导出方法风格与 XT_XmlParser 一致。
- **原因**: 项目此前仅支持 XT XML 解析，XML 中缺少 FormID 等关键字段。SST 二进制文件提供更完整的字符串表数据，弥补信息缺口。

### `src/transbridge/converter/translation_entry.py` (改)
- **修改内容**: 顶部新增 `from src.transbridge.parser.sst_parser import SST_Entry` 导入。在 `TranslationEntry` 类中新增 `create_from_sst_entry()` 工厂方法，将 SST_Entry 转为 TranslationEntry，字段映射：id=`"{edid}:{form_id:08X}|{index}"`，original=text，translation=""（空），stage=STAGE_UNTRANSLATED(0)，context=edid，editor_id=edid。
- **原因**: 遵循 ADR-001 的统一数据模型设计，所有解析来源通过工厂方法转为 TranslationEntry。
