# 006: SST FNV-1a Hash 实现、序列化增强与写出接口屏蔽

**日期**: 2026-05-21
**类型**: 改
**关联**: Epic: 文件解析 > Story 11: SST 序列化器

## 修改文件

### `src/transbridge/parser/xt/sst_parser.py` (改, +19)
- **修改内容**: 新增 `sst_string_hash()` 函数——实现 FNV-1a 32-bit 哈希算法（常量 `_FNV_OFFSET=0x811C9DC5`、`_FNV_PRIME=0x01000193`），对应 xTranslator 的 `TESVT_Const.stringHash`（HashSalt=''）；`SST_Entry.f2` 字段注释修正为「xTranslator internal record ID (1:1 mapped to form_id, not a hash)」
- **原因**: SST 从零创建需要计算 EDID 名称哈希；原 f2 注释「疑似 xTranslator 内部数据库主键」已被验证为 xTranslator 内部记录 ID（与 form_id 1:1 映射）

### `src/transbridge/parser/xt/sst_serializer.py` (改, +83)
- **修改内容**: (1) 新增 `SST_Serializer.create_new(plugin_name, entries)` 类方法——从零创建 SSU9 SST 文件（构建最小 header + 逐条 `_build_ssu9_record()`），无需模板 SST 文件; (2) `to_bytes()` 增强：基于 `entry._raw` 区分模板路径（`_rebuild_ssu8/9` 重建）和从零创建路径（`_build_ssu9_record` 基于 entry 字段重建），支持 `update_and_save` 后重新序列化; (3) `_rebuild_ssu9()` 增强：重建时更新 `form_id`/`unk12`/`str_len` 头字段，`unk12` 从 `(group_index << 16) | ((index-1) & 0xFFFF)` 计算
- **原因**: 原 `from_parser()` 仅支持基于已解析 SST 文件模板的修改；`create_new()` 支持无模板的从零创建场景；`to_bytes()` 双路径支持从零创建记录的重新序列化

### `src/transbridge/parser/xt/__init__.py` (改, +4)
- **修改内容**: 注释掉 `SST_Serializer` 和 `sst_string_hash` 的公开导出，添加注释「write functionality disabled pending xTranslator compatibility verification」
- **原因**: SST 写出功能在 xTranslator 兼容性验证完成前暂时屏蔽，防止写出损坏的 SST 文件导致上游工具崩溃
