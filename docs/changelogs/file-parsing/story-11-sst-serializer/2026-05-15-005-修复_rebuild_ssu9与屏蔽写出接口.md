# 005: 修复 _rebuild_ssu9 字段更新 + 屏蔽写出公开接口

**日期**: 2026-05-15
**类型**: 改
**关联**: Epic: 文件解析 > Story 11: SST 二进制序列化器

## 修改文件

### `src/transbridge/parser/xt/sst_serializer.py` (改)
- **修改内容**: `_rebuild_ssu9()` 方法原来只更新 `str_len`（offset 22），现在同时更新 `form_id`（offset 0）、`unk12`（offset 12，从 index+group_index 反向计算）、`f2`（offset 16）。使用 4 次独立 `struct.pack_into()` 替代原来的单次 `pack_into("<H")`
- **原因**: 向真实 SST 文件追加新条目时，模板 `_raw` 头中的 form_id/unk12/f2 仍是模板的值。追加后重新解析无法找到新条目（form_id 不匹配）。现在基于 entry 当前字段值完整更新头部

### `src/transbridge/parser/xt/__init__.py` (改)
- **修改内容**: 注释掉 `SST_Serializer` 和 `sst_string_hash` 的公开导出，保留 `SST_Parser` 和 `SST_Entry`。源码文件未删除，可通过直接导入（`from sst_serializer import ...`）在开发调试时访问
- **原因**: xTranslator 交叉验证未通过——从零创建和模板追加的文件均无法被 xTranslator 读入。在兼容性问题解决前，屏蔽写出功能避免用户误用。解析功能不受影响

## 验证

- 开发调试：`from parser.xt.sst_serializer import SST_Serializer` → 正常
