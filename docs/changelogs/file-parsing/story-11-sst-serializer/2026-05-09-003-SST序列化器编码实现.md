# 003: SST 二进制序列化器编码实现

**日期**: 2026-05-09
**类型**: 增/改
**关联**: Epic: 文件解析 > Story 11: SST 二进制序列化器

## 修改文件

### `src/transbridge/parser/xt/sst_serializer.py` (增)
- **修改内容**: 新建 `SST_Serializer` 类，实现 SSU9 模板重建写回。`from_parser()` 从 SST_Parser 提取原始二进制构建序列化器；`_rebuild_record()` 从 entry._raw 复制 26B 固定头（保留 unk12/str_idx/pad），覆盖 str_len 为实际 UTF-16LE 字节数，写入 eng_text + chn_len + chn_text + extra；`to_bytes()` 拼接 header + 所有记录；`save()` 原子写入；`update_and_save()` 单条 form_id 修改写回；`update_entries()` 批量修改返回 {matched, updated, not_found}
- **原因**: FR1.9.5 要求支持将修改后的译文序列化回 SST 二进制格式，基于解析模板重建

### `src/transbridge/parser/xt/sst_parser.py` (改)
- **修改内容**: `SST_Entry` 新增 `_raw: bytes`（26B头+eng_text原始二进制）和 `_tail: bytes`（chn_len+chn_text+extra原始二进制）字段（默认 b""，向后兼容）。`SST_Parser.__init__` 新增 `raw_header` 和 `magic` 参数。`_parse_ssu9()` 构造每条 entry 时填充 `_raw` 和 `_tail`，返回 parser 时传入 `raw_header=data[:start]` 和 `magic=b"SSU9"`。`_parse_ssu8()` 传入 `magic=b"SSU8"`
- **原因**: 序列化器需要原始二进制数据作为模板——SST_Entry 为 frozen dataclass 未存储 unk12/str_idx/pad 等字段，需从 _raw 保留原始值；_tail 保留 extra/subrecords 原始字节供原样拷贝

### `src/transbridge/parser/xt/__init__.py` (改)
- **修改内容**: 新增 `from .sst_serializer import SST_Serializer`
- **原因**: 公开序列化器接口供外部使用

## 验证

- 往返测试：8487 条记录的 SSU9 文件解析 → 序列化 → 重解析，条目数与文本完全一致
- SSU8 拒绝：from_parser() 对 SSU8 正确抛出 ValueError
- 单条更新：update_and_save() 通过
- 批量更新：update_entries() 返回 matched/updated/not_found 正确
- 发现并修复 bug：str_len 字段为 UTF-16LE 字节数（非字符数），初始按字符数写入导致重解析偏移错误
