# 导航账户与服务入口及可见性修复

- **日期**：2026-08-25
- **Epic**：`start-center-launch-hub`
- **Story**：S05 导航账户与服务入口
- **需求关联**：FR28.5、NFR1.4～NFR1.7
- **类型**：功能增量与真实截图缺陷修复

## 目的

把共享导航左下角原本只能展示 ParaTranz 用户状态的静态区域升级为可发现、可操作的账户与服务入口，为当前 ParaTranz 账户信息、服务/API 配置和通用设置提供统一入口，同时给 Nexus Mods 等未来真实 provider 留出菜单扩展位置。用户随后在真实应用截图中发现按钮内容被压缩到窗口底部，头像、用户名和状态几乎不可见，本记录同时归档该可见性缺陷的根因修复。

## 真实变更

### 需求与计划

- `docs/requirements.md`（修改）
  - 新增并实现 FR28.5：用户身份区整体可由鼠标和键盘激活，菜单只展示真实连接状态和既有能力。
  - 明确不显示 Token/密码，不为尚未接入的 Nexus Mods 等站点伪造登录状态；未来 provider 通过同一菜单结构扩展。
- `plans/start-center-launch-hub/plan.md`（修改）
  - 在既有 S01～S04 后增加 S05，记录账户入口的交互、canonical intent、无障碍、长用户名和 provider 扩展验收标准。
  - 回写 S05 完成状态和聚焦、相关及完整 UI QA 证据。
- `plans/INDEX.md`（修改）
  - 将 `start-center-launch-hub` 更新为 5/5 Story 完成，保留账户菜单待用户视觉复验的真实状态。

### 可点击账户入口与真实服务状态

- `src/transbridge/ui/shell/navigation_rail.py`（修改）
  - 将静态 `QFrame` 用户区改为保留头像、名称和在线状态内部布局的语义 `QPushButton`，增加 hover/focus、tooltip、指针光标、StrongFocus 和“⋯”可发现提示。
  - 激活后在用户区上方非模态打开账户菜单，不切换开始、工作台或 ParaTranz 页面。
  - ParaTranz 未连接时条目显示“未连接”并提交 `SETTINGS_SERVICES`；已连接时显示真实用户名并提交 `SETTINGS_ACCOUNT`。
  - 菜单始终提供“服务与 API 配置…”和“外观与通用设置…”，继续通过现有 `intent_requested` 路由，不复制业务回调或发起新网络请求。
  - 长用户名在导航和菜单中按像素省略，完整名称保留在 tooltip；头像 fallback 与在线状态语义保持。
  - 根据用户真实截图修复可见性：为空文本 `QPushButton` 设置至少 `32px` 头像加上下边距的最小高度，防止 Qt 默认 `sizeHint` 把内部布局压成窗口底部细条。
- `src/transbridge/ui/foundation/visual_style.py`（修改）
  - 把用户区集中主题选择器切换为 `QPushButton#tbNavigationUser`，增加 hover、focus 和 pressed 反馈，继续只使用 palette/theme token。

### 回归测试

- `tests/ui/test_modern_workbench_visual_shell.py`（修改）
  - 覆盖鼠标点击、Space 键、菜单向上展开、已连接/未连接 ParaTranz 的 canonical intent、服务/通用设置入口、当前页面不变和长用户名 tooltip。
  - 新增可见性门禁：按钮高度不得低于 48px，头像、用户名、状态点、状态文字和“⋯”必须全部可见且几何范围位于按钮内部；该断言在缺陷实现上会失败。
- `tests/ui/foundation/test_visual_style.py`（修改）
  - 锁定账户按钮 hover/focus 集中主题规则。
