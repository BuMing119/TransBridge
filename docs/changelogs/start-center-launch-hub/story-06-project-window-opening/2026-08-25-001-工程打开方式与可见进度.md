# 工程打开方式、独立窗口与可见进度

- **日期**：2026-08-25
- **Epic**：`start-center-launch-hub`
- **Story**：S06 工程打开方式与可见进度
- **需求关联**：FR28.6、FR19.4、NFR1.4～NFR1.7
- **架构关联**：ADR-025
- **类型**：功能增量、性能反馈与真实截图缺陷修复

## 目的

解决用户从开始中心切换本地工程时存在明显等待但没有可见反馈的问题，并允许用户明确选择在当前窗口切换或保留当前上下文、在独立新窗口打开另一工程。初版使用工程行锚定菜单，用户要求改为独立弹出页；真实主题截图随后暴露两张打开方式卡片被普通按钮样式压缩、内部两行内容遭裁剪，本记录同时归档这两次基于真实应用复验的修正。

## 真实变更

### 需求、架构与计划

- `docs/requirements.md`（修改）
  - 新增并实现 FR28.6：非当前可用工程提供当前窗口和新窗口两种打开方式；当前窗口复用 dirty 与权威工程打开合同，新窗口不改变当前工程、页面、任务和 dirty 状态。
  - 明确工程准备期间使用不伪造百分比的不确定进度，冲突操作被禁用，显式启动路径优先于活动工程指针且仍需 canonical 校验。
- `docs/adr/025-project-window-launch-and-open-progress.md`（新增并修正）
  - 选择独立 GUI 进程而非同一 `QApplication` 内复制 `MainWindow/AppRuntime`，冻结态与源码态均通过参数列表启动，不拼接 shell 命令。
  - 将初版“轻量菜单”决策按用户反馈修正为专用模态弹出页；弹出页展示工程名称和路径，并承载两个完整打开按钮。
  - 记录全局活动工程指针的跨进程影响，以及首期不承诺同一工程跨进程编辑锁。
- `plans/start-center-launch-hub/plan.md`、`plans/INDEX.md`（修改）
  - 增加并完成 S06，回写实现落点、验收标准、依赖、风险和自动化 QA 证据；Epic 状态更新为 6/6。

### 独立打开方式弹出页与工程面板

- `src/transbridge/ui/shell/start_center_projects.py`（新增）
  - 从已超过责任审查阈值的 Landing 中抽取本地工程行、列表、空状态、打开选择和进度状态，保留列表原生鼠标、Enter/Return、禁用和可访问语义。
  - 活动工程仍直接返回工作台；非活动可用工程打开独立选择页；不可用工程不发出请求。
  - 当前窗口打开期间禁用工程列表，并显示 4px 不确定进度细线和真实阶段文案。
- `src/transbridge/ui/shell/project_open_choice_dialog.py`（新增）
  - 新增模态“打开工程”页面，展示工程名称与路径，并以“在当前窗口打开”“在新窗口打开”两个双行卡片按钮发出稳定信号。
  - 为卡片提供鼠标、焦点、键盘和可访问名称；取消不会提交任何工程操作。
  - 根据真实主题截图把卡片高度所有权固定在双行组件上，避免普通按钮的紧凑 `sizeHint` 裁剪标题和说明。
- `src/transbridge/ui/foundation/visual_style.py`（修改）
  - 增加 `tbProjectOpenMode` 集中主题规则：卡片保持约 88px 内容高度、零额外 padding，并统一标题/说明字号；继续只使用 palette/theme token。
- `src/transbridge/ui/shell/start_center_landing.py`、`src/transbridge/ui/shell/start_center.py`（修改）
  - Landing/facade 转发当前窗口与新窗口两条信号，代理工程面板渲染和打开进度，同时保留既有 compatibility aliases。
  - 打开期间禁用插件、FOMOD、打开工程、创建空工程和工程列表，终态恢复真实能力。

### 当前窗口后台打开与进度终态

- `src/transbridge/ui/coordinators/project_coordinator.py`（修改）
  - 当前窗口继续复用 `CurrentProjectOpener.prepare_path()/activate()`、dirty 保存/丢弃/取消和单一 `ApiWorker`，不在 View 中读取或修改 Project。
  - project-open、save 或 foreground worker 正在运行时拒绝并发切换；worker 启动后同时投射 Workbench 与开始中心进度，完成、业务失败和线程异常均统一清理。
  - 源插件解析的 Workbench 进度延迟到 `AppContext.add_slot()` 与同步集合落地之后隐藏，避免最后一段主线程渲染开始前进度提前消失。
- `src/transbridge/ui/main_window.py`（修改）
  - 增加开始中心工程打开进度的窄 host port，并把可选显式工程路径传给 `ProjectCoordinator.init_workspace()`。

### 独立进程与显式工程启动链

- `src/transbridge/ui/shell/project_window_launcher.py`（新增）
  - 使用 `QProcess.startDetached()` 启动独立 GUI 进程；源码/安装态构造 `python -m transbridge.cli gui --open-project <path>`，冻结态构造 `<TransBridge.exe> gui --open-project <path>`。
  - 参数以列表传递，不使用 shell；返回值只表达操作系统是否接受进程，不伪装目标工程已经加载完成。
- `src/transbridge/ui/shell/start_center_controller.py`（修改）
  - 当前窗口选择继续提交既有 `PROJECT_OPEN`；新窗口选择调用独立 launcher，成功只提示已请求启动，失败或异常提供稳定诊断。
- `src/transbridge/cli.py`、`src/transbridge/entrypoints/gui.py`、`src/transbridge/ui/app.py`（修改）
  - 新增仅 GUI 有效的 `--open-project`，沿 CLI → GUI adapter → application composition → MainWindow 传递可选路径。
  - 新进程优先 `prepare_path()` 所选工程而不是先恢复 `active-project.json`；缺省启动语义保持不变。

### 回归测试

- `tests/ui/test_start_center_guided_project.py`（修改）
  - 覆盖活动/普通/不可用工程、鼠标和键盘打开弹出页、两个打开按钮、模态与无障碍语义、4px 进度条、冲突入口禁用及终态恢复。
  - 增加真实应用主题几何门禁：两个双行卡片高度不得低于 88px，标题和说明的几何范围必须完整位于按钮内部；该断言针对用户截图中的裁剪缺陷。
- `tests/ui/test_project_window_launcher.py`（新增）
  - 锁定源码态、冻结态命令形态，以及含空格路径使用参数列表而非 shell 字符串。
- `tests/ui/test_background_gui_operations.py`（修改）
  - 证明当前窗口工程准备不阻塞 GUI 线程，开始中心进度在 worker 生命周期中显示并于终态清除。
- `tests/integration/entrypoints/test_cli_entrypoint.py`、`tests/ui/ux/test_current_user_journeys.py`（修改）
  - 锁定 `--open-project` 转发、显式路径优先于活动指针，以及缺省启动链兼容。
