# FR5.16 全 Story 实现与 QA 收口

- **日期**：2026-08-28
- **Epic**：`project-terminology-build-versioning-reporting`
- **Story**：Story 00～12
- **需求**：FR5.16（并关联 FR5.2、FR5.13、FR6.10、FR8、FR24.8、FR26.6/FR26.12）
- **Plan**：[`plans/project-terminology-build-versioning-reporting/plan.md`](../../../../plans/project-terminology-build-versioning-reporting/plan.md)
- **ADR**：[`ADR-034`](../../../adr/034-project-terminology-build-versioning-reporting.md)（仍为“提议”）

## 增量目的

实现 FR5.16 Story 00～12 的代码与测试资产：从 Project 注册来源和当前 Variant 捕获权威输入，生成可重复、可增量的项目术语 BuildResult；以项目隔离 SQLite 保存构建、草稿、版本、报告和 changelog；通过 TaskRuntime、分页 renderer、effective terminology adapter 与独立工作台提供受门禁控制的消费路径。实现后由三个独立 QA 子 Agent 分别审查核心语义、跨层接线和性能/迁移，主会话修复发现并完成扩大回归。

正式性能证据尚未在指定参考硬件执行，因此本增量只记录“代码与测试实现完成”；analysis/report、draft/publish、effective、history/revert/changelog 和 partial publish 的正式 feature stage 继续 fail-closed。

## QA 后修复的关键问题

- LLM enabled 状态遗漏于 build/component key，可能错误复用关闭 LLM 的结果。
- 双语关系曾仅按 local key 对齐，可能跨 namespace 错配；现改为完整 EntryKey 优先。
- 全局 Variant digest 曾使所有关系组件失效；现按组件关联来源/entries/fingerprints 计算。
- conflict resolution 曾只返回临时 projection；现进入 Draft、Version、Report 和 changelog 事实链。
- DraftStore 曾删除重插 ManualAction；现强制 append-only 并提供生产事务 adapter。
- Report factory 曾允许注入与 pinned draft 矛盾的事实；现严格拒绝。
- Build/CAS 曾缺 effective/base/decision 内容摘要；现全部进入身份。
- 报告分页曾解码完整 snapshot payload；现以 manifest/section SQL 直接分页，并以 50,000 术语测试验证。
- SQLite migration 曾可能复用不属于当前源库的旧备份；现使用 source digest 绑定新备份。
- v2 ProjectDto 通过公共 save 写入时曾直接按 v3 校验失败；现先 canonical migrate。
- runtime 曾把所有 workload enum 误报为已绑定；现只报告实际 runner，未绑定提交不会残留 job。
- plugin scope 语义召回曾因 scope identity 不同直接返回空；现锁内按作用域重建并搜索。
- plugin context 曾在统一 postprocess/proofread 链丢失；现通过 TranslationInput/report details 传递。
- benchmark smoke 曾可能把未执行 phase 汇总为 0 秒；schema 2 现显式记录 diagnostic profile、缺失 phase/semantics 和 gate-ineligible 原因。
