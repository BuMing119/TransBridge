## 增量结果

术语工作台按四张横版参考图重新组织为“概览 / 术语 / 版本 / 报告”四个用户对象页面。顶部统一展示产品与当前项目上下文，页面使用横向导航、卡片、状态摘要和就地操作；原先暴露给用户的“构建→检查→调整→发布→历史→导出”六步流水线及重复页签已移除。底层阶段仍由既有 coordinator、runner、repository 和事务边界执行，但不再要求用户理解内部流程。

界面数据继续来自真实项目、草稿、已发布版本、冲突和报告资产，没有把参考图中的示例数字或项目名写入运行时。主操作会根据实际状态显示“创建术语库”或“更新术语库”；不可操作状态给出业务原因，历史、比较、恢复、发布和报告能力归入对应对象页面。

发布候选基准、迁移验证和质量证据已从安装版运行时彻底解耦。它们继续作为 CI/发布验收证据存在，但 `not-run` 或性能未达标不会再让“创建术语库”、草稿、发布、历史、报告或翻译消费在用户机器上统一变灰。真实业务保护仍保留：未完成草稿、未解决冲突、陈旧草稿、部分构建禁止发布、只读/损坏仓储、缺少已发布版本等状态仍按各自规则处理。

本记录取代上一条记录中“发布证据决定全部运行时门禁”的产品运行策略结论；旧记录保持不变，以保留当时的实现与验收事实。

## 关键实现与修复

- `ui/tools/terminology/workbench_shell.py` 与四类页面视图重构为横向信息架构，统一标题、项目选择器、导航、卡片、空状态和动作层级。
- `ui/foundation/visual_style.py` 增加术语工作台所需的现代化 QSS；`view_models.py`、`presenter.py`、`window.py` 投影真实项目上下文、数量、版本和现有资产状态。
- `build_view.py`、`draft_view.py`、`conflicts_view.py`、`history_view.py`、`reports_view.py`、`object_views.py` 将构建、冲突决定、发布、比较/恢复和导出操作放回对应对象页面，同时隐藏底层处理环节。
- `TerminologyUiServices`、presenter、production commands 与 TaskRuntime wiring 移除 release-evidence gate 依赖；构建命令恢复为始终创建草稿。
- `bootstrap/composition.py`、`bootstrap/terminology*.py` 不再读取 `terminology_release_evidence_path`、注册证据诊断或向 UI/命令暴露 `terminology_feature_gates`。
- `VersionPublisher` 移除通用 `enabled=False` 功能开关和 `PublishFeatureDisabledError`，继续依赖版本仓储的真实发布前置条件。
- effective terminology adapter 改为按“是否存在已发布版本”启用；无版本时保持既有 legacy fallback，有版本时消费冻结快照。
- `application/terminology/feature_gates.py` 保留为 CI/发布工具的证据评估器，并明确禁止产品运行时依赖；相关需求、Plan、Story 与 ADR 同步说明该边界。
- 增补和更新 presenter、窗口生命周期、publish、bootstrap wiring、effective snapshot、发布事务及翻译消费回归测试。

## 检查同类问题

已检索生产 bootstrap、术语应用层、UI 与翻译消费路径中的 feature gate、release evidence、default-off 和 disabled 分支。除 `application/terminology/feature_gates.py` 与基准聚合代码保留给测试/发布工具外，生产组合根和 UI 不再导入发布证据评估器，也不存在“发布测试未运行就禁用用户功能”的同类路径。

其余不可用状态均有独立产品含义：用户未选择可选 LLM/MCP、缺少可选依赖、没有已发布版本、部分构建禁止发布、仓储只读/损坏、提交版本过期或安全校验失败。这些保护未被放宽。
