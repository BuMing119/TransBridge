# 工作台词条批量操作与 AI 选区闭环

- **日期**：2026-09-05
- **Epic**：`unplanned`
- **Story / 主题**：`workbench-batch-entry-actions`（计划外缺陷修复，无对应的已规划 Story）
- **需求来源**：用户根据工作台词条多选截图反馈，翻译状态等菜单虽然可以在多选状态下打开，但底层可能仍只处理单条，并要求修复。
- **相关记录**：[右键取消翻译与批量清空保护](../workbench-translation-reset/2026-08-31-001-右键取消翻译.md)。该记录已实现“取消翻译”的选择范围，本次将同一范围规则复用于状态和标签，并补齐 AI 翻译入口。

## 归属说明

现有 [`batch-operations`](../../../../plans/batch-operations/plan.md) 计划描述的是多插件、多 `CollectionSlot` 的解析、上传、下载、写回和 AI 处理，不包含工作台词条行级右键批量操作。现有 [`ui-workbench`](../../../../plans/ui-workbench/plan.md) 与 [`ai-translation`](../../../../plans/ai-translation/plan.md) 计划均已完成，且没有与本次缺陷完全对应的未完成 Story。因此本次使用明确的计划外归属，不回写或改变既有计划状态。

## 目的与用户可见行为

- 在工作台右键已选中的词条时，“翻译状态”、标签分配/移除、新建标签和“取消翻译”作用于全部选中词条；右键未选中的词条时只处理该词条。
- 多条词条状态不一致时，状态菜单不伪造统一勾选项；用户仍可选择任意目标状态，包括右键词条已经处于的状态，并将其应用到整批。
- 批量修改翻译状态保留每条现有译文。工程投影模式使用完整 `EntryKey` 一次提交全部状态，携带 Project/Variant 修订和 `VariantRef`；提交失败或捕获范围已过期时不修改可见词条。
- 批量标签操作一次提交完整标签投影；新建标签后立即分配给整批目标。
- 修复权威工程中 UI 兼容 `TranslationEntry.id` 与 `EntryKey.local_key` 不同时，界面标签看似改变但提交未命中目标的缺陷。标签投影以序列化完整 `EntryKey` 保存权威映射，对活动集合再映射回 UI 条目 ID，避免不同来源的同名 local key 串写。
- 从工作台点击“AI 翻译”时，如主表存在选中行，配置窗口自动锁定这些精确词条 ID，并显示“当前选择 N”预设；锁定和隐藏词条继续按既有规则排除。用户可在窗口中重新点击该预设以读取最新选区。
- “检查”和“写回/发布”等原有筛选级或文件级动作不改为词条选择级，保持既有语义。

## 逐文件变更

### 新增：统一词条动作范围

[src/transbridge/ui/workbench/entry_action_scope.py](../../../../src/transbridge/ui/workbench/entry_action_scope.py)

- 新增 `resolve_entry_action_scope()`：只有右键词条属于当前选区时才返回完整选区，否则只返回右键词条。
- 按源集合顺序解析稳定词条 ID，避免菜单动作依赖当前已渲染行或表格排序位置。

### 新增：批量状态原子提交动作

[src/transbridge/ui/workbench/translation_stage_action.py](../../../../src/transbridge/ui/workbench/translation_stage_action.py)

- 新增 `TranslationStageAction` 和 `TranslationStageChange`，捕获范围、原状态、译文、活动来源、集合、版本身份和修订号。
- 工程模式通过 `replace_entry_states()` 一次提交整批目标，并保留各自译文；仅在权威提交成功后同步兼容的可见对象。
- 来源、集合或目标内容在执行前变化时拒绝旧操作；命令服务不可用或提交失败时给出原因，不留下部分状态修改。
- 非权威投影模式在整批修改后只标记一次 dirty。

### 修改：工作台菜单、标签与刷新接线

[src/transbridge/ui/workbench/entry_menu.py](../../../../src/transbridge/ui/workbench/entry_menu.py)

- `build_entry_menu()` 改为接收目标 ID 集合、共同标签和共同状态，而不是把单个词条绑定到每个菜单动作。
- 标签和新建标签回调传递整批目标；状态项使用 `triggered`，使混合状态选区可以应用右键词条已有的状态。

[src/transbridge/ui/workbench/labels_presenter.py](../../../../src/transbridge/ui/workbench/labels_presenter.py)

- 新增 `toggle_many()` 与 `create_many()`，在副本中处理全部目标后调用一次提交边界。
- 既有单条 `toggle()` / `create()` 委托给批量方法，保留原公共行为。

[src/transbridge/ui/workbench/step2.py](../../../../src/transbridge/ui/workbench/step2.py)

- `_on_context_menu()` 使用统一范围解析器计算目标 ID、共同标签交集和共同状态，并将捕获的选区接入菜单动作。
- `_on_stage_change()` 委托给原子批量动作。单条变更沿用局部刷新；多条变更重新计算统计和筛选标签，仅当状态筛选成员关系改变时重建表格，否则逐行增量刷新。
- 标签切换和快速新建改用批量 presenter，成功后刷新标签和表格。

[src/transbridge/ui/workbench/translation_reset.py](../../../../src/transbridge/ui/workbench/translation_reset.py)

- 删除重复的选区解析逻辑，复用 `resolve_entry_action_scope()`，使取消翻译与新增的状态/标签动作遵循同一右键范围合同。

### 修改：权威标签身份映射

[src/transbridge/ui/context.py](../../../../src/transbridge/ui/context.py)
