# 001: TaskManager QObject 化 + pyqtSignal 异步通知

**日期**: 2026-05-12
**类型**: 改
**关联**: Epic: Smart Assistant QA 全面修复 > Story 02: 异步任务完成通知

## 修改文件

### `src/transbridge/smart_assistant/tools/task_manager.py` (改)
- **修改内容**: `TaskManager` 改为继承 `QObject`，新增类级 `task_completed = pyqtSignal(str, dict)` 和 `task_failed = pyqtSignal(str, str)` 两个信号。新增 `notify_completed(task_id, result)` 和 `notify_failed(task_id, error)` 方法供后台线程调用
- **原因**: B2 修复 — 原 TaskManager 是纯 threading 类，后台翻译/润色线程完成后仅调用 `set_status(task_id, "completed")` 静默退出，LLM 拿到 task_id 后无从得知任务何时完成

### `src/transbridge/smart_assistant/tools/tool_translator.py` (改)
- **修改内容**: `_tool_start_translation` 和 `_tool_start_polish` 的 `_run()` 后台线程中：成功完成时调用 `tm.notify_completed(task_id, {...})`，InterruptedError 时调用 `tm.notify_failed(task_id, "任务已被用户停止")`，通用异常时调用 `tm.notify_failed(task_id, str(exc))`
- **原因**: 原后台线程完成/失败时无任何通知机制，修复后在状态更新同时通过 pyqtSignal 通知 ChatWidget

### `src/transbridge/ui/tools/smart_assistant/chat_widget.py` (改)
- **修改内容**: `__init__` 中连接 `TaskManager().task_completed` → `self._on_task_completed` 和 `task_failed` → `self._on_task_failed`。新增 `_on_task_completed()` 和 `_on_task_failed()` 方法：收到信号后追加 observation 消息到对话并触发 `_run_llm_round()` 使 LLM 自动收到通知
- **原因**: ChatWidget 需订阅 TaskManager 信号，将后台任务结果自动注入对话上下文

### `src/transbridge/smart_assistant/prompts.py` (改)
- **修改内容**: 在执行策略部分前新增「重要提醒」段：告知 LLM `start_translation`/`start_polish` 是异步工具，完成后会自动通知；补充工具失败时的重试判断原则（网络可重试、权限/配置不可重试）
- **原因**: 系统提示词原完全不提及异步通知机制，LLM 不知道任务完成会自动通知
