# 003: Phase 1 后端 QObject 解耦与 C 栈溢出根治

**日期**: 2026-05-13
**类型**: 改
**关联**: Epic: Smart Assistant QA 修复 > Story 02: 异步任务完成通知

## 背景

用户点击 AI 助手 → 发消息 → 进程闪退，错误码 0xC00000FD (Windows C 栈溢出)。经评审委员会讨论 (`docs/council-review-stack-overflow-decoupling.md`)，根因是后端 6 个类继承 QObject/QThread，在 UI 初始化 + 消息发送路径上 C 栈累积超出 Windows 1MB 限制。

前期修复（惰性 `__getattr__`、4 阶段 UI 延迟、TaskManager 延迟初始化）仅将崩溃从「打开面板」推迟到「发第一条消息」，未消除根因。

Phase 1 按委员会共识执行 4 项改动，从源头上削减后端 QObject 数量。

## 修改文件

### `src/transbridge/smart_assistant/memory/memory_store.py` (改)
- **修改内容**: `MemoryWriterThread` 父类从 `QThread` 改为 `threading.Thread`；移除 `from PyQt6.QtCore import QThread`；`super().__init__(daemon=True)`；`stop()` 中 `self.wait(3000)` 改为 `self.join(timeout=3)`
- **原因**: 该线程完全不使用 pyqtSignal，只依赖 `threading.Condition` + `threading.Event`。QThread 的 C++ 元对象系统开销是白白承担的，改为 `threading.Thread` 减少 `MemoryStore.__init__` (在 `_init_ui_stage1` 中调用) 的 1 个 QObject 创建

### `src/transbridge/smart_assistant/tools/task_manager.py` (改)
- **修改内容**: 移除 `QObject`/`pyqtSignal` 继承，改为纯 Python 类；新增 `on_completed(callback)`、`on_failed(callback)`、`remove_listener(callback)` 三个回调注册方法；`notify_completed()`/`notify_failed()` 从 `pyqtSignal.emit()` 改为遍历回调列表调用；`reset()` 增加 `_listeners.clear()` 清理；新增 `import logging` + `logger`
- **原因**: TaskManager 已有完整 `threading.Lock`/`threading.Event` 基础设施，pyqtSignal 只是「二次通知」。去除 QObject 继承消除 `TaskManager()` 单例的 C++ 元对象分配（信号表/槽表/父子关系跟踪），这是 C 栈溢出路径上的关键削减。回调模式保持跨线程安全——`notify_*` 本身就在锁内调用

### `src/transbridge/smart_assistant/tools/__init__.py` (改)
- **修改内容**: 移除 `from .task_manager import TaskManager` 及 `__all__` 中的 `"TaskManager"`
- **原因**: TaskManager 不再需要从工具包子包预导入，各调用方直接 `from .task_manager import TaskManager` 按需加载

### `src/transbridge/ui/tools/smart_assistant/chat_widget.py` (改)
- **修改内容**:
  - **日志审计**: 新增 `import logging` + `logger`；11 处 `except Exception: pass` 改为分级日志（`logger.error`/`warning`/`info`/`debug`），覆盖 QSettings 读写、Embedding 创建、LLM 配置加载、记忆记录/检索、Worker 信号断开、TaskManager 初始化、护栏配置降级等路径
  - **TaskManager 适配**: `_ensure_task_manager()` 中 `tm.task_completed.connect(...)` → `tm.on_completed(...)`、`tm.task_failed.connect(...)` → `tm.on_failed(...)`；异常日志从静默改为 `logger.error`
  - **Micro-stage 拆分**: `_run_llm_round()` 拆为 3 阶段：
    - Stage A (`_run_llm_round`): 纯 Python 准备（`_ensure_task_manager`、`_get_llm_client`、system prompt 构建、`_react_depth` 递增、LLMConfig 读取），保存中间状态到 `self._round_messages` / `self._round_max_tokens`，调度 Stage B
    - Stage B (`_run_llm_round_stage_b`): 创建 `MessageBubble` (QWidget) + 插入布局，调度 Stage C
    - Stage C (`_run_llm_round_stage_c`): 创建 `ChatWorker` (QThread) + 4 个 signal 连接 + `start()`，清理临时状态
  - **初始化**: 新增 `self._round_messages` / `self._round_max_tokens` 临时状态属性
- **原因**:
  - 日志审计消除了崩溃路径上的完全静默——之前栈溢出发生时连一条日志都留不下
  - Micro-stage 拆分将原先单帧内 3 QObject (TaskManager + MessageBubble + ChatWorker) 的创建分散到 3 个事件循环帧，每帧 C 栈完全展开后再进入下一帧。配合 TaskManager 已去 QObject 化，现在每帧最多 1 个 QObject

### `src/transbridge/ui/tools/smart_assistant/panel.py` (改)
- **修改内容**: `closeEvent()` 中 `tm.task_completed.disconnect(...)` / `tm.task_failed.disconnect(...)` 改为 `tm.remove_listener(...)`
- **原因**: 适配 TaskManager 从 pyqtSignal 到回调列表的 API 变更

### `docs/council-review-stack-overflow-decoupling.md` (增)
- **修改内容**: 评审委员会讨论纪要，4 角色（架构师/开发者/QA/安全）分析 QObject 耦合根因，输出 7 条共识建议 + Phase 1-3 分阶段执行计划
- **原因**: 为 Phase 1 编码提供决策依据，记录分歧点（ExecutionEngine 是否立即解耦）供后续裁决
