# 002: TaskManager 延迟初始化修复 C 栈溢出

**日期**: 2026-05-13
**类型**: 改
**关联**: Epic: Smart Assistant QA 修复 > Story 02: 异步任务完成通知

## 修改文件

### `src/transbridge/smart_assistant/__init__.py` (改)
- **修改内容**: 移除全部 13 行模块级 `from .X import Y` 导入（覆盖 conversation_manager/chat_worker/execution_engine/tool_registry/context_builder/prompts/agents/graph_types/guardrails/observability/mcp/tools），替换为惰性 `__getattr__` 机制 —— 按需通过 `importlib.import_module()` 加载子模块并返回对应符号
- **原因**: 原 `__init__.py` 在被导入时一次性加载全部 12+ 子包，其中 6 个包含 QObject/pyqtSignal 定义（ChatWorker/ExecutionEngine/AgentWorker/ObservabilityCollector/TaskManager 等，共 ~17 个 pyqtSignal），每个涉及 C++ 对象创建。在 Windows 1MB C 栈上累积过深导致 `STATUS_STACK_OVERFLOW (0xC00000FD)` 进程终止。惰性加载后各子模块按需独立加载，C 栈在每次导入间完全展开

### `src/transbridge/ui/tools/smart_assistant/chat_widget.py` (改)
- **修改内容**: `ChatWidget.__init__` 第 98-102 行，将同步的 `TaskManager()` 创建和信号连接替换为 `QTimer.singleShot(0, self._init_task_manager)`；新增 `_init_task_manager()` 方法（第 559-573 行），封装 TaskManager 单例获取和 `task_completed`/`task_failed` 信号连接，带 try/except 保护
- **原因**: 次级防御：即使 `__init__.py` 惰性加载解决了导入期栈溢出，`ChatWidget.__init__` 中仍有多个 QObject 创建（QThread/MemoryWriterThread/ObservabilityCollector），将 TaskManager 信号连接延迟到事件循环空闲时进一步降低峰值 C 栈深度
