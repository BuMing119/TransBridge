# 004: QA 审查 Blocker 修复 — TaskManager 跨线程回调投递

**日期**: 2026-05-13
**类型**: 改
**关联**: Epic: Smart Assistant QA 修复 > Story 02: 异步任务完成通知

## 背景

Phase 1 去 QObject 化 (003) 将 TaskManager 的 pyqtSignal 改为纯 Python 回调列表。但 `tool_translator.py` 的 worker 线程调用 `notify_completed()` 时，回调在 worker 线程同步执行，直接操作 QWidget → 违反 Qt 线程安全规则。

原 `pyqtSignal.emit()` 在非主线程调用时，Qt 自动通过 `QMetaObject::activate` 排队到主线程。纯 Python 回调丧失了此保护。

## 修改文件

### `src/transbridge/smart_assistant/tools/task_manager.py` (改)
- **修改内容**:
  - 新增 `from PyQt6.QtCore import QMetaObject, Qt, QCoreApplication` 导入
  - `notify_completed()`: 不再直接同步调用回调，改为遍历回调列表，通过 `QMetaObject.invokeMethod(app, lambda, Qt.QueuedConnection)` 将每个回调投递到主线程执行
  - `notify_failed()`: 同上
  - 新增 `_safe_callback(cb, *args)` 静态方法：统一包装 try/except 隔离单回调异常
  - 模块 docstring 更新：说明跨线程安全机制
- **原因**: 修复 QA 审查发现的 Blocker (SEC-001/REG-001)。`QMetaObject.invokeMethod` 提供与原 pyqtSignal 等价的主线程排队行为，但只需函数级 Qt 依赖（QMetaObject/Qt/QCoreApplication），无需 QObject 继承
