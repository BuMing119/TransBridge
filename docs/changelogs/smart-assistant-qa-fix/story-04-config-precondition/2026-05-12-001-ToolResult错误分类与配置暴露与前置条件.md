# 001: ToolResult 错误分类 + 配置暴露 + 前置条件检查

**日期**: 2026-05-12
**类型**: 改
**关联**: Epic: Smart Assistant QA 全面修复 > Story 04: 配置与工具前置条件

## 修改文件

### `src/transbridge/smart_assistant/tools/base.py` (改)
- **修改内容**: `ToolResult` dataclass 新增 `error_category: str | None`（network/auth/input/permission/config/internal）、`error_code: str | None`、`recovery_action: str | None`、`warnings: list[str] | None` 四个字段。`fail()` 类方法新增 `error_category`/`error_code`/`recovery_action` 关键字参数；`ok()` 新增 `warnings` 参数。`to_dict()` 和 `get()` 方法同步扩展新字段。新增 `@require_collection` 装饰器用于统一集合前置检查
- **原因**: C10 — 原 ToolResult.fail() 仅接受 message 和 failed_items，LLM 无法区分错误类型（网络/权限/配置）以决定重试策略；M3 — 6 个文件各自实现 collection-is-None 检查

### `src/transbridge/smart_assistant/tools/tool_translator.py` (改)
- **修改内容**: `_tool_start_translation` 参数校验后新增前置条件检查：读取 LLMConfig 验证 api_key 非空（否则返回 error_category="config", error_code="API_KEY_MISSING"）。`_tool_get_translation_config` 重写返回结构：新增 `api_key_configured` 字段；新增 `post_process` 子对象（从 LLMConfig 的 pp_enable_* 属性聚合 7 个后处理开关）；新增 `term_database` 子对象（术语数据库文件路径+条目数）；新增 `paratranz` 子对象（token_configured + api_url）；移除永远返回 None 的 `post_process_stages` 和 `term_database` 虚假属性
- **原因**: C3+C4 — 原 start_translation 不检查 API Key/术语数据库等关键前置条件；原 get_translation_config 使用 `getattr(llm, 'post_process_stages', None)` 访问 LLMConfig 中不存在的属性

### `src/transbridge/smart_assistant/tools/tool_default.py` (改)
- **修改内容**: `_tool_get_app_state` 返回数据新增 `paratranz_configured` 布尔字段（从 ParatranzConfig.load_from_file() 读取 token 是否已配置）
- **原因**: C5 — 原 AI 完全不知道 ParaTranz API 是否已配置，无法判断 upload_entries/download_entries 等工具是否可用
