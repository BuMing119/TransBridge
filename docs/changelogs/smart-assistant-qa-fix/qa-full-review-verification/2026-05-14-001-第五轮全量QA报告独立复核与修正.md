## 修改文件

### `docs/test-reports/smart-assistant-full-qa-2026-05-14.md` (改)
- **修改内容**:
  - **B6 推翻**: 从 Blocker 降级为误报（FALSE）。`_do_streaming_flush()` 实际逻辑是首次创建 QLabel，后续仅调用 `setText()` 复用，并非每帧重建。当前实现是正确的持久化 QLabel 模式。
  - **B2 修正**: 补充说明 local `import os` 不进入模块全局命名空间，`NameError` 是无条件崩溃（比原描述"如果 LLM 先调用 list_collections"更严重）。
  - **B7 修正**: 移除"闭包引用循环"的不准确描述——`lambda cb: cb()` 是无捕获的参数 lambda，不形成引用循环。保留无 parent QObject 问题。
  - **C10 修正**: TranslationEntry 是 `@dataclass`（非 QObject），修改其字段不违反 Qt 线程亲和性。`translation_scope` setter 不发射 pyqtSignal。真正风险是无同步并发读写共享可变状态。
  - **C16 修正**: 从列表中移除 proofreader 工具（其函数确实不接受参数，`parameters={}` 正确）。仅保留 ParaTranz（8工具）和 writer（4工具）。
  - **C22 修正**: httpx 0.28.x 默认超时为 5 秒（非"无限"）。实际风险方向相反：对 LLM API 调用（30-60s+）可能过短导致虚假超时。
  - **C23 修正**: 补充 OpenAI SDK（max_retries=2）和 Anthropic SDK（max_retries=2）内置重试机制。应用层确实缺少显式配置和错误日志。
  - **C24 修正**: CPython GIL 保护 dict 结构完整性，"损坏"用词不准确。实际风险为 RuntimeError（并发迭代）、FAISS C++ 索引与 _id_map 失同步、丢失更新。
  - **C25 修正**: `set_input()` 是 ChatWidget 的公开方法（无下划线前缀），非私有成员。3 项中有 2 项确实是私有成员访问。
  - **C27 修正**: tool_registry.py 仅导入 `tools/tool_v1.py`（一个模块），非"所有"工具模块的级联导入。副作用范围被夸大。
  - **C30 修正**: 编译正则对 ~200 行文本的匹配约 10-50ms，远低于人眼感知阈值。真正瓶颈是 `block.render()` 中的 QWidget 创建。
  - **新增复核章节**: 文末添加完整独立复核章节，含复核方法（13 Agent 并行）、40 项明细表（29 CONFIRMED / 10 PARTIAL / 1 FALSE）、复核结论。
  - **统计数据更新**: Blocker 10→9，总问题 167→166，综合评分 34/60→37/60，P0 优先级列表移除 B6。
- **原因**: 原始报告由 8 Agent 并行审查生成，独立复核发现 1 项误报（B6）和 10 项描述偏差（PARTIAL）。通过 13 Agent 逐项读取代码验证，确保报告准确性，避免误导后续修复工作。报告整体可信（问题识别率 97.5%），但 Infra 层（C22/C23/C24）描述有夸大倾向。
