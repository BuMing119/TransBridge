# 001: 线程取消 + _paused 实例化 + 面板/对话清理

**日期**: 2026-05-12
**类型**: 改
**关联**: Epic: Smart Assistant QA 全面修复 > Story 05: 线程与资源生命周期管理

## 修改文件

### `src/transbridge/smart_assistant/agents/agent_worker.py` (改)
- **修改内容**: `run()` 方法在工具执行前新增 `if self._cancelled: self.error.emit("任务已取消"); return` 中断检查。原 `cancel()` 方法已设置 `_cancelled` 标志但 `run()` 从未检查
- **原因**: M7 — AgentWorker.cancel() 调用后 worker 继续运行直到工具完成，cancel 是空操作

### `src/transbridge/smart_assistant/execution_engine.py` (改)
- **修改内容**: `_paused: threading.Event` 从类级属性（`_paused: threading.Event = threading.Event()`）改为 `__init__` 中的实例属性（`self._paused = threading.Event()`）
- **原因**: M8 — 类级属性导致所有 ExecutionEngine 实例共享同一个 Event，一个会话暂停会影响另一个会话

### `src/transbridge/ui/tools/smart_assistant/panel.py` (改)
- **修改内容**: 新增 `closeEvent()` 覆盖：关闭面板时检查 `_chat._worker` 是否运行中 → cancel + wait(3000ms)；检查 `_chat._engine` 是否存在 → cancel
- **原因**: M13 — 面板关闭时 ChatWorker 和 ExecutionEngine 线程继续运行，可能尝试发射信号到已销毁的 widget 导致崩溃

### `src/transbridge/ui/tools/smart_assistant/chat_widget.py` (改)
- **修改内容**: `_clear_conversation()` 开头新增：检查并取消运行中的 `_worker`（cancel + wait 2s），取消 `_engine`，重置 `_react_depth` 和 `_consecutive_errors`，清除 UI 消息后释放 `_uploaded_docs` 字典
- **原因**: M14 — 原 _clear_conversation 不检查或取消运行中的 worker/engine，用户清空对话时如有 LLM 调用进行中，worker 完成信号连接到正在销毁的 widget 可导致释放后使用
