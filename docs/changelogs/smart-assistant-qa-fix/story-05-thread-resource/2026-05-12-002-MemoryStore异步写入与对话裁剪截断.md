# 002: MemoryStore 异步写入 + ConversationManager 裁剪截断 + Token 预算

**日期**: 2026-05-12
**类型**: 改
**关联**: Epic: Smart Assistant QA 修复 > Story 05: 线程与资源生命周期管理

## 修改文件

### `src/transbridge/smart_assistant/memory/memory_store.py` (改)
- **修改内容**: (M9) 新增 `MemoryWriterThread(QThread)` 后台写入线程类 — 持有 Condition 队列，每 500ms 批量刷写 metadata JSON + FAISS 索引到磁盘；`MemoryStore.__init__` 新增 `max_entries` 参数(默认 1000) + `_access_order` LRU 链表 + `_lock` 线程锁 + `_writer` 线程实例(自动启动)；`add()` 改为仅内存操作（更新 metadata + LRU + 向量索引）+ `enqueue()` 通知 writer 后立即返回，不再同步写磁盘；新增 `_update_lru()` / `_evict_lru()` 方法实现 LRU 淘汰；新增 `close()` 方法 — stop writer 线程 + 最终刷盘
- **原因**: 原 `add()` 每次调用同步写 JSON + FAISS 文件，在 UI 线程中阻塞磁盘 I/O，大量记忆累积时卡顿明显；异步写入解耦 UI 线程与磁盘 I/O，LRU 淘汰防止记忆无限增长

### `src/transbridge/smart_assistant/conversation_manager.py` (改)
- **修改内容**: (M10) `_trim()` 重写为按轮次裁剪 — 新增 `_is_observation()` / `_is_plan_result()` 判定方法；一轮定义为 user(非 observation/plan_result) → assistant → [observation*] → [plan_result*]；裁剪时整轮移除（含该轮关联的所有 observation 和 plan_result 消息），而非仅移除 user+assistant 对；(M12) `add_observation()` 和 `add_plan_result()` 方法中结果文本超过 2000 字符时自动截断，追加 `...(已截断，共 N 字符)` 后缀
- **原因**: 原 `_trim()` 仅按 user+assistant 对数裁剪，observation/plan_result 消息永不移除导致上下文无限膨胀；观察结果无截断可能导致单条消息占用大量 token

### `src/transbridge/smart_assistant/prompts.py` (改)
- **修改内容**: (M11) `build_system_prompt()` 新增 `namespace: str | None = None` 参数，透传到 `ToolRegistry.build_tool_schema_for_prompt(namespace)`，支持按 Agent namespace 过滤工具 schema 以节省 prompt token
- **原因**: 原固定返回全部工具 schema，多 Agent 场景下每个 Agent 仅需其 namespace 的工具定义，可节省 50%+ token

### `src/transbridge/ui/tools/smart_assistant/panel.py` (改)
- **修改内容**: (M13 补) `closeEvent()` 新增 `self._chat._memory_store.close()` — 关闭面板时停止 MemoryStore 的 writer 线程并最终刷盘
- **原因**: 面板关闭后 writer 线程若未停止会导致资源泄漏，且未刷盘的记忆数据可能丢失
