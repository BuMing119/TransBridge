# 003: v2工具模块未导入 + max_tokens硬限制导致输出截断修复

**日期**: 2026-05-13
**类型**: 改
**关联**: Epic: Smart Assistant QA 全面修复 > Story 5: 线程与资源

## 修改文件

### `src/transbridge/smart_assistant/tools/__init__.py` (改)
- **修改内容**: 新增 `from . import tool_editor/tool_translator/tool_proofreader/tool_paratranz/tool_writer/tool_parser/tool_default` 共7个 v2 工具模块导入
- **原因**: v2工具模块底部的 `_register_*_tools()` 为模块级调用，需要模块被导入时才执行。原 `__init__.py` 仅导入 `.base`，7个工具模块从未加载，导致 `ToolRegistry` 中只有5个 v1 deprecated 工具。`build_tool_schema_for_prompt()` 过滤 deprecated 后工具列表为空，LLM 看到"可用工具列表："后无任何工具名称，无法调用 `search_entries`/`edit_translation` 等完成用户请求

### `src/transbridge/ui/tools/smart_assistant/chat_widget.py` (改)
- **修改内容**: (1) `_round_max_tokens` 默认值从 2048 改为 0；(2) 删除 `_run_llm_round` 中从 `LLMConfig.load_from_file()` 读取 `max_output_tokens` 的代码块；(3) `_run_llm_round` 中每轮重新赋值 `self._round_max_tokens = 0`（因 `_run_llm_round_stage_c` 会 `del` 该属性）
- **原因**: Smart Assistant 作为对话型 Agent 不应与 AI 翻译器共享 `max_output_tokens` 配置。原逻辑 `0 or 2048` 将 2048 硬传入 API，对于需要输出思考过程+工具调用JSON+多轮回复的 Agent 严重不足，导致 API 因 max_tokens 耗尽截断输出（finish_reason=length），且代码中无 finish_reason 检测

### `src/transbridge/smart_assistant/chat_worker.py` (改)
- **修改内容**: `__init__` 的 `max_tokens` 参数默认值从 2048 改为 0
- **原因**: 配合 chat_widget 的修改，0 表示不限制。传入 LLM 客户端后：OpenAI 兼容 API 不设置 max_tokens 参数（使用模型默认上限），Anthropic API 回退到 8192
