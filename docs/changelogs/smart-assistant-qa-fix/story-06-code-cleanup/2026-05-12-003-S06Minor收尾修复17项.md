### `src/transbridge/smart_assistant/tool_registry.py` (改)
- **修改内容**: 
  - (m2) 移除 `get_collection_summary` 的 ToolRegistry 注册及相关 import
  - (m7) `_ToolRegistry` 7 个方法（register/get/list_all/list_namespace/list_all_namespaces/build_tool_schema_for_prompt）全部补充简短 docstring
  - (M2) `ToolSpec` 新增 `deprecated: bool = False` 字段；`_register_v1_tools()` 中 5 个 v1 工具全部标记 `deprecated=True`，display_name 和 description 添加 `[已废弃]` 前缀并指向 namespace 替代工具；`build_tool_schema_for_prompt()` 排除 `deprecated=True` 的工具
- **原因**: 死代码清理；统一文档规范；v1 工具深度去重——保留注册以兼容旧调用路径，但在 LLM prompt schema 中隐藏以引导使用新 namespace 工具

### `src/transbridge/smart_assistant/execution_engine.py` (改)
- **修改内容**:
  - (m9) `__init__` 新增 `self._decision_cv = threading.Condition()`；`provide_decision()` 新增 `self._decision_cv.notify_all()`；`_run_single()` 和 `execute_graph()` 中 2 处忙等轮询（`time.sleep(0.5)` 循环）改为 `self._decision_cv.wait(timeout=0.5)` + 取消检查
  - (m11) `__init__` 新增 `self._executor = ThreadPoolExecutor(max_workers=4)`；`execute_graph()` 中 `with ThreadPoolExecutor(...) as pool:` 改为直接使用 `self._executor.submit()`
- **原因**: 忙等轮询浪费 CPU 且在 Qt 事件循环中可能阻塞 UI；ThreadPoolExecutor 频繁创建/销毁增加线程开销，复用线程池提升性能

### `src/transbridge/smart_assistant/observability/collector.py` (改)
- **修改内容**:
  - (m12) `start_conversation()` 方法开头新增 `self._session_tokens = TokenStats()`，确保新会话开始时重置 token 统计
  - (m15) `end_conversation()` 方法中新增 `self._active.tools_called.clear()`，对话结束时清空工具调用记录
- **原因**: 会话切换时残留旧统计数据会导致 Token 用量和工具调用计数不正确

### `src/transbridge/infra/vector_store.py` (改)
- **修改内容**:
  - (m14) `__init__` 新增 `self._dirty = False` 标记；`remove()` 方法设置 `self._dirty = True`；新增 `rebuild_index()` 方法 — 遍历 FAISS 索引保留未删除向量重建新索引；`save()` 方法在保存前检查 `_dirty` 并自动调用 `rebuild_index()`
- **原因**: FAISS 不支持直接删除向量，原 `remove()` 仅从 id_map 中移除引用但向量仍占用索引空间，频繁软删除后索引膨胀。重建索引物理移除已删除向量

### `src/transbridge/ui/tools/smart_assistant/chat_widget.py` (改)
- **修改内容**:
  - (m19) `_on_retry()` 中 `self._worker.wait(3000)` 包裹 try/except；若 3s 内未完成则添加警告消息
  - (M6) `_on_tool_executed()` 中 ReAct 重试循环重构：导入 `RetryHandler`，使用 `retry_handler.should_retry()` 判定可重试性，使用 `retry_handler.analyze_and_adjust()` 调整重试步骤参数（替代原简单 network/internal 分类重试）
- **原因**: worker.wait() 可能阻塞超过 3s 且无反馈；ReAct 简单重试无法利用 RetryHandler 的参数调整能力（如调整 temperature/max_tokens 后重试）
