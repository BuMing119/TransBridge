# 001: Prompt注入修复 + MCP认证 + v1路径校验 + 校验放宽

**日期**: 2026-05-12
**类型**: 改
**关联**: Epic: Smart Assistant QA 全面修复 > Story 03: 安全加固

## 修改文件

### `src/transbridge/smart_assistant/context_builder.py` (改)
- **修改内容**: `build()` 方法中上传文件的 `raw_text[:200]` 直接拼接改为仅注入文件名+格式+字符数摘要（`{name} ({format}, {char_count}字符) — 使用 search_memory 工具检索内容`）
- **原因**: C6 — 用户上传文件内容直接注入系统提示词，攻击者可上传含提示注入内容的文件劫持 LLM 行为

### `src/transbridge/smart_assistant/mcp/server.py` (改)
- **修改内容**: `MCPServer.__init__` 新增 `config: dict` 参数；`run_stdio()` 中每个请求处理前调用 `_authenticate(request)` 检查；新增 `_authenticate()` 方法：从 `config["auth_token"]` 读取 token，空则放行，非空则验证请求 params._meta.authorization
- **原因**: C7 — MCP stdio 通道原无任何认证机制，任何能写入进程 stdin 的程序都可调用 MCP 工具

### `src/transbridge/smart_assistant/tools/tool_v1.py` (改)
- **修改内容**: `_tool_export_json` 在 output_path 非默认时调用 `_validate_output_path()` 校验路径安全；`_tool_write_back` 在 target_path 上调用 `_validate_output_path()` 并限制扩展名白名单（.esp/.esm/.esl/.xml/.strings）
- **原因**: C8 — v1 工具原直接使用 ctx.esp_path 写入文件未经路径验证，而 namespace 工具有 `_validate_path`/`_validate_output_path` 检查

### `src/transbridge/smart_assistant/guardrails/input_validator.py` (改)
- **修改内容**: `_INJECTION_PATTERNS` 中移除常见翻译文本的误伤模式：删除 `\bSELECT\b.*\bFROM\b`（"Select the item from..." 合法文本），将 `INSERT/UPDATE/DELETE/SELECT` 从 `';\s*;\s*(...)` 模式中移除（仅保留 DROP/ALTER/EXEC/UNION/TRUNCATE）。新增 `_SAFE_HTML_TAGS` 集合（font/b/i/u/br/p/h1-h6/div/span/img 等游戏标记语言标签）供后续增强使用
- **原因**: M16 — 原注入检测模式过于激进，翻译文本中的合法 HTML 标签和 SQL-like 关键词被误判为注入攻击
