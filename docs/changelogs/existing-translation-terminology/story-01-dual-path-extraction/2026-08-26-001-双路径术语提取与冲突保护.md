# 双路径术语提取与冲突保护

- **日期**：2026-08-26
- **Epic**：`existing-translation-terminology`
- **Story**：Story 1：双路径提取与最小安全合并
- **关联计划**：`plans/existing-translation-terminology/plan.md`
- **状态**：实现完成，相关 QA 通过

## 目的

让已经完成大半翻译的项目可以只从可靠存量译文中初始化术语：名称类字段直接使用整条双语值，普通文本只接收同一双语条目中的连续原样子段，并在写入动态术语库前完成去重、冲突检查和已有术语保护。

## 真实变更

- `src/transbridge/ai_translator/existing_term_extractor.py`（新增）
  - 新增独立的 `ExistingTermSeeder`，排除空文本、隐藏和“有疑问”条目，避免不可靠译文进入术语库。
  - `AUTO_TERM_CONTEXTS` 名称字段整条生成 `existing_name` 术语；其他文本按每批 20 条交给现有 `NounExtractor`，生成 `existing_text` 术语。
  - 源术语使用 Unicode NFKC、空白收敛和不区分大小写分组；同词同译折叠，同词多译整组跳过，原文与译文相同的保留词仍可写入。
  - 写入前通过现有术语管理器检查全部来源，保持人工、导入和既有动态术语不变；检测到动态库已有 `existing_text` 时不重复调用文本抽取。
- `src/transbridge/ai_translator/noun_extractor.py`（修改）
  - 对模型返回结果执行运行时门禁：原文子段和译文子段必须同时连续、原样出现在同一个输入对中。
  - 对相同术语对去重；提示词构建、LLM 调用或响应解析失败时安全返回空结果。
  - 使用当前规范 `TermEntry` 模型，保持抽取结果与动态术语库格式一致。
- `src/transbridge/ai_translator/prompt_builder.py`（修改，本记录仅归属内置术语抽取提示词）
  - 内置 fallback 明确要求从同一双语对提取连续原样子段，不改写大小写、词形或标点；运行时校验不依赖用户自定义提示词是否包含该要求。
- `tests/ai_translator/test_existing_term_extractor.py`、`tests/ai_translator/test_noun_extractor.py`（新增）
  - 覆盖名称整条提取、普通文本子段提取、隐藏/存疑排除、已有术语保护、同词多译跳过、保留词、重复运行，以及跨双语对错配和 LLM 失败降级。

## 兼容性与遗留项

- 不引入翻译记忆、整句复用、置信度、候选晋级或人工审批流程，也不改变术语来源优先级、匹配算法和向量召回。
- 文本抽取首次初始化可能增加 LLM 调用；动态库出现 `existing_text` 后，后续运行会跳过这一路抽取，名称字段仍可低成本补齐。
- 同词多译采用保守的整组跳过；首版不按 context 保存多个译法，以避免扫描顺序造成错误覆盖。
- 仓库级 `ruff check src tests` 和 `ruff format --check src tests` 已尝试，但被本次范围外的既有 lint 问题和 142 个待格式化文件阻断；本次目标文件门禁均已通过。
- 工作区还存在术语格式、AI 工作流、报表等并行改动；本记录不把这些差异归入本 Story。
