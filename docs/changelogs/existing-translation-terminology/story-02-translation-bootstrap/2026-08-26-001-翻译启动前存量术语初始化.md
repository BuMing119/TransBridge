# 翻译启动前存量术语初始化

- **日期**：2026-08-26
- **Epic**：`existing-translation-terminology`
- **Story**：Story 2：翻译启动前自动初始化
- **关联计划**：`plans/existing-translation-terminology/plan.md`
- **状态**：实现完成，相关 QA 通过

## 目的

在项目同时含有可靠存量译文和待翻译条目时，把存量术语初始化接入现有自动翻译启动流程，使新增术语在同一次运行的首个翻译批次前即可参与既有精确匹配与术语召回。

## 真实变更

- `src/transbridge/ai_translator/translator.py`（修改，本记录仅归属存量术语初始化接线）
  - 术语来源加载完成后，检查当前集合是否同时存在可用存量译文和未翻译候选；只在启用术语检索且属于部分翻译项目时启动初始化。
  - 初始化发生在翻译批次执行前，因此新增的 `existing_name` / `existing_text` 术语本次运行立即可用，不需要重启任务。
  - 新增术语计入 `TranslationResult.new_dynamic_terms`，日志分别报告名称、文本、冲突和已有术语跳过数量。
  - 初始化异常只记录可定位警告并继续使用原有术语库，不改变全新项目、无候选项目或抽取无结果时的翻译行为。
- `tests/ai_translator/test_existing_term_extractor.py`（新增，本记录归属启动流程用例）
  - 覆盖“有存量译文且有未翻译候选”判定，以及存量名称术语在同一次 `AutoTranslator` 运行中完成精确直填。
- `plans/existing-translation-terminology/plan.md`（新增）
  - 固化仅处理术语的目标与非目标、两个 Story、验收标准、失败降级、重复运行和回退边界，并回写 2/2 完成及 QA 证据。
- `plans/INDEX.md`（修改，本记录仅归属本 Epic 行）
  - 增加 `existing-translation-terminology` 的完成状态、Story 数和计划入口。

## 当前流程

1. 加载现有人工、导入、动态等术语来源。
2. 判断是否为“已有可靠译文 + 仍有待翻译候选”的部分翻译项目。
3. 从存量译文执行名称整条提取和普通文本子段提取，并安全合并到动态术语库。
4. 使用更新后的同一个术语管理器进入既有精确直填、逐条术语匹配和翻译批次流程。
5. 汇总本次新增术语和冲突/跳过计数；初始化失败时退回原有术语库继续翻译。
