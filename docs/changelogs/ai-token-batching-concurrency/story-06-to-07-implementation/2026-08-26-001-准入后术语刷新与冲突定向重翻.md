## 变更

### LLM 准入与逐调用日志

- `src/transbridge/infra/limited_llm_client.py`
  - 新增 `chat_prepared` 与 `chat_stream_prepared`，在取得共享请求额度后才调用消息工厂。
  - 旧 `chat` / `chat_stream` 复用同一准入路径；消息构建、Provider、流回调和取消异常均通过 lease 上下文释放额度。
- `src/transbridge/ui/tools/ai_translator/workflow_logging_client.py`
  - 延迟请求在提交时保留稳定 Call ID，在实际准入并完成 Prompt 后记录最终请求。
  - Provider 异常写入异常类型、消息及可取得的 HTTP 状态、错误码、响应体、request id；请求与错误字段统一脱敏。
  - 成功但空白的响应写入显式 `[EMPTY RESPONSE]`，所有路径写入预算指标和 `[END CALL]`。
- `src/transbridge/ui/tools/ai_translator/workflow_log_store.py`、`run_controller.py`、`_translation_worker.py`、`_batch_translation_worker.py`
  - 独立翻译和批量翻译接入与混合/润色相同的逐调用日志包装。
  - 批量模式可将调用日志直接写入现有插件日志目录，现有日志查看器无需递归即可显示。

### 权威术语冲突修复

- `src/transbridge/ai_translator/existing_term_extractor.py`
  - 直接名称和文本抽取候选保留来源 `EntryKey`，返回冻结的 `TermConflictEvidence`。
  - 区分候选内部冲突与有效术语库冲突；同译法只计为已有，不写入冲突候选。
- `src/transbridge/ai_translator/term_database.py`
  - 增加 `resolve_term` 窄接口，仅解析主术语；NFKC、空白与 casefold 规则和正式精确匹配一致。
  - 大小写或 Unicode 形式不同的同名来源使用 last-wins 选择，保持来源优先级的权威结果。
- `src/transbridge/ai_translator/translator.py`
  - 在术语初始化完全结束后，仅把 `effective_library` 冲突按完整 `EntryKey` 聚合为单条修复任务。
  - 修复任务从普通候选中去重、逐条执行 Token 预检，并与所有翻译/术语请求共享同一运行并发额度。
  - 请求顺序固定为“等待并发槽 → 读取最新术语 → 构建 Prompt → 请求模型”；必选术语在准入后重新解析并最后覆盖普通召回结果。
  - 修复响应禁止流式提前接受，需通过权威译法、Unicode/空白和异常重复检查；失败保留原译文且不递归入队，成功也不反向写入动态术语。
  - 修复队列及完成 EntryKey 写入翻译断点，避免存量文本抽取完成标记导致恢复时丢失任务；权威值变化会更新候选指纹并使旧完成项失效。
