# 业务内容 Token 分批与共享请求并发实现

- 日期：2026-08-26
- Epic：`ai-token-batching-concurrency`
- Story：Story 1–5「Token 计数与分批、运行级请求预算、翻译/术语迁移、校改入口迁移、配置与可观测性」
- 需求：FR5.11.4、FR5.13.9

## 背景

旧实现把并发数参与到批次大小和批次数计算，导致提高并发会改变单请求内容规模；术语初始化固定 20 条串行抽取，混合并行的翻译与校改分支还可能各自达到 `max_concurrent`。本次按用户确认语义拆开两个参数：`max_concurrent` 只限制一次运行内同时在途的 LLM 请求总数，`max_tokens_per_batch` 只限制单请求业务内容 Token，二者不再互相改变。

## 变更

### 通用 Token 分批与请求预算

- **[新增]** `src/transbridge/application/translation/token_batching.py`
  - 定义 `ContentTokenCounter`、稳定贪心分批、批次指纹和单条超限诊断；保持输入顺序与 `EntryKey` 身份。
- **[新增]** `src/transbridge/infra/token_counting.py`
  - 已知模型使用对应 tiktoken 编码；未知兼容模型使用离线、确定且带安全系数的 UTF-8 保守估算并标记 estimate。
- **[新增]** `src/transbridge/application/translation/ai_request_budget.py`
  - 提供运行级 lease、等待/在途/峰值快照，以及暂停、取消和超时感知的准入控制。
- **[新增]** `src/transbridge/infra/limited_llm_client.py`
  - 在完整 `chat`/`chat_stream` 调用边界获取并可靠释放共享 lease；异常、流式回调失败和取消均不泄漏槽位，并记录本次准入等待指标。
- **[修改]** `src/transbridge/application/translation/__init__.py`
  - 导出运行内 LLM 后处理适配器，供正式翻译后处理链复用受限客户端。

### 正式翻译与术语抽取

- **[修改]** `src/transbridge/ai_translator/batch_planner.py`
  - 以原文业务 Token 替代字符估算与并发驱动拆批；保留 Round、分类和 quest 屏障，`max_workers` 仅保留兼容入口且不影响批次边界。
- **[修改]** `src/transbridge/ai_translator/translator.py`
  - 正式翻译和术语客户端复用同一 `AiRequestBudget`；移除填满线程池的尾批拆分；Round 2 固定为 quest 间并发、同 quest 内串行。
  - 对话翻译完成后的动态术语抽取按“原文＋译文”重新 Token 分批，超限项在请求前跳过并写入诊断日志。
  - 内部质量检测、修复、润色和裁决改走当前运行的受限 LLM 客户端，禁止绕过共享并发。
- **[修改]** `src/transbridge/ai_translator/existing_term_extractor.py`
  - 存量译文术语抽取按“原文＋已有译文”Token 分批并采用有界并发；批次可乱序完成，但结果按原批次索引稳定合并。
  - 首错后停止补交、取消待运行任务、等待在途任务退出，并丢弃不完整的文本术语结果。

### 校改阶段与全部运行入口

- **[修改]** `src/transbridge/ai_translator/post_processor/post_processor.py`
  - QualityGate、Refiner、Polisher、Arbiter 按各自实际业务字段 Token 分批；原 `pp_*_batch_size` 继续作为附加条目数上限。
- **[修改]** `src/transbridge/ai_translator/post_processor/proofread_pipeline.py`
  - 接收模型、Token 上限和可注入计数器，并把统一分批配置交给后处理器。
- **[修改]** `src/transbridge/application/translation/postprocess_stages.py`
  - 增加通过既有 LLM 客户端执行的后处理端口；LLM 阶段支持 Token 与条目数双上限。
  - QualityGate 在调用前检查“原文＋候选译文＋上下文”，单条超限生成 `POSTPROCESS_CONTENT_TOKEN_LIMIT`，不发送请求。
- **[修改]** `src/transbridge/ui/tools/ai_translator/run_controller.py`
  - 从冻结后的 `max_concurrent` 为每次运行创建唯一预算，并通过 `TranslationRunRequest` 传递；无效值在运行开始前明确拒绝。
- **[修改]** `src/transbridge/ui/tools/ai_translator/_mixed_worker.py`
  - 翻译、术语抽取与校改分支共享父运行预算；校改客户端采用 `raw → Limited → WorkflowLogging` 包装顺序。
- **[修改]** `src/transbridge/ui/tools/ai_translator/polish_runtime.py`、`ai_translator_window.py`
  - 独立润色复用请求中的共享预算，并将模型和 Token 上限传给校改流水线。
- **[修改]** `src/transbridge/ui/tools/ai_translator/_batch_translation_worker.py`、`batch_runtime.py`
  - 一个批量运行内的所有插件复用同一预算，插件顺序和共享动态术语行为保持不变。
