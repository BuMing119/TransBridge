# 001: Story-08 安全护栏中间件编码实现

**日期**: 2026-05-10
**类型**: 增/改
**关联**: Epic: Agent框架升级 > Story 08: 安全护栏中间件

## 修改文件

### `src/transbridge/smart_assistant/guardrails/base.py` (增)
- **修改内容**: GuardMiddleware ABC（before_execute/after_execute 两个钩子）+ GuardResult 数据类（allowed/reason/modified_args/modified_result）。中间件链的标准接口契约，before/after 双阶段形成洋葱模型。
- **原因**: FR7.13.8 安全护栏的抽象基类。复用 ADR-009 RetryHandler 注入范式，允许任意数量的 Guard 实现以中间件链形式插入工具执行路径。

### `src/transbridge/smart_assistant/guardrails/permission.py` (增)
- **修改内容**: PermissionGuard（read 放行/write 可配置确认/admin 弹窗确认）。从 ToolSpec.permission 读取权限级别，admin 触发 step_requires_confirmation 信号等待用户确认（后台线程轮询 QEventLoop 模式，300s 超时）。
- **原因**: FR7.13.8.1 工具调用权限分级。admin 操作（写回 ESP/EET/XT）需用户显式确认防止误操作。

### `src/transbridge/smart_assistant/guardrails/input_validator.py` (增)
- **修改内容**: InputValidationGuard——类型校验 args 必须为 dict + 字符串长度 ≤ 100KB + 注入模式检测（正则 6 组：SQL 注入/XSS/事件注入/命令注入/管道注入/反引号注入）。递归遍历嵌套 dict/list 校验所有字符串值。
- **原因**: FR7.13.8.3 输入校验。防止恶意内容通过 LLM 生成的工具参数注入到系统中。

### `src/transbridge/smart_assistant/guardrails/output_validator.py` (增)
- **修改内容**: OutputValidationGuard——类型校验/message 截断 10KB/data 大小限制 100KB/敏感信息脱敏（3 组正则：OpenAI sk-/Anthropic sk-ant-/Bearer Token）。脱敏后替换为 ***REDACTED***。递归处理嵌套 dict。
- **原因**: FR7.13.8.4 输出校验。防止工具返回异常大数据撑爆 LLM 上下文窗口（>100KB），同时防止 API key 泄露到对话中。

### `src/transbridge/smart_assistant/guardrails/__init__.py` (增)
- **修改内容**: 导出 GuardMiddleware/GuardResult/PermissionGuard/InputValidationGuard/OutputValidationGuard 5 个公开符号。
- **原因**: guardrails/ 子包公开 API。

### `src/transbridge/smart_assistant/tool_registry.py` (改)
- **修改内容**: ToolSpec 新增三个安全字段——permission(str="read")/require_confirmation(bool=False)/max_output_size(int=102400)。v1 工具标注 permission：lookup_terms/check_quality/get_collection_summary→read、translate_entries/export_json→write、write_back→admin。
- **原因**: FR7.13.8.1 每个工具需声明权限级别供 PermissionGuard 拦截。向后兼容：未标注的工具默认 "read"。

### `src/transbridge/smart_assistant/execution_engine.py` (改)
- **修改内容**: ExecutionEngine 新增 step_requires_confirmation 信号 + _middlewares 列表 + provide_decision 方法。_run_single() 注入安全护栏中间件链：before 链（PermissionGuard→InputValidationGuard）→ Reflexion 重试（现有逻辑）→ after 链（OutputValidationGuard）。admin 确认通过后台线程轮询 _pending_decisions + 300s 超时实现。
- **原因**: FR7.13.8 中间件链注入——不改变工具本身实现，通过执行引擎层面的中间件链实现安全护栏。洋葱模型确保输入校验→权限检查→执行→输出校验的完整防护。

### `src/transbridge/config/llm.py` (改)
- **修改内容**: LLMConfig 新增 [guardrails] INI section 支持——guardrails_enable_admin_confirm(bool=True)/guardrails_enable_input_validation(bool=True)/guardrails_enable_output_validation(bool=True)/guardrails_max_input_size(int=102400)/guardrails_write_require_confirm(bool=False)。save_to_file()/load_from_file() 追加对应读写逻辑。
- **原因**: S08 步骤6 护栏配置持久化。用户可通过 INI 文件或 UI 调整护栏行为。

### `src/transbridge/ui/tools/smart_assistant/chat_widget.py` (改)
- **修改内容**: `_on_plan_confirmed` 中从 LLMConfig 读取 guardrails 配置构建中间件链（InputValidationGuard→PermissionGuard→OutputValidationGuard），传递给 ExecutionEngine。连接 step_requires_confirmation 信号→`_on_confirm_required`→QMessageBox.question 弹窗。
- **原因**: S08 步骤7 UI 确认交互。admin 工具调用时暂停执行并弹窗询问用户，实现人机协同的安全确认。
