# 001: Story-07 Agent 编排与并行执行编码实现

**日期**: 2026-05-10
**类型**: 增/改
**关联**: Epic: Agent框架升级 > Story 07: Agent 编排与并行执行

## 修改文件

### `src/transbridge/smart_assistant/agents/orchestrator.py` (增)
- **修改内容**: Orchestrator 类（decompose_task LLM分解→Subtask列表/map_to_steps 生成ExecutionEngine step dict + AgentInstance绑定/summarize_results LLM汇总）。Subtask 数据类（task_id/agent_type/action/input_data/depends_on）。LLM prompt 模板内联，解析失败时单任务兜底（orchestrator 自己处理）。
- **原因**: FR7.13.6.2 任务分解与调度。Orchestrator 是 Phase 2 核心调度组件，负责任务编排的全流程——用户请求→子任务分解→Agent分配→结果汇总。

### `src/transbridge/smart_assistant/agents/agent_worker.py` (增)
- **修改内容**: AgentWorker(QThread) 类，信号 progress(str)/finished(StepResult)/error(str)。run() 按 AgentSpec.namespace 从 ToolRegistry 查找工具并执行，工具不存在或权限不足时 emit error。cancel() 设置 _cancelled 标志。
- **原因**: FR7.13.6 多 Agent 并行执行。AgentWorker 遵循 ADR-004 QThread 异步模式，通过 namespace 隔离确保 Agent 只能调用其授权工具。

### `src/transbridge/smart_assistant/execution_engine.py` (改)
- **修改内容**: StepResult 新增 agent_instance_id 字段。ExecutionEngine 在 _run_single() 中支持按 step 的 agent 字段路由到对应 AgentWorker 执行。
- **原因**: FR7.13.6.2 调度集成——执行引擎需感知 Agent 身份以路由工具调用和追溯执行来源。

### `src/transbridge/ui/tools/smart_assistant/chat_widget.py` (改)
- **修改内容**: 输入框上方新增 Agent 状态指示器（QHBoxLayout + 3 个 QLabel），显示 translator/proofreader/orchestrator 状态（○空闲灰色/◉执行蓝色/●完成绿色/✕失败红色）。`_update_agent_indicators()` 方法接收状态字典动态更新。`_on_plan_confirmed` 设置 translator/orchestrator 为执行态；`_on_plan_all_finished` 重置全部为 idle。
- **原因**: FR7.13.6 UI 交互——用户需实时感知各 Agent 运行状态，Agent 状态指示器提供一目了然的并行任务监控。

### `src/transbridge/ui/app.py` (改)
- **修改内容**: main() 函数中 window 创建前调用 `AgentRegistry.init_presets()` 注册 translator/proofreader/orchestrator 三个预置 Agent。
- **原因**: S06 步骤6 预置 Agent 启动注册。Agent 系统在应用启动时初始化，确保智能助手面板可用时 Agent 已就绪。
