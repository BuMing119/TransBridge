## 问题与范围

原版 ESP 与同一内容身份的汉化 ESP 在建项时合并为一份翻译基线，但 Project 保留两条来源登记。移除原版时，旧逻辑只移除原版登记和唯一基线，留下汉化来源登记，触发 `ValueError: an authoritative baseline registration must not be empty`。生命周期把异常包装为 `ACTIVE_CONTENT_CHANGE_FAILED`，工作台只显示通用英文提示，且日志未记录底层异常。

本次仅记录该配对来源移除、重开规则、错误可见性及相应测试的增量。工作区原有的权威保存、建项、ParaTranz、AI 和界面改动不归入本条记录；`source_commands.py` 虽然仍为 Git 未跟踪文件，但本次是在已有实现上修改 `remove_source()`，不是新增整个服务。

## 逐文件变更

- **新增** [application/projects/source_content.py](../../../../src/transbridge/application/projects/source_content.py)：提供 `source_content_identity()`、`folded_plugin_pairs()` 和 `authoritative_baseline_sources()`。从旧格式或规范化来源登记读取内容 namespace；按每个 namespace 识别唯一的原版/汉化插件配对，并检查已有关系是否冲突。旧记录缺少关系时允许用明确角色和共同 namespace 识别；多个候选或显式冲突关系不进行合并判断。文件指纹用于校验版本，不作为内容归属的唯一依据。
- **修改** [application/projects/source_commands.py](../../../../src/transbridge/application/projects/source_commands.py)：`ProjectSourceMutationService.remove_source()` 移除原版时同时移除已合并汉化来源登记、相关关系和诊断，再通过既有 `commit_active_content()` 一次提交 Project、Variant 和基线变更。单独移除已合并的导入登记时保留原版基线和当前译文。基线匹配同时约束已知 namespace 与指纹，防止误匹配其他来源；不确定的剩余依赖返回 `PROJECT_SOURCE_DEPENDENCY_AMBIGUOUS`，残留来源却没有基线时返回 `PROJECT_SOURCE_BASELINE_REQUIRED`，不放宽空基线约束。
- **修改／提取** [persistence/current_project.py](../../../../src/transbridge/persistence/current_project.py)：将旧的 `_authoritative_baseline_sources()` 和 `_legacy_content_identity()` 职责提取到上述 application 模块，删除原位置的重复实现。`CurrentProjectOpener.prepare_path()` 使用共享规则并传入来源关系；工程加入其他独立插件后，既有汉化导入记录仍不会成为重复基线。
- **修改** [application/projects/lifecycle.py](../../../../src/transbridge/application/projects/lifecycle.py)：`_from_exception()` 在包装非 `DomainError` 异常前记录错误码和原始异常堆栈，保留定位底层失败的证据。该既有大模块仅作局部日志补充，配对规则放在独立模块中。
- **修改** [ui/workbench/widget.py](../../../../src/transbridge/ui/workbench/widget.py)：`_on_remove_slot()` 在权威工程模式下明确提示会移除工程内内容、译文状态及已合并汉化来源登记，不删除磁盘源文件；说明保存后重开不会恢复内容，重新导入文件不能保证恢复工程内编辑。`ACTIVE_CONTENT_CHANGE_FAILED` 显示中文提示和日志检查方向；确认取消或命令失败时不删除工作台 slot。旧工作台模式保留原有移除语义。
- **新增** [tests/application/projects/test_source_removal.py](../../../../tests/application/projects/test_source_removal.py)：使用真实生命周期服务覆盖规范化及旧格式登记、主源与附属导入分别移除、相同指纹下的来源隔离、独立迁移来源保留、歧义拒绝、多 Variant 保护、错误 Variant 上下文，以及基线发布失败时状态不变和异常日志。
- **修改** [tests/persistence/v2/test_project_provisioning.py](../../../../tests/persistence/v2/test_project_provisioning.py)：已有恢复规则测试改为调用共享函数；增加多个独立原版存在时的配对恢复及冲突关系检查。将原有插件合并测试扩展为主源/导入来源两种移除路径，验证保存、关闭服务、重新打开后的内容，以及两个 ESP 文件字节保持不变。
- **修改** [tests/ui/test_workbench_slices.py](../../../../tests/ui/test_workbench_slices.py)：新增确认/取消与提交成功/失败的四种组合测试，验证移除范围提示、失败中文提示，以及仅在确认并提交成功后移除视图内容。

## 用户可见行为

- 移除一份已合并的插件翻译内容时，对应原版和汉化版的工程登记一并移除，保存后重开不会重新出现。
- 单独移除附属汉化导入记录不会撤销已经合并或编辑的译文。
- 其他独立插件不受影响，磁盘上的原版和汉化版 ESP 文件不被删除。
- 取消、冲突或提交失败时保留原状态；需要排查内部错误时可以从日志取得原始异常。
