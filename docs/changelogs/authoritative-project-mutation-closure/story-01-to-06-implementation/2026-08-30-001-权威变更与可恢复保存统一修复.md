# 权威变更与可恢复保存统一修复

- **日期**：2026-08-30
- **Epic**：`authoritative-project-mutation-closure`
- **Story**：S01～S06（权威变更、可恢复保存、来源生命周期、Adapter 迁移、autosave 与回归门禁）
- **关联需求**：[FR19.9～FR19.13](../../../requirements.md)
- **关联架构**：[ADR-035](../../../adr/035-authoritative-project-mutations-and-recoverable-save.md)
- **关联计划**：[authoritative-project-mutation-closure plan](../../../../plans/authoritative-project-mutation-closure/plan.md)

## 目的

修复“删除旧翻译、添加新插件、导入新译文并手动保存后，重启软件又恢复旧状态”的系统性根因。原实现中部分入口只修改 `TranslationEntryCollection`/slot 投影，`save_active()` 看到权威 Project/Variant 仍为 clean 后会成功 no-op；多来源重开时又只恢复一个来源，因而界面上的修改无法持久化。

本增量将来源增删、译文/标签/外部引用修改、AI、词典、Smart Assistant 和 ParaTranz 合并收口到活动 Project/Variant 命令，并为 Project+Variant 保存加入双 revision/digest CAS、持久化 journal 及启动恢复。

### S01：活动 Project/Variant 权威命令

- **新增** `src/transbridge/application/projects/variant_commands.py`：`EntryStatePatch`、`update_entry_by_key()`、`replace_labels()`、`patch_entry_states()` 与 `patch_entry_records()` 纯构建器按完整 `EntryKey` 更新译文、stage、标签和 `external_refs`，不原地修改投影。
- **修改** `src/transbridge/application/projects/lifecycle.py`：`commit_active_variant()`、`commit_active_content()` 和 Project metadata 提交在生命周期锁内校验 Project/Variant identity 及 expected revision，完整构建候选聚合后一次切换 active。

### S02：双 revision CAS 与崩溃可恢复保存

- **新增** `src/transbridge/persistence/v2/project_save_journal.py`：`ProjectSaveProtocol` 在正式写入前同时预检 Project/Variant revision，保存精确 preimage bytes、target digest/revision 和 manifest digest；中断后只在实体仍匹配 preimage/target 时完成或回滚，遇到较新/同 revision 不同 digest 则 fail-closed。
- **修改** `src/transbridge/persistence/v2/repository.py`：`JsonRepository` 保留已读原始字节及 SHA-256；`ProjectRepository.save_if_revision()` 与 `VariantRepository.save_if_revision()` 统一 revision+digest conditional save 语义。
- **修改** `src/transbridge/persistence/v2/lifecycle_transactions.py`：`ProjectLifecycleTransactionStore` 使用 `ProjectSaveProtocol`，启动和每次事务前恢复 pending journal；journal 未清理时阻止所有正式变更。
- **修改** `src/transbridge/persistence/v2/atomic_documents.py`、`filesystem.py`：添加 staging 复读、持久 replace/remove 及目录 fsync 能力；Windows 使用 write-through 替换语义，POSIX 持久化父目录。
- **修改** `src/transbridge/persistence/v2/schema.py`、`variant.py`：把 entry `external_refs` 纳入 Variant schema、DTO 与 snapshot 收集，使 ParaTranz 外部身份可持久化。
- **修改** `src/transbridge/persistence/v2/baselines.py`：`BaselineRegistry` 提供 snapshot/replace/restore 边界，供 Project/Variant/source 联合提交失败时完整回滚。
- **修改** `src/transbridge/bootstrap/persistence.py`：组合 `ProjectSaveProtocol`、projection consistency guard 和 source mutation service，不再依赖 UI 反向构造持久化内容。

### S03：来源增删、初始导入与全来源恢复

- **修改** `src/transbridge/application/projects/provisioning.py`、`src/transbridge/persistence/project_provisioning.py`：保留所有已准备 source hydration，并把输入格式/命名空间与初始 entry states 交给权威建项/增源流程。
- **修改** `src/transbridge/persistence/current_project.py`：`PreparedCurrentProject`/`CurrentProjectOpener` 为全部已登记来源读取 baseline 和 hydration，某一来源不可读时整体失败，不返回半恢复状态。
- **新增** `src/transbridge/ui/source_hydration.py`：`collection_from_hydration()`、`slot_from_hydration()` 和 `apply_variant_projection()` 按完整 `EntryKey` 将权威 Variant 状态投影到每个来源的独立 slot。
- **修改** `src/transbridge/ui/coordinators/parse_coordinator.py`：插件解析和已有译文导入使用 add-source/精确 EntryKey 命令，命令失败时不发布新 slot。
- **修改** `src/transbridge/ui/coordinators/project_coordinator.py`、`src/transbridge/ui/workbench/widget.py`：打开/激活工程时一次恢复全部 slot；移除来源先提交权威命令，再更新工作台投影。
- **修改** `src/transbridge/ui/workbench/step2.py`、`cards/download_card.py`：使用 source locator/namespace 与权威移除边界，不再仅删除可见 collection。

## 用户可见结果

- 删除旧翻译来源、加入新插件、导入新译文后，手动保存实际持久化 Project source registry 和 Variant 内容；重启后恢复的是新状态。
- 工作台、词典、AI、Smart Assistant 和 ParaTranz 的成功操作会增长权威 revision 并正确显示 dirty；冲突、取消或迟到结果不会留下“看得到但保存不了”的内容。
- 保存只有在权威 revision 已落盘时才显示 clean；发布中断可由 journal 恢复，较新外部写入不会被自动降级覆盖。

## 兼容、迁移与遗留项

- `GuiProjectCommandFacade` 现有公开 API 保留；短调用方可在 facade 调用时捕获 revision，长时间/后台任务必须显式传入 expected identity/revision。
- Variant JSON 只增加已定义的 `external_refs` 持久化数据；journal 属于持久化协议文件，不改变 Project/Variant 业务 schema major version。
- ParaTranz 对未知远程条目的本地 create/delete，以及 source-owned original/context 更改仍缺少可靠的 source/baseline 语义；当前明确拒绝，不静默降级。
- 多 Variant 来源删除/同身份换源暂无跨全部 Variant 的物化事务，当前返回 `PROJECT_SOURCE_MULTI_VARIANT_MIGRATION_REQUIRED`。
- 尚未增加多个独立 OS 进程同时写同一 persistence root 的跨进程文件锁；本次完成的是桌面应用单进程内 revision+digest CAS、durable journal 和崩溃恢复。
- `docs/requirements.md` 中 FR19.9～FR19.13 当前标记仍是“草稿（统一修复实施中）”，与已完成的 plan 状态存在文档状态差异；本次 chronicle 不重写需求正文。
- 未使用真实 ParaTranz Token/项目执行联机写入，未执行打包后 GUI 人工重启实物复验。
