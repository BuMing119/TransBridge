# Story 01～04：一次校对润色与自定义工作流实现

- **日期**：2026-08-27
- **Epic**：`ai-compact-proofread-custom-profiles`
- **状态**：已完成
- **关联需求**：FR5.13.10、FR6.9
- **关联架构**：ADR-028

## 本次增量

### 一次校对润色

- 新增共享 `CombinedProofreadStage`，按业务内容 Token 预算合批，并在取得共享并发槽后读取最新术语、构建 Prompt 和请求模型。
- 同一次请求完成对照原文纠错、术语一致和表达优化；响应只包含稳定条目键与最终译文，不再默认索要修改原因、模型置信度或裁决结果。
- 本地只检查响应结构、条目一一对应、非空译文和程序占位符/标签完整性。数字、人名、否定、引号、长度、改动比例和普通术语字符串不参与本地语义拒绝。
- 无效条目保留原译文并记录诊断；其他有效条目可独立进入既有候选和单一提交边界，不追加第二次 LLM 裁决。

### 策略与兼容

- 执行档案增加显式 `combined` / `strict` 策略；新建翻译、润色和混合预设默认使用一次校对润色。
- 旧保存配置缺少策略字段时按严格链迁移，继续保留独立检测、修复、润色和裁决能力。
- 严格链的输出 Token 上限统一服从配置：`0` 和正数均原样传给所有 LLM 阶段，未提供字段时保留旧构造默认值。OpenAI 兼容供应商对 `0` 省略参数；Anthropic 因 API 必填而要求显式正数，不再偷偷回退到 8192。
- 运行摘要、digest、进度和报告只展示实际执行阶段。

### 具名自定义工作流

- AI 翻译窗口增加第四个「自定义」入口，支持多个具名配置的新建、选择、重命名、删除、导入和导出。
- 自定义配置明确复用翻译、润色或混合基础模式的作用域、预检、Worker、报告和提交边界，没有新增第四套执行引擎。
- 使用版本化 JSON 白名单和原子导入；供应商、模型、Base URL、API Key、凭据引用与本地术语路径不进入导出文件。
- 自定义 overlay 与三个内置预设隔离；没有可用配置时禁用启动并提示原因。

### 通用入口与可观测性

- GUI 翻译后处理、独立/混合润色以及 Smart Assistant 默认校改复用同一 combined/strict 执行语义和共享请求预算。
- Smart Assistant 默认将多条短文本按 Token 合批，API 异常写入对应工作流日志并保留原译文；高级诊断工具仍保留显式多阶段合同。
- LLM 日志窗口改为手动刷新文件列表，只有选择日志后才加载单个文件，避免日志增多时一次性扫描和渲染全部内容阻塞 Qt 主线程。
- 暂停、停止和 Worker 生命周期沿用统一事件与控制器边界，运行面板按实际阶段显示「校对润色」。

## 兼容与回退

- 已保存且没有策略字段的旧配置按 `strict` 解释，不静默改变其原有多阶段语义。
- 用户可在高级配置中显式切换严格策略作为即时回退。
- 自定义配置导入失败时保持原配置库不变；combined 响应技术校验失败时保持对应原译文不变。
- 内部自定义配置文件损坏或版本过新时降级为空自定义状态并保留诊断，三个内置入口仍可打开；非空配置库缺少选中项时原子选择首项。
