# 008: FR7.13 Phase 2 全部 7 Story 编码实现

## 修改文件

### `src/transbridge/smart_assistant/agents/agent_spec.py` (增)
- **修改内容**: AgentSpec 数据类（agent_id/name/role/namespace/tools/skills/system_prompt/enabled）+ AgentInstance 数据类（instance_id uuid4.hex/agent_spec/project_path/ctx）。AgentInstance.ctx 类型标注为 object 避免循环导入。
- **原因**: FR7.13.6 多 Agent 协作的数据模型基础。AgentSpec 描述 Agent 的静态定义，AgentInstance 绑定运行时项目上下文，支持同类型多实例并行（多项目翻译）。

### `src/transbridge/smart_assistant/agents/agent_registry.py` (增)
- **修改内容**: AgentRegistry 类级别单例（register/get/list_all/list_enabled/enable/disable/init_presets）。init_presets() 注册 translator（namespace="translator"）、proofreader（namespace="proofreader"）、orchestrator（namespace=None 全工具可见）三个预置 Agent。
- **原因**: FR7.13.6 多 Agent 运行时的注册与查询基础设施。类级别单例保持与 ToolRegistry 一致的设计模式。

### `src/transbridge/smart_assistant/agents/orchestrator.py` (增)
- **修改内容**: Orchestrator 类（decompose_task LLM分解→Subtask列表/map_to_steps 生成ExecutionEngine step dict + AgentInstance绑定/summarize_results LLM汇总）。Subtask 数据类（task_id/agent_type/action/input_data/depends_on）。LLM prompt 模板内联，解析失败时单任务兜底（orchestrator 自己处理）。
- **原因**: FR7.13.6.2 任务分解与调度。Orchestrator 是 Phase 2 核心调度组件，负责任务编排的全流程。

### `src/transbridge/smart_assistant/agents/agent_worker.py` (增)
- **修改内容**: AgentWorker(QThread) 类，信号 progress(str)/finished(StepResult)/error(str)。run() 按 AgentSpec.namespace 从 ToolRegistry 查找工具并执行，工具不存在或权限不足时 emit error。cancel() 设置 _cancelled 标志。
- **原因**: FR7.13.6 多 Agent 并行执行。AgentWorker 遵循 ADR-004 QThread 异步模式，通过 namespace 隔离确保 Agent 只能调用其授权工具。

### `src/transbridge/smart_assistant/agents/__init__.py` (增)
- **修改内容**: 导出 AgentSpec/AgentInstance/AgentRegistry/Orchestrator/AgentWorker 5 个公开符号。
- **原因**: agents/ 子包公开 API。

### `src/transbridge/smart_assistant/guardrails/base.py` (增)
- **修改内容**: GuardMiddleware ABC（before_execute/after_execute）+ GuardResult 数据类（allowed/reason/modified_args/modified_result）。中间件链的标准接口契约。
- **原因**: FR7.13.8 安全护栏的抽象基类。复用 ADR-009 RetryHandler 注入范式，before/after 双阶段形成洋葱模型。

### `src/transbridge/smart_assistant/guardrails/permission.py` (增)
- **修改内容**: PermissionGuard（read 放行/write 可配置确认/admin 弹窗确认）。从 ToolSpec.permission 读取权限级别，admin 触发 step_requires_confirmation 信号等待用户确认（后台线程轮询 QEventLoop 模式，300s 超时）。
- **原因**: FR7.13.8.1 工具调用权限分级。admin 操作（写回 ESP/EET）需要用户显式确认防止误操作。

### `src/transbridge/smart_assistant/guardrails/input_validator.py` (增)
- **修改内容**: InputValidationGuard（类型校验 args 必须为 dict + 字符串长度 ≤ 100KB + 注入模式检测正则 6 组：SQL 注入/XSS/事件注入/命令注入/管道注入/反引号注入）。递归遍历嵌套 dict/list 校验所有字符串值。
- **原因**: FR7.13.8.3 输入校验。防止恶意内容通过工具参数注入（如通过 LLM 生成 SQL/命令注入到工具调用中）。

### `src/transbridge/smart_assistant/guardrails/output_validator.py` (增)
- **修改内容**: OutputValidationGuard（类型校验/message 截断 10KB/data 大小限制 100KB/敏感信息脱敏 3 组正则：OpenAI sk-/Anthropic sk-ant-/Bearer Token）。脱敏后替换为 ***REDACTED***。递归处理嵌套 dict。
- **原因**: FR7.13.8.4 输出校验。防止工具返回的异常大数据撑爆 LLM 上下文窗口（>100KB），同时防止 API key 等敏感信息泄露到对话中。

### `src/transbridge/smart_assistant/guardrails/__init__.py` (增)

### `src/transbridge/smart_assistant/graph_types.py` (增)

- **原因**: FR7.13.7 Graph 编排的类型系统。自研轻量方案，零外部依赖。

### `src/transbridge/smart_assistant/observability/collector.py` (增)

### `src/transbridge/smart_assistant/tool_registry.py` (改)
- **修改内容**: 三处关键变更：
  1. ToolSpec 新增 permission(str="read")/require_confirmation(bool=False)/max_output_size(int=102400) 三个安全字段
  2. _ToolRegistry 内部存储从 _tools dict 迁移到 _namespaced_tools dict（{"namespace": {"tool_name": ToolSpec}}）。register() 新增 namespace 参数（默认"default"）。get() 新增 namespace 参数（None=搜索全部namespace 编排Agent特权）。新增 list_namespace()/list_all_namespaces() 方法。build_tool_schema_for_prompt() 新增 namespace 参数。list_all() 改为跨 namespace 去重返回
  3. v1 工具分配 namespace 和 permission：lookup_terms/translate_entries→translator, check_quality→proofreader, get_collection_summary/export_json/write_back→default；permission: 3个read/2个write/1个admin
- **原因**: FR7.13.6 ToolRegistry namespace 扩展实现工具按 Agent 隔离 + FR7.13.8 ToolSpec 安全字段支持权限分级。现有调用方完全向后兼容（register/get/list_all 不传 namespace 时行为不变）。

### `src/transbridge/smart_assistant/execution_engine.py` (改)
- **修改内容**: 五处架构性变更：
  1. StepResult 新增 agent_instance_id 字段（追溯 Agent 执行来源）
  2. ExecutionEngine 新增 step_requires_confirmation 信号 + _middlewares 列表 + provide_decision 方法
  3. _run_single() 注入安全护栏中间件链：before 链（PermissionGuard→InputValidationGuard）→ Reflexion 重试（现有逻辑）→ after 链（OutputValidationGuard 逆序）。admin 确认通过后台线程轮询 _pending_decisions + 300s 超时实现
  4. 新增 execute_graph() 图执行方法（BFS 层级遍历 + 4 种 Node 类型 dispatch + 条件表达式受限 eval + Checkpoint 自动保存/恢复 + HumanConfirmNode HITL 暂停+超时兜底）
  5. execute() 向后兼容适配：内部将 steps 转为线性 GraphSpec 委托给 execute_graph()。新增 pause()/resume() 方法 + _eval_condition 安全条件求值 + _safe_serialize 递归类型校验
- **原因**: 整个 Phase 2 的执行层核心变更。中间件链复用 RetryHandler 注入模式（ADR-009），Graph 引擎自研（ADR-011），人机协同通过信号+轮询实现（QEventLoop 替代方案）。向后兼容保证现有 ChatWidget 和 PlanCard 调用方式不变。
