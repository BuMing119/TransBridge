# 006: FR7.13 Phase 2 需求展开与架构决策

**日期**: 2026-05-10
**类型**: 增/改
**关联**: Epic: Agent框架升级 > Phase 2 需求分析 + 架构设计

## 修改文件

### `docs/requirements.md` (改)
- **修改内容**: FR7.13 Phase 2 从 5 行简述展开为 22 个详细子需求条目。分三批：
  P0（多Agent协作 6子需求 + 安全护栏 6子需求）、P1（Graph编排 6子需求 + 可观测性 5子需求）、P2（MCP Server 5子需求）。
  FR7.13.7 移除"(LangGraph 模式)"措辞改为功能性描述。新增 Phase 2 专属异常场景 7 条。
  Phase 1 状态更新为"已实现（QA通过）"。需求变更历史追加 2 条记录。
- **原因**: Phase 2 原有需求过于简略，无法支撑架构设计和方案策划。经委员会评审确认 Graph 选型为自研方案后同步修正需求措辞。

### `docs/adr/008-smart-assistant-code-layering.md` (改)
- **修改内容**: 追加"### 更新: 2026-05-10 - Phase 2 多 Agent 协作架构"节。新增 agents/ 子包（agent_spec/agent_registry/orchestrator/agent_worker 4文件），定义 AgentSpec/AgentInstance/AgentRegistry 数据模型与接口，扩展 ToolRegistry namespace 机制，预置 translator/proofreader/orchestrator 三个 Agent，定义 AgentWorker QThread 接口契约。
- **原因**: Phase 2 多 Agent 协作需要独立的 Agent 定义与调度层，遵循 ADR-008 既有的「业务逻辑与 UI 分离」原则，在 smart_assistant 下新增 agents/ 子包。

### `docs/adr/011-graph-orchestration-engine.md` (增)
- **修改内容**: 新建 ADR-011，确定自研有状态图编排引擎方案。8 个决策点：技术选型（自研 StatefulDAGExecutor，零新依赖）、GraphExecutor ABC 抽象基类、4 种 Node 类型体系（Action/Condition/Loop/HumanConfirm）、Checkpoint 序列化契约（data 字段协议约束）、向后兼容策略（execute() 保持不动）、Graph 执行流程（BFS+并行+条件路由+循环）、人机协同 QEventLoop 模式、文件变更清单（3文件）。备选方案对比表覆盖 LangGraph/自研/不升级。
- **原因**: Phase 2 需要将 ReAct 循环升级为有状态图编排。经委员会三角色评审（架构师/开发者/产品）一致确认自研方案，拒绝 LangGraph（asyncio/Qt 冲突、30+传递依赖、PyInstaller 打包风险）。

### `docs/adr/012-safety-observability-mcp.md` (增)
- **修改内容**: 新建 ADR-012，覆盖三个正交架构层面。安全护栏：GuardMiddleware ABC + GuardResult 中间件链注入模式，PermissionGuard（read/write/admin 三级），InputValidationGuard（类型+长度+注入检测），OutputValidationGuard（大小截断+敏感信息脱敏），step_requires_confirmation 信号。可观测性：复用 pyqtSignal 管道，ObservabilityCollector + ConversationTrace/ToolCallRecord/TokenStats 数据模型，JSON 存储+30天清理。MCP Server：stdio JSON-RPC 传输，MCPAdapter（ToolSpec→MCP Tool 映射），admin 白名单+write deny 安全约束。
- **原因**: 护栏和可观测性共享 ExecutionEngine 注入模式，MCP 依赖护栏权限体系，三者合并为一个 ADR 降低碎片化。

- **原因**: 索引一致性维护。

### `docs/council-review-*.md` (增)
- **修改内容**: 委员会三角色（架构师/开发者/产品）评审 Graph 编排引擎选型，一致推荐自研轻量方案，拒绝 LangGraph。共识建议：FR7.13.7 移除 LangGraph 措辞、Phase 2 分三批实施、定义 GraphExecutor ABC 预留替换空间。
- **原因**: 用户对 Graph 选型要求多角色分析，委员会意见作为架构决策的输入依据。
