# 001: 工具系统编码实现与 API 修复

**日期**: 2026-05-07
**类型**: 增/改
**关联**: Epic: 智能助手侧边栏 > Story 04: 工具系统

## 修改文件

### `src/transbridge/ui/tools/smart_assistant/tool_registry.py` (增/改)
- **修改内容**: 
  - 新建 `ToolSpec` 数据类（name/display_name/description/parameters/is_long_running/execute 六个字段）
  - 新建 `_ToolRegistry` 类级别单例，提供 `register()`/`get()`/`list_all()`/`build_tool_schema_for_prompt()` 四个类方法
  - 实现 6 个 v1 工具执行函数：`_tool_lookup_terms`（调用 TermDatabaseManager.match_terms_enhanced）、`_tool_translate_entries`（调用 AutoTranslator，is_long_running=True）、`_tool_check_quality`（调用 PostProcessor，仅检测模式关闭修复/润色/裁决）、`_tool_get_collection_summary`（迭代统计已译/未译数）、`_tool_export_json`（调用 collection.to_json_file）、`_tool_write_back`（调用 PluginWriter.apply_collection + write，is_long_running=True）
  - `_tool_translate_entries` 修复：`AutoTranslator(cfg)` 构造不再传入 collection；`translator.translate(collection=collection, target_entry_ids=None, progress_callback=..., stop_event=...)` 正确传入所有必需参数
  - `_tool_check_quality` 修复：PostProcessorConfig 字段名改为 `enable_refinement`/`enable_polish`/`enable_llm_arbitration`（去掉错误的前缀 pp_）；`PostProcessor(cfg)` 构造不再传入 collection；`processor.process(collection)` 正确传入 collection；report 属性用点号访问（dataclass 而非 dict）
  - `_tool_write_back` 修复：`PluginWriter(slot.plugin, strings_lookup=slot.strings_lookup, language=slot.strings_lang)` 使用正确的构造函数签名；先 `apply_collection(collection)` 再 `write(ctx.esp_path)`
  - 模块导入时自动执行 `_register_v1_tools()` 注册全部 6 个工具
- **原因**: Story-04 工具系统实现，ExecutionEngine 通过 ToolRegistry 查找并执行工具；初始实现存在 3 处 API 签名不匹配（AutoTranslator/PostProcessor/PluginWriter 接口理解错误），已修复为正确的调用方式

### `src/transbridge/ui/tools/smart_assistant/prompts.py` (增)
- **修改内容**: 新建 `HYBRID_SYSTEM_PROMPT` 模板（Plan/ReAct 双模式 System Prompt），含 `{context}` 和 `{tools_desc}` 占位符；`build_system_prompt(context)` 函数调用 `ToolRegistry.build_tool_schema_for_prompt()` 填充工具描述
- **原因**: LLM 需要工具描述和模式选择指导才能正确输出 plan/react JSON 格式，工具列表由 ToolRegistry 动态生成保持同步
