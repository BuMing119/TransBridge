# 001: FR7.17 完整开发增量 — 分析→架构→方案→编码

**日期**: 2026-05-14
**类型**: 增/改
**关联**: Epic: llm-chat > Story 10: ToolResult 观察消息序列化增强

## 修改文件

### `src/transbridge/smart_assistant/tools/base.py` (改)
- **修改内容**: `ToolResult` 数据类新增 3 个可选字段 `pagination`（分页）、`execution_meta`（执行元数据）、`tool_suggestions`（后续工具建议）。新增 `to_observation(tool_name, max_chars=2000)` 方法将 ToolResult 序列化为 LLM 可解析的观察文本。新增 `_serialize_data(max_chars)` 私有方法实现大数据智能摘要（列表→count+sample、长字符串截断）。`to_dict()` 和 `get()` 方法增加新字段处理。文件顶部新增 `import json`。
- **原因**: `_handle_result()` 原本只提取 `message` 字符串传给 LLM，`data` 字典中的结构化数据被完全丢弃。新增方法作为 ToolResult → LLM 观察消息的统一序列化入口，遵循已有 `to_dict()` 的设计先例。

### `src/transbridge/ui/tools/smart_assistant/tool_execution_handler.py` (改)
- **修改内容**: 文件顶部新增 `from src.transbridge.smart_assistant.tools.base import ToolResult` 导入。`_handle_result()` 重写：结果归一化为 ToolResult，用户可见状态行保持简洁不变，LLM 观察消息改为调用 `tr.to_observation(tool_name)` 生成富文本。移除 `execute_step()` 和 `_handle_result()` 中的冗余内联导入。
- **原因**: 消除 `data` 丢弃瓶颈，使 LLM 能看到工具返回的结构化数据，同时保持 UI 显示简洁。

### `src/transbridge/smart_assistant/conversation_manager.py` (改)
- **修改内容**: `add_observation()` 的截断逻辑从简单字符截断（`result[:max]`）改为换行感知截断——优先在最后一个换行符处裁剪，避免在多字节字符或 JSON 中间截断。
- **原因**: `to_observation()` 输出为多行格式，换行感知截断确保截断后的内容仍是合法的多行文本，作为 `to_observation()` 内置截断的兜底安全网。

### `src/transbridge/smart_assistant/tools/tool_editor.py` (改)
- **修改内容**: 5 个筛选/搜索工具补充 `data` 参数——`filter_by_stage`（data={"stages": stages}）、`filter_by_category`（data={"categories": categories}）、`filter_by_label`（data={"labels": label_names}）、`search_entries`（data={"query": query, "field": field}）、`clear_all_filters`（data={"filters_cleared": true}）。所有 5 工具新增 `tool_suggestions` 引导 LLM 合理下一步。`get_visible_entries` 新增 `pagination` 字段（page/page_size/total_count/returned_count/has_more）和条件 `tool_suggestions`。
- **原因**: 这 5 个工具之前未填充 `data`，结构化信息仅放在 `message` 字符串中。补充后 LLM 可基于 `data` 中的结构化值进行后续推理。pagination 使 LLM 能判断是否需要翻页获取更多数据。

### `src/transbridge/smart_assistant/tools/tool_translator.py` (改)
- **修改内容**: `stop_task` 工具的成功和失败分支均补充 `data` 参数——成功返回 `data={"task_id": task_id, "stopped": True}`，失败返回 `data={"task_id": task_id, "stopped": False}`。
- **原因**: `task_id` 是程序可消费的结构化值，之前仅放在 `message` 字符串中，补充后下游可确认被停止的具体任务。

### `docs/adr/012-safety-observability-mcp.md` (改)
- **修改内容**: 文末追加 `### 更新: 2026-05-14 - ToolResult 观察消息序列化格式约定` 节。决策 4 项：序列化逻辑归属 ToolResult（非独立类）、扩展字段为正式 dataclass 字段（非 data 约定键名）、三级截断管线（_serialize_data → to_observation → add_observation）、观察消息格式（`key: value` 行结构）。附 3 个备选方案对比。
