# Story 06：AI 翻译完成报表统一与生产链修复

- 所属 Epic：`unified-task-translation-runtime-v2`
- 所属 Story：`story-06-postprocess-report`
- 增量日期：2026-08-25
- 状态：修复完成，定向与相关回归验证通过

## 背景与原因

AI 翻译完成后的生产界面仍混用 legacy `PostProcessResult`、临时统计和独立 Excel 生成路径，与 Story 06 已定义的 canonical `ReportSnapshot` 合同不一致。结果是未启用后处理时也可能读取不存在的旧字段而崩溃，单文件/批量界面、Excel 与历史记录的计数和 `run_id` 可能分叉，且报告渲染仍可能阻塞 Qt 事件循环。

本次修复把“翻译结果汇总、后处理结果、界面展示、JSON/CSV/Excel 导出和历史识别”统一到同一个 `ReportSnapshot`，同时保留旧报告生成器的外部兼容分支。

## 代码增量

### 应用层与翻译运行结果

- `src/transbridge/application/translation/completion_report.py`（新增）：增加 `TranslationCompletionResult`、`TranslationReportEntry` 协议和 `build_translation_report_snapshot()`。该构建器以翻译结果、实际作用域与可选后处理快照合成最终报告，统一稳定 `run_id`、翻译/失败/取消计数、entry before/original/candidate、诊断与运行规格摘要；失败消息进入结构化诊断，不再伪装成译文。
- `src/transbridge/application/translation/__init__.py`：公开 `build_translation_report_snapshot`，让生产翻译工作流从应用层入口构建完成快照。
- `src/transbridge/ai_translator/translator.py`：将 `TranslationResult.post_process_result` 的权威类型改为 `ReportSnapshot`，新增 `report_paths` 与 `report_diagnostics`；空的 `target_entry_ids` 现在表示空作用域而不是全量作用域；后处理只覆盖本次实际翻译输入和 checkpoint 已完成批次，沿用翻译 `run_id`；无论是否启用后处理，结束时都生成 canonical 完成快照。

### 报告渲染与兼容边界

- `src/transbridge/application/translation/postprocess_report.py`：扩充 canonical Excel 投影。`Summary` 写入运行规格，`Entries` 增加 original/before/candidate/stage/accepted/phases/context，新增 `Diagnostics` 与 `Stages` 工作表，并将复杂运行规格安全序列化为单元格值。
- `src/transbridge/ai_translator/post_processor/report_generator.py`：`generate_translate_report()` 收到 `ReportSnapshot` 时委托 canonical `ExcelReportRenderer`；legacy `PostProcessResult` 仍保留原五工作表投影，避免破坏尚未迁移的外部调用方。独立润色报告行为未改变。
- `src/transbridge/ui/tools/ai_translator/reporting.py`（新增）：集中提供 `report_overview()`、`render_translation_report()` 与诊断 entry 映射。每个插件从同一快照派生 JSON、CSV、Excel，按格式保留最近 20 份；渲染失败以可操作诊断返回，不改写翻译业务结果。

### 单文件与批量 UI 生产链

- `src/transbridge/ui/tools/ai_translator/_translation_worker.py`：翻译完成后在线程内生成 canonical 报告产物，把路径与渲染诊断附加到 `TranslationResult`，避免在 Qt 主线程执行文件渲染。
- `src/transbridge/ui/tools/ai_translator/_batch_translation_worker.py`：每个插件完成后在线程内生成同一套报告产物，并使用真实 ESP 文件 stem 命名，避免展示名与历史文件名不一致。
- `src/transbridge/ui/tools/ai_translator/_translation_progress_window.py`：完成页改为消费 snapshot overview 与 worker 已生成的报告路径，移除主线程内二次报告生成和 legacy DTO 字段访问；报告按钮直接打开 canonical 快照对话框。
- `src/transbridge/ui/tools/ai_translator/_batch_translation_progress_window.py`：批量完成统计和插件明细改读 canonical overview/路径，不再自行实例化旧 `ReportGenerator`，并保留每个插件的渲染诊断。
- `src/transbridge/ui/tools/ai_translator/_translation_report_dialog.py`：报告对话框直接展示 `ReportSnapshot` 的 summary、entries 和 diagnostics，翻译前后文本、阶段、接受状态与严重级别均来自同一快照；修正中文问题筛选项与枚举值不匹配导致的筛选失效。
- `src/transbridge/ui/tools/ai_translator/_report_history_dialog.py`：历史扫描使用配置的数据目录，识别 canonical `postprocess-report-<16hex>.xlsx` 文件名，同时保留旧时间戳 Excel 的兼容解析。
- `src/transbridge/ui/tools/ai_translator/_batch_report_summary_dialog.py`：批量汇总的历史目录 fallback 改用配置数据目录，不再依赖进程当前工作目录。
