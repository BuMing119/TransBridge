# 头像后台下载与欢迎页原生崩溃修复

- **日期**：2026-08-24
- **Epic**：`modern-workbench-visual-shell`
- **Story**：S01 后续稳定性修复
- **需求关联**：FR27.1

## 目的

在头像媒体 URL 修复后，应用停留欢迎页时仍可能以 Windows 访问冲突 `0xC0000005`（进程退出代码 `-1073741819`）终止。头像网络请求不应由导航控件持有 Qt 网络对象；用户资料获取、头像下载和客户端释放应在既有后台 `ApiWorker` 中完成，GUI 线程只接收普通字节并生成 pixmap。

本记录补充并取代 [001 记录](2026-08-24-001-用户头像展示下载与媒体URL修复.md) 中关于“NavigationRail 使用 QNetworkAccessManager 下载头像”的早期实现描述；既有日志按 append-only 规则保留，本文件记录当前真实实现。

## 真实变更

### 后台下载与资源所有权

- `src/transbridge/ui/shell/tool_windows.py`（修改）
  - `_fetch_current_user()` 在同一个 `ApiWorker` 调用中创建 `ParatranzUserAPI`、获取用户资料、下载头像字节并在 `finally` 中关闭客户端。
  - 头像下载失败时记录带堆栈的 warning 并返回已获取的用户资料，头像故障不再让登录用户资料整体失败。
  - `ToolWindows.load_current_user()` 继续只在 worker result 回调中更新 `context.current_user`，不在 GUI 控件生命周期内持有网络 reply/session。

- `src/transbridge/paratranz/api/paratranz_user_api.py`（修改）
  - 新增 `with_avatar_payload()`，复用 ParaTranz client 的 requests session 下载头像，并把结果写入复制后的 `_avatar_bytes` 字段。
  - 请求只接受 HTTP/HTTPS 完整 URL，使用 `Accept: image/*`、最多 8 秒超时和显式 redirect；响应与最终 URL 均经过检查。
  - 读取 `response.content`，不再设置 2 MiB 人工大小限制。

- `src/transbridge/ui/shell/navigation_rail.py`（修改）
  - `NavigationRail.set_user()` 只读取 `_avatar_bytes` 并在 GUI 线程生成圆形 pixmap；控件不创建、不持有 `QNetworkAccessManager` 或 `QNetworkReply`。
  - 无字节或图片解码失败时保留昵称首字回退；用户清空时恢复本地模式。

### 回归测试

- `tests/paratranz/test_user_api.py`（新增）
  - 覆盖相对/绝对媒体 URL、资料保存 URL 还原，以及超过 2 MiB 的头像响应仍完整返回。

- `tests/ui/ux/test_current_user_journeys.py`（修改）
  - 验证用户资料与头像下载在同一后台 fetch 调用内完成，客户端最终关闭，并返回 `_avatar_bytes`。

- `tests/ui/test_modern_workbench_visual_shell.py`（修改）
  - 验证导航只消费头像字节、不持有 `_avatar_manager`，并覆盖在线/本地状态、首字回退和圆形居中裁剪。
