# 表头排序与显示顺序隔离

- **日期**：2026-08-31
- **Epic**：`modern-workbench-visual-shell`
- **Story**：S04/S05 后续表格交互与性能增强
- **关联计划**：[现代流体化翻译工作台实施计划](../../../../plans/modern-workbench-visual-shell/plan.md)
- **需求来源**：用户要求点击词条表头排序、支持恢复默认，仅改变前端显示，并保证大列表响应性能。

## 目的与行为

为词条表提供可发现、可恢复的显示排序，同时保留已有筛选、编辑、批量选择、定位和增量渲染合同。

- 无需勾选或全选；点击表头对当前全部筛选结果排序，包括尚未加载的后续批次。
- 同一表头连续点击按“升序 → 降序 → 默认顺序”循环；切换列从升序开始。活动排序显示箭头，恢复默认后隐藏箭头。
- `#` 按默认序号排序，标签按数量排序；Key、原文、译文按完整文本排序，忽略大小写，空译文在升序时靠前；类型/状态先按类型名称，再按 Stage 数值排序。相同排序值保持源顺序。
- 空白选择列表头不参与排序，也不改变当前排序箭头。表头提供排序说明与无障碍描述。
- 排序只生成显示行索引，不修改 `TranslationEntryCollection`、业务筛选序列或原 `RenderSession`，不改变后台、保存和导出顺序；不新增配置、持久化字段或迁移要求。
- 排序后从顶部查看结果，筛选刷新继续应用当前排序；默认顺序来自当前筛选结果的原始顺序。已有译文/Stage 单行更新路径保持不变，未新增编辑后自动重排逻辑。

## 逐文件变更

### 新增：显示排序与表头状态

[src/transbridge/ui/workbench/translation_table_sorting.py](../../../../src/transbridge/ui/workbench/translation_table_sorting.py)

- `ordered_source_rows()`：对轻量源行索引进行稳定排序，每个词条只提取一次排序值；文本排序不受单元格 80 字符预览截断影响。
- `TranslationTableSorting`：独立管理三态点击、排序箭头和列说明，不启用 Qt 内建 item 排序，避免未完成批次被局部重排。
- `_show_indicator()`：还原空白选择列表头点击可能引起的 Qt 箭头移动，使提示始终对应实际排序状态。

### 修改：分批渲染、身份与选择恢复

[src/transbridge/ui/workbench/translation_table.py](../../../../src/transbridge/ui/workbench/translation_table.py)

- `start_render()`、`_sort_display()`、`append_batch()`：使用 `_display_order` 映射显示行，继续每批渲染 250 条；以独立 `_batch_generation` 取消过期批次，不更改业务渲染会话的代次。
- `_render_row()`：序号展示当前筛选结果中的默认序号，而非排序后的显示行号。
- `find_entry_row()`、`_select_pending()`：通过 `_entry_rows` 按词条身份定位，替代逐行扫描，使排序后的编辑和定位仍对应正确词条。
- `selected_entry_ids()`、`_capture_view_state()`：保留尚未重新加载的已选词条，使快速连续排序和加载期间的操作范围不丢失选择。
- `_restore_view_state()`、`_sync_check_selection()`：合并连续选择区间、按范围同步复选框，降低大量勾选后的恢复开销；恢复当前行时临时禁用自动滚动，避免覆盖筛选前的滚动位置或使排序后的页面跳回旧词条。
- `clearSelection()`、`selectionCommand()`、`locate_entry()`：新选择、取消选择或显式定位可覆盖待恢复的旧选择。
- `close_rendering()`：释放排序映射及待恢复身份，取消剩余批次，保持关闭时的生命周期安全。

### 性能测量

```powershell
uv run --offline --no-sync python scripts/benchmark_translation_table_sorting.py --entries 10000 --repetitions 5
uv run --offline --no-sync python scripts/benchmark_translation_table_sorting.py --entries 10000 --repetitions 5 --select-all
```

环境：Windows 11（10.0.26200）、Python 3.12.12、Qt 6.10.0、PyQt 6.10.2、`QT_QPA_PLATFORM=offscreen`。两个场景均使用 10,000 条合成数据，在完整工作台中各运行 5 次，退出码均为 0。

- 普通排序：索引排序中位数 3.32 ms；首批显示中位数 47.43 ms（44.33～65.61 ms）；全部渲染中位数 696.78 ms（681.54～702.88 ms）；五次运行中最大的事件循环间隔为 65.86 ms。
- 全选后排序：索引排序中位数 3.31 ms；首批显示中位数 96.38 ms（86.88～162.30 ms）；全部渲染中位数 1565.33 ms（1501.94～2093.67 ms）；五次运行中最大的事件循环间隔为 162.85 ms。

全选是验证选择恢复的额外性能场景，不是启用排序的条件。这些结果是本机初始测量，不是与旧版排序的性能回归对比，也不构成跨硬件或任意数据规模的响应时限保证。
