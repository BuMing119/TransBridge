## 背景与范围

请求主链路已具备独立目标、后台归属和自动继续能力，但缺少可查看的处理过程，也没有用于区分合成回放与真实模型结果的验收入口。本轮增加持久化诊断事实、只读过程界面和路由验收工具，使“为什么暂停或继续”“模型提案在哪里被拒绝”能够追查。

归档以当前 HEAD `4090f3a` 之后的工作区差异和本次开发记录为依据，暂存区为空。前置取消、长上下文和术语界面已进入基线，不重复归档。本记录只描述本轮已发生的变化；原设计和实现增量保持不变。新增事件用于诊断，不成为调度命令，不重放业务副作用，不记录模型隐藏思维过程。

## 逐文件变更

下列生产代码路径相对 `src/transbridge/`；其余路径相对仓库根目录。

### S01：事务内生命周期事件

- 新增 `application/assistant_requests/journal.py`：`EventCause` 描述操作来源；`observe_state`、`append_events` 从状态差异构造事件，保存 UTC 时间、序号、会话/请求身份和消息、批次、轮次、任务引用。`read_events` 提供请求过滤和游标分页，不改变状态。
- `journal.py` 同时处理内存元组与持久化列表的等价性，避免重复命令产生伪变化；已接纳轮次的相同记录不重复追加。模型提供的局部、事项和步骤标签采用稳定摘要；澄清 JSON 回执只提取实际诊断码，避免把正文或 JSON 字段名当错误码写入过程。
- 新增 `application/assistant_requests/transactions.py`：`commit_request_change` 承接原 `RequestService.transact` 的保存职责，将事件和状态放入同一次 Session 发布。CAS 冲突重新读取状态并计算事件序号；保存失败不留下成功事件。被拒绝的路由丢弃候选状态，只保存拒绝事实与提案摘要，再向调用者返回拒绝。
- 新增 `application/assistant_requests/turns.py`：从 `RequestBinding` 抽出 `accept_turn` 和失败记录职责；轮次接纳失败释放对应许可，执行轮次失败保存暂停及来源，尚未创建请求的路由失败也可留下会话级记录。
- 修改 `application/assistant_requests/service.py`：事务委托独立模块；输入、路由、恢复、管理命令携带 `EventCause`。`update_request` 和 `command` 支持由实际调用入口提供原因，复用既有授权、范围和保存边界。
- 修改 `application/assistant_requests/task_events.py`：`RequestTaskEventRouter` 写入后台结果时关联原 job/run，标记 `task.result`，避免结果完成时当前界面焦点改变其来源。
- 修改 `application/assistant_requests/task_controls.py`：任务中心控制标记用户来源及具体 pause/resume/cancel 操作，关联 job/run；实际动作和原有许可检查保持原入口。
- 修改 `application/assistant_requests/reconciliation.py`：人工核对以 `request.reconciled` 记录用户来源及核对输入、effect/dispatch 引用；单请求过程能查看该核对依据的关联。
- 修改 `application/assistant_requests/deletion.py`：删除准备事务关联用户命令和 `session.deletion`；继续沿用原停止收敛及未知结果屏障。

### S02：只读过程界面

- 新增 `ui/tools/smart_assistant/request_timeline_view.py`：`RequestTimelineView` 通过非模态窗口和后台读取展示分页事件；中文说明操作、状态变化和等待原因，诊断 JSON 默认折叠且以纯文本呈现。支持加载更多、刷新后续、空日志与读取失败提示，关闭窗口不等待读取结束。
- 修改 `ui/tools/smart_assistant/request_list_view.py`：新增独立 `timeline` 信号及“查看过程”“会话过程”入口；无选中请求时禁用请求级查看。尚无请求或路由失败时仍可访问会话过程。
- 修改 `ui/tools/smart_assistant/request_management_binding.py`：`show_timeline` 捕获原会话上下文并连接只读分页；查看不调用 interrupt/wake/fail/command。路由暂停和恢复补充用户来源，刷新不再隐藏空请求会话的过程入口。
- 修改 `ui/tools/smart_assistant/request_binding.py`：连接独立查看信号；轮次接纳和失败逻辑委托应用层 `turns.py`；完整回答提交事件关联模型轮次及回答消息，与原回答和覆盖证据一起保存。
- 职责复核后 `RequestService` 为 486 行、`RequestBinding` 为 489 行；新诊断、事务、轮次、界面和评测功能没有继续集中到原大类中。

### S03：语料、采集与回放

- 新增 `smart_assistant/request_evaluation.py`：`case_input` 复用生产路由输入；`make_capture` 保存供应商无关的模型输出并绑定输入/schema/当前状态摘要；`evaluate_capture` 经实际 `LlmTurn`、控制协议解析与 `apply_proposal` 比较动作、目标、程序回执和请求变化。缺失控制输出作为单场景失败，不让整批因断言退出。
- `request_evaluation.py` 的 `evaluate_corpus` 分别统计合成结果与真实模型结果，拒绝陈旧、重复或未知场景录制；没有真实结果不能显示真实验收通过。来源标记是记录者声明，输入摘要不等于供应商真实性证明。
- 新增 `scripts/evaluate_assistant_requests.py`：提供离线 `--replay`、显式 `--live` 和 `--require-live`。采集复用现有客户端，只从显式环境变量读取凭据，不写入录制内容；新建输出不得覆盖现有文件。按供应商选取默认端点，明确拒绝当前 Anthropic 客户端不支持的自定义 `--base-url`，避免静默忽略配置。
- 新增 `tests/fixtures/assistant_request_routing/corpus.json`：12 个合成中文场景，覆盖补充约束、进度追问、新问题、取消换任务、确认期间插话、引用命令、歧义、版本竞态和多指令；其中 3 个为仅回放的协议边界。
- 新增 `tests/fixtures/assistant_request_routing/synthetic_captures.json`：人工编写的控制输出，明确标记 `origin=synthetic`，只用于回放器和程序校验回归。
- 新增 `tests/fixtures/assistant_request_routing/README.md`：说明语料输入、录制绑定、离线和显式采集命令、凭据及输出边界、退出码和真实评测门禁。语料是多轮背景下的单次路由截面，不宣称覆盖整段模型对话。
