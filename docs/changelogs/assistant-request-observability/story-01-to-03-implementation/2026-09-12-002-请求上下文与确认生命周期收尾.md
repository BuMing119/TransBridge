### 上下文归属、预算与续轮

- `smart_assistant/request_context_assembler.py`：新增 `assign_history_requests`，以请求来源消息、修订来源和回答证据合并消息归属，允许同一用户输入关联多个请求；工具结果继承调用归属，路由控制批次不进入业务执行材料。投影不修改原始历史。
- 同文件 `_belongs` / `assemble`：最新用户输入、最新工具结果和明确指定的必需材料也接受请求归属检查；跨请求的必需材料明确拒绝，原生工具组继续完整保留或整体排除，避免“必需材料”绕过普通历史过滤。
- 同文件 `_project`：按本次实际预览长度判断是否截短，使低于默认 800 字阈值的工具结果也能在预算紧张时进一步缩短；保留原始长度、摘要校验值与回查引用。
- `ui/tools/smart_assistant/request_binding.py`：`prepare_model_input` 合并 `result_owners` 与 `message_owners`，固定当前请求的真实来源输入；续轮重选仅传入原请求，释放旧许可后清空 admission。原请求未就绪时返回 `REQUEST_NOT_READY`，不再先占住其他请求的租约再报错。

### 确认恢复与等待状态

- `application/assistant_requests/reducer.py`：`reduce_request` 处理 `unblock` 时，对不存在指定等待原因的事项保持原样，避免把无审批等待的 FAILED 或 RUNNING 事项重置为 PENDING。
- `ui/tools/smart_assistant/request_confirmation_binding.py`：`capture` 将确认身份、精确 `item_ids`、请求修订、请求 `lease_epoch` 和 parsed 提案与审批等待一起持久化。恢复由 `restore`、`_candidate`、`_select` 仅为原请求及原事项获取临时租约；显示卡片不解除持久化审批等待，不提前安装执行 gate。
- 同文件 `validator` / `_consume`：点击时核对真实 scheduler 租约、请求身份/修订/scope、请求 epoch、会话视图 epoch 和事项集合，再原子消费确认记录。批准后才安装 gate；明确忽略消费确认并暂停请求，回调后释放许可。拒绝或保存失败释放取得的临时租约，不执行旧步骤。
- 同文件 `_repropose_legacy`：旧记录缺少确认身份、事项归属或请求 epoch 过期时作废旧提案并请求重新提议，不猜测旧操作归属，也不将旧参数重放到同请求后续事项。资源、未知结果等独立等待仍阻塞批准。
- `ui/tools/smart_assistant/request_binding.py`：`control` 将确认恢复交给上述绑定，移除对全部事项解除审批等待以及按优先级可能误选其他请求的旧逻辑；`confirmation_validator` 转发批准/忽略意图。
- `ui/tools/smart_assistant/confirmation_view.py`：`_connect_intent` 将 `accepted` 传给请求确认校验；工具、批量工具和计划的忽略/取消按钮使用 `accepted=False`。未配置请求 scope 的通用卡片保留原行为。
