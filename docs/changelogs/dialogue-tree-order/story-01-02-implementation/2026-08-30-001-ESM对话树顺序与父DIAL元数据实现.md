# ESM 对话树顺序与父 DIAL 元数据实现及 QA

- **日期**：2026-08-30

- **Story**：Story 01～02
- **关联 Plan**：[ESM 对话树顺序与父 DIAL 元数据](../../../../plans/dialogue-tree-order/plan.md)
- **记录依据**：当前工作区 `git status --short`、`git diff`、对应 Plan、本轮自动化测试与 Vigilant 实物验证输出

## 增量目的

修复插件解析阶段把直系 Record、子 Group 和全局 FormID 排序混用所造成的对话树拆散问题，使本地 Collection 与分类 ParaTranz JSON 按 ESM 的 `group.children` 物理树输出 `DIAL → TopicChildren/INFO`。同时在既有 V2 metadata envelope 中保存父 DIAL 完整 FormID 和稳定源顺序，为 XT/EET 译文迁移与后续重新导出提供可追溯顺序，而不改变 EntryKey、legacy key、context 或 ParaTranz 公共 JSON schema。

## 文件级变更

### 插件树解析与顺序元数据

- `src/transbridge/parser/plugin/plugin_with_context.py`
  - 操作：修改。
  - 变化：将直系 Record 与子 Group 合并为一次 `group.children` 顺序遍历，保留 Normal DIAL 预建的完整 `dial_context_map` 和 TopicChildren 递归上下文；删除最终的全局 FormID 排序。
  - 原因：旧实现会先输出全部 DIAL Record、再输出全部 TopicChildren INFO，随后又按每条记录自身 FormID 重排，导致同一父 DIAL 的对话块被拆散。
- `src/transbridge/parser/plugin_parser.py`
  - 操作：修改。
  - 变化：在 `skip_empty` 过滤前使用完整提取列表的绝对索引分配 `source_order`，并传给插件条目映射。
  - 原因：过滤空字符串后仍需保留相对于原插件树的稳定位置，不能因过滤选项重新编号。
- `src/transbridge/converter/plugin_entry_metadata.py`
  - 操作：新增。
  - 变化：集中定义和校验 `plugin.source_order`、`plugin.parent_dial_formid`，规范化 metadata tuple，并提供分类导出的保守顺序恢复。
  - 原因：来源专有字段应留在 ADR-017 定义的 metadata envelope 中，且不继续扩张已超过 500 行的解析/条目模块职责。
- `src/transbridge/converter/translation_entry.py`
  - 操作：修改。
  - 变化：`create_from_plugin_entry()` 接受可选 `source_order`，将完整父 DIAL FormID 与源顺序写入 metadata；原有身份、DSD 和 context 字段保持不变。
  - 原因：旧映射只保留任务 FormID，丢弃了 `InfoContext.dialogue_topic` 中已有的父 DIAL 关系。
- `src/transbridge/converter/translation_entry_collection_export.py`
  - 操作：修改。
  - 变化：对每个对话任务文件仅在所有条目都具有合法、唯一、非负整数 `plugin.source_order` 时恢复源顺序；缺失、非法或重复时整组保持 Collection 原顺序。
  - 原因：新解析数据应按树序导出，旧项目或混合来源数据不能被部分排序而产生新的不可预测顺序。

- EntryKey、legacy `id`/`key`、context、DSD 字段和 ParaTranz 核心 JSON 字段没有变化，已有译文可按原 key 迁移。
