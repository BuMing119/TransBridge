# ParaTranz 文件上传与分类布局

更新：2026-10-25。当前合同为 [ADR-047](../adr/047-opt-in-categorized-project-upload.md)；历史词条核验、批次关联保存与旧性能测量见 [S11 历史记录](../changelogs/paratranz-categorized-upload/story-11/2026-10-25-001-direct-upload-and-fixed-paths.md)，不再是常规 GUI 上传流程。

## 用户操作

单独和批量上传中选择普通或分类模式，默认普通。普通生成根目录 `插件名.json`；分类生成 `插件名/分类.json`。Quest 对话、未关联对话及合并任务日志位于 `插件/任务/`。插件名保留扩展名，同名来源使用稳定来源摘要消歧，单独与批量命名一致。

任务对话按 Quest ID 分组，文件名优先采用同一完整来源中准确 FormID 对应的 `QUST:FULL.original`：`任务/对话_[任务原名].json`。不用任务译名、日志或目标文本。名称缺失、空白或同一 Quest 有不同原名时回退 `对话_[QuestID].json`；无关联使用未关联任务。文件名清理/截断/大小写重名时追加 Quest ID，命名在文件选择前确定。分类与脚本共用唯一核心，不按每个文件重建名称索引。

选择文件后直接在后台上传。内容模式为仅更新原文、仅安全导入译文、仅强制导入译文、原文加安全译文。原文更新默认增量保留远端余项；仅译文模式跳过不存在的文件，也不会新增词条。安全模式保护人工译文，强制模式允许覆盖。译文导入需要项目管理员以上权限。

普通与分类都能在同一文件容纳同 key 不同原文的词条，不再生成 `__冲突_*.json`。原文限定身份（requires_original_match）使用 `__transbridge_key__:v1:o:<base64url原key>:<完整SHA256原文>` 作为传输 key，原文精确 UTF-8，不规范化空白、换行或 Unicode。普通 key 保持原值，命中保留前缀时以 v1:k 转义。编码由完整本地身份决定，不依赖选择、分类、顺序或译文；不改变本地/插件 key 和全局顺序，不传历史远端词条 ID。编码后仍重复的同身份词条明确失败。

## 官方 API 合同

依据 [官网 OpenAPI 0.5.7](https://paratranz.cn/api-docs?format=json)，2026-10-25 只读核查：

- POST /projects/{id}/files：真实内容创建，path 指定虚拟目录。响应读取 file.id。
- POST /projects/{id}/files/{fileId}：只更新原文。incremental=true 保留缺失项；平台默认 false 会删除上传内容中缺失的词条。skip=false 启用平台哈希检查，重复内容返回 hashMatched。
- POST /projects/{id}/files/{fileId}/translation：按目标文件内 key 匹配，仅导入 translation/stage，不新增词条，不改 original/context。直接 JSON 使用 items 和带扩展名 filename；不发送自造 hash。force=false 保留服务端安全导入规则。
- GET /projects/{id}/files/{fileId}/translation：一次返回全部词条，不分页，仅用于下载等读取场景，不是上传必经步骤。

hashMatched/unchanged 是成功无变更；empty 表示没有导入内容，不能报成功。423 表示文件被其他更新/回滚锁定。全局官方上限为每用户每分钟 480 请求，本应用文件网关保守地每秒最多发起一次，多个任务共享同一用户预算。明确 429 按 Retry-After 有界等待重试，等待可取消，不自动重试超时或其他不明 POST 结果。

## 执行及恢复

本地生成所选文件 → 一次云端文件列表 → 按完整路径查当前 ID → 文件创建/原文更新/译文导入 → 文件回执。

正常上传不下载云端词条，不逐条发送 strings 请求，不回读每个词条，不保存上传关联，不隐式保存本地未保存编辑。旧绑定缺失或无效不阻止新上传。

同路径文件被删除重建后，使用当次文件列表里的新 ID。执行时明确返回 404，最多刷新列表并重新定位一次；不会因为 ID 变化要求额外审阅。超时保留结果待核实；再次点击会重新获取列表，避免重复创建已存在文件。权限失败、文件忙与部分完成有明确文件结果；原文已提交但译文失败会分别说明。

413 时原文/创建请求按确定性序号拆文件，保留传输 key 与来源顺序。译文导入过大则在原文件内拆批；单条仍过大则失败，不回退到逐词条接口。旧文件和旧分片不会自动删除。

工程、版本、账号或本地修订改变时停止后续操作，已发生的云端写入不会撤销。取消等待当前请求退出，显示已完成和未完成结果。GUI 每 100ms 消费最新进度，统计按文件，详情限制 200 行/32,000 字符。

## 下载与复核

当前工程通过唯一的“从paratranz上同步”入口打开同一窗口，默认只勾选当前插件，也可全选、全不选或选择多个插件。未打开具体插件时仍能选择工程来源。点击一次“下载并保存”，后台自动读取、对照、更新并保存，无需手动对照或再次确认保存。可靠项先自动保存，真正无法确定的词条保留本地并提供复核；确认复核选择后自动继续保存。

保存后主按钮显示“已保存”并禁用，无差异同步显示“已完成”，不用再次点击。只有真实来源/文件/保存失败才显示“重试未完成项”；修改插件或策略恢复开始按钮，复核接受后直接自动继续。

打开窗口只读工程来源目录和当前版本数量，不解析全部插件，也不请求云端；选定后后台解析所选来源。重复对照和保存复用有界的不可变文本解析结果，每次校验文件及 Strings/BSA 依赖的实际内容，并叠加最新版本编辑。缓存不持有完整插件二进制、写回模板或旧译文；外部文件变化不会因大小、时间戳相同而漏检。

下载只读取所选来源的普通根文件、共享分类器当前生成的精确分类文件和 `_N.json` 分片。任务文件名同样优先 QUST:FULL 原名，不扫描整个插件目录；旧任务名/ID 文件、冲突文件、未选插件及任意同名目录不参与。不读取保存的 file_id/entry_id，不回退全项目词条。命名基于全部启用来源，选择子集不会改变同名插件路径；路径无法确定的来源明确排除，不阻止其他可靠来源。

带插件后缀的 `Base.esm.json`、`Base.esm/分类.json` 优先；没有新布局文件时兼容旧版 `Base.json`、`Base/分类.json`，`.esp/.esm/.esl` 均适用。优先级按完整来源选择，不混合新旧根文件、分类和分片。新文件为空或读取失败不回退旧译文；读中 404 只重定位同代路径，明确重试才重新选择代际。路径大小写精确匹配优先，其余唯一时兼容。旧名归属由全部启用来源判断，包括未选插件；同 stem、当前名占用或数字分片重名的旧路径不猜测归属。

一轮只验证一次项目权限、读取一次文件列表，每个匹配文件读取一次完整内容。复核后重算和保存复用这份不可变内容，不重复下载成功文件。要获取新的云端修改，关闭后重新打开下载窗口。批量中的缺文件和读取失败不缓存不完整结果，可以在原窗口重试“下载并保存”；404 按当前路径自动重新定位一次，重建包含数字分片的完整来源范围。普通验证状态从未验证变为可用不会误判账号切换。

当前工程在同一插件内按精确原文与译文内容自动匹配，旧 key 改变也能回退原文。唯一非空译文直接采用，相同译文不因上下文/状态差异或多个本地 key 复用而要求确认，不依赖云端 ID 归属。真实不同译文先用准确 key/上下文、本地已有译文等确定证据收窄，仍不能唯一确定才复核；没有一致原文或只有空译文时保留本地并说明，不要求无意义确认。不跨插件、不模糊匹配或归一化原文；空原文只允许准确 key，限定身份与正文不一致仍保护。

同原文同译文的状态一致时采用真实状态；状态不同且本地现译已一致则保留本地状态，否则保守设为已翻译，不把状态数字当作置信度排序。下载只更新已有译文/状态，不保存云端关联，保留本地原文、上下文、顺序及未选来源。同步期间同条新编辑仍受保护，不能以内容自动匹配跳过复核。来源改名自动重新对照，实际账号/工程版本切换仍停止提交。逐来源详情汇总自动匹配、同译文合并及未采用原因；已保存统计以实际磁盘提交为准。

当前工程的单插件与批量下载都在更新前创建真实历史还原点，再将当前版本的完整候选自动保存到磁盘。成功保存后统一刷新全部已加载插件的译文、状态和当前工作台统计，不需要再点击“保存”；切换插件和重新打开版本保持一致。当前版本中其他已有未保存编辑也一并保存，内容保留。版本切换和取消保护覆盖实际写盘及内存发布。

工作台按同工程、同版本和完整词条身份同步权威状态：译文与状态成对推进，关联独立同步，不覆盖真正未提交的编辑。后台接收批量提交时先准备替换集合，Qt 线程核对来源、集合和词条未变化后统一发布；准备期间发生编辑则按最新视图重新协调。普通投影交付期间，并行后台保存等待已接收更新完成后核验，不把正常交付间隔当作未提交草稿，不因此暂停自动保存；视图关闭会唤醒等待者。新建/打开事务检查当前已安装视图对应的权威快照，不等待自身事务结束，也不拿待安装新工程与旧槽位比较；开启切换或完成安装时唤醒相关等待者，比较期间事务、序列或已安装快照变化则重读。保存和退出一致性检查继续保留，不以关闭检查掩盖界面滞后；小范围更新仍保留筛选、排序、选中及滚动位置。

至少一个所选来源完整读取成功后，即使没有新远端差异，也保存当前版本已有未保存编辑；版本本来已保存且无差异时不重复写入。所选来源全部缺文件或读取失败时保持本地工作状态，不把下载失败说成保存成功。自动重算最多接续两次，持续变化后保留选择可原地重试。

写入失败时保留原工作内容、下载前还原点和本轮下载内容，在同一窗口即可重试；相同本地内容不重复创建还原点，不重读成功云端文件。若文件已写成但回执或验证读取暂时失败，会精确核验完整工程和版本，确认成功后继续发布，避免假失败或重复写入。提交成功后的迟到取消不反转成功结果。

在线下载和下载 JSON 导入共用编解码：识别版本、还原原 key，利用记录 original 核对哈希，恢复含精确原文的完整本地身份。哈希不符或格式无效明确诊断，不猜测截断，不新增网络校验或映射表。当前路径内的裸 key 是合法格式；离线 JSON 不依赖云端路径。

首次切换新 key 应先上传原文（或选择原文加译文），仅译文不会建立新 key。仅省略插件后缀的旧文件可直接同步，无需先重新上传；历史冲突文件和旧任务文件名不在兼容范围。不自动迁移或删除旧文件，不迁移评论/历史。旧本地词条关联在下载中忽略，实际合并时移除当前项目关联，其他系统/项目关联保留。

## 本地脚本与清理边界

`export_to_categorized_json_files(collection, output_dir, ...)` 保留签名，仅把共享分类结果写到输出目录；任务文件位于 `output_dir/任务/`。两个脚本可从源码检出目录执行，也可在其他工作目录通过脚本绝对路径调用：

```powershell
uv run python scripts/convert_plugin_to_jsons.py plugin.esp output_dir
uv run python scripts/plugin_eet_to_json.py plugin.esp translations.xml output_dir
```

脚本不再含个人硬编码路径，支持 `--indent`、`--ensure-ascii`。第二个脚本保留原转换函数签名。分类对未知类型使用其他兜底，源顺序及哈希 key 与上传一致。

旧分类上传方法、专用冲突/选择窗口、无调用的逐词条计划/执行闭环及分类绑定读写/回执保存已删除；两个只测旧保存流程的基准脚本同步删除。普通单文件兼容上传、独立通用同步、权威来源读取和修订保护、普通适配器需要的网关及取消/列表工具继续保留。历史工程分类绑定扩展字段不再读取，不为清理代码而改写用户工程。

## 代码与排查

- application/file_upload.py：布局、序列化、文件执行/恢复及回执。
- application/io/paratranz_classification.py：共享分类、QUST:FULL 原名索引、重名与顺序；converter/translation_entry_collection_export.py 仅负责本地写入。
- application/io/paratranz_keys.py：唯一传输 key 编解码；paratranz_mapping.py 负责 JSON 往返。
- paratranz/api/paratranz_files_api.py：带官方使用备注的基础接口。
- paratranz/file_publication.py：文件传输、统一请求节流、429 等待与文件响应解析。
- paratranz/path_snapshot.py：按当前路径读取完整文件内容。
- paratranz/batch_download_snapshot.py 与 application/sync/batch_download.py：共享文件列表、来源隔离、404 完整重定位、逐来源规划和本地编辑重基。
- application/sync/reviewed_snapshot.py 与 ui/operations/download_session.py：本轮不可变下载内容及会话复用，授权和执行不重复联网。
- ui/operations/categorized_upload_bridge.py 和 categorized_upload_dialog.py：工程快照、来源范围、后台任务、内容策略与文件结果。
- ui/operations/batch_download_session.py、batch_download_commit.py 和 batch_download_dialog.py：批量选择/复核、原窗口恢复、任务取消仲裁及一次本地提交。
- application/projects/durable_variant.py：下载候选的完整版本事务保存、写后核验和内存发布；普通编辑默认仍沿用原工作状态提交。
- ui/operations/facade.py 和 production.py：普通生产入口接入文件执行；分类入口共用同一流程。

沿用现有应用日志与 PARATRANZ_CATEGORIZED_UPLOAD 作用域。file_http_response 记录方法、相对端点、耗时及有界业务状态；file_upload_result 记录文件状态和原文/译文阶段是否提交；operation_failed 保留操作与异常。日志不输出翻译载荷或凭据。phase_finished 表示函数返回，最终结果须看文件回执，不能据此断言所有翻译均被覆盖。

本次验证使用受控响应和本地工程，不访问真实用户云端内容。旧性能测量属于历史实现，不能用来宣称新流程的线上加速倍数。
