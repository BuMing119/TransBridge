# FR3 ParaTranz 集成纵向审查

- 审查 Agent：`fr03_vertical_review`
- 状态：完成；只读审查

## 结论

GUI 主链具备基本能力，但“已实现”状态过度乐观。同步可靠性和多入口一致性不足；Agent 工具链存在确定运行时断裂，上传/下载存在静默部分失败，Token 有明文泄露。

## 用户主要兼容场景：离线 ParaTranz JSON

用户提供的约 12MB/32,372 条样本明确了本需求的首要目标：支持 `id/key/original/translation/stage/context` 数组的导入与导出。ParaTranz 会重写数值 `id`，用户自己的稳定 ID 保存在 `key`。

这会调整 FR3 的优先级：在网络同步 v2 之前，先完成一个不依赖 API 的 `ParaTranzJsonAdapter`。

必须满足：

- 导入以 `key` 匹配/建立本地条目，远端 `id` 只保存为带 scope 的 external reference；
- 导出始终把用户稳定 ID 写入 `key`；远端 `id` 有同 project/file scope 时可写回，否则按已验证协议省略或生成占位；
- 离线 JSON 导入和在线 Downloader 对相同数据产生同构 ChangeSet；
- 明确区分 ParaTranz JSON、TransBridge 内部 JSON、DSD JSON；
- GUI 提供显式“导入/导出 ParaTranz JSON”，Agent/MCP 使用 typed 工具而非含糊的 `import_json`。

详细格式与测试矩阵见 [ParaTranz JSON 双 ID 兼容性调整](paratranz-json-compatibility-adjustment.md)。

## P1/P2

- Token 明文 INI 存储。
- 配置对话框在 UI 线程串行验证 API。
- 仅 429 重试，网络异常/5xx 不重试；部分请求绕过统一 Session。
- 退避 `sleep` 无取消、抖动和上限。
- 上传/下载/导出无统一取消 token。
- Artifact 直接写最终路径，中断可能留下半文件。
- ZIP 缺文件数/总大小/单文件/压缩比预算。
- Stage 被当作数值质量序列，-1 特殊语义丢失。
- 远端陈旧分片不清理，缺号分片处理不完整。
- UI、Workflow、Agent 各自构造 API 客户端；分片/冲突策略位于 UI。
- API 返回裸 dict，无响应 schema。

## 推荐方案

短期先做安全热修；主方案采用统一 ParaTranz 应用服务层：

- `ParaTranzTransport`：HTTP、鉴权、重试和错误分类。
- `ParaTranzGateway`：项目/文件/词条/术语/工件端口。
- `PlanUploadUseCase` / `ExecuteUploadUseCase`。
- `PlanDownloadUseCase` / `ExecuteDownloadUseCase`。
- `SyncTermsUseCase` / `ExportArtifactUseCase`。
- `CancellationToken`、`SyncManifest`、结构化 `SyncResult`。

GUI、Agent、MCP 只负责参数、确认与展示，调用同一服务。持久化 outbox/断点同步只在 ParaTranz 成为高频核心流程后再引入。

## 验收标准

- 日志、异常、ToolResult 不出现完整 Token。
- 401/403/429/5xx/timeout/断流返回统一 typed error。
- retry 区分幂等、遵守 Retry-After、支持抖动/上限/取消。
- 任一子阶段失败显示 partial，列出文件、阶段、错误码、重试性。
- 未分类 context 进入显式清单。
- 下载先生成 mutation plan，致命失败时本地集合零变更。
- -1/9 Stage round-trip 正确；未知 Stage 不做数值比较。
- Artifact 写 `.part`，验证后原子 rename，失败清理。
- GUI/Agent/MCP 对同 fixture 产生相同同步计划与结果。
- 导出后即使 ParaTranz 重写所有数值 id，再导入时 key/译文/Stage 仍能无损对应。
- 缺 key 或重复 key 不得用远端 id 自动兜底或静默覆盖。
- fake HTTP server 覆盖鉴权、限流、5xx、timeout、截断响应。

## 迁移顺序

1. 建 HTTP contract tests 和行为快照。
2. 移除 Token 输出，修 Agent 接口。
3. 引入 Transport/Gateway，旧 API 暂作 facade。
4. 用 Use Case 包裹现 Workflow。
5. 迁 GUI，再迁 Agent/MCP。
6. 加入 dry-run、事务合并、取消和原子文件。
7. 删除 UI 业务逻辑和直接 requests。
