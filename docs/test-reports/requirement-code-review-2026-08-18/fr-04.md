## ParaTranz JSON 导出补充

用户明确需要把集合导出为 ParaTranz 的 `id/key/original/translation/stage/context` 数组。FR4 的 WriteBack/Export 目标因此必须增加独立 `ParaTranzJsonAdapter`：

- `key` 输出用户稳定 EntryKey；
- `id` 只输出有 scope 的 ParaTranz external reference，不能把它当本地 key；
- 不与 DSD JSON 共用 serializer；
- 输出前验证 key 唯一、Stage 合法；
- 导出结果给出有/无远端 id 的数量，避免用户误以为本地能生成有效的 ParaTranz 数据库 ID。

该 Adapter 应进入 `WriteBackService`/FormatAdapter 合同和 GUI 写回目标列表。详见 [专项调整](paratranz-json-compatibility-adjustment.md)。

## 需求完成度

- ESP inline/localised：约 40–50%；Writer 不看 Stage，保存非原子。
- EET update/new：约 45%；update 存在，宣称的 builder 文件不存在，GUI 强制已有源模板。
- XT update/new：约 35–45%；builder 不存在，Writer 不看 Stage。
- 纯 Strings：约 20%；不是明确策略，且只输出有译文的 string_id，可能生成不完整文件。
- 批量写回：约 55%；GUI 多 Slot 循环实际只覆盖 ESP，不是 Plan 声称的 ESP/EET/XT。
- SST：Serializer 代码存在但公开导出被屏蔽，无当前 pytest/xTranslator 兼容门禁。

## P0

1. 本地化写回从空 mapping 开始，只添加有译文条目，未翻译 string_id 会从 `.strings/.dlstrings/.ilstrings` 中消失。
2. Agent EET/XT 调用 `EETWriter().write(collection,path)`，真实 API 需要 parser + apply + write，成功路径必坏。
3. 全版本写回循环修改共享 collection，异步排 worker 后立即切下一版本并提前显示成功，可能所有输出均取到错误/相同版本。
4. Stage 契约漂移：Plugin/XT 忽略 Stage；EET 对 locked/hidden 也不能按统一语义更新模板旧值。
5. ESP/XML/Strings 缺统一 staging、原子替换和备份；Agent 默认可能原地覆盖源文件；FOMOD 写回异常被吞后仍继续打包。

## P1/P2

- EET/XT builder、batch、多项 Story 被错误标完成。
- ElementTree 直读直写可能改变注释、编码、BOM、空元素和格式，无 fidelity golden test。
- Agent strings 的路径被误当插件文件路径解释。
- GUI/FOMOD/Agent 各自 new Writer，路径/Stage/结果类型不同。
- apply 先修改内存树再写磁盘，失败会污染共享对象，多版本相互泄漏。

## 推荐方案

采用 `WriteBackService + 格式 Adapter + OutputTransaction`：

```text
WriteRequest(source_snapshot, variant_snapshot, target, mode,
             destination, overwrite, backup, verify)
  -> WriteResult(artifacts, counts, warnings, failures)
```

ESP/EET/XT/Strings/SST/ParaTranz JSON 各自实现 adapter；统一 `ExportPolicy` 处理七级 Stage。产物先写 staging，重解析/结构校验后原子 publish；in-place 必须备份。GUI/Agent/FOMOD 只做参数和结果适配。

长期可在此之上演进为可复现 Artifact Build Pipeline：source/variant hash、manifest、dry-run、批次整体提交。

## ADR / Plan / Story

- 新增 ADR：Write-back Artifact Pipeline（不可变输入、ExportPolicy、adapter、事务、校验后发布）。
- 更新 ADR-001：hidden/locked/0/1/2/3/5 的输出矩阵。
- 更新 ADR-006：全版本写回必须使用独立 VariantSnapshot。
- 更新 ADR-012：Agent 默认不得原地覆盖；in-place 二次确认+备份。
- 更新 ADR-014：FOMOD 写回失败默认阻止发布，partial 必须显式。
- 更新 ADR-015：三入口只能调用统一服务。
- 新 Stories：Stage 契约、OutputTransaction、ESP adapter、Localized 完整快照、EET/XT patch+builder、ParaTranz JSON 双 ID adapter、typed service、批量/variant snapshot、入口迁移、golden/fault tests、SST 兼容 gate。

## 验收标准

- 七级 Stage 全格式参数化矩阵通过。
- Localized 写回保留全部原 string_id；parse→write→parse 集合等价。
- temp sibling → reparse → `os.replace`；故障注入后旧目标不变。
- in-place 生成可恢复备份。
- EET/XT 保留未知节点、属性、顺序和编码策略；builder 可被本项目与目标工具读取。
- GUI/Agent/FOMOD 对同 request 生成相同内容 hash 与同构 WriteResult。
- 多版本输出互不串译，任一失败不虚报成功。
- FOMOD 插件写回失败默认不发布 archive。

## 迁移

P0 止血 → 引入 ExportPolicy/事务/typed request → 旧 Writer 包装成 adapters → 迁 GUI/Agent/FOMOD → 补 builders/fidelity/variant snapshot → xTranslator 验证后再开启 SST。
