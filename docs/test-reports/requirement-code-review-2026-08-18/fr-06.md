# FR6 AI 后处理与报告纵向审查

- 审查 Agent：`fr06_vertical_review`

## 结论

检测、修复、润色、裁决、报告骨架存在，但候选数据链、Stage、断点续传与报告快照存在系统性偏差。功能骨架约 70%，需求语义/正确性约 45–55%，暂不适合无监督大批量生产。

## P0

1. 修复结果 B 没有成为润色输入；Polisher 仍消费原译文 A，最终 C 覆盖 B，流水线不是真串联。
2. pass 写 stage=1、reject 写 stage=0、pending 不写 Stage；`needs_review/auto_fixed` 统计也未正确维护。
3. 未给 target ids 时后处理所有有译文条目，可降级 stage=3/5/9/-1；应只处理本次成功 key。
4. Checkpoint 恢复先提交所有 LLM future，完成后才检查已完成批次，恢复仍重复付费请求；Agent 停止后还删除 checkpoint。
5. 批次异常只写日志，最终任务仍 completed；结构化 errors 未累加，用户无法识别 partial。

## P1

- 一致性仅做术语，不含风格、重复原文、角色语气。
- 格式验证未完整支持需求列举的 printf/命名占位符和 Creation Engine 标签。
- 需求要可配置加权质量门，代码却是 LLM pass/fail/uncertain 分类。
- LLM JSON 缺 schema、ID归属、重复/缺失、confidence 范围校验。
- pause 通过 cancel 共享 client，易将暂停变成业务失败。
- 独立润色 Worker 有 pause/stop，但 UI 无按钮。
- 预览表为每行重复连接 `cellClicked`，一次点击触发 N 次切换。
- 报告 accepted 用 confidence>0 推导，不能反映用户最终接受/拒绝。
- UI 读取顶层 refine/polish/decision，但 AutoTranslator 只设置嵌套 post_process_result，UI 与 Excel 数据不一致。
- Excel Entries 只从问题/结果 ID 反推，正常通过条目快照为空；缺 config snapshot。
- 筛选使用中文显示值比较英文内部值；排序后行号到 entry 的映射错误。
- 报告写入异常被吞；历史目录硬编码相对路径，不适配打包数据目录。
- Agent phases 依赖关系失真，本地检查也强制 API key，execution 无法关闭。

## 推荐方案：显式候选状态流水线

每条 Entry 保存完整候选链：original/current/issues/refine/revalidate/polish/revalidate/decision/commit/provenance。每阶段只消费前一阶段 candidate；只有 CommitStage 修改 Collection。

```text
GUI / Agent / Batch / Mixed
  -> PostProcessApplicationService
  -> PostProcessSession
      Detect -> Refine -> Revalidate -> Polish
      -> Revalidate -> Arbitrate -> Commit
  -> CheckpointRepository / ReportRepository / TaskRuntime
```

关键契约：`EntryPostProcessState`、`StageOutcome`、`BatchOutcome`、`CommitPolicy`、统一 `PostProcessReportModel`、含版本/config/input hash 的 checkpoint manifest、区分 pause/stop/network failure 的 CancellationToken。

## 验收标准

- Refiner 输出 B 后 Polisher 输入必须为 B。
- pass→3、pending→2；stage=9/-1 在任何入口完全不变。
- 目标集合严格等于本次成功 key。
- 已完成 checkpoint 恢复 LLM 调用数为 0。
- pause 不产生 confidence=0 失败；stop 保留 checkpoint，任务为 partial/cancelled。
- 任一批次失败不得 completed，必须有 per-batch error。
- Excel 行数等于目标条目数，UI/Excel verdict/stage/accepted 一致。
- 预览拒绝在报告中仍为 rejected；单击只切换一次；排序后跳转正确。
- consistency/format-only 不要求 API key。
- 报告写失败提示用户但应用内报告仍可开；统一 data dir 可查历史。

## 迁移

冻结行为 → 修 Stage/保护/精确目标/checkpoint过滤 → 外包 EntryPostProcessState → 先迁 Agent → GUI/独立润色 → 批量/Mixed → UI/Excel 共用 ReportModel → 删除旧拼装与动态结果字段。
