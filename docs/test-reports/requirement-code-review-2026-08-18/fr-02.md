# FR2 核心条目、Stage 与标签纵向审查

- 审查 Agent：`fr02_vertical_review`
- 状态：完成；只读审查

## 结论

基础 UI 和数据类“看起来已实现”，但核心状态合同没有统一。版本隔离、Stage、标签、`key/id` 与持久化之间存在会导致串版、丢状态、错误写回的高风险断层。

## 对 `id != key` 结论的范围校正

用户提供的 ParaTranz JSON 证明：ParaTranz 数值 `id` 与用户稳定 `key` 不同是正常交换语义，不应把二者强制合并。

修订后的 FR2 身份合同是：

- `EntryKey` 是本地唯一业务主键；翻译、标签、Stage、Variant、TM、AI 和写回都关联它；
- ParaTranz `id` 是 `ExternalEntryRef(system="paratranz", project/file scope)`，不进入 Collection 主索引；
- 历史 `TranslationEntry.id` 在迁移期不能同时承担“本地辅助 ID”和“远端 ID”两种含义；
- 原报告中“`id != key` 全链正常”的验收，应解释为“内部逻辑只依赖 key；外部 id 可任意变化且不影响本地身份”，而不是要求两个字段最终相等。

详细合同见 [ParaTranz JSON 双 ID 兼容性调整](paratranz-json-compatibility-adjustment.md)。

## 完成度

- FR2.1 统一模型：来源基本进入 `TranslationEntry`，但模型完全可变、无统一校验，各模块直接修改字段。
- FR2.2 预览筛选：Stage/category/search 存在；标签与状态有多份数据源。
- FR2.3 多选：行选择、标签选择、Agent `_selected_ids` 是三种不同语义。
- FR2.4 迁移追加：链路存在；EET/XT fallback 缺统一 overwrite/conflict policy。
- FR2.5 Stage：常量/UI 文案基本统一，但持久化、后处理、Agent 润色和 Writer 仍违反七级语义。

## P0

1. `VariantStore.apply_to()` 是稀疏覆盖而非替换：空版本不会清除上一版本译文，全版本写回可能串版。
2. Stage 不持久化，3/5/9/-1 跨重启丢失，恢复后甚至可能出现 `stage=0 + translation`。
3. `collect_from()` 只保存非空译文，用户清空后旧译文会在重启/切版时复活。
4. Step2 编辑译文、Stage、标签均未可靠 `mark_dirty()`；加载反而可能标脏。
5. 标签存在 AppContext 与 Step2 两份状态源，UI 使用 id、Agent 使用 key，互不可见。
6. AI 返回以 key 为键，`_update_collection()` 却按 id 查询；`id != key` 时结果静默丢失。
7. 旧 JSON 缺 key 时默认空串，多条记录加入 Collection 后互相覆盖，只剩最后一条。
8. Plugin/XT Writer 不执行 hidden/locked 统一策略；EET 对 locked+空译文也偏离文档。
9. PostProcessor 将 pass 写 stage=1、reject 写 stage=0 且保留译文，与 FR2.5 不一致。
10. Agent 润色可处理 stage=9/-1，并手工重建 Entry 时丢 `string_id/form_id/DSD` 字段。

## P1/P2

- TM 应用译文不更新 Stage；冲突选择也只改 translation。
- UI 清空译文不回退 Stage；Agent 非法 new_stage 会在返回失败前已修改译文。
- locked 权限没有在统一 mutation 层执行。
- Stage 色条、多标签圆点、标签重命名与默认标签未满足需求。
- `TranslationEntry` 字段公开可变，存在大量手写拷贝遗漏字段的风险。
- `Collection.filter()` 文档写返回 Collection，代码返回 list。
- 核心 Collection 测试文件默认不被 pytest 收集。

## 推荐方案：Entry State Contract v2

保留现有 `TranslationEntry` 兼容视图，新增：

- `EntryKey`：唯一稳定关联键；id 仅用于来源/API 兼容。
- `ExternalEntryRef`：保存 ParaTranz 等外部系统 ID，并带 system/project/file scope。
- `TranslationStage(IntEnum)` 与集中转换规则。
- `EntryMutationService`、`StageTransitionPolicy`、`LockedPermissionPolicy`。
- `ExportPolicy`：各 writer 共用 Stage 输出矩阵。
- 单一 `LabelStore`。
- `VariantStateV2`：按 key 持久化 translation/stage/labels/provenance。
- `EntryChangeSet`：统一 dirty、UI 刷新和审计事件。

长期可演进为不可变 `EntryDefinition + Variant Overlay`，但当前不建议直接做完整 event sourcing。

## 验收标准

- ParaTranz `id != key` 或远端 `id` 被整体重写时，翻译、标签、筛选、持久化和写回全部以 key 保持稳定。
- 两个外部记录具有相同 ParaTranz id 但 key 不同，不得在本地互相覆盖；应报告 external-ref 异常。
- 旧 JSON 缺 key 自动回填 id，条目数不减少。
- 切换到空 Variant 后上一版本译文完全消失；清空译文重启后仍为空。
- Stage 3/5/9/-1 和标签随版本保存、切换、重启。
- Agent/UI 标签双向立即可见。
- 所有修改路径触发 dirty。
- ESP/EET/XT 对七级 Stage 通过参数化输出矩阵。
- 非管理员不能解锁 9；hidden 永远按统一策略输出。
- CI 禁止业务模块新增直接 `.translation =` / `.stage =`。
