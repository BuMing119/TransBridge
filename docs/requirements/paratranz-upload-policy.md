# FR3.8 ParaTranz 项目上传政策

状态：2026-11-25 已接入上传入口、Owner 编辑器、助手上传和补传。云端文件读写通过模拟项目验证，真实平台联调待验证。

同一项目里的主要人员可以都是 ParaTranz 管理员。负责人应能单独指定每个上传操作由谁执行，同时统一云端文件布局及允许的译文写入方式。下载沿用 FR3.3。

## 点击「上传…」时的行为

- 每次点击 ParaTranz 的「上传…」，在后台读取当前绑定项目根目录的政策，再显示本次账号可用的布局和上传操作。读取期间显示加载状态，完成前不能提交。若其间切换账号或项目，旧结果不能用于新目标。
- 本次云端没有政策时，使用默认上传流程，项目不额外限制布局或操作。找不到政策文件、文件为空（含纯空白）、词条数组为 `[]` 均属此情形。平台权限和原有上传条件照常生效。
- 成功读到非空词条数组时按 v1 格式整份解析。缺少某项操作的名单仍表示无人可用。网络失败、访问被拒、政策内容损坏或版本无法识别时，显示具体原因，本次暂停上传，用户可重新尝试。
- 窗口保留现有选项。政策固定分类时，选中「分类上传」并将「普通上传」置灰；固定普通时反向处理。五种内容操作按本次账号分别启用，禁用项可见且无法通过鼠标或键盘选中。鼠标悬停在灰色布局或操作上时显示原因，选项保留原名。项目未开放对应写入方式时优先说明项目限制，项目已开放时说明账号的授权或身份问题。原默认项不可用时选中可用项；全部不可用时禁用提交，并说明当前账号没有可用上传操作。

## 项目所有者编辑政策

当前绑定项目的 Owner 可以在 TransBridge 内创建、查看和修改项目政策。Owner 首次进入上传且云端没有政策时，先提供选择；其他成员直接进入上传流程。有云端政策时直接进入按政策设置的上传窗口。Owner 可随时主动打开同一编辑界面，即使五种上传操作全部禁用，也能管理政策。

编辑界面提供上传布局、三种译文写入方式及五个操作各自的允许和排除名单。成员按昵称展示、按 ParaTranz 用户 ID 保存。取消编辑不修改云端。保存成功后，当前上传窗口按已保存的政策刷新，提交翻译文件仍由用户单独发起。

首次弹窗文案：

> **要为这个项目设置上传规则吗？**
>
> 你可以为你的项目配置更加自定义的上传规则，以约束成员的上传行为
>
> **否，使用默认权限并继续**　　**设置上传规则**

选择「否，使用默认权限并继续」时，软件在内存生成默认 v1 政策（布局自选、三种写入方式全开、五项均允许项目成员、排除名单为空），在后台直接上传到绑定项目根目录。自定义政策同样直接写入云端。本地不保存政策文件、持久缓存或首次设置标记。默认权限保存并读回成功后，弹窗提示「默认上传规则已保存到当前 ParaTranz 项目。」，点「继续」进入上传窗口，用户另行选择并提交翻译文件；下次点击「上传…」重新读取云端。选择「设置上传规则」时打开编辑器。关闭首次提示则取消本次上传，不写文件。

## 非空政策文件格式

每个项目根目录可有一份 `transbridge-policy.json`，内容为 JSON 词条数组。每条使用字符串 `key` 和 `original`；生成文件时 `translation` 写空串。读取时忽略译文、状态及平台附加字段，词条顺序无关。规则名和枚举值区分大小写，多个值以英文逗号分隔，允许值周围有空白。

- `policy.version` 必填，v1 的原文为字符串 `"1"`。
- `upload.layout` 必填。取 `user_choice` 时沿用普通或分类选择，`flat` 固定普通，`categorized` 固定分类。改变布局不自动迁移、改名或删除已有文件。
- `upload.translation_mode` 必填，枚举所开放的一种或多种写入方式：`fill_empty`、`safe_import`、`force`。开放其中一种不会开放其他方式。只允许原文上传的项目可省略所有译文操作名单。

## 五份独立的操作名单

| 名单 key | 实际操作 | 所需项目写入方式 |
| --- | --- | --- |
| `upload.orig_only` | 仅增量更新原文 | 无 |
| `upload.trans_fill_empty` | 仅填补云端空译文 | `fill_empty` |
| `upload.trans_safe` | 仅安全导入译文 | `safe_import` |
| `upload.both` | 增量更新原文并安全导入译文 | `safe_import` |
| `upload.trans_force` | 仅强制导入差异译文 | `force` |

每个 key 的原文是允许名单。同名 key 加 `.deny` 是本操作的排除名单。两者都接受 `user:<正整数账号 ID>`、`role:translator`、`role:proofreader`、`role:admin`、`role:owner` 和 `project_member`，可逗号混写；`none` 须单独使用。角色精确匹配，项目所有者与管理员可分别点名。省略或填 `none` 表示空名单。未命中允许名单、命中排除名单或缺少所需写入方式时，该操作均不获准。名单按本项目已核实的成员身份匹配，平台实际权限仍是上限。

授权 `both` 仅授予该组合操作；两项单独操作的名单也不推导出组合授权。某个人的强制操作授权独立于安全导入和补空名单。项目关闭某种方式时可以保留其人员配置。强制导入沿用现有确认；填空沿用现有云端读取及安全导入语义。

## 示例与验收

```json
[
  { "key": "policy.version", "original": "1", "translation": "" },
  { "key": "upload.layout", "original": "categorized", "translation": "" },
  { "key": "upload.translation_mode", "original": "fill_empty,force", "translation": "" },
  { "key": "upload.orig_only", "original": "user:101", "translation": "" },
  { "key": "upload.trans_fill_empty", "original": "role:admin,role:owner", "translation": "" },
  { "key": "upload.trans_fill_empty.deny", "original": "user:103", "translation": "" },
  { "key": "upload.trans_force", "original": "user:102", "translation": "" }
]
```

- 101、102、103 同为管理员时，101 可更新原文和补空，102 可补空和强制修订，103 无可用操作。单独给 103 增加某个其他操作时，补空排除仍只作用于补空。删除项目写入方式中的 `force` 后，102 的强制操作随之关闭。
- 调整词条顺序或修改任意译文字段不改变政策。无效顶层结构、缺必填项、重复或未知规则 key、不支持的版本、无效账号/角色/枚举、空名单片段及混用 `none` 必须报错；有错误时整份政策不可用，诊断定位到规则或词条。
- 云端有示例政策时，101、102、103 点击「上传…」应看到同一组操作及各自不同的可点状态。云端没有政策时，Owner 先选择默认或自定义设置，其他账号进入默认流程。读取超时显示失败原因。工作台、助手与补传在云端写入前执行相同的政策判断；政策文件从日常上传和翻译同步中排除。
- 待在线验证：真实平台的文件创建、替换和原文读回，以及项目管理员直接在平台网页替换、删除政策文件的能力。
