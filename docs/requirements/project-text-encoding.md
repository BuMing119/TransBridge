- 优先级：P0。
- 设计：[ADR-055](../adr/055-project-text-encoding.md)；计划：[project-text-encoding](../../plans/project-text-encoding/plan.md)。
- 历史：[S01～S06 实施记录](../changelogs/project-text-encoding/story-01-to-06/2026-11-14-001-project-text-encoding.md)、[旧项目保存补齐](../changelogs/project-text-encoding/story-01-to-06/2026-11-14-002-persist-missing-encoding-defaults.md)。日志保留当时事实，本文件维护当前有效需求。

## 目标与范围

用户能够以源语言、目标语言及明确码页控制 Skyrim SE 插件与 Strings 的读取和输出；已有项目保持已保存原文的解释一致性，需要应用新规则时使用既有“更新来源”。全部翻译版本与状态须安全保留。

范围包含 ESP/ESM/ESL 普通显示文本及 `.strings`、`.dlstrings`、`.ilstrings`，包括关联松散文件、BSA 内来源和未引用字符串。VMAD 等专用字段遵守各自规范。SST、EET、XML 等翻译存档及 ParaTranz/DSD JSON、项目配置保留自身格式编码合同。

不新增游戏、文件级编码设置、临时导出编码、任意编码猜测、独立主动重读、新缓存或旧项目格式迁移；不保存插件本体，不修改依赖。语言设置独立于 AI 翻译语言 profile；只绑定编码，不改变既有 Strings 伴随文件路径命名，旧项目补写 Chinese 不得重命名原 English 文件。

## 已确认行为与验收

### FR33.1 程序默认与项目设置独立

两级设置均包含源语言、目标语言、输入编码和输出编码。源语言关联读取规则，目标语言关联输出默认码页，用户仍可明确手选码页。新项目冻结创建时程序默认，之后全局修改不改变已有项目。Skyrim SE 初始为 English、Chinese、UTF-8、UTF-8；语言不能误当作强制 Windows 码页。

验收：项目 A 创建后修改全局默认，A 保持原值，新项目 B 采用新默认；保存、重开、复制和项目包往返保留四项设置。常用 Windows 码页名称明确，至少包含 1250、1251、1252、936。未知语言或不支持的 codec 明确失败，不从 AI profile 隐式推导设置。

### FR33.2 按语言逐字段读取

新解析采用 xTranslator 风格规则：选择 UTF-8 时，每个普通字段先尝试 UTF-8，失败后只使用该源语言备用码页；English 对应 Windows-1252、Polish 对应 Windows-1250、Russian 对应 Windows-1251 等。一个文件内合法 UTF-8 与备用码页字段可以共存。显式非 UTF-8 codec 直接读取，不先试 UTF-8，不遍历其他语言码页。

验收：插件和 Strings 的混合字段正确读取；源语言变化影响非 UTF-8 字段解释；显式 Windows-1250 不被 UTF-8 优先规则覆盖。无法解释时给出文件、操作、编码及记录/字段或字节位置，不能静默切到不相关码页或掩盖失败。历史兼容规则只用于 FR33.5 的既有来源解释。

### FR33.3 全部普通文本统一输出且严格无损

已译、未译、未修改字段和全部 Strings 物理记录均以输出 codec 编码。即使输入、输出都为 UTF-8，语言备用码页字段仍须转成真实 UTF-8，不能按 codec 名称相等复用旧文本字节。译文选择沿用阶段策略，零译文也可纯转码。

验收：全部受控文本统一目标编码，保留记录数量、ID、顺序、未引用 Strings 和非文本结构；专用字段遵循自身规则。中文无法写入 Windows-1252、码页往返改变 Unicode、长度溢出或截断均明确失败，不以问号、替换或忽略字符凑成成功。先暂存，严格按输出 codec 回读核验预期文本和结构，失败不发布；BSA 仅作输入，关联产物按既有整组事务回滚。严格无损输出是 TransBridge 保留的区别，不照搬上游替换或截断。

### FR33.4 老项目保存补齐固定缺省值

缺失语言/编码字段固定解释为 English、Chinese、UTF-8、UTF-8，不继承当前全局默认。打开仅使用已存文字；下一次保存即使没有译文修改也补写缺字段。已有值保留，无效已有值明确报告。

验收：无修改旧项目可保存补齐四项，再次无修改保存恢复正常无操作；过程不读来源、不重建原文、不改译文/阶段/标签等状态。核验数据库实际字段写入，不能以“缺省解释相等”代替落盘证据。补写 UTF-8 不证明历史来源曾显式按 UTF-8 读取。

### FR33.5 历史来源保持读取事实

导出、补充实际输入等还原既有来源的操作以来源登记时读取事实为准，当前项目设置不得覆盖历史事实。无策略记录的旧 vendor 插件沿用历史逐字段 UTF-8、Windows-1250、Windows-1252、Windows-1251、replacement 顺序；旧独立与关联 Strings 分别复现各自历史 decoder，不套用插件码页列表。还原结果与项目已存 baseline 逐项匹配。前次明确记录的严格来源继续严格读取。

验收：修改项目源语言/输入编码后，未更新的来源仍按原事实导出；无法匹配 baseline 时阻止并给出行动建议。自动补写 UTF-8 的项目仍按来源事实判断。真实旧项目的 `Annaďg` 不得被新 English 规则静默变成 `Annaïg`。兼容历史 replacement 不代表允许输出新增替换字符。

### FR33.6 用既有更新来源功能应用新规则

设置保存只保存设置，不解析来源；不提供独立“重新读取原文”按钮或主动重读流程。需要改变已存原文时复用“更新来源”：用当前项目规则准备更新、展示预览、建立备份并提交。文件字节/既有指纹相同但读取策略改变，也允许更新。

验收：同文件新规则可预览原文差异；可靠一对一匹配迁移全部 variants，保留译文、标签、显式清空及锁定/隐藏保护，原文改变且有译文时标为待复核。定位不可靠时阻止，不能删除再新增而丢译。缺来源复用补充机制；失败、取消、预览后文件变化或并发编辑按既有事务回滚，不提交部分版本。恢复点恢复来源读取事实、原文及版本状态。设置保存与之后来源更新为独立动作，更新失败不虚构已保存设置也已回滚。

### FR33.7 全入口一致与真实数据验证

新增/导入和明确更新来源使用当前项目规则；还原历史来源使用登记事实；全部输出统一项目输出 codec。GUI、助手、CLI/MCP、单/批/多方案及 FOMOD 共用应用层规则，操作开始冻结设置。界面明确源/目标语言、编码和范围，无文件级覆盖，不把原生翻译存档误称为受插件编码控制。

验收：各入口选择相同读取事实与输出设置，输出校验不使用输入 fallback。除合成测试外，对用户提供的 `BSAssets.esm`、`BSHeartland.esm` 和现有 20,075 条目项目执行只读输入、隔离副本验证，分别报告来源匹配、旧项目普通保存、设置不读源、全版本来源更新和输出回读及未运行项。旧测试数字或离屏测试不能代替本轮真实场景。

## 约束与未决项

解析、来源更新和发布验证沿用后台 worker/coordinator、取消、预览、备份及事务边界，不阻塞 Qt 事件循环。项目只保存翻译内容、最小定位、来源路径和必要读取事实。七项产品行为无待确认项；实现细节与测试状态由计划维护。
