# ADR-043：助手回合结果提交、取消与显式撤销

- 日期：2026-09-22；状态：提议，产品交互已由用户确认，授权本地实现与验证。
- 关联：FR30.16～26；[综合计划](../../plans/assistant-task-context-consistency/plan.md)。
- 延续 ADR-040 的权威请求、ADR-041 的稳定上下文；取代以 GUI 串行回调承担控制工具最终结果一致性的实现方式。不是重写 DAG。

## 背景

旧实现将查询最后核验和保存留在 GUI，回答保存后才更新内存，查询却相反；中断根据内存扫描补取消。简单后台化会造成持久成功与内存取消冲突。业务 TaskRuntime 已有真实提交屏障，应复用。取消清理失败被 cancelled 覆盖、恢复投影误走已失效写许可均为已核实缺陷。

## 决策

应用层拥有控制工具结果最终提交，后台适配执行用例，Qt 只做输入和结果投影。使用稳定 call/result 身份和原子消息追加：父调用已持久化且归属有效，同一调用一个终结结果，相同重复返回既有结果，冲突报错。成功与取消在同一顺序边界裁决，保存成功才发布；业务副作用仍由原 runtime/effect 屏障裁决。

用户取消默认保留已提交结果，不弹二选一；未提交临时投影按原合同清理。停止收尾后提供“撤销本轮修改”。撤销是新的显式应用命令，不是图 checkpoint restore，也不是加载整份旧 Session/Variant。真实用户输入定义轮次，其关联必须显式保存；多输入/多请求归属无法唯一证明时不能猜测。

撤销凭证记录目标身份、修改前后值和修订、操作归属与提交事实。冲突检测保护后续独立编辑；不能完整支持的外部效果/缺失记录先说明限制，不静默部分撤销。Project 聚合提交不等于磁盘持久化，Session 与 Project 没有跨存储原子事务；需写前意图与提交后核验或同源持久凭证，未闭合不得展示完整可撤销。

撤销保留对话和审计，追加撤销事实，使相关许可/图恢复资格失效，不倒退 revision。DAG checkpoint 继续记录执行状态，失败/取消节点不能据 completed 名称当作成功；本轮不新增自动跨进程图恢复。

## 备选与取舍

- 仅将 save 搬线程：无法解决 GUI 合成取消与后台提交竞争，不采用。
- 整体恢复 Variant snapshot：会覆盖独立编辑与非本轮操作，不采用。
- 建立通用事件溯源/actor 系统：范围过大，无必要；复用现有事务和 runtime。
- 自动撤销：与用户确认的默认保留结果冲突，不采用。

## 失败、迁移及验证

清理失败显式保留失败原因，禁止取消终态掩盖。父调用缺失、陈旧资格、消息冲突、撤销凭证不闭合、结果未知和恢复冲突均停止对应操作，不无限重试。旧记录可读取但不补造撤销能力；旧任务缺少工作轮次时禁止新增助手写操作，用户的新输入经路由建立新轮次后才可继续修改。助手撤销服务缺失是接线错误，写入前明确失败，不退回独立工具路径。独立 MCP/非助手工具使用领域命令，不伪造助手轮次；已声明不能安全撤销的领域操作仍可执行并登记真实归属。UI 关停必须先封闭投递和新操作，再由生命周期等待必要收尾，不直接丢弃写队列。

验收覆盖取消先/提交先/通知丢失/存储失败/换版本/后续编辑/重启；上下文只追加必要新事实，缓存收益与真实模型语义独立评估。

## 已实现能力与保留限制

本版使用真实 work_round_id、同事务 effect/归属登记、不可变凭证及单调撤销序号。既有条目/标签、指定非敏感配置、授权打包/写回文件和本地项目绑定分别有逆操作；远端及尚无安全领域合同的结构/词典/术语写入允许执行但明确不可自动恢复。具体范围见综合计划 Story 06，不能凭工具执行成功推断“整轮可恢复”。

多域先预检再逐域执行，故障进度保留为 undoing，不自动重放；完成后同一 Session 事务追加 round_undo_receipt，GUI 合并已保存历史，模型看到后续撤销事实。凭证及备份按实际写入增长，当前无自动过期删除。新代码不承诺旧版本降级时仍安全识别撤销事实。
