# ADR-033：共享语言档案与语言中立提示词

- **状态**：提议
- **日期**：2026-08-28
- **关联 ADR**：ADR-005、ADR-032

## 背景

主翻译和专有名词抽取曾把完整提示词存放在 `data/prompts/langs/zh_CN.toml`，而后处理阶段、FOMOD 和 UI 又分别解析语言文件、维护语言名映射或硬编码 `zh_CN`。新增目标语言因此需要复制提示词并修改多处代码。更严重的是，语言文件缺失或字段无效时，若干调用方会静默使用 `Simplified Chinese`，使请求可能被发送到错误的目标语言。

## 决策

1. `data/prompts/langs/{locale}.toml` 只保存语言元数据：稳定 locale、面向用户的名称、模型可读的源语言和目标语言，以及可选的成对示例数据。
2. 翻译、抽取、质量门禁、修复、润色和裁决分别维护唯一的阶段级 `default.toml`。模板通过 `$source_lang`、`$target_lang` 等运行时变量适配语言；语言档案不得复制完整指令。
3. `transbridge.config.language_profiles` 是跨模块唯一语言档案入口。它校验 locale，阻止路径穿越，验证必需字段并向 UI 提供可发现档案列表。
4. 未知、缺失、损坏或不完整的语言档案在调用 LLM 前明确失败，不再猜测或回退到简体中文。通用提示词文件仍可回退到语言中立的 Python 内置模板。
5. FOMOD、Smart Assistant 配置入口和 AI 翻译 UI 复用同一档案契约。`LLMConfig.target_lang` 继续保存 locale code，以保持公共配置字段稳定。
6. 不兼容旧的语言文件内 `[translation]` / `[extraction]` 提示词，也不兼容后处理阶段的 `{locale}.toml`；维护者必须把自定义指令迁移到对应阶段的 `default.toml`。

## 备选方案

- 每种语言复制完整提示词：会造成规则漂移和多语言维护成本，拒绝。
- 各调用方保留 locale-to-name 字典：无法形成单一事实来源，且新增语言容易漏改，拒绝。
- 未知语言回退到 `zh_CN`：结果可通过结构校验但语义上翻错目标语言，拒绝。
- 把自然语言名直接写入 `target_lang` 配置：会破坏现有持久化值和文件选择契约，拒绝。

## 影响

- 新增语言只需新增一个通过校验的 `langs/{locale}.toml`；所有翻译阶段和 FOMOD 自动使用其语言名。
- UI 从可发现档案生成选项；已保存但当前不可用的 locale 会被明确标记，并在实际运行前失败。
- 固定示例作为语言数据注入通用模板，不再让语言文件拥有整段提示词。
- 旧自定义语言模板需要一次性迁移，没有兼容层或静默降级路径。
