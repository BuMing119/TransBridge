# ADR-042：项目作用域优先的助手长期记忆

- 状态：提议；2026-09-13 用户要求详细规划，尚未授权实现。
- 计划：[assistant-durable-memory](../../plans/assistant-durable-memory/plan.md)。
- 需求：[FR31.1～FR31.10：智能助手自动长期记忆](../requirements.md#fr31-assistant-memory)（草稿）；不恢复已废除的 FR7.13.3 / FR10.5。
- 依赖：[ADR-016](016-modular-monolith-application-composition.md)、[ADR-018](018-project-session-persistence-v2.md)、[ADR-040](040-assistant-user-request-lifecycle.md)、[ADR-041](041-assistant-context-compaction.md)。
- 关系：新增跨会话记忆域；不替代现有请求、摘要、术语、翻译记忆或 Skill 的所有权，不改变 ADR-041 保留旧摘要的约定。

## 背景与已核实事实

旧助手长期记忆已退役，已有用户记忆文件不读取、不迁移、不删除，见[退役记录](../changelogs/maintenance/legacy-assistant-memory/2026-09-13-001-remove-legacy-memory.md)。

当前 ConversationManager 保存完整消息及稳定 message_id；assistant_requests 拥有目标、执行证据和权限；assistant_context 维护请求级 ContextEpoch、冻结材料、不可变摘要链和预算。上下文和 transcript 通过既有附件仓储及 Session CAS 发布，Qt 的 RequestContextPreparation 已提供后台准备入口。现有公开 DTO 没有长期记忆类型，不能把下述接口当成已实现能力。

新需求主要是跨会话保留用户偏好、项目决策理由和已验证经验。运行进度、术语译名、译文、实时服务配置已经有各自的权威来源。

## 决策

### 1. 独立应用域，复用现有运行时

新增 `application/assistant_memory/`，包含作用域、记忆生命周期、查询、提取和失效契约；不依赖 Qt 或供应商 SDK。持久化在 `persistence/assistant_memory/`，供应商与后台运行适配在 `smart_assistant/`，组合入口在 `bootstrap/assistant_memory.py`。

现有 ConversationOrchestrator、ChatWidget、RequestBinding 只增加薄接线；不得承载分类、去重或后台整理实现。不引入 LangChain/LangGraph，不恢复旧 MemoryStore/MemoryWriterThread。理由是现有运行时已经承担所需职责，迁移成本与本次目标不匹配；不将历史 ADR-005 中的框架能力比较当作当前框架限制。

### 2. 内容与作用域

- 记忆类型：`preference`、`project_decision`、`verified_experience`。
- 作用域：本地 profile 的个人记忆，或同一 profile 下的 Project 记忆；Project 记忆可进一步限制 Variant 和目标语言。
- profile 是本地安装/配置身份，不复用每次窗口变化的 owner_id，也不等同于 ParaTranz 用户。owner_id 与 RequestContext 用于当前调用授权。
- 默认写当前 Project；能从用户表达确定为跨项目个人偏好的信息可自动保存为个人记忆，不要求点击确认。不能确定范围时采用更窄的已知范围或暂不写入；没有工程身份时不保存工程特定内容。
- Project/Variant 使用稳定 ID；路径只是存储位置。复制为新 Project 不继承记忆，项目移动但 ID 不变可以继续关联；导出、跨机共享不属于首期。
- 同一语言/范围内冲突不能仅按更新时间解决。当前请求指令优先于偏好；精确范围优先于较宽范围；用户明确纠正优先于模型归纳。无法确定的候选不得替代有效条目。
- 修改作用域不能当作普通正文修订。缩小范围先撤销旧范围的使用资格；扩大范围需明确用户意图。跨 scope 转移以可恢复意图执行“撤销旧条目→在目标 scope 创建新条目”，分别校验权限，不同时持有两个 scope 锁；目标写入失败时旧条目保持撤销，UI 提供完成转移重试，不能悄悄恢复旧范围。
- 模型无权借记忆改变工具权限、许可、任务完成状态、术语库或配置。需要改变这些内容时仍走现有应用命令。

### 3. 数据模型与来源

以下名称是拟新增合同。`MemoryEntry` 保存 memory_id、schema_version、revision、scope、kind、subject_key、content、conditions、origin、source_refs、status、created_at、updated_at、supersedes、verified_at 和适用版本条件。时间使用 UTC；发生时间与记录时间分开，不能以较晚记录时间推断事实较新。

`origin` 区分显式用户要求、用户反馈、模型归纳。`source_refs` 保存 session_id/request_id/message_id 或结果引用及 digest；模型不能自造来源。记忆仓储拥有经过校验的最小摘录，来源全文仍由原会话拥有。跨会话读取记忆不自动获得来源全文读取权限；原文回查经专用授权适配器，不放宽既有 read_request_history 的请求隔离。

持久条目状态为 active / superseded / forgotten / invalid。提取候选只是后台校验阶段的内部数据，不是等待用户审批的条目；未通过校验不参与召回，不提供待确认列表。普通修订保留有界历史和关系；忘记操作不在审计中保留被忘记的正文，只留必要 ID、来源抑制键和处理状态。引用源不可用时明确标注；来源被撤销或删除的后台结果和派生记忆按下面的删除合同失效。

### 4. 存储、原子性与跨进程

首期在应用数据根的全新 `assistant_memory_v1/` 下保存结构化 JSON，按 profile 和 Project scope 分片。每个 scope 用单个版本化文档原子发布 entries、commands、抑制记录和后台工作状态；避免正文和索引双写不一致。目录布局与 ID 编码由仓储控制，模型不接收任意路径写入能力。

复用 PersistenceFilesystemPort、AtomicDocumentStore 的路径边界和写入机制，新增专用 scope OS 锁及 expected_revision 检查。不能把原子替换当成并发事务，也不能借 Session 锁保护跨 Session 的共享记忆。锁只覆盖校验与提交；LLM、长检索及 UI 回调不在锁内。idempotency_key 保证相同命令返回同一结果。

首期有界规模目标为个人加当前 Project 共 2,000 条有效记忆；先以规范化文本和字段扫描检索。容量达到限制时提示整理或拒绝新增，不能静默 LRU 删除有效条目。规模目标通过 S10 验证，未验证前不宣称达到时延指标。JSON schema 独立版本化，未知版本拒绝写入；无记忆目录时不创建空目录，首次保存/显式启用自动整理时才初始化。

未来若查询与写入成本不达标，可在端口后替换为 SQLite；向量索引只作为可重建的派生投影，不能成为权威存储。

### 5. 写入与后台提取

自动记忆是默认工作方式，用户不承担逐条保存或审批工作。明确“记住”以及可确定的长期偏好、用户纠正走即时写入；任务经历通过后台整理自动写入。所有入口都校验真实来源、作用域、内容类型和版本，自动写入资格来自有效的记忆设置与当前调用权限，不依赖模型伪造的 `user_confirmed=true`，也不要求每条记忆都包含“记住”关键词。

读取已保存记忆与自动整理默认开启，提供独立全局和会话开关。后台只从本地已持久化、当前可读且允许学习的来源提取；请求终态或闲置是触发信号，不构成任务完成证据。提取后通过准入、去重和冲突校验即可自动发布 active 版本；候选只在内部处理，不展示待采纳队列。

新事实有可靠来源且范围明确时自动保存；用户明确纠正可自动替代旧版本，完整保留条件与来源。纯猜测、不能确定的冲突、过度概括或需要扩大未知范围时暂不写入，保留既有有效条目，不弹“是否保存记忆”。只有歧义会影响当前任务的实际结果时，才按原有业务交互澄清事实。批量去重、补充证据和等价条目合并可以自动进行，不能借整理改变原意或放宽条件。显式保存显示可撤销回执，普通后台整理在记忆管理中可查看，默认不逐条打扰。

后台按 source watermark + source revision/digest + extractor_version 幂等执行，区分待处理、处理中、完成、失败。默认闲置 5 分钟、每批最多 3 个请求、最多 12,000 个估算输入 token、并发 1、一次有界格式修复；这些是待实测的产品初值。暂停、取消、关闭、来源删除和设置变更都使旧结果失去发布资格。复用用户现有 AI 服务，独立客户端和 usage purpose，不新增隐藏计费服务。

失败保留未消费水位，设置退避与重试上限；用户聊天优先，不能与当前业务调用争抢最后一个并发槽。应用退出停止本地工作；重新打开后按有效水位续整理，不创建无人值守定时任务。

### 6. 召回与稳定上下文

请求开始时按程序提供的 profile、Project、Variant、语言和权限过滤，加载少量适用 active 条目；经验默认通过 `search_memories` / `read_memory` 按需查询。模型不得传入另一个 Project ID 绕过程序作用域。

自动召回初始预算为 `min(1,200 tokens, 可用输入预算的 5%)`，最多 8 条；显式详情查询最多单页 2,000 tokens，并继续受总 ContextBudget 限制。空结果不添加空提示；超限先舍弃低相关经验，不能截断否定条件或挤掉当前 RequiredState。

召回生成 `MemorySnapshot`：条目 ID/revision、scope_revision、policy_revision、digest、来源与内容。它是 material-only 参考材料，在当前请求上下文中按稳定 ID 追加，不伪造 user ingress，不动态改写 system。首次布局、工具结果布局和两供应商最终 payload 均纳入验证。

普通续跑不重新检索/重排已发送快照。明确新查询可以追加新材料。每次 dispatch 前校验已使用记忆的版本与撤销状态：无关新增不使整个前缀失效；相关修订生成一次明确更正事件，并在继续前重新核验。更正不得覆盖用户当前明确要求，也不能悄悄修改 RequiredState 或业务配置。

现有 ContextEpoch/FrozenContextItem 需显式增加 memory source 命名空间、快照引用和依赖元数据，不能伪装成原始消息绕过 authorized_records。具体 schema 升级在 S05 完成；读旧版本映射为空记忆依赖，保留摘要正文和顺序。

### 7. 修改、忘记与不可变摘要

区分三个用户行为：修改记忆、忘记保存的记忆、删除会话原文。普通修改保留“过去如此、现在更正”的历史，追加有效版本说明即可；忘记不得继续把该内容作为记忆材料提供；删除会话由既有会话生命周期负责。

首期采取保守且可验证的活动上下文策略：请求一旦消费某条记忆，该请求后续上下文都记录其依赖（允许多标记，不能漏标记）。该记忆被忘记后，阻止所有受影响请求的后续模型 dispatch，丢弃迟到模型建议和未发布摘要，但继续接收已运行业务任务的真实结果。用户可开启不复制旧历史的干净会话；不自动复制旧计划、权限或重放工具。

不声称已经抹除旧会话或模型已经收到的内容；UI 说明“已停止后续记忆使用；原对话仍保留，受影响会话需要新开干净会话”。原来的任务和结果可从任务中心查看。未来如需在原请求上无感重建干净上下文，另行设计来源依赖过滤并明确修订 ADR-041；首期不绕过不可变摘要合同。

Forget 提交先原子发布 forgotten 状态、正文移除和来源抑制，再使已读版本失效。重复后台提取同一来源不得复活；同 subject_key 的候选也受抑制，只有新的明确保存要求可解除。不能承诺对任意未知同义改写实现绝对语义去重，首期通过来源键和领域主题键验证。

删除源会话时，先持久化删除意图并停止新提取/召回，失效以该会话为依据的条目，再执行既有删除流程；失败保持删除处理中且禁止该来源重新进入记忆。项目删除对项目记忆同样处理。来源全文及会话备份仍归既有删除策略；不能用“忘记记忆”冒充全设备安全擦除。旧备份恢复后必须重放当前撤销记录；撤销记录不可用则禁用记忆等待处理，禁止自动启用旧有效条目。

上述恢复保证针对应用提供的受控恢复入口。用户在应用外替换整个数据目录及撤销记录时，程序不一定能识别其历史，不能宣称能够检测任意文件系统回滚；首期不提供绕过受控恢复的记忆导入入口。

### 8. 错误与用户控制

- `MEMORY_VERSION_CONFLICT`：保留新版本，重新加载；不得用旧模型结果覆盖。
- `MEMORY_SCOPE_DENIED` / `MEMORY_SOURCE_REVOKED`：拒绝并记录原因，不回退跨项目搜索。
- `MEMORY_STORE_UNAVAILABLE`：新请求明确提示后可不使用记忆继续；已消费记忆的请求若无法校验撤销状态，进入准备等待。
- `MEMORY_CONTEXT_REVOKED`：停止受影响模型续跑，提供干净会话入口；不把业务请求标记失败。
- `MEMORY_EXTRACT_FAILED`：普通聊天继续；后台显示可重试诊断。
- `MEMORY_CAPACITY_REACHED`：不静默删除，提供整理入口。

UI 提供个人/当前项目列表、来源、最近自动更新、编辑、范围、忘记、当前会话使用记忆/允许学习开关；不设置候选审批、批量采纳或待办提示。复用主题与 worker/coordinator，不将磁盘扫描或模型调用放入 Qt 事件循环。

### 9. 可观测性与验证

记录写入/召回/修订/撤销原因、条目版本、命中但未采用原因、预算、后台调用 usage 和耗时；默认日志不保存正文、API Key 或用户原文。依赖现有 request/session/attempt 身份，但 memory revision 独立。

先用合成资料验证正确性、隔离、重复操作、崩溃、双进程写、三次压缩后更正/撤销、最终供应商 payload 和 UI 响应。真实模型比较使用相同 provider/model、任务集、预算与工具：无记忆、仅显式记忆、默认自动记忆三种策略；不把关键词检索命中率当成任务成功率。增加无需“记住”口令、无需点击保存即可跨会话使用的端到端门禁，同时验证不确定信息不会被错误写入。

## 备选方案与取舍

- Markdown 索引＋模型直接改文件：直观，但作用域、版本、撤销和并发规则仍需额外实现；首期采用 UI 编辑结构化记录，未来可提供 Markdown 导出。
- JSON 结构化记录＋应用管理：复用现有持久化方式、依赖少，首期采用；代价是有界规模下的扫描和整 scope 写入，S10 设替换条件。
- SQLite 权威库＋检索索引：事务与大规模查询更合适，保留为规模门槛后的替换候选；当前不同时维护两种权威存储。
- 全量聊天向量化：难以直接表达否定、更新与授权，不满足自动记忆的筛选与纠错合同。
- 完整框架迁移：与本次跨会话记忆目标不成比例。

## 迁移、回退与发布条件

新目录独立启用，不扫描旧 `data/memory`。无需迁移 Project/Variant 业务 schema；上下文扩展必须版本化并更新附件清理器。现有会话只在功能启用且首次使用记忆时产生新格式；关闭自动提取不撤销已保存记忆，关闭读取按上述活动上下文规则处理。

工程上先完成 S01～S07 的存储、调用和管理基础，再完成 S08～S09 的自动提取与整理；内部阶段验收不代表可发布功能。首个用户版本需通过 S01～S09 与 S10 完整门禁，提供无需点击保存的自动记忆闭环。忘记、跨项目隔离和活动上下文撤销未通过前，不发布可读取长期记忆的版本。

回退使用同版本关闭功能或升级前整套备份；旧程序不保证可读取新增上下文 schema。恢复备份必须保留较新的撤销记录，且不宣称供应商侧历史调用已经删除。
