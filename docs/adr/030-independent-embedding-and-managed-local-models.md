# ADR-030: 独立 Embedding 配置与受管本地模型生命周期

- **状态**: 提议
- **日期**: 2026-08-27
- **对应需求**: [FR5.14](../requirements.md)
- **关联 ADR**: [ADR-010](010-infra-extraction.md)、[ADR-013](013-vector-retrieval-enhancement.md)、[ADR-020](020-high-performance-ui-foundation.md)

## 背景与约束

TransBridge 已有 `disabled`、`local`、`api` 三种 Embedding 模式，并以独立 `EmbeddingConfig` 和凭据引用保存部分配置。然而当前边界仍不完整：

- API 客户端工厂、连接检查和运行前预检会在 Embedding Key 或 Base URL 为空时回退到主 LLM。
- Embedding 面板也用“留空则复用上方 LLM”引导用户，配置体验与主 LLM 的成熟度不一致。
- 本地客户端接收模型名称后可由 `sentence-transformers` 在加载时访问网络，选择本地模式可能变成不可观察、不可取消的隐式下载。
- 配置只保存一个自由文本本地模型值，没有应用内预设目录、安装完整性、下载状态、选择或安全删除合同。
- 本地模式缺少模型时，用户只会在预检或加载失败处看到技术性错误，不能明确选择关闭或进入配置。

Embedding 是可选增强能力。缺少它不得阻断不依赖语义检索的解析、编辑、精确术语匹配、翻译、保存和写回旅程。统一配置仍必须遵守 FR21.9 的 `ConfigRepository`、独立 credential reference 和原子 revision 合同；UI 继续遵守 ADR-020 的主题、后台任务和展示边界。

## 决策

### 1. Embedding API 是独立配置域

`EmbeddingConfig` 继续作为 Embedding 的权威配置对象，拥有自己的 mode、provider、model、Base URL、API Key credential reference 和本地模型选择。主 LLM 与 Embedding 可由同一服务商承载，但只允许用户在两个面板分别显式填写；以下边界禁止任何字段回退：

- View/Presenter 的渲染、保存与校验；
- 运行前预检；
- `create_embedding_client()` 及具体 API adapter；
- 独立连接检查和诊断。

配置仍通过统一 `ConfigRepository` 原子提交，不另建第二套 INI。这里的“独立”指值、凭据和验证语义独立，不是绕过统一配置基础设施。

`EmbeddingConfig.mode` 是启停的权威事实来源。关闭引导必须持久化 `disabled`；兼容字段不得形成另一个可以与 mode 冲突的启停真相。

### 2. 本地模型使用版本化预设目录和受管存储

应用随版本提供离线可读、版本化的预设模型目录。每个条目至少声明稳定 model ID、展示名称、用途说明、来源、固定 revision、预估大小和运行所需入口信息。目录只描述可供选择的模型，不代表模型已随应用安装。

受管模型存储位于应用数据目录下的专用 Embedding 根目录。每个完整安装保存独立 manifest，至少包含 catalog/model ID、revision、安装状态和可用于索引身份的模型指纹。配置只持久化稳定的选中模型身份；运行时由模型管理服务解析为已验证的本地路径，不把用户输入的仓库名直接交给推理客户端。

模型目录读取、状态扫描、选择、删除和下载编排由独立的模型管理服务负责；Qt View 只提交意图并渲染快照，Embedding 推理 adapter 只加载已解析的本地安装。业务运行不得反向承担下载或目录修复责任。

### 3. 显式下载与本地推理解耦

只有模型管理界面的用户动作可以启动网络下载。下载在工作线程执行，写入受管根目录内的任务专属 staging 目录，支持进度、取消和重试；内容完成并通过完整性检查后，再通过同一文件系统内的原子切换发布为可用安装。

取消、异常退出、校验失败或磁盘不足时，staging 不得成为 installed 状态，也不得覆盖既有完整安装。推理客户端使用只读、本地限定加载方式；预检、连接检查、索引初始化、应用启动和正式运行均不得触发模型下载。

### 4. UI 使用同一产品语言，但不共享值

Embedding API 区复用主 LLM 配置已经建立的信息层级、Provider 选择模式、密码显示/隐藏、字段校验、连接检查和状态反馈。Provider 预设可以填充 Embedding 自身的端点和建议模型，不能读取或改写主 LLM 值。

本地模式使用模型管理视图替代自由文本“模型名”输入。视图按 catalog 项展示未安装、下载中、已安装、当前选中和失败状态，并提供下载、取消、重试、选择和删除动作。下载完成后可以自动选中该模型，但不自动开始业务运行或索引构建。

### 5. 无可用模型时使用事件触发的引导闭环

引导只在以下事件发生且没有完整、已选中的本地模型时出现：

1. 用户主动选择本地语义检索；
2. 用户启动一个确实需要本地语义检索的运行。

应用普通启动、仅打开设置或存在无效历史值不会无条件弹出引导。引导明确说明语义检索不可用而普通功能不受影响，并提供“关闭语义检索”和“前往模型配置”。

“关闭语义检索”、窗口关闭按钮与 Esc 是同一命令：原子持久化 `mode=disabled` 后关闭引导。“前往模型配置”打开并定位本地模型管理区；完成有效安装与选择前，持久化模式仍保持 disabled，从而避免 UI 显示开启而运行时不可用。

### 6. 删除与索引失效遵守安全边界

删除动作只接受模型管理服务返回的受管 model ID，并在解析后验证最终路径仍位于专用模型根目录内；不得接受 UI 传入的任意文件系统路径。删除当前选中模型需要确认，并先原子切换到 disabled、释放运行时引用，再删除该安装。

模型选择与 revision 进入 ADR-013 的 embedding fingerprint。切换、升级或删除模型后，旧索引只标记为 stale 并在下次需要时重建；删除模型不递归清理不属于该模型安装的用户数据或其他模型。

## 关键契约与错误语义

- API 模式缺少任一独立必填字段时，在网络请求前返回定位到 Embedding 面板的校验错误；不得用主 LLM 值让请求“碰巧成功”。
- 本地模式只有完整 manifest、目录边界和运行入口均通过校验后才可选；目录存在不等于安装成功。
- 所有模型下载、扫描和删除操作不得阻塞 Qt 事件循环。窗口关闭或应用退出时应请求取消并安全收敛，不发布半成品。
- API Key 不进入配置明文、日志、错误、model manifest、catalog 或索引 fingerprint。
- 下载源错误、网络失败、磁盘不足、校验失败和取消需要可区分诊断；这些失败不改变既有已安装模型与当前 API 配置。
- disabled 模式不加载本地推理依赖、模型、FAISS 索引或语料，也不显示无模型引导。

## 备选方案

### 默认复用主 LLM 配置

填写更少，但会继续混淆两种 API 的模型、端点、权限和计费边界，也无法可靠解释连接检查结果，拒绝。

### 保留自由文本模型名并让 `sentence-transformers` 自动下载

实现改动小，但下载时机、来源、进度、取消、空间和失败恢复均不可控，且运行与网络副作用耦合，拒绝。

### 随安装包捆绑一个默认模型

离线开箱即用，但显著增大安装体积，重新形成产品与单一模型版本的强绑定，也剥夺用户选择，拒绝。

### 仅提供文件夹选择器

支持高级用户自备模型，但无法为主要用户提供可理解的预设、安装状态与安全生命周期，也扩大任意路径删除风险；本轮不作为主流程。

## 影响与风险

- 正面影响：API 责任与错误来源清晰；本地模型下载可见、可取消、可恢复；无模型时形成明确退出与修复路径。
- 兼容影响：过去依靠主 LLM fallback 才能工作的 Embedding API 配置将在升级后被判定为不完整，需要用户在 Embedding 面板显式填写。
- 存储影响：应用数据目录会持有一个或多个可删除的模型安装，UI 必须显示预估大小与状态。
- 实现风险：下载取消、进程退出和 Windows 文件占用可能留下 staging；模型管理服务必须把它与 installed 严格区分，并只清理由自身创建且通过根路径校验的目录。
- 产品风险：预设目录中的模型来源、revision 和说明需要随发布维护；目录变更不得静默替换已安装模型或改变当前选择。

## 迁移与回退

- 保留已有显式填写的 Embedding provider/model/Base URL 和独立凭据引用；空字段不再从主 LLM 补齐。
- 旧 `local_model_path` 或模型名称不得触发网络。升级后若它不能映射为完整的受管安装，则切换为 disabled；只在用户再次选择本地模式或运行相关任务时显示引导。
- 旧索引因缺少新的受管模型身份或 fingerprint 不匹配而安全重建一次，不静默复用。
- 回退实现时不得删除已下载模型；可把 Embedding 切换为 disabled，并保留受管目录供后续版本重新发现。需要清理时必须由用户在模型管理界面显式删除。
