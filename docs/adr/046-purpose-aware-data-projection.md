# ADR-046：按来源与用途保护凭据，业务数据保持原样

状态：已接受（用户于 2026-10-07 确认方案并授权完整实施）。

部分取代 ADR-012 的全量字符串模式脱敏及 ADR-016 对共享脱敏边界的泛化解释；权限、路径授权、大小预算和安全存储决策继续有效。

## 背景与约束

同一递归 redactor 曾用于 ToolResult、重试参数、MCP、报告 metadata 和日志。游戏文本中的 password/token 被当成凭据；包含原文的 EntryKey 失去可往返性，查询重试改变搜索条件，报告诊断不能归属词条。报告 metadata 还混入后续术语匹配使用的插件作用域。

原文、译文、术语、上下文、标签、查询、路径、业务身份和 schema 必须按其来源保持原样。真实账户凭据必须隔离；不能通过取消凭据保护来修复误伤，也不能通过修改源 key/id 或引入临时词条编号绕开问题。

## 决策与关键契约

- 业务投射 `project_business_data(value)` 只递归分离副本，不按普通字符串内容或字典键名猜测凭据。显式 `SecretValue` 投射成隐藏标记；显式 `DiagnosticValue` 表示来自技术错误/认证诊断，按技术规则投射。普通业务字典中的 token/password 是合法键。
- `SecretValue` 放在 application/security，原 config 导入路径保持兼容。真实配置凭据只在认证边界解封；配置查询显式列出普通字段和凭据是否配置，不输出密钥。
- `SecretRedactor` 保留为技术诊断策略，可使用请求实际绑定的已知凭据做精确替换；模式匹配仅用于该技术来源，不能重新扫描业务正文。技术日志处理完整异常栈；本地业务请求/响应日志保持正文，包括分段和格式校验失败响应。
- ToolResult/Observation/MCP 使用相同业务投射合同，`get`、下标和序列化含义一致。类型/大小检查保留，模型展示摘要可截断但不修改执行证据。技术错误在产生处明确处理，不把含词条身份的失败说明统一当凭据字符串。
- 重试提示保留完整业务参数和工具 schema；显式凭据类型或 schema 的 writeOnly 属性保护真正凭据，执行恢复由程序负责。未声明参数不把值送给修复模型。一次性确认令牌与账户凭据分开，保留原有作用域和重放校验。
- 报告业务说明、原文译文和诊断定位字段保真；技术细节显式标注。术语插件作用域从 report_details 移到业务字段。旧快照可读取，新的 checkpoint/history 保留该字段。
- 工程、撤销、断点、会话与请求状态保留身份和业务内容；日志/展示副本不作为恢复权威。HTML/CSV 转义、路径授权、输入 schema 和权限确认不受此决策影响。

## 备选方案

整体关闭保护无法满足凭据安全；仅豁免 original/key 字段会漏掉查询、动态字典键、术语和诊断引用；临时词条编号不能修复业务文本及重试被改写。因此选择来源显式分类和业务保真投射。

## 兼容、风险与回退

不修改源 key/id、普通 EntryKey 格式，不迁移用户文件。新增业务字段有默认值，读取旧 report_details 中的插件作用域作为兼容输入，新写出使用明确字段。旧 checkpoint 没有保存的作用域，仅在输入指纹通过核验后按 EntryKey 从原始输入补回；没有可靠来源时不猜测。旧记录已经替换的文字不能猜测恢复，有原始来源时重新查询/生成。

普通字符串不再由全局启发式保护，新增出口必须显式隔离账户凭据，技术异常使用诊断投射。测试同时覆盖业务保真和真实凭据不泄露。回退时不可把新保存的业务正文误判为必须删除的凭据。
