# ADR-044：源文件更新与多版本迁移

- 状态：提议（实现已按用户授权推进）
- 日期：2026-10-01
- 需求：[FR19.14](../requirements.md#fr19-source-update)；ParaTranz 顺序衔接遵守 [FR22.9～FR22.11](../requirements.md#fr22-context-order)。
- 关联：ADR-018、[实现计划](../../plans/source-file-update/plan.md)
- 部分取代：来源修订保留与打开恢复遵守 [ADR-049](049-task-result-lifecycle.md) 的持久来源成果契约；本 ADR 的源更新预览和多版本事务保持。

## 背景与约束

来源指纹不匹配时，既有工程进入只读恢复；来源管理仅有新增和移除。正式 Variant 不保存原文与源顺序，不能靠比较翻译版本还原插件升级差异。一个工程的多个 Variant 共用来源登记，单独迁移当前版本会让其余版本无法正常加载。

## 决策

使用独立“更新源文件…”用例，接受一组来源与同格式新版的配对。每对来源保持登记 ID，按该来源唯一 local_key 迁移全部版本，并更新内容 namespace、指纹与路径。正常工作台与恢复窗口共用准备和提交服务，Qt 负责配对、后台调度及确认。

预览令牌绑定 owner、生命周期代际、工程与全部版本的预览前状态，以及本批每个来源的原引用路径和新版解析结果。确认时重新解析全部新版，核验每项解析结果与源文件指纹。来源更新本身不访问 ParaTranz。

原文可验证且内容相同的条目保留状态；原文/上下文变化或旧原文无法验证时保留译文并标为待复核；新增沿用新基线；删除保留在完整旧工程/旧版本备份中。跨来源快照恢复使用快照中留存的来源和版本数据。

## 持久化与故障恢复

项目存储使用一次 SQLite 写事务核验工程和全部 Variant 版本及每个旧来源引用。事务为所有版本建立同一批次的更新前快照，并一次写入来源登记、来源事实和全部 Variant。事务失败时这些写入一并回滚。批处理中每对来源继续使用原有匹配规则，应用层合并迁移结果后仅推进一次工程及版本 revision。

活动工程使用既有 lifecycle 内容提交边界，持久化成功后同步内存及已保存 revision。若提交回执丢失，按预览令牌对应的事务快照和已提交版本确认结果。来源基准缓存更新失败时清除旧缓存，后续从 SQLite 读取。Qt 使用已提交来源和当前工作副本安装工作台视图，恢复期间的新译文保持未保存，视图安装失败可单独重试。非活动工程提交使过期的待激活计划失效，继续保留当前工作台。

跨来源快照恢复复用已提交来源的视图恢复入口，恢复前备份与来源恢复在同一 SQLite 事务中写入。手工打开文件、拖入插件、助手登记和移除来源使用当前工作副本安装槽位，来源增删随显式保存落盘。两种视图恢复都由 ProjectViewBinding 安装，刷新重试只重新读取或发布视图。

## 备选与影响

- 先删除再新增：会丢失条目状态、破坏多版本关系，拒绝采用。
- 忽略指纹直接打开：不能区分旧译文与新原文，也没有可审阅的影响预览，拒绝采用。
- 只更新当前翻译版本：工程级来源登记会与其他版本冲突，拒绝采用。
- 来源修订持久保留：由 ADR-049 的内容寻址成果提供完整输入与基线，不新增用户版本历史；已有成果可用于更新前的原文比对，旧工程确实没有可验证成果时仍标待复核。

工程数据库中的更新前快照保留可恢复的翻译状态。旧文件已覆盖或丢失时，可使用工程已保存的来源内容继续更新。需要来源修复时从恢复窗口进入。本地化插件依据已保存的翻译事实核对旧原文，无法取得可靠旧内容时采用无法验证策略。
