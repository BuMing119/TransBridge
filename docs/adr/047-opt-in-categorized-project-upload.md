# ADR-047：普通与分类上传使用文件 API

状态：已接受。2026-10-25 用户明确授权文件 API 方案及实施，取代此前逐词条实时核验和本地上传关联保存合同。历史实现与测量保留在既有 changelog，不作为当前要求。

## 背景与约束

普通和分类上传都曾将已有文件拆成词条操作，外层/底层重复读取词条、文件路径，上传后还保存全部外部关联，导致请求数及本地保存成本随词条数增长。

官网 OpenAPI 0.5.7（2026-10-25 只读核查，https://paratranz.cn/api-docs?format=json）已提供文件级创建、增量原文更新、按 key 批量导入译文及服务端保护策略。不能再在客户端重建同一套逐词条同步机制。

## 决策与关键契约

- 普通固定根目录 `<插件名>.json`，分类固定 `<插件名>/<分类>.json`；Quest 对话及任务日志保持 `插件/任务/`。名称以全部登记来源计算，单独/批量一致。保留本地原 key、原文限定身份与来源顺序；原文限定词条在传输时编码，不生成冲突小文件。
- 分类上传和本地脚本仅使用 application/io/paratranz_classification.py 的共享分类结果。每个完整来源内索引准确 FormID 对应的 QUST:FULL.original，唯一非空任务原名优先，缺失/歧义回退 Quest ID；分组身份始终是 Quest ID。清理/截断/大小写撞名时追加 Quest ID，选择前确定路径，不使用译文作为文件名。未知类型进入其他，完整来源顺序按统一策略投影。脚本输出根下同样使用任务/子目录，保留旧导出函数及两个脚本转换能力。
- 传输规则由 application/io/paratranz_keys.py 统一：限定身份生成 `__transbridge_key__:v1:o:<无填充base64url原key>:<完整SHA256精确UTF-8原文>`；普通 key 不变，命中保留前缀则用 v1:k 转义。依据完整本地身份编码，与所选子集、顺序、分类、译文及 ID 无关。同身份重复仍拒绝，不用编号制造新身份。在线下载及 JSON 导入还原完整 EntryKey；无法识别或哈希不符明确诊断。原始线上载荷仍参与远端修订计算，旧上传快照不解码，避免误用于词条写入。
- 单独/批量入口先选择普通或分类；文件窗口只读加载本地文件并选择上传内容。支持仅原文、仅安全译文、仅强制译文、原文加安全译文。默认仅原文，原文更新显式传 `incremental=true`，保留云端缺失项。纯译文模式不创建文件或词条。
- 应用层 `application/file_upload.py` 生成文件布局、序列化不含远端 ID 的记录、执行文件操作并汇总回执。每次上传获取一次当前文件列表，以完整路径解析当前 file_id；不读取项目词条、不逐词条核验或回读、不调用 strings 写接口。
- HTTP 层 `paratranz/file_publication.py` 使用 `ParatranzFilesAPI`：新建 POST /files；原文 POST /files/{id}；译文 POST /files/{id}/translation，直接提交 key/translation/stage 数组。原文/上下文由所选接口语义决定；译文安全模式沿用服务端人工保护。文档明确译文导入需管理员以上权限，不降级到词条接口。
- `hashMatched`、`unchanged` 是成功无变更；`empty` 不当作成功。创建响应读取 {file, revision} 中的文件 ID。只确认文件操作完成，不宣称安全模式覆盖了每一条译文。
- 每个服务/已验证用户共享保守的每秒一次请求预算（缺用户身份时用凭据摘要隔离）；默认串行调用。仅明确 429 拒绝可按 Retry-After 有界重试；423 显示文件忙。超时/未知写入不自动重放；明确 404 最多刷新文件列表重新定位一次。同路径重建使用当前 ID，不因历史 ID 不同要求审阅。
- 413 保留确定性文件拆分及来源顺序；译文请求过大时在同一文件内拆批，不创建其他文件。新建/原文阶段与译文阶段分别记录已提交事实，部分失败不报全部成功。
- 上传保留本地工程、版本、账号和修订的轻量检查，后台运行、可取消、有界进度及日志；进度/结果按文件计数。上传不修改译文版本，不提交 file_id/entry_id 关联，不隐式保存未保存工作。
- GUI 下载按当前插件根文件、共享分类器当前生成的精确分类路径及 `_N.json` 分片解析本轮 ID，使用 GET /files/{id}/translation 一次读取完整词条。2026-10-25 用户明确要求同时兼容带插件后缀及旧版省略后缀的文件：整来源优先 `.esp/.esm/.esl` 新布局，新布局不存在时才读旧布局，不混合两代内容，不以新文件为空或读取失败触发降级。读中 404 限同代重定位，明确重试重新选择；大小写精确优先、其余唯一时兼容。全部启用来源决定旧名归属，防止未选来源、同 stem 或数字分片名串读。不扫描整个分类目录，不读取旧文件绑定、旧任务名/冲突文件或回退全项目 strings；无法确定当前源路径时明确失败。
- 一轮下载只验证一次项目权限、读取一次完整文件列表和每个匹配文件的内容。不可变快照贯穿复核、策略/选择修改、授权和执行；后两阶段只验证本地状态，不再请求云端。更换目标、账号、配置、来源路径、本地内容/修订、工程版本或重开窗口创建新快照，不建立跨窗口缓存。
- 当前工程同步按同一插件的精确原文/译文内容自动匹配，允许旧 key 变化及同内容供多个本地 key 复用，不保存云端身份。唯一非空译文直接采用，相同译文不因上下文/状态不同制造冲突；不同译文先按准确 key/上下文、本地现译等确定证据收窄，仍不唯一才复核。无一致原文或云端无译文保留本地并说明，不跨插件、不归一化原文，空原文只按准确 key。状态分歧保留已一致本地状态或保守已翻译，不凭空制造审阅/锁定状态。内容模式由当前工程显式启用，独立严格下载、上传及双向同步保持原合同；原文限定身份、响应完整性和同步期间新编辑保护继续有效。GUI 不新增或删除源条目，保留原文、上下文和顺序，提交前核对目标/版本及本地修订。
- 一次点击自动保存后按钮显示“已保存”并禁用，完整无变化时显示“已完成”；只有实际未完成的读取/保存或持续重规划允许原地重试。真正复核接受后自动继续，已保存项不要求第二次点击。同工程/版本的权威提交统一推进全部已加载槽位的译文与状态，更新当前工作台统计；以提交前权威值、当前可见值和新权威值三方协调，真正未提交内容保持保护。批量替换在接收提交的后台线程准备，Qt 核对准备输入未变化后整体发布，过期准备重新协调；保存/退出一致性检查不绕过。
- 无业务调用的旧分类 planner/direct/executor 闭环、逐词条冲突拆文件、旧分类 upload_collection 与专用窗口移除。旧分类 FileBinding、工程绑定读写/保存回执及只服务该闭环的基准脚本一并删除；工程权威来源 snapshot/current 与修订保护保留。普通单文件兼容上传、独立通用同步和共享文件工具按真实调用保留。历史工程扩展字段不再读取，不触发额外工程迁移。

## 影响与风险

新增职责独立于 PyQt，复用工程权威来源读取与现有分类规则。生产 facade 的普通上传与分类入口共用文件窗口和执行器；注入自定义计划窗口的兼容调用仍使用独立同步合同。

安全/强制导入遵守平台规则，无法替代多人协作的服务端条件写入。文件列表读取后若别人移动文件，平台不提供路径条件写入，不能承诺客户端原子保护；不以增加逐条检查冒充保证。增量默认不会清理旧文件或远端余项；镜像删除不是默认行为。

## 备选方案

拒绝继续优化逐词条 GET/PUT 或增加并发：请求数量仍随条目数增长，且重复了服务端文件导入功能。拒绝依赖历史 file_id 识别替换并要求重新审阅：当前完整路径已定义业务目标。

## 迁移与回退

不修改工程 schema、本地/插件 key 或持久化格式。省略插件后缀的旧根文件/分类目录可按上述优先级直接只读同步，无需先重传；历史冲突文件、旧任务名/ID 路径不在兼容范围。不自动搬迁或删除云端旧记录，不宣称迁移评论/历史。下载忽略旧关联，发生本地合并时当前项目的旧词条关联退出本地状态，其他系统/项目关联保持。当前路径内的裸 key 仍是合法传输格式；离线 JSON 编解码按文件内容处理，不承担云端路径兼容。初次切换传输 key 必须先建立原文再导入译文。删除旧直接下载/绑定下载接口会影响仓库外直接调用方，应改用当前文件快照和计划入口；两个转换脚本及本地导出函数保留。真实云端写入未在本次自动验证中执行；受控 HTTP/session 和真实本地工程回归不替代线上验收。
