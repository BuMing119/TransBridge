# ADR-003: 三轮 AI 翻译策略

- **状态**: 已接受
- **日期**: 2026-03 (回顾性记录于 2026-05-06)
- **决策者**: BuMing

## Context

AI 翻译需要处理不同类型的游戏文本：专有名词（NPC 名称、地名、物品名）、对话文本（按任务线组织）、长文本（书籍、信件、描述）。不同类型的文本对翻译质量和上下文连贯性有不同的要求。需要定义翻译的批次划分和执行顺序。

## Decision

采用**三轮翻译策略**，按文本类型和上下文需求分轮次执行：

| 轮次 | 目标 | Context 匹配 | 并发模式 | 术语写入 |
|------|------|-------------|----------|---------|
| Round1 | 命名实体 | NPC_/BOOK/QUST/CELL/WOOP/MGEF 等的 FULL/DESC/SHRT | 全部并发 | 自动写入动态术语库 |
| Round2 | 对话 | INFO:NAM1\|{quest_formid} | quest 间并发，quest 内串行 | 抽取专有名词 |
| Round3 | 长文本 | BOOK CNAM/DESC, INFO 长响应 | 全部并发 | 不写入 |

**核心原则**: Round1 先建立术语基础 → Round2 利用术语库确保对话上下文内术语一致 → Round3 最后处理需要完整上下文的文本。

## Consequences

- **正**: Round1 结果即时对 Round2/3 可见（in-flight 术语缓存），术语一致性显著提升
- **正**: 同一 quest 的对话串行执行，保持上下文连贯
- **正**: quest 间并发，整体吞吐量不低
- **负**: Round2 的混合并发模型（组间并发+组内串行）实现复杂
- **负**: 如果 Round1 翻译错误，错误术语会传播到 Round2/3

## Alternatives Considered

- **全并发单轮**: 所有条目一次性并发翻译 → 拒绝：术语不一致，上下文断裂
- **全串行**: 逐条翻译 → 拒绝：太慢，无并发优势
- **LangGraph 状态图**: 用 LangGraph 编排多轮 → 拒绝：见 ADR-005
