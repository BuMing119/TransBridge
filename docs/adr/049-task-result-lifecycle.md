# ADR-049：固定任务输入、独立成果与局部合入

- 状态：已接受；用户明确确认统一运行流程、工程包自动升级、仅兼容 `.transbridge` 与删除旧执行链。各轮实现验证记录不代替用户桌面验收。
- 日期：2026-10-26
- 需求：FR19.15，及 FR3.3、FR5.13、FR19.13 的相关修订
- 局部取代：[ADR-037](037-unified-ai-task.md) 中整版本有效性守卫及反复后置快照；[ADR-047](047-opt-in-categorized-project-upload.md) 中因本地编辑失效、下载成果仅会话内保留的约束；[ADR-044](044-source-file-update.md) 中不持久保存来源修订及无法保留旧 Strings 的限制。身份、线程、文件 API 与原子发布边界仍保留。

## 背景与约束

AI 已经具有独立 TaskDraft 和恢复记录，但执行后仍比较全局项目修订、所有 collection 和实时配置。应用结果复制全量词条并重新捕获全项目；结果整理和磁盘写入绑定导致保存失败时成果没有交付 UI。下载已有局部 rebase，但单项冲突仍可阻塞整批，成果缓存只在会话中。VariantAggregate.snapshot 重复构建 immutable snapshot；dirty no-op 保存会额外增加版本修订。

保持当前项目文件格式、产品入口和用户手动历史功能。删除仓库内部废弃接口及其专属测试，不为未使用的 Python 入口维持第二套运行逻辑。原有 pyproject.toml/uv.lock 的 0.2.1.8 修改不属于本任务。

## 决策与关键契约

1. 开始时固定输入、请求配置与冲突偏好。捕获过程需一致，完成捕获后不以实时全局 revision 或未来任务设置判断已有任务有效性。
2. 产出、耐久保存、合入三种状态独立。磁盘错误不得丢失内存成果或要求重新调用 AI。自动合入之前先保留成果；覆盖前工作台内容也必须有可恢复证据。
3. `application/translation/result_merge.py` 提供无 Qt、磁盘和配置依赖的三方比较。只遍历 incoming 中的目标条目。translation/stage 是关联状态；未修改字段不覆盖。current==incoming 幂等，incoming==base 保留 current，current==base 应用 incoming，其余为真冲突。
4. 原文/相关上下文变更、缺失/删除始终待处理；默认策略不越过此边界。下载、导入和词典成果额外捕获来源指纹、定位元数据和 string_id 的签名，来源定位变化不得强行合入。已有审阅状态未捕获该可选签名时按其实际捕获字段比较，不把新增字段本身误判成用户编辑。KEEP_CURRENT、PREFER_INCOMING、DEFER 分别保留当前、采用新成果、暂缓。真正冲突的三方证据始终保留，包括已自动决策的条目。
5. 项目命令适配读取当前权威数据，复用稀疏 patch 和原子 CAS。小批量目标从已排序 snapshot 中定位，大批量单次遍历；空 patch 不扫描条目，但仍执行必要提交保护和 dirty 保存。CAS 使用本次合入读取的 revision，竞争时有界重新比较；不把任务开始 revision 当作整批永久门禁。成果审阅绑定原始持久记录的目标身份，不能将当前界面目标当作原任务归属。
6. 成果存储与任务/下载适配独立。包含来源、目标身份、固定输入、新结果、处理策略、覆盖前内容和处理状态。提交尝试证据与实际成功回执分开，恢复仅消费后者证明的应用项；回执失败保留重试材料，不撤销已发生的应用。未处理成果不能被临时清理；重复写入应覆盖同一记录或复用不可变 payload，不能每次处理复制整个项目。
7. 设置使用 ConfigRepository 独立 section，不扩大 LLMConfig。AI、下载分别配置，缺省 KEEP_CURRENT。UI 集中呈现分歧，支持以后处理和当前批次主动选择。
8. unchanged aggregate 复用 snapshot，no-op 保存不增加内容 revision。自动保存当前文件继续；任务不按部分应用/重试反复创建完整历史，使用必要的局部恢复证据。手动历史保持。
   历史列表单次读取每个文件，仅校验展示元信息，不构造 VariantSnapshot；实际恢复仍完整验证内容。正常翻译不再写或删除旧 ProgressCheckpoint 文件，当前候选、校对和后处理恢复记录各自保留其现行职责。
   工作台合入使用已经安装并验证的来源原文，按 baseline 对象身份和来源指纹复用读模型；文件在外部变化应通过更新来源安装。插件输出使用完整捕获的来源修订及本地化依赖；目标覆盖仍核对实际目标内容，单纯另存不因外部源文件后来改变而失效。普通任务保存仅固定工程/版本身份，保存最新内容；不因中途无关修订拒绝保存。
   投影仅保留上轮不可变条目及冻结行，未变对象复用，目标切换和关闭释放；正常修订、dirty 与界面通知保留。clean 保存不重建投影，只确认保存状态时不复制整份内容。同一保存事务按实际读取的完整字节复用验证结果，缓存不跨事务；目标和写后内容仍验证，外部写入不能依靠相同 revision 命中缓存。
9. 退出保留线程和原子写入的收尾机制，提供取消退出；旧 close attempt 的回调不能关闭新会话。待处理冲突不是运行中的后台任务。
10. 运行时只使用当前工程投影、命令服务和存储。删除 ProjectHandle/VariantStore、旧 AI 启动与进度链、旧 Sync GUI 执行器、缺少新接口时调用旧接口的回退。GUI 保存合并并发请求，保存完成只确认原目标；期间新编辑保留 dirty。手动历史仍由同一工程服务管理。
11. 兼容限定在读取边界：只接受 `.transbridge` → 自动识别包内格式并迁移 → 当前工程发布 → 同一打开流程。工程、翻译版本及历史快照内嵌版本一起转换，不提示用户选择新旧格式或另行升级；未打包的目录和独立 `project.json` 不提供兼容入口。导入不修改原包，不覆盖已有工程，不因升级额外创建正式版本或历史；保留所有版本、历史、显式空译文、阶段与来源证据。旧历史仅存局部词条时，以已验证来源补全缺失项，使其成为可恢复的完整历史；明确保存的空译文不能被来源默认值覆盖。来源无法证明时保持只读恢复。旧 AI 报告、恢复记录、校对检查点及下载成果随工程保留为拥有原路径与摘要记录的附件；可解析的 AI 成果在历史读取入口展示和导出，不授予旧任务覆盖当前工程的权限。坏的附属成果保留原始字节和诊断，不阻断其余工程内容；路径穿越、链接与超限仍在输入边界拒绝。旧云端文件名解析保留。
12. 旧 workspace 中的工程目录不再作为运行时工程目录或活跃引用。仍需的界面偏好由会话设置持久化，读取已有文件时保留未知旧字段。当前工程目录与身份来自 repository。
13. 助手翻译、润色与 GUI 共用应用层的固定草稿、逐条成果及恢复记录，不从助手反向调用 Qt TaskSession，也不维护第二套合并算法。下载、导入和词典以明确成果种类复用存储、查询与逐条合入，不伪造 AI 执行记录；下载默认只保存，导入追加和词典保存后合入。成果查询和再次合入不依赖运行线程仍存在；再次合入不重新请求模型、远端、解析器或词典。请求外层仅固定目标身份与选区，不使用开始时全局修订号拒绝工具读取；实际即时修改比较目标条目或标签基线，并取得最新 CAS。运行许可、取消、请求所有权及实际提交的撤销证据仍有效。
14. 助手逐条上传固定远端配置和请求内容，单独保存请求前状态、已确认回执与不确定结果。远端成功与本地关联成功分开记录；关联仅更新对应 external_refs，保留合入时最新译文、阶段及其他引用。网络中断后的未知结果不能当作未上传自动重发；已确认上传的关联恢复只执行本地命令。上传凭据不写入成果记录。
15. 来源导入将原始字节、解析条目、部分失败诊断及歧义候选作为成果保留，正式来源准备与助手使用同一构造契约；登记和恢复使用已准备内容，不再次读取路径。重复完整身份的导入候选全部隔离，不采用最后一条。结构登记分 attempting、failed、committed，尝试不证明成功；真实成功回执失败保留内存补写，跨重启仅剩尝试记录时不自动重放新增，也不冒认后来由其他操作登记的来源。用户删除已登记来源后，恢复不得将其复活。
16. 独立成果查询通过工具声明明确不依赖原选区完整性；请求许可、工程版本身份和成果所有权仍检查，选区修改工具不得声明此豁免。下载列表按记录隔离损坏 JSON/结构，保留原件、展示诊断，正常记录仍可重开；真实目录或权限故障继续报告。
17. 恢复存储将固定输入与变动状态分开：来源内容按完整摘要引用复用，小 manifest 保存身份、状态和展示摘要；旧内联记录只在存储入口适配。词条封套属于业务数据，不以元数据字段名判定凭据，旁侧执行配置仍拒绝凭据。普通状态更新不重新读取固定输入，无变化不写；成功持久化的相同结果复用证据。可变成果只保留当前引用的内部代次，发布和清理属于同一跨进程事务，不能误删其他写入者尚未发布的数据。内部路径使用短文件名并校验完整摘要和任务归属，避免新增深层路径破坏 Windows 保存。
18. 恢复发现只读摘要，先按工程、版本和状态筛选；选择查看或继续时才完整读取输入、成果及检查点。摘要不是写入授权。状态报告复用同一成果 payload，候选或取消语义变化才重建；metadata 更新绑定该 payload 代次，不能修改另一写入者的新报告。
19. 保存前一致性核验复用已交付的投影证据，以集合发布和词条修改通知失效；共享词条订阅与写入采用同一原子边界。变更日志有界，落后读者只回退一次集合核验；关闭和切换释放证据。嵌套可变远端关联仍按相关条目复核，不能以 dirty、对象地址或未被可靠维护的修订号代替真实修改检测。保持后台保存等待 Qt 投影交付的保护。
20. 打开准备、正式加载、保存和激活日志复用同一内容证据机制。证据限定一次操作，绑定 repository、完整引用及实际原始 bytes；磁盘读取、CAS、写后读回和冷日志恢复继续执行。只读 DTO 的嵌套数据不共享给其他调用者，不能让调用方修改已验证对象后继续冒用证据。准备产物显式携带证据与不可变版本状态，跨线程激活不依赖线程上下文继承；旧格式只读视图不得绕过正式迁移。允许已完成的等义升级必须匹配确切规范化输出摘要；本次迁移还核对原文件摘要，不能借迁移掩盖准备后外部改写。
   冷读仍完整验证实际内容。单次 schema 执行仅复用固定本地子规则的校验器对象，所有输入值继续经过现有 JSON Schema handler，业务规则保持单一来源；错误路径、完整语义检查及类型行为保持一致。作用域引用、未知关键字或显式 resolver 配置走标准执行，缓存不跨调用、不缓存输入通过结果，嵌套及线程隔离。
21. 同一操作内已有可信完整前态时，保存的新版本可以复用未变词条的结构校验证据；顶层结构和跨条目语义仍检查实际完整目标。内容比较必须区分 JSON 类型、完整字段和实际值，错误定位保持原始条目下标；冷读取、缺少前态及不匹配内容继续完整校验。不得把“跳过重复计算”变成“文件已成功保存”的证明。
22. 打开候选视图与正式投影发布共用同一冻结词条容器。候选缓存与当前缓存隔离，按实际工程及版本对象绑定，失败/关闭释放；保存状态等元信息按正式状态更新，不以相加后的 revision 作为内容身份。隐藏对话编辑器只维护来源失效和表格成员访问，首次实际使用时后台建立索引，同源译文变动复用，真实来源或关系结构变化重新建立；迟到结果仍按原目标/代次隔离。

23. 工程来源正式引用不可变解析成果，Project/Variant 仍是编辑及版本的唯一权威。成果保存来源基线、词条定位/上下文及完整原始输入闭包，人工编辑只写 Variant。成果 ID 覆盖 codec/解析契约与全部依赖；相同插件但不同 STRINGS 不得混用，下游原文读模型缓存也按成果 ID 区分。二进制内容独立存储，小记录聚合为有边界校验的 blob 切片，不把大型插件反复编码为 JSON 字符串或制造海量小文件。恢复将实际依赖收集融合到解码，返回前精确比较闭包；每个唯一 blob 校验实际摘要，各切片仍逐个检查边界。不可变内容先落盘，引用通过既有工程事务发布；失败留下未引用内容不影响当前工程。普通创建和内部加源不重新持久化刚产生且未变的成果；原版与汉化来源真正折叠后才记录 folded_into_baseline，并持久化合并后的基线；普通翻译关联不授予折叠身份。外部交付的 prepared 对象不得仅凭旧成果 ID 跳过最终捕获。
24. 打开、启动恢复、切换工程和版本统一恢复已保存来源。命中成果时不读取 live 来源，仍验证成果内容和工程身份；来源路径变化或消失不改变已保存的原文/译文。新建、添加、更新来源共用持久 preparer，新增成果由正式登记引用。缺引用的旧工程只在首次打开解析，并在成功激活的现有 CAS 事务补引用；准备阶段不改权威工程，不创建正式版本。成果损坏不能静默替换成当前外部文件，保留 Variant 并报告恢复原因。上传及结果合入的冷读同样使用已登记成果，只有显式更新才读取新来源。准备产物中的来源绑定以私有 bytes 固定；版本和基线的可变嵌套元数据仅记录相应子树证据，激活复用时检查，避免篡改污染或再次序列化整个版本。
25. 工程包包含引用成果及完整输入闭包，BSA 字符串保留所选 member 的原始 bytes，并提供可移植散装 companion。导入校验包内成果，不借用目的地已有缓存掩盖缺失成员；换工程身份/路径只重定位读模型，保留成果内容身份。旧 `.transbridge` 仍集中入口升级。普通输出共用完整来源 snapshot；覆盖目标继续遵守原子发布、备份及冲突保护。codec/parser ABI 不兼容时给出明确诊断，不静默从外部来源升级解析结果；本轮不自动 GC 可能被历史备份引用的成果。

## 备选方案

- 保留所有全局守卫、仅放宽报错：不能解决任务失效和重复全量成本，放弃。
- 引入完整 Git 分支/rebase 系统：超过应用需要，增加迁移和使用负担，放弃。
- 每条任务各自实现三方比较：容易形成不同语义，采用小公共纯函数与业务适配替代。
- 仅加进程内来源缓存：无法改善每次重启，且不能保留外部源覆盖前的工作状态，采用持久内容引用。
- 把全部插件对象序列化或使用 pickle：保存运行时实现细节并扩大解码风险，采用显式来源契约和独立内容 blob。

## 风险、兼容与迁移

旧成果缺少可靠 base 时只读保留，不推测覆盖。源身份和 source hydration 保真约束保留。合入后回执保存失败依靠当前内容与 incoming 相同实现幂等恢复。性能以构建/全量处理次数及可重复样本验证，不能用单元测试通过宣称实测提速。

## 回退

不做破坏性数据迁移、不移除旧用户历史。新增记录独立可读；需要回退实现时先保留新增成果文件和恢复证据。不得通过删除成果实现回退。
