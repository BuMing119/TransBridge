# ADR-027：规范术语模型与格式适配器

- **状态**：已接受（2026-08-26）
- **日期**：2026-08-26
- **关联**：[ADR-013](013-vector-retrieval-enhancement.md)、[AI 自动翻译计划](../../plans/ai-translation/plan.md)、[ParaTranz 集成计划](../../plans/paratranz-integration/plan.md)

## 背景与约束

当前动态术语库、本地 JSON、Excel 与 ParaTranz API 在进入匹配流程前各自解析。它们只共享 `term`、`translation`、`variants` 和部分大小写信息，ParaTranz 的 `pos`、`note`、只读标识与时间字段会丢失，本地 JSON 中的 `caseSensitive` 也不会进入匹配模型；CSV 尚未成为术语来源。

兼容目标是让所有已知字段进入统一模型、在目标格式允许的范围内可导出，并尽量保留未来出现的未知字段。几种格式不需要具有相同的字面结构。现有术语优先级、匹配、逐条作用域、缓存回退和动态库路径必须保持兼容。

## 决策

### 1. 单一规范模型

在 AI 术语模块中建立一个不依赖 Qt 或 ParaTranz 客户端的 `TermEntry`，覆盖：原文、译文、来源、上下文、创建时间、大小写敏感、变体、词性、注释、外部标识以及未知元数据。

`term` 与 `translation` 仍是参与匹配的必需字段。其他字段只提供格式保真和后续消歧上下文，不改变现有匹配结果。现有从 `term_database` 导入 `TermEntry` 的公共路径继续可用。

### 2. 边界适配而非统一文件字面结构

新增独立格式适配模块，负责：

- JSON：读取简单键值对象、术语数组、`terms`/`results` 包装对象；识别 snake_case、camelCase 和常见列名别名。
- CSV：按表头读取 UTF-8/UTF-8 BOM 文件；支持规范字段和 ParaTranz 风格字段，变体既接受 JSON 数组文本，也接受常见分隔文本。
- Excel：优先按表头识别完整字段；没有可识别表头时继续使用原文列/译文列配置。
- ParaTranz：完整映射可写字段，并把服务端只读字段及未知字段保留在规范模型中。
- 动态库与缓存：读取旧字段集合，保存规范字段集合；旧文件无需一次性迁移，下一次正常保存即升级。

适配器提供明确的目标序列化模式。ParaTranz 输出不提交 `id`、项目、创建/更新时间等只读字段；规范 JSON、CSV 和 Excel 则保留这些信息。

### 3. 来源配置与错误语义

CSV 成为与 JSON、Excel 同级的可排序来源，并拥有独立路径。旧配置缺少 CSV 字段时使用空路径，原优先级保持有效。

空行和缺少原文/译文的记录跳过；文件不存在视为空来源；格式损坏、列结构不可识别或依赖不支持时抛出带路径和格式信息的异常，由现有来源缓存回退机制处理并记录加载日志。不得静默把损坏文件当作空术语库。

### 4. 依赖方向

```text
配置/UI/智能助手
        ↓
TermDatabaseManager（优先级、缓存、合并）
        ↓
term_formats（规范模型、JSON/CSV/Excel/ParaTranz 适配）
        ↓
标准库 + openpyxl
```

格式模块不导入 Qt、配置仓储、网络客户端或匹配器。`term_database.py` 已超过职责阈值，不再承载新的解析责任。

## 备选方案

### 直接把 ParaTranz JSON 作为内部格式

会把远端 API 的命名和只读字段扩散到动态库与匹配层，也无法自然表达内部来源和上下文，拒绝。

### 每个加载器继续手写字段映射

改动较小，但导入、缓存、批量预检和未来导出会继续产生不一致字段丢失，拒绝。

### 只增加 CSV 两列加载

能解决入口缺失，但不能解决现有 JSON/ParaTranz 元数据丢失和双向互转，拒绝。

## 影响与风险

- `TermEntry` 新增字段但保持现有构造调用兼容；缓存和动态库会在保存后出现更多键。
- 未知元数据可提高前向兼容性，但只能保证在规范格式间保留；导出 ParaTranz 时仍受其 API 可写字段限制。
- CSV 分隔文本存在歧义，规范导出统一把 `variants` 和未知元数据写为 JSON 文本。
- `.xlsx` 使用 `openpyxl`，旧式 BIFF `.xls` 使用专用的 `xlrd`；两者读取后进入同一规范模型。受密码保护或损坏的工作簿返回明确错误。

## 迁移与回退

无需批量迁移。旧动态 JSON、缓存、简单 JSON 和两列 Excel 继续读取。移除新 CSV 来源配置并回退格式适配调用即可恢复旧加载路径；已经保存的新动态 JSON 中新增字段均有默认值，旧版本若使用严格 `TermEntry(**item)` 可能无法读取，因此发布说明应提示动态库升级后的向后版本兼容限制。
