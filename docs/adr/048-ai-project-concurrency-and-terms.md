# ADR-048：AI 多插件公平并发与共享生成术语

- 状态：已接受（本会话确认的产品规则）；并发、共享池及项目名称首批屏障已实现并通过相关回归（2026-10-24）
- 日期：2026-10-23
- 部分取代：[ADR-003](003-three-round-translation-strategy.md) 的任务级执行及空 Quest 顺序假设；保留明确 Quest 内顺序和来源内三轮质量依赖。

## 背景

多个插件共用项目术语，但旧入口逐插件执行完整流程，第一插件校对时第二插件尚不能翻译。请求额度在耗时术语检索前取得，导致“在途”包含准备工作。空 Quest 被合并为一个串行组，没有真实依赖也会等待。

## 决策

1. 各来源有独立阶段进度，在同一任务内并行推进；所有模型阶段共享按来源/阶段公平准入的硬上限。空闲额度可借用，不按插件永久分配。
2. 请求分昂贵准备与轻量最终合入。准备有独立有界容量；发送前合入已接纳的最新术语。模型槽覆盖一次逻辑 provider 调用及 SDK 内部重试，不宣称逐 HTTP 计量。
3. 项目任务开始先统计本次所有来源选中的真实名称（物品名、地名、人名等）。校验通过的已有译法先经持久化候选和受保护提交写入任务独立草稿，再翻译剩余代表名称；本地复用不受名称模型屏障阻挡。名称准备完成前所有来源仍不得进入后续正文翻译、后处理或校对。这个首批屏障取代初版各来源各自准备名称的规则。其余内容仍保留来源内基础术语及三轮顺序：明确 Quest 只执行队首，翻译和必要术语抽取完成后后继才可运行；未知 Quest 的稳定批次没有相互顺序依赖。
4. 项目/Variant/目标语言共用一个持久化生成术语池；已发布项目术语、插件作用域特例仍按既有权威规则解析。新词成功保存并验证后可见；冲突不能最后写者获胜，校对文本修改不是术语发布。
5. 任务最终结束前，对所有来源输出检查共享参考资料变化；仅对未评估的新差异补充综合 AI 校对，保留修订、保留原译、参考可疑或待复核结论。术语字面差异不作为翻译失败条件。源已结束不等于整个任务一致性检查结束。
6. 已发布项目术语、本地和 ParaTranz 参考首次捕获后作为同一任务的固定基线，名称、翻译、校对、收尾、失败项重试和跨进程继续复用。外部参考更新不作为结果应用条件；本任务共享池仍允许发布新生成术语。外部写入冲突只拒绝对应生成术语发布并留下诊断，不能把成功译文改成失败。

## 接口与责任

- 请求预算只负责准备/调用准入、取消、暂停、公平与计量。
- 批次调度负责就绪批次及依赖释放，来源执行负责阶段组合；不在 Qt 主线程执行。
- 执行和界面通过有界缓冲交接，当前仍为同一进程内的 QThread 与线程池。生产任务窗口每 50ms 在 GUI 线程拉取各来源、项目阶段和请求计数的最新绝对值；后台不持续向 Qt 排入过时的进度事件。简短过程日志先过滤、再有界缓冲，省略必须可见。来源开始/结束和任务完成按缓冲中的顺序可靠交付，worker finished 前交付尾部；取出数据后释放缓冲锁，再更新控件。旧执行尝试隔离，传统信号订阅入口保持兼容。运行期间刷新不得逐事件遍历全部结果；暂停/取消控制不等待日志排空。
- 名称准备协调器在每阶段开始时固定所有来源分母，再累计来源绝对计数并发送不可变快照；术语、提交和整理回调只更新说明，不能覆盖名称计数。窗口分别展示项目阶段汇总和来源阶段、计数、当前处理；名称准备后先展示来源流程进度，收尾时切为当前来源的加载、扫描、综合校对、结果整理及完成进度，最终完成仍由任务运行时确认。扫描限频汇报并在条目边界响应暂停/取消，模型批次完成回调进入同一有界反馈路径。
- 共享术语池负责身份、修订、持久化及冲突证据；manager 只提供当前插件适用的视图。
- 普通翻译、校对与后处理复用有界的作用域术语视图、精确索引及匹配器；缓存键覆盖已发布版本、动态修订、加载代次和发布事务身份。共享池每个发布事务只冻结和归一化一次，并按插件作用域复用不可变读取记录；旧 `entries` 接口继续提供可修改的独立副本。冻结的已发布快照只验证、建索引一次，后续仍校验项目/Variant/版本。读取已捕获的批次快照不得替换为最新池；未知可变 provider 保持即时查找。远程加载不能持有全项目共享池锁，失败事务不得留下可被后续同修订发布误命中的视图。
- 提示词准备负责检索与最终作用域合入；不把并发数用于分批。
- 候选、检查点、最终提交和恢复继续校验来源、原文、当前译文及修订；TaskConsistency 校验执行配置身份。冻结参考由独立 TaskReferenceStore 管理，恢复目录中的原子快照含校验和、任务与项目/Variant/语言身份，不含配置凭据。只读参考变化不触发失败，生成写入保护只在发布边界执行。
- 候选检查点持久层使用带校验链的增量日志和原子提交头，批次成功返回前完成刷盘及验证，只有提交头覆盖的前缀可恢复；周期压缩仍受同一存储租约保护。普通读取返回原有不可变 `TranslationCheckpoint`，旧 schema 1 快照在首次成功保存时迁移为 schema 2 存储布局。缓存检测文件身份/大小/时间签名变化后重新验证；同修订外部变化和并发旧修订写入不能覆盖已接受结果。候选身份查找按 collection revision 复用索引，不逐条扫描来源集合。
- 启动和结果收尾由独立协调组件管理。GUI 分片捕获输入和选择意图，后台完成筛选、深复制、术语/配置验证、结果吸收及索引；交付前复核版本和完整内容。正式项目发布仍由 GUI 的受保护权威入口执行，提交后的基线整理也异步进行，失败不得撤销已提交证据。快照/保存只捕获固定项目依赖和独立输入，worker 不读取 live UI context；术语验证使用冻结的依赖对象。记录串行写入且最多保留一个最新待办，完成通知等待持久化收尾。日志/预览/报告采用后台投影与可丢弃的代次请求；控件更新和确认决定仍在 GUI，预览使用虚拟表。兼容同步 API 复用同核心逻辑，生产任务入口使用异步路径。
- 名称规划首先仅按原文和语义类别线性聚合，再加载术语并检查复用约束，保留每个出现位置的来源与词条身份。同名异类、插件特例或已有异译不得无条件合并或提升为全局术语。每个插件作用域复用已验证的术语索引与编译后的匹配器；不得逐名称重算整份快照摘要。独有且无已有译文的名称沿原翻译流程处理，名称接受只验证有效文本、身份和保护标记；术语差异在后续综合校对时作为疑点，不做前置全词库硬校验。统计、加载和约束检查从启动时就显示进度。名称描述不属于名称；初批仍按内容 Token 预算拆分并共享模型额度。
- 名称准备分两条路径：已有译法在模型请求前写入任务草稿，记录原始输入、提交后快照和独立提交证据；未知译法在隔离集合中沿现有候选校验与提交路径生成，完成后统一发布无歧义名称。正常来源接续已写入项的证据，仅为其余条目接受候选和提交，全部结果仍执行原有后处理与最终术语检查；不能只凭非空译文推断成功，也不能把提前复用再次写入或提交到模型。候选/草稿接续逻辑独立于 Qt 和大型翻译主控。单个名称失败传播到其各出现位置而不重复请求，无关内容继续；真实存储故障或身份错误明确失败，外部生成文件冲突只跳过术语发布，保留名称译文。
- 2026-10-24 即时复用修订（技术设计为提议；产品时机已确认，S10 已实现）：`application/translation/draft_reuse.py` 负责候选持久化、受保护草稿提交及 `CommittedDraftTranslations` 证据；`task_name_reuse.py` 负责来源编排和未完成结果保留。任务独立草稿可在名称准备阶段变化，替代此前“准备阶段草稿完全不变”的假设；主窗口来源、项目保存及取消边界保持不变。暂停阻止下一次本地提交，取消阻止迟到提交/模型请求；已有草稿证据不得被名称模型失败覆盖。恢复校验原文、上下文、完整身份及修订；原地伪造相同译文不能冒充已提交结果。旧检查点不具备提前提交证据时不得按新路径猜测恢复，可新建任务重新执行。

## 备选与代价

单纯增大线程数不会消除依赖和准备占槽，且会增加无界等待线程。全并发同 Quest 会改变术语传播和上下文质量，首版不采用。共享一个无作用域字典会污染插件特例，因此复用既有作用域解析并增加共享生成层。最终参考差异检查可能增加少量综合校对请求，已判断的同一差异不重复请求，无关条目不重跑。

## 迁移与验证

新增共享生成数据不覆盖已发布库或自动提升历史局部词。共享池按项目、Variant、目标语言身份哈希写入 `data/ai_translator/project_terms/`，同一路径的读入和发布事务复用持久化层 OS lease；另一个独立任务持有写入权或修改生成文件时跳过本次发布并标注，沿用内存参考且保留成功译文。真实 IO 故障及初始文件损坏仍明确报告。无项目入口保持兼容。来源键进入新任务检查点身份，独立 `AutoTranslator` 默认仍保留旧 ESP 检查点接口。新任务和“重新开始”捕获新的参考；旧任务缺少完整参考快照时，首次继续重新捕获一次并保留历史候选校验流程。

S15 的 schema 2 候选检查点由提交头和其引用的日志共同组成，备份或移动时必须保留两者。新版本可读取旧 schema 1，单纯读取不迁移；首次成功保存后旧程序不能直接读取新布局。如需降级继续同一任务，应在新版本中通过 `load(run_id).to_dict()` 导出完整 schema 1 快照到独立目标，并验证后再交给旧版本；不能仅复制提交头或忽略日志。

S10 的提前提交以来源为单位，不承诺整个项目原子提交。后一来源候选保存失败会停止首批模型调度，前一来源已提交文本保留在任务草稿中，结果标为尚未完成检查。`committed_draft` 默认为空，已有调用方无需迁移；本次不增加跨进程翻译恢复入口。证据缺失或当前草稿变化时拒绝接续，回退实现应新建任务。验证见[即时草稿复用 QA](../test-reports/ai-name-immediate-reuse-qa-2026-10-24.md)。

模型额度为 N，准备额度默认为 min(4, N)，翻译批次执行线程为 N 加准备额度，允许下一批准备与当前调用重叠；来源协调线程有界，等待的 Quest 后继不占批次线程。以事件/barrier 模拟验证重叠、公平、暂停取消、失败释放、作用域与修复闭环；真实模型吞吐和语义质量另行验证。补充综合校对允许保留原译，不用字符串匹配强制改词；无法完成时保留原成功译文并记录待复核。
