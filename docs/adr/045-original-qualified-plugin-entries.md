# ADR-045：插件定位冲突使用原文限定身份

状态：已接受（用户于 2026-10-06 明确要求按该方案实施）

## 背景与约束

插件解析库的 index 不是唯一标识；同一 key 可能对应多条不同日志。用户要求保留 key/id 的原值，新增默认 false 的 requires_original_match 字段；冲突组通过 key 与精确原文共同识别。不采用 UUID、位置编号或修改导出 key。

## 决策

扩展 ADR-017 的 EntryKey 身份契约：namespace/local_key 保持不变，增加可选 original 分量。普通身份保持现有两元素序列化；需要原文匹配时增加第三元素。TranslationEntry 的布尔字段与该身份一致，并随 JSON 与工程快照恢复。

插件提取先保留全部物理条目，再按 key 分组；冲突组全体标记。相同 key 下原文不同的条目保留，相同 key+原文的全部条目跳过并记录 warning。不得规范化原文空白、换行或大小写。

集合、编辑、持久化和投影使用完整 EntryKey。标记词条的 original 是身份的一部分，不允许作为普通字段编辑；translation 可独立编辑。插件回写从不可变源快照验证完整身份，并提前保存物理目标，避免译文等于另一条原文时串写。

自动导入对标记词条要求精确原文证明，缺少原文或不相同则跳过并记录 warning。ParaTranz 上传与下载可使用当前云端项目内已确认且唯一的远端关联，或通过同 key、精确原文及上下文证据唯一匹配；仍有歧义时保持目标端不变并进入人工复核，其他确定项可以先执行。用户明确选择具体云端候选时，将选择应用到指定的本地身份；原文参与身份的现有条目始终保留本地身份原文。上传已有记录只发送译文和状态，不能改写云端原文、上下文、key 或顺序；云端改 key 后仍按确认的远端 ID 更新。决定绑定操作方向和所见快照，禁止复用过期选择、抢占远端关联或将同一云端记录关联多个本地身份。上传成功项的远端关联经本地权威事务保存，取消或部分失败时保留逐项事实；不能因关联未保存而盲目重复新增。旧工程和普通词条保持兼容；无法表达完整身份的其他路径仍不得静默合并冲突项。该上传扩展于 2026-10-20 由用户明确授权，实施与验收见 [ParaTranz 同步 S05～S10](../../plans/paratranz-sync-operation-ux/plan.md)。

## 备选方案

只加布尔字段而不扩展内部身份会在集合和持久化层覆盖记录；UUID/位置身份不符合用户选择；修改 key/id 不符合兼容约束。

## 影响、迁移与回退

旧数据缺省为 false；普通 EntryKey 的 wire format 不变。新冲突项不能保证被旧程序读取，不自动重写用户工程文件。旧工程若此前已跳过冲突项，需要重新加载/更新源文件才能引入。回退代码前应保留新工程数据备份；不将含冲突项的数据降级为重复裸 key。

实现与验收见 [计划](../../plans/original-match-entries/plan.md)。
