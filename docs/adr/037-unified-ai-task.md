# ADR-037：统一多来源 AI 任务

- 状态：已采纳并实施（用户授权按统一效果图实施）
- 日期：2026-09-06
- 取代：ADR-036 中独立批量入口、弹窗与运行链的决策；统一设置中心决策继续有效。

## 背景与约束

单内容与多插件已经共用 AutoTranslator，但范围、预设、模式、进度与提交边界不同。
用户要求统一入口与完整流程。既有 EntryKey、Stage policy、请求预算、校改管线与版本持久化需复用。

## 决策与关键契约

任务输入是一组有序来源，每个来源保留源路径、完整上下文集合和明确的翻译/校改候选。
单来源与多来源走同一个 worker 和结果窗口，按来源顺序执行。混合阶段内部可串行或并行，所有 LLM
共享一个 run-scoped budget。保留来源级身份，不把跨插件相同 legacy id 的条目交给一个有歧义的映射。

配置窗口使用 detached draft；只有用户明确保存预设才写入安全预设仓库。服务配置仍由设置中心负责。
运行冻结所有来源副本、版本 identity/revision 与术语绑定；后台创建执行前快照。
取消和执行错误保留报告但不修改权威翻译；完成并确认预览后一次 CAS 提交。显式保存创建保存后快照。
单来源遵守相同发布规则，避免来源数量改变失败行为。失败重试复用成功副本并重新执行失败来源。

## 备选与影响

仅合并外观会继续维护两种模式和提交语义，因此不采用。
把多个来源直接拼成一个 collection 会使 legacy id、ESP 上下文和动态词库路径产生歧义，因此不采用。
新组合根按范围、执行、持久化和展示拆分，避免扩大现有大型 AutoTranslator。

## 迁移与回退

旧批量 intent/公开入口委托统一窗口；删除不再可达的批量实现，文件格式和长期配置无需迁移。
旧版工程若包含跨插件重复的 legacy ID，会明确阻止提交并提示迁移到 V2；V2 通过 EntryKey 隔离。
原运行报告与旧断点文件保留；新任务采用冻结来源范围与配置校验，不静默套用不匹配的旧断点。
回退应整体回退本次任务改造，不能只切换 UI 而留下不同的提交约定。
