# ADR-026：AI 工作流预设、有效执行档案与校改润色流水线

- **状态**：已接受（2026-08-25）
- **日期**：2026-08-25
- **对应需求**：[FR5.13、FR6.9、FR26.7.1](../requirements.md)
- **关联 ADR**：[ADR-007](007-mixed-translation-polish-mode.md)、[ADR-016](016-modular-monolith-application-composition.md)、[ADR-019](019-unified-task-runtime.md)、[ADR-021](021-ui-presentation-modularization.md)
- **取代**：ADR-007 第 1 节的“硬模式保持原行为”和第 6 节“混合模式强制禁用后处理润色”

## 背景与约束

AI 窗口已展示完整的检测、修复、润色和裁决配置，但独立“润色”入口只调用 `LLMPolisher`，部分可见配置不参与执行；混合入口还会按模式强制覆盖用户配置。这使界面承诺与实际行为不一致，也使恢复、重试和报告无法准确说明本次运行采用了哪些阶段。

本次改动必须保留翻译、润色、混合三个易懂入口，不阻塞 Qt 事件循环，不让 UI 成为业务状态所有者，并遵守 ADR-019 的不可变运行规格与 candidate → validate → commit 边界。

## 决策

### 1. 三个“模式”改为工作流预设

翻译、润色和混合仅负责选择推荐的主动作、作用域和阶段初值。用户在高级配置中的当前选择具有最高优先级；运行开始后不允许模式分支再次改写阶段开关。

每个预设保存自己的后处理阶段设置。首次迁移时：翻译继承旧全局设置；润色使用完整校改默认值（检测、修复、润色、裁决均启用）；混合继承旧设置但不再强制关闭润色。用户修改后保存到当前预设，切换预设时恢复该预设，而不是污染其他预设。

### 2. 有效执行档案是单次运行的唯一事实来源

应用层新增冻结的 `AiExecutionProfile`，包含预设、主动作以及所有后处理阶段参数。配置优先级固定为：

```text
系统默认 < 预设默认 < 该预设已保存配置 < 当前界面值
```

点击开始时由当前界面构建一次档案并放入 `AiRunSpec`。Worker、恢复、重试、进度和报告只能读取该档案或其冻结配置副本，不得重新读取配置文件，也不得根据模式名暗中增删阶段。

### 3. “润色”是可配置的校改流水线

独立润色默认顺序为：

```text
检测原文/现译文/上下文/术语
  -> 对已发现问题进行定向修复
  -> 以修复后的候选译文继续语言润色
  -> 最终裁决 pass / pending / reject
  -> 预览或受控提交
```

检测范围包括错译、漏译、增译、语义偏差、否定/数字/专名错误、术语不一致以及占位符、标签和引号等格式问题。每个阶段都尊重档案中的显式开关；因此可形成只检查、检查并修复、纯语言润色或完整校改。

修复结果必须成为后续润色的输入。若裁决关闭，采用保守规则生成明确的 pass/pending/reject；失败或待审候选不得在非预览模式下静默覆盖正式译文。

### 4. 业务与 UI 边界

- 配置模块负责预设配置的迁移、序列化和合并，不持有 QWidget。
- 应用/AI 后处理模块负责执行校改流水线并返回结构化候选、问题、阶段结果和最终决定，不修改正式集合。
- Qt Worker 只转发暂停、取消、进度和结果。
- Result Presenter 是唯一提交边界；仅提交用户明确接受或最终裁决为 pass 的候选，并用不可变替换保留 EntryKey/revision 元数据。
- 混合模式为每个稳定 EntryKey 生成唯一动作，公共后处理读取同一有效档案，禁止重复执行同一阶段。

## 关键契约与错误语义

- 任一可见阶段开关必须能在有效档案和运行摘要中找到对应字段；找不到即为配置错误并阻止启动。
- 无检测器时不伪称“已检查”；无修复器时检测到的问题保持 pending/reject；无润色器时使用修复候选或原译文。
- LLM 单条失败产生带原因的失败候选，不吞异常、不覆盖原译文，批次可继续处理其他条目。
- 自动提交只接受 pass 且有有效最终译文的候选；pending/reject/failed 保留原译文并进入报告或预览。
- 报告记录预设名、有效阶段摘要、原译文、问题、修复候选、润色候选、最终译文与裁决理由。

## 备选方案

### 继续保留硬模式并在代码中强制覆盖配置

实现较少，但界面配置会继续失真，且新增组合会产生更多互斥分支，拒绝。

### 把错误检测全部塞进 Polisher 提示词

一次调用成本较低，但无法独立关闭阶段、追踪问题或验证修复是否生效，也不能复用现有 Checker/Refiner/Arbiter，拒绝。

### 直接让旧 PostProcessor 修改正式 TranslationEntry

可快速复用，但预览取消、任务取消和迟到结果仍可能污染集合，违反 ADR-019，拒绝。采用“对候选副本运行、在 Presenter 单点提交”的过渡适配。

## 影响与风险

- 正面：高级配置全部可解释且生效；润色可修正错误翻译；三预设互不污染；报告能复现实际流程。
- 成本：需要迁移旧全局后处理配置，并统一独立润色与混合润色的执行入口。
- 风险：旧后处理组件历史上混用 `id`/`key`。适配层必须按稳定 EntryKey 归一化映射，并用回归测试覆盖两者不同的条目。
- 风险：完整校改增加 LLM 调用和耗时。UI 需显示有效阶段摘要，用户可关闭不需要的阶段。

## 迁移与回退

1. 读取旧配置时生成三个预设配置，但保留旧字段作为兼容 facade。
2. AI 窗口切换为“载入当前预设 → 用户编辑 → 构建有效档案”；旧配置文件无需用户手工迁移。
3. 独立润色先通过候选副本复用现有 Checker/Refiner/Polisher/Arbiter；验证稳定后可再迁移到底层统一 application workload。
4. 混合入口删除强制关闭润色逻辑，并复用同一档案。
5. 若新流水线发生回归，可回退到旧执行 adapter，但保留预设配置和不可变档案；不得恢复“显示配置但运行忽略”的行为。
