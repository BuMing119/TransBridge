# ADR-051：正式项目自包含存储与单一升级边界

- 状态：已接受；S01～S03 本地实现与相关 QA 完成，999 通过、1 项环境跳过；S04 缺内容自动恢复本地实现与相关 QA 完成，广域未全绿，详见增量（2026-11-03）。
- 日期：2026-11-03。
- 需求：FR8.3、FR8.4、FR8.8、FR19.7、FR19.10、FR19.11、FR19.14.5。
- 计划：[project-self-contained-storage](../../plans/project-self-contained-storage/plan.md)。
- 局部取代：[ADR-050](050-application-preflight-and-optional-source-reference.md) 中旧结构在运行时继续提供来源 fallback 的边界；其来源路径可空、已激活工程按需补输入、未知原文不猜测和应用层预检职责保留；旧工程缺内容先自动修复，失败停止正常激活。ADR-018、ADR-035 的 repository、revision 和 journal 继续复用。

## 背景与约束

已有来源 artifact 能保存解析成果、输出模板 bytes 和实际使用的本地化 Strings，Variant 保存译文、状态和标签。因此问题是闭包归属、保存结果和兼容边界，不能用另建全量存储或每次保存重复 hash 扫描解决。用户已明确授权实施自包含项目，并要求运行只支持新结构、旧结构仅经自动升级转换。

## 决策与契约

1. Project/Variant 和它们引用的来源 artifact 共同构成正式项目。原文、上下文、类型、顺序及定位由 artifact 保存；译文、Stage、标签和版本状态由 Variant 保存。原始路径不参与来源身份，也不是完整项目内容读取前提；仅缺内容修复可把明确登记原路径作为最后候选，输出路径单独选择。
2. schema 5 的 SourceRegistration 保留 `source_artifact_id`，新增必需 `content_state`。`captured` 要求 artifact ID，`missing` 不含有效 ID（规范序列化省略，schema 允许 null）；状态只表示捕获事实，实际读取继续使用现有 artifact 完整性规则。普通保存不重新 hash 扫描整个闭包。
3. 旧 Project/Variant 只经已有迁移链转换到当前结构。schema 4 已有引用直接保留并标记 captured，缺引用标记 missing；目录只读发现不发布升级或运行来源修复；打开/激活准备发现缺内容时进入第 4 条修复，发布沿用 repository 的备份、现有来源事务及原子替换。打开准备可持久化修复但不改变当前 GUI；界面先完成保存/放弃/取消决策，直接打开 API 的显式取消在修复前返回。运行时不得保留旧字段解释或外部 baseline loader 的来源兜底。旧包带有可靠输入时，只能在导入升级边界转换成当前 artifact。
4. 缺内容自动恢复是现有升级流程的阶段，覆盖旧 schema 转换后缺内容及已经为 schema 5 的 missing 项目。依次使用项目已保存内容/已有快照、项目所属备份、明确登记原路径；同存储其他工程明确登记且内容指纹相同的路径可作为已知来源引用候选；仅恢复能按现有来源身份与条目匹配证明的内容，不全盘搜索、不按文件名猜配、不恢复已移除来源。复用来源补齐与原子备份发布，把恢复内容保存到内部 artifact，保留当前全部正式版本的译文、Stage、标签、引用和未匹配条目。真实原文不等于输出模板或 Strings；不得根据译文、key、占位文本或虚构空值补造缺失证据。较高优先级候选已满足需要即停止搜索，正常完整项目不扫描历史、不读取外部源内容。全部候选尝试后仍不足则明确报告缺失、停止正常激活，保留项目和备份，不直接删除。
5. 完整保存必须满足来源内容可用。Project/Variant 已持久化但来源缺失时返回部分保存，明确译文已保留而完整项目尚未保存；clean no-op 不例外。修复后重新准备操作，沿用原目标和权限边界。
6. 捕获 localized 输入时保存实际使用的 Strings；非零 ID 缺失明确失败，不允许过滤掉相关条目后宣称解析成功。
7. `.transbridge` 仅打包正式项目数据与其必要依赖。任务日志、AI 历史、运行成果和缓存不属必要内容。保留换源备份时，必须带走旧来源 artifact 闭包，不能仅保留指向原机器缓存的备份 JSON。历史 preimage 原样保留在导入项目的自有目录，保留原项目身份作为历史证据；不安装为活跃 journal，不新增全历史一键恢复接口。

## 备选方案

- 继续运行时解释旧结构：形成双份恢复语义，且旧路径读取无法保证自包含，拒绝。
- 在每个 Variant 重复存原始输入与全部元数据：与现有 artifact 职责重复，增加更新和包大小，拒绝。
- 复用 artifact 并统一升级、保存结果及归档范围：改动集中于现有权威边界，采用。

## 影响、迁移与回退

缺失原始内容的历史项目先按限定候选恢复；所有证据均不足时停止正常打开并保留已存项目与备份。已激活工程后续丢失输入时仍保留译文，并按保存合同明示部分保存。捕获状态不能替代磁盘完整性检查，也不能成为新增全量扫描门禁。现有 journal 保证 Project/Variant 原子发布；未关联的 artifact 清理继续沿用既有机制。

本次不修改真实用户 data、不运行批量迁移。失败保留旧正式文件与备份，代码回退不得删除新 artifact 或将新文档降级覆盖。实现和验证证据见计划及[增量记录](../changelogs/project-self-contained-storage/story-01-to-03/2026-11-03-001-self-contained-project-storage.md)；该记录仅覆盖 S01～S03；S04 的最终聚焦 50 项通过、广域 1158 通过/4 失败/1 跳过及复验、全库静态检查见 [S04 增量](../changelogs/project-self-contained-storage/story-04/2026-11-03-001-automatic-source-content-repair.md)。未执行真实用户数据迁移，不提供任意历史回滚功能。
