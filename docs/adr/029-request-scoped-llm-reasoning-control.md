# ADR-029：请求作用域的 LLM 思考控制与能力探测

- **状态**：已采纳（2026-08-27）
- **日期**：2026-08-27
- **关联 ADR**：ADR-026、ADR-028

## 背景与约束

AI 翻译的大多数请求不需要模型展开高强度推理；全局修改 LLM 配置却会同时改变智能助手的行为。不同 OpenAI 兼容服务还可能分别使用 `reasoning_effort`、`thinking.type` 或 `enable_thinking`，而模型列表接口通常不能证明某个模型是否真正识别并执行这些控制字段。Anthropic 协议的默认非扩展思考又以“省略 thinking 参数”表达。

本项目只兼容既有的 OpenAI-compatible 与 Anthropic 两种协议，不维护供应商或模型能力表。探测不得持久化 API Key、提示词、响应正文或思考内容，也不得破坏 ADR-028 规定的标准校对“每批恰好一次业务 LLM 调用”。

## 决策

### 1. 工作流只声明意图

LLM 调用增加三个请求级意图：

- `INHERIT`：不附加思考控制；智能助手运行时保持该语义。
- `PREFER_DIRECT`：在已证明支持时关闭思考；AI 翻译、术语抽取和普通校对使用该语义。
- `PREFER_LOW`：在已证明有低强度控制时请求低强度思考；严格策略中经过本地快速判断后仍需 LLM 裁决的条目使用该语义。

意图不是用户配置项，也不写入全局 `LLMConfig`。不支持目标意图时按 `PREFER_LOW -> PREFER_DIRECT -> INHERIT` 保守降级。

### 2. Provider 协议负责探测与参数映射

OpenAI-compatible 协议使用固定、有限的协议字段候选进行握手探测，不按供应商或模型名分支。每个候选先发送非法哨兵值；只有服务端明确校验该字段后，才分别验证协议存在的合法关闭值和低强度值。服务端接受非法值说明字段可能被忽略，不能判定为支持。响应中的 reasoning 内容或 reasoning token 仅作“没有关闭成功”的辅助证据；低强度请求出现 reasoning 证据属于预期。

Anthropic 协议以省略 `thinking` 作为直接回答机制，不为低强度思考猜测跨版本参数。未来如协议形成稳定低强度合同，应通过提高探测版本扩展该协议实现。

探测只能证明控制字段得到服务端验证并可用，不能证明供应商内部绝对没有隐藏推理。

### 3. 隐式初始化并持久化能力

请求作用域包装器创建时在后台启动单飞探测；首个相关请求若探测尚未完成，会在工作线程等待同一个结果，不阻塞 Qt 事件循环，也不会重复探测。

结果写入独立、版本化的 `llm_reasoning_capabilities.json`，键由协议、规范化 Base URL 的不可逆摘要、模型名和探测版本组成。记录状态、机制和探测时间，不包含端点原文、凭据或请求/响应内容。缓存过期、探测版本变化或正式请求明确拒绝已缓存控制字段时失效并允许后续重探测。

状态包括 `supported`、`unsupported` 与 `indeterminate`；运行中的 `probing` 只存在内存中。能力分别记录 direct 与 low 机制，因此模型可以处于“不能关闭但可请求 low”的受支持状态。`unsupported` 表示协议字段被识别但两个目标控制均不可用，`indeterminate` 表示字段可能被忽略或探测被非能力错误打断。

### 4. 包装顺序保持现有运行语义

Provider 客户端最内层接收请求级控制，其外依次保留共享并发限制和工作流日志包装。能力探测不计入 ADR-028 的业务阶段调用次数，也不携带用户翻译数据；业务校对仍只有一次正式调用。智能助手的共享 LLM 运行时不安装该作用域包装器。

## 关键契约与错误语义

- 能力未知、探测失败或低强度不可表达时，正式请求不得携带未经证明的控制参数。
- Prompt cache 降级重试只移除缓存字段，必须保留已验证的思考控制字段。
- 已缓存字段在正式请求中收到明确的 400/422 参数拒绝时，以短期 `indeterminate` 负缓存抑制重复探测并以 `INHERIT` 重试一次；认证、限流、超时和普通模型错误原样上抛。
- 同一能力键在一个进程内最多有一个探测执行者；并发调用等待同一结果。
- 假客户端或第三方 `LLMClient` 未实现能力协议时自然降级为 `INHERIT`，保持现有测试与扩展兼容性。

## 备选方案

### 全局配置关闭思考

会同时改变智能助手，并把工作流策略泄漏到供应商配置，拒绝。

### 维护供应商/模型能力表

无法覆盖用户自填代理地址和快速变化的模型版本，且会形成长期维护负担，拒绝。

### 只发送关闭参数并把 HTTP 200 当作支持

许多兼容网关会静默忽略未知字段，存在假阳性，拒绝。

### 每次请求都探测

增加延迟、费用和限流风险，拒绝；采用版本化持久缓存与运行时失效。

## 影响、迁移与回退

- 不迁移 `transbridge.ini`，也不新增用户可见 Provider 配置。
- 首次使用一个协议、地址和模型组合时会产生少量无用户数据的探测请求；后续使用持久化结果。
- 删除能力缓存文件即可回到未探测状态；移除请求作用域包装器即可完全恢复既有继承行为。
- 新增控制机制时提高探测版本，使旧缓存自然失效，不按模型名添加特例。
