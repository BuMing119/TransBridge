# ADR-028：Proofread 校对与具名自定义工作流

- **状态**：已采纳（2026-08-27；同日增补命名迁移与有界恢复决策）
- **日期**：2026-08-27
- **对应需求**：FR5.13.10、FR6.9
- **关联 ADR**：ADR-019、ADR-021、ADR-026
- **取代**：ADR-026 第 3 节关于默认完整多阶段校改链的决策；ADR-026 的候选、冻结档案和单一提交边界继续有效

## 背景与约束

现有默认校改会对同一批译文依次执行 LLM 检测、修复、润色和裁决，造成重复输入和高 Token 成本。仓库中翻译后处理与独立/混合润色还存在两套组装路径，仅修改界面开关或 `LLMPolisher` 会产生入口语义分叉。与此同时，用户需要第四个「自定义」入口和可复用的具名配置，但现有运行控制器、作用域和报告只证明了翻译、润色、混合三种业务执行语义。

改动必须继续复用共享请求并发预算、Token 批次规划、候选式处理、暂停/取消、日志与受控提交；不得把语义判断迁移为易误判的本地规则，也不得新增第四套 Worker。

## 决策

### 1. 显式区分校对与严格策略

有效执行档案增加显式处理策略：

- `proofread`：默认策略，仅执行一个 Proofread 校对业务阶段。
- `strict`：兼容策略，按用户开关执行独立检测、修复、润色和裁决。

新建的翻译、润色和混合内置预设默认使用 `proofread`。旧 `combined` 值只在配置、具名 profile、Smart Assistant 参数和 Python 导入的兼容边界被接受，读取后立即归一为 `proofread`，新写入与对外展示不再产生 `combined`。已有明确保存且没有策略字段的旧预设仍按 `strict` 解释，避免把用户既有阶段选择静默改义。策略进入执行档案摘要和 digest，checkpoint 不得跨策略复用。

### 2. Proofread 校对的职责与返回合同

校对阶段接收原文、当前译文、上下文和该条目相关术语，要求模型依次处理语义纠错、术语语境、流畅度和风格；原译文合格时原样返回。批量响应只包含稳定条目标识和最终译文，不要求修改理由、模型自报置信度或裁决字段。

同一个应用层阶段实现同时供翻译后处理和独立/混合润色适配，避免两条路径再次漂移。阶段继续使用既有 `StableContentBatcher`、全流程 `LimitedLLMClient` 和工作流日志包装器。

### 3. 本地只维护技术可用性

本地验证只检查：

- JSON/结构可解析；
- 响应键与请求键严格一一对应，不缺失、不重复、不出现未知键；
- 最终译文非空；
- 原文中的程序占位符和格式标签按多重集合保持。

本地不检查或改写数字、人名、否定、引号、括号、长度、改动比例和自然语言术语。技术无效的条目保留原译文并记录诊断；技术有效的结果直接形成候选，不自动追加 LLM 裁决。

技术无效不会立即成为最终失败。阶段先移除完整的 Markdown JSON fence、`<think>` 前缀和 BOM；仍无效时只重试失败条目子集一次，恢复响应整体仍无效且子集大于一条时仅二分一层。Provider 异常只额外发起一次逻辑调用，取消零重试。中间失败诊断不进入最终失败数，只有恢复后仍无效的条目保留失败诊断和原译。

### 4. 「自定义」是元入口而不是第四个运行模式

每个具名自定义配置声明 `base_mode = translate | polish | mixed`。界面选择自定义配置后，启动时解析为对应基础模式并原样复用其作用域、预检、Worker、报告和提交语义。首版不支持任意 DAG，也不允许关闭基础业务动作；自定义负责保存处理策略、严格阶段开关、运行额度，以及混合模式的执行顺序和动作规则。

自定义配置使用独立、版本化的 JSON 仓库和导入/导出 envelope。白名单明确排除模型、供应商、Base URL、API Key、Token、凭据引用、Embedding 凭据和本地术语路径；这些值始终从当前全局配置继承。导入采用全量校验后原子替换，任何未来 schema、非法枚举、越界值、重复 ID 或疑似秘密字段都会拒绝整个导入。

## 关键契约与错误语义

- `proofread` 始终只有一个业务判断阶段，不得创建 QualityGate、Refiner 或 Arbiter 请求；为获取同一 JSON 合同而发起的有界恢复调用不构成新的业务阶段。
- 同文返回是合法成功，不产生无意义写入；兼容结果中的 `confidence=1.0` 仅表示技术响应有效，不表示模型置信度。
- 标准阶段必须由共享请求预算包装，等待、失败、暂停和取消不得泄漏并发槽。
- 自定义配置没有可用项时开始按钮禁用，不得静默回退为翻译。
- 自定义配置 overlay 只作用于 detached execution config，不得污染全局服务设置或三个内置预设。
- 严格策略保留 ADR-026 的阶段顺序、候选传递、预览和保守提交语义。

## 备选方案

### 仅关闭默认检测、修复和裁决开关

无法表达兼容迁移，也容易让翻译后处理和独立润色两条组装路径继续分叉，拒绝。

### 继续让现有 `FormatValidator` 负责标准本地验证

该组件还检查引号、括号、非法字符和零宽字符，超出技术完整性边界并会产生误拒绝，拒绝。标准阶段使用独立的程序标记验证器。

### 为「自定义」新增第四套 Worker 和作用域

会复制 mixed/translate/polish 的运行、恢复和报告状态机，增加未证明的组合语义，拒绝。采用具名配置加基础模式解析。

## 影响、迁移与回退

- 新用户和新建预设获得默认校对流程；旧 `combined` 配置自动迁移，旧的无策略明确保存配置继续按严格策略执行。
- 运行面板只显示「校对」，严格策略继续显示实际多阶段链。
- 具名配置仓库不存在时视为空，不修改现有 `transbridge.ini`；内部库与导入/导出共用 schema v1。
- 若标准阶段回归，可把预设切换为 `strict` 复用旧链；不得删除具名配置或恢复默认多次扫描。
