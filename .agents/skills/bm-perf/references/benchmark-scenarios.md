# TransBridge 性能场景

在项目确定正式基准数据前，以下是场景选择准则，不是可直接声称通过的性能门槛。

## 转换路径

- 小型输入：用于发现固定开销和启动退化。
- 常见输入：反映普通用户的转换耗时和内存。
- 大型输入：用于检查批处理吞吐量、峰值内存和算法复杂度。

每个样本应记录来源、文件格式、条目数、文件大小和是否允许提交到仓库。含用户数据或受版权限制的样本不得提交；可用脱敏的合成 fixture 代替。

## 翻译与 AI 路径

- 将本地解析、提示构建和后处理与远程 LLM 请求分开计时。
- 除非专门验证服务端体验，否则使用 mock 或离线 fixture，避免网络波动掩盖本地回归。
- 首次模型加载与热缓存运行必须分别记录。

## UI 路径

- 记录打开大文件、首次渲染、筛选/搜索、批量操作等用户可感知动作。
- 优先使用自动化测试或分析器；人工测量必须写明步骤、计时起止点和重复次数。

## 基线记录

经用户确认需要长期保存时，在 `docs/performance/` 中记录：场景版本、环境、命令、原始结果、中位数、范围和对应提交。输入样本变更后，应新建或明确更新场景版本，不能直接与旧结果混比。
