# BM 发布验证

## 目标

确认候选版本可从受控环境构建、安装并运行核心入口，且版本、许可证、校验和与发布说明彼此一致。

## 意图与写入权限

- “发布检查/准备发版”默认只读或仅构建本地临时产物；不改版本号、不创建 Git tag、不上传包、不创建 Release。
- “制作本地候选包”可在用户同意的输出目录构建，但不覆盖已有发行物。
- 更新版本、更新日志、签名、上传或正式发布均须由用户明确授权。

## 执行约定

1. 先读取 `plans/release-hardening-v2/plan.md`、当前 Git 状态、`pyproject.toml`、`src/transbridge/_version.py` 和相关发布脚本/配置。
2. 检查版本单一来源及 `docs/更新日志.md` 是否反映用户声明的发布范围；不擅自补写发布说明。
3. 先运行最小发布基线：`tests/packaging/test_package_baseline.py` 与 `tests/packaging/test_clean_release_smoke.py`；再按风险扩展相关功能测试和最终 QA 门禁。
4. 构建验证必须从干净 checkout 或等价隔离环境开始，并记录 Python、依赖锁、命令、Git 提交和工作树状态。
5. 若存在候选发行物，记录 SHA-256、版本和许可证清单，并验证安装态不依赖仓库 `src` 路径。
6. GUI、CLI `--help` 和 MCP stdio 的 smoke 应尽量在目标安装态执行；目标 Windows 安装/升级/卸载验证不能被开发机源代码运行替代。

## 发布阻断

以下情况应标为 Blocker，停止把候选包表述为“可发布”：构建失败、核心入口无法启动、版本不一致、安装态依赖源码路径、缺失必要许可证证据、校验和不一致，或应有的干净 Windows 环境验证缺失。

## 报告

报告包含：候选版本、Git 状态、环境/锁定依赖、运行命令和退出码、产物路径及哈希、入口 smoke 结果、许可证状态、未完成验证与原因、以及是否具备发布条件。

若用户要求保存报告，遵循仓库 `docs/test-reports/` 的既有命名和证据格式。
