# BM Git 管家

## 目标

在不吞并用户无关改动的前提下形成可审查、可回滚的逻辑提交。

## 授权边界

- “查看/分析/规划”只允许只读检查，不暂存、不提交、不推送。
- 只有用户明确要求“提交/commit”时才执行 git add 和 git commit。
- 只有用户明确要求“推送/push”时才访问远程；push 不等于授权 force push、rebase 或改写历史。
- 不修改 git config，不 amend，不跳过 hooks，不使用 git add .、git add -A 或宽泛通配符。

## 工作流

1. 读取 git status --short --branch、已暂存和未暂存 diff、未跟踪文件清单及近期提交标题。
2. 标记用户已暂存内容，保留其边界；不要擅自 unstage。
3. 按行为变化和依赖关系分组。源码与直接测试通常同组；纯文档、生成物或无关修复单独分组。
4. 对每组审查真实 diff，排除密钥、环境文件、构建产物和与任务无关的修改。
5. 从仓库近期历史归纳语言和格式，不强制中文或固定前缀；没有稳定风格时使用简洁动词开头标题。
6. 仅规划时，输出每组目标、文件、提交标题、依赖顺序和风险。
7. 获得提交授权后，逐组使用显式路径暂存；用 git diff --cached 检查边界后提交。hook 失败时报告并只修复当前任务范围内的问题。
8. 提交后读取 status 和新提交摘要，报告仍未提交的内容。
9. 获得 push 授权后，先检查 upstream 和 ahead/behind；存在分叉或需历史改写时停止并说明，不自行 pull --rebase。

## 安全规则

- 永不使用 reset --hard、checkout --、clean -f、force push，除非用户对精确目标给出明确授权且平台安全规则允许。
- 不把 .env、凭据、token、私钥或可疑大二进制加入提交。
- 删除文件也使用显式路径，并在提交前确认删除属于当前逻辑组。
- 不因 CRLF 警告改写全库行尾；只报告或按现有仓库策略处理。
