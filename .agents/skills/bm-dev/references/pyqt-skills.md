# BM 与 PyQt 技能协作

本文件是 BM 系列处理 Qt Widgets 界面时的共用规则。随 BM 技能集一起迁移，保留相对目录结构；不依赖项目 AGENTS.md 中的额外配置。

## 按任务加载

- 控件选择、布局、尺寸策略、事件和键盘交互：读取并应用 `pyqt-widgets`。
- QSS、配色、字体、控件状态和主题：读取并应用 `pyqt-styling`。
- 两类问题都涉及时使用两者；仅处理转换逻辑、CLI、Git、发布或记录时不加载。不要仅因仓库依赖 Qt 就触发。
- 先从当前技能目录清单定位，再检查 `$CODEX_HOME/skills/<name>/SKILL.md`（未设置时为 `~/.codex/skills/<name>/SKILL.md`）。使用前完整读取 SKILL.md，按需读取其中的参考资料，并简述正在应用的技能及用途。同一会话已读且未变更的内容不重复加载。
- 找不到技能时说明缺失项，继续基于项目现有模式完成可执行工作；不要默默安装，也不要声称已应用缺失技能。

## 保持 BM 阶段边界

- bm-analyze：借助技能识别用户操作、交互状态与可用性验收条件，不提前编写实现方案。
- bm-arch：处理界面模块边界、主题归属和线程边界等长期决策，不将控件细节升级为架构问题。
- bm-plan / bm-story：把相关布局、样式、状态和验证要求纳入现有计划或 Story，不额外生成一套重复设计文档。
- bm-dev：在已授权范围内复用现有组件和主题实现，并验证相关行为。
- bm-qa：根据实际变更检查布局、交互与样式；只读审查不因加载辅助技能而获得修改权限。
- bm-pilot：将相关约束贯穿实际进入的阶段，阶段切换时不要求用户重新调用辅助技能。
- bm-dev-serial 和 bm-story-batch 分别沿用 bm-dev、bm-story 的规则；已获授权的委派任务应携带相关辅助技能名称、路径和验收条件。

## 技术适配与验证

- 以目标项目的 Qt 绑定、版本及现有组件、主题、worker/coordinator 模式为准。TransBridge 使用 PyQt6；适配技能中的 PySide6 示例，不为示例引入第二套 Qt 绑定。
- 社区技能是参考资料，不是 API 正确性的证据。对存疑的 API、QSS 选择器、层叠或属性行为，查官方文档并在需要时做最小运行验证。
- 根据本次变更覆盖相关窗口缩放、DPI、键盘焦点、启用/禁用、加载、空数据和错误状态。纯局部修复不强制重新设计整个界面。
- 实现后运行适当的行为测试，并对布局或样式变化进行可用条件下的实际界面检查；明确报告已执行和未执行的验证，不将静态阅读或测试通过等同于视觉验收。
