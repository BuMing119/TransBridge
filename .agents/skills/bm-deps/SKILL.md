# BM 依赖审计

## 目标

将直接依赖、锁定解析结果、运行时能力和许可证/安全风险对应起来，区分可执行建议与需要用户决策的风险。

## 意图与写入权限

- “依赖审计/检查漏洞/许可证检查”默认只读：不更新锁文件、不升级包、不联网安装依赖。
- “升级依赖”仅在用户明确指定范围后修改 `pyproject.toml`、锁文件或测试；破坏性升级须先说明兼容风险和回退方式。
- 涉及外部漏洞数据库、许可证信息或包索引时，先说明数据来源、查询时间和网络可用性；无法查询时不得声称“无漏洞”。

## 执行约定

1. 读取 `pyproject.toml`、锁文件（如存在）、导入点、可选能力定义和 `tests/packaging/` 的能力/许可证基线。
2. 区分直接依赖、间接依赖、开发依赖和可选能力；不要只用环境中已安装的包替代项目声明。
3. 对每个风险说明影响版本、来源、是否可达、受影响功能和建议处置。无可达证据的风险应标为“待确认”，而非直接归为应用漏洞。
4. 许可证审计应记录包名、版本、许可证证据位置和分发形态；缺失元数据应列为需人工确认项。
5. 升级建议按低风险补丁、需要回归验证的功能升级、可能破坏兼容性的主版本升级分组，并列出对应测试。
6. 对 PyQt、Torch、FAISS、LLM SDK 和压缩/游戏格式依赖，重点检查 Windows 打包兼容性、可选能力降级和许可证随发行物携带情况。

## 报告

报告包含：审计范围、声明与锁定状态、数据来源及时间、风险等级、证据、可达性、建议和未能检查的项目。用户要求持久化时，按仓库既有 `docs/test-reports/` 结构写入报告。

## 边界

- 不将“最新版本”视为自动应升级版本。
- 不在缺少联网数据时得出安全结论。
- 不为消除告警而移除仍被生产路径使用的依赖。
